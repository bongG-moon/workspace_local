실제 목록 삭제 API 검사에서 앱 대화 기록과 가상 원본을 포함한 파일 5개의 SHA-256이 삭제 전후 동일했습니다. 본문이나 실제 Claude 기록을 삭제하는 경로를 추가하지 않았습니다.

별도 코드 검토에서 발견한 두 경합도 수정했습니다. 삭제한 업무의 옛 알림을 눌러도 현재 업무의 메시지 갱신을 유지하며, 알림 표시 준비 중 질문을 해결하거나 업무를 숨기면 늦은 표시 및 busy 재등록을 취소합니다. 네이티브 호스트가 이미 수락한 표시 요청까지 원자적으로 철회하는 것은 보장하지 않습니다.

## 자동 검사

- 관련 31개 모듈: 550개 실행, 546개 통과, 4개 제외.
- 최종 경합 수정 후 영향 범위 재검증: 120개 실행, 119개 통과, 1개 네이티브 알림 opt-in 제외.
- 실행기·진단: 32개 실행, 31개 통과, 1개 Windows 환경별 진단 제외.
- 로컬 서버·기능 통합 최초 실행 137개 중 3개 실행기 검사는 샌드박스 사용자 때문에 WS-31 발생. 실제 로그인 사용자로 해당 3개를 다시 실행해 모두 통과. 이 문제를 우회하기 위해 사용자 검증을 약화하지 않았습니다.
- 제외된 네이티브 opt-in 검사는 실제 트레이 QA와 구분합니다. Windows 심볼릭 링크 생성 권한이 없어 해당 검사 1개를 제외했습니다.

검사 결과는 중복 실행을 포함하므로 총합을 독립 검사 개수로 합산하지 않습니다.

## 실제 EXE 및 ZIP

단일 EXE를 별도 한글 경로의 EXE만 있는 폴더에서 실행했습니다. 설치된 Python 3.13.5를 자동으로 찾았고 기존 Claude Code 2.1.285 인증으로 초기 연결을 완료했습니다. 초기 연결은 모델 claude-sonnet-5-5, effort medium, 명령 141개를 보고했으며 AI 사용자 요청은 보내지 않았습니다. 두 번째 실행은 동일 서버 PID와 창을 재사용했습니다. 테스트 종료 후 개인 설정 5개 비교에서 변경은 0개였습니다.

VBS용 ZIP의 압축 해제 후 서버·인증 API·화면 자산·한글 폰트·안내서·가상 업무·정상 종료를 검사했습니다. 실제 VBS 아이콘 더블클릭은 이 검사와 별개입니다. EXE와 VBS는 동일 소스 100개 및 검증된 네이티브 자산 7개를 포함합니다. Python 설치 파일이나 개인 인증·대화·자료는 포함하지 않습니다.

## 확인된 한계

실제 PC에서 창을 숨긴 후 Windows 알림 조회는 HRESULT 0 / 상태 코드 2였으며, 네이티브 호스트는 notificationReason=suppressed, accepted=false를 반환했습니다. 따라서 이 상태에서 PC 배너가 실제로 표시됐다고 주장하지 않습니다. 앱 설정이나 PC 알림 정책은 변경하지 않았습니다. 질문·완료는 앱 알림함에 남으며, 배너 표시가 허용되는 PC 상태에서 최종 시각 확인은 추가로 필요합니다.

백그라운드 예약·질문 검사는 실제 네이티브 창·서버·디스패처와 가상 Claude 이벤트로 수행했습니다. 이번 변경 검증에서 실제 AI에게 예약 요청을 보내거나 회사 HCP/DRM·다중 모니터·네트워크 폴더를 새로 검증한 것은 아닙니다. 네트워크·특수 폴더는 보조 Windows 선택창을 이용합니다. 잠자거나 꺼진 PC를 깨우는 기능은 없습니다.

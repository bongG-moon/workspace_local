# Workspace 0.17.0: 창 재사용과 대화 이어가기

## 사용 중 달라지는 부분

- 실행 아이콘, 트레이 열기, 알림에서 열기는 같은 앱 창을 찾고 활성화합니다. 최소화하거나 숨겨 둔 창도 다시 표시합니다. 창을 실제로 닫았다면 새 창을 열고 기존 서버와 업무를 유지합니다.
- Edge를 찾지 못하면 설치된 Chrome을 주소창 없는 앱 창으로 실행합니다. 기본 경로 외에 Windows에 등록된 App Paths도 조회합니다. 두 브라우저를 모두 실행할 수 없을 때만 기본 브라우저를 사용합니다. 브라우저 설치나 기본 앱 설정은 바꾸지 않습니다.
- 넓은 화면에서 왼쪽 영역은 268px입니다. 업무 행의 위아래 여백을 줄였습니다. 좁은 화면의 접힘 동작은 유지합니다.
- 같은 이름의 새 업무, 이름 변경, 대화 불러오기, 분기에 `(2)`, `(3)`을 붙입니다. 첫 질문으로 이름을 자동 지정할 때도 적용합니다. 기존 업무 이름과 실제 폴더명은 바꾸지 않습니다.
- **이전 대화 → 대화 선택 → 업무에 추가하고 이어가기**를 누르면 원래 폴더와 Claude 세션 ID를 가진 업무가 추가됩니다. 입력창에서 후속 질문을 보내면 `--resume`으로 이어집니다. 같은 세션을 이미 가져왔다면 기존 업무를 엽니다. 폴더의 후크·MCP 실행 전에는 기존 폴더 확인 절차를 유지합니다. 기존 터미널의 작업은 먼저 끝내 주세요.
- 스킬·도구 화면은 기본적으로 현재 살아 있는 연결을 선택합니다. 드롭다운에서 다른 업무를 직접 고르면 그 선택을 유지합니다. **연결하고 목록 확인**은 AI 질문 없이 CLI를 준비해 명령과 MCP 상태를 확인합니다. 도구 목록을 첫 실제 요청에만 제공하는 CLI도 있습니다. 이때는 `CLI 미제공`으로 표시하며, 목록이 0개라는 뜻은 아닙니다.

## 설계와 원인

기존 실행기는 서버를 재사용한 뒤에도 브라우저를 매번 `--new-window`로 열었습니다. 이제 인증된 기존 서버의 `/api/window/open`을 호출합니다. 서버는 창을 열기 전에 실행별 임의 제목, 브라우저 실행 파일, 사용자 SID, 로그인 세션, 프로세스 생성 시각을 검증합니다. 재사용 요청 실패를 새 창 실행으로 바꾸지 않아 일시적인 오류로 창이 늘지 않게 했습니다. 초기 페이지 로딩 중의 중복 클릭도 합칩니다. 다른 버전의 서버가 실행 중인 경우 기존 버전 충돌 안내를 유지합니다.

일부 PC에서 Chrome 탭으로 열리는 것은 기존의 Edge 고정 경로 탐색 실패 후 기본 브라우저로 연결하던 동작이 원인 후보였습니다. 이번 버전은 등록 경로와 Chrome 앱 모드를 추가합니다. 회사 정책이 브라우저 앱 모드를 제한하는 모든 환경을 보장하지는 않습니다.

`[ede_diagnostic]`은 Claude CLI가 반환한 실행 실패 진단입니다. 앱은 이를 성공이나 최종 답변으로 표시하지 않고 남은 승인·질문 상태를 종료한 뒤 같은 세션의 후속 요청을 받습니다. 작업을 자동 재실행하지 않습니다. 오류 전에 실행된 파일 변경은 되돌리지 않으므로 결과를 확인한 뒤 이어서 요청하세요. 상류 SDK에는 중단 이후 같은 계열의 오류가 보고되어 있으나, 이번 사용자 사례의 원인이 동일하다고 단정할 근거는 없습니다. [상류 재현 사례](https://github.com/anthropics/claude-agent-sdk-typescript/issues/366).

이전 대화 불러오기의 백엔드는 원래 세션 ID를 보존하고 있었습니다. 이번에는 추가 버튼을 스크롤과 분리하고, 추가 이후 같은 대화에서 후속 질문을 보낼 수 있다는 안내를 명시했습니다. 재개한 CLI가 다른 ID를 보고하면 새 대화로 조용히 대체하지 않고 중단합니다. 원본 JSONL을 앱이 수정하지 않습니다. 이후 Claude 자체의 정상 대화 기록은 계속 저장됩니다.

목록의 `연결 전`은 설치된 스킬과 실행 중 CLI의 보고 목록을 같은 상태로 취급하면서 생긴 혼동입니다. 공통 설치 스킬과 선택한 업무의 실행 정보는 여전히 구분합니다. 연결 준비 시 SDK의 `mcp_status` 읽기 제어를 사용하고, 서버의 인증 정보·URL·설정은 화면 데이터로 복사하지 않습니다. CLI가 제공하지 않은 도구 목록을 추정해 채우거나 목록 확인용 가짜 AI 질문을 보내지 않습니다.

## 유지하는 사항

기존 Windows/UAC, Claude 인증·모델·승인 설정, 개인 스킬·MCP·플러그인·후크를 변경하지 않습니다. Company Agent 설치를 요구하지 않습니다. EXE는 기존 설치 Python과 Claude를 확인하는 실행기이며 Python 설치 파일을 포함하지 않습니다. 통합 알림함, 대기열, 예약, 단축키, 파일 비교와 대화 분기는 유지합니다.

검증 결과와 운영 환경에서 남은 확인은 [검증 기록](https://github.com/bongG-moon/workspace_local/blob/main/docs/VALIDATION_0.17.0.md)에 구분합니다.

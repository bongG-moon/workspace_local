# Company Workspace 0.21.10 — 좌우 패널 색상 복원

검증일: 2026-10-02 (한국 시간). 색상 복원과 버전 전환, 배포 묶음의 검증 범위를 기록합니다.

## 원인과 수정

- 기존 색상 복원본과 파란색 배포본이 모두 0.21.9였습니다. 같은 버전을 실행하면 백그라운드 앱을 다시 사용하므로 새 EXE에 포함된 스타일로 전환되지 않을 수 있었습니다.
- 실제 사용자의 실행 중인 0.21.9 서버에서 파란색 패널 스타일이 계속 제공되는 것을 확인했습니다. 직전 전달 EXE의 내장 CSS에는 해당 스타일이 없었습니다.
- 좌우 패널의 추가 색상 규칙을 제거한 상태를 유지하고 복원본의 버전을 0.21.10으로 구분했습니다. 서버, 실행기, 묶음 이름, 진단 대상 버전과 진단 소스 해시를 함께 갱신했습니다. 버전 전환 정책 자체는 변경하지 않았습니다.
- 업무 자료 목록, 파일 확장자 표시, 폴더·결과 카드, 자료·결과 탭, 선택·호버 상태를 포함한 기존 CSS는 라벤더 적용 전 커밋 `90ea216`과 같습니다. 이후 추가된 HTML 화면/코드 전환과 단축키 안내 기능은 유지합니다.

## 검증 결과

- 자동검사: 버전 전환·시작 진단 관련 39개 중 **38개 통과, 1개 건너뜀**. 실제 사용자 토큰 검사는 별도 opt-in 조건으로 제외됐습니다.
- EXE 내장 파일 117개의 해시와 압축 해제를 검증했습니다. Python 설치·다운로드는 하지 않습니다.
- VBS ZIP을 격리된 폴더에 풀어 앱 서버를 시작하고, 버전·초기 상태, 인증 경계, 주요 화면 자산, 자료 목록·업무 API, 정상 종료의 5가지 항목을 확인했습니다. WSH 더블클릭 전체 경로를 재시험한 것은 아닙니다.
- 합성 자료를 사용한 실제 네이티브 업무 화면에서 오른쪽 자료 목록과 파일 표시를 확인했습니다. 시험용 앱은 정상 종료했습니다.
- 현재 PC의 실제 앱을 0.21.9에서 0.21.10으로 정상 전환했습니다. 진행 중인 업무가 없는 것을 먼저 확인했으며, 강제 종료는 하지 않았습니다.
- 실제 앱의 서버 PID 교체, 업무 ID 6개 보존, 확인 대상 개인 설정 파일 4개의 해시 보존을 확인했습니다.
- 전환된 실제 앱이 제공하는 CSS가 복원 소스와 바이트 단위로 일치하며 파란색·라벤더 패널 추가 규칙이 모두 없는 것을 확인했습니다.
- 실제 0.21.10 네이티브 창 하나에서 업무 폴더의 파일 11개가 표시되는 자료 패널과 원래 색상을 직접 확인했습니다.

## 실제 Claude 연결에서 확인한 원인

Claude Code 2.1.306에서 텍스트 응답 중 `apply_now`를 실행하면 다음 중지 진단이 반환되는 것을 두 차례 재현했습니다.

```text
[ede_diagnostic] result_type=user last_content_type=n/a stop_reason=null
```

기존 코드는 `stop_reason=tool_use`만 예상된 중지로 구분했습니다. 따라서 위 응답을 실제 실행 오류로 처리해 대기 요청 전환을 멈췄습니다. 재현 당시 CLI 프로세스는 계속 살아 있었으며, 화면의 연결 표시와 오류 상태가 동시에 나타날 수 있었습니다.

수정 후에는 현재 세션에 실제 중지 요청이 대기 중인 경우에만 이 정확한 null 진단을 인정합니다. 중지 ACK와 종료 응답을 모두 받은 뒤에만 다음 요청을 전송합니다. 정상 전환 시 기존 CLI 프로세스·세션·선택 설정을 유지합니다. 중지 요청이 없거나 진단이 섞였거나 알려지지 않은 오류인 경우에는 계속 실패로 처리하며, 이전 요청을 자동 재실행하지 않습니다.

실제 오류 이벤트에는 제출 여부·중지 ACK 여부·허용된 진단 필드만 추가했습니다. 원문 stderr, 대화 본문, 인증 정보는 추가 기록하지 않으며 별도 기록 스레드도 만들지 않았습니다.

## 클릭 지연과 화면 갱신 개선

- 한 번에 수신한 이벤트 전체를 동기 처리하던 루프를 최대 16개 또는 8ms 단위로 나누어 포인터·키보드 처리가 끼어들 수 있게 했습니다.
- 각 상태 이벤트가 기존 목록 조회를 취소하고 새 조회를 시작하던 동작을 동시 1개 조회와 후속 갱신으로 합쳤습니다. 브라우저의 요청 취소가 이미 시작한 서버 작업까지 취소하지는 않는 문제를 줄였습니다.
- 진행 기록의 SQLite 저장·조회와 느린 HTTP 응답 전송을 전역 앱 잠금 밖으로 이동했습니다. 기록은 동기적으로 저장하며, 요청/세션을 다시 검증해 늦은 기록을 다음 요청으로 잘못 표시하지 않습니다.
- 진행 기록의 작은 집계 값만 캐시합니다. 대화 이벤트 메모리 상한을 변경하거나 새 백그라운드 저장 스레드를 추가하지 않았습니다.
- HTTP 이벤트 응답은 잠금 안에서 복사한 스냅샷을 사용해 순서 번호와 상태의 일관성을 유지합니다.
- 이벤트 조회의 일시적인 네트워크/5xx 오류만 250·500·1,000·2,000ms 간격으로 재시도합니다. 마지막 처리 순서 이후부터 읽으며 작업 전송은 재시도하지 않습니다. 인증 오류·잘못된 요청·업무 전환·종료에서는 중단합니다.

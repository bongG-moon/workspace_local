# 0.23.20 백그라운드 프로세스·대기 부하 개선

검증일: 2026-10-06. 버전은 0.23.20을 유지하며, 앞서 수정한 버튼 반응성·실행 중 승인 모드 변경도 포함합니다.

## 확인 범위

운영 PC의 프로세스 기록은 받지 못했으므로, 당시 많이 남았던 PowerShell이 전부 Workspace에서 생성됐다고 단정하지 않습니다. 점검 시 개발 PC에서 발견한 PowerShell 2개는 BixbySystray가 시작한 프로세스였습니다. 다른 프로그램의 프로세스는 종료하지 않았습니다.

기존 Claude 설치의 실행 스크립트나 PowerShell 함수를 이용하는 경우, 연결된 업무마다 PowerShell이 실행되는 것은 정상일 수 있습니다. 앱의 동시 Claude 연결 한도 3개를 유지합니다. 창의 X 버튼은 백그라운드 유지이며, 트레이의 완전 종료와 다릅니다.

## 수정한 원인

- CLI 버전·지원 옵션 확인에서 기존 `subprocess.run(timeout=...)`은 래퍼만 종료했습니다. 자식 PowerShell이 출력 파이프를 상속하면 시간 제한 이후에도 대기가 끝나지 않을 수 있었습니다. 짧은 확인 작업은 실행 전 Windows Job에 배정하고, 성공·실패·시간 초과·취소 모두에서 소유한 프로세스와 자식만 정리합니다. 출력은 임시 파일로 받아 메모리와 파이프 대기를 제한합니다.
- 동일한 관리 방식을 시작 조건 검사, WebView2 검사, 제한된 로컬 관리 명령, 파일 선택 창에도 적용했습니다. 사용자 앱 열기와 장시간 Claude 연결, 새 앱으로 넘기는 실행기는 서로 수명이 다르므로 기존 목적에 맞는 별도 소유 경로를 유지합니다.
- 단일 EXE가 90초 후 시작 실패를 표시하면서 시작용 PowerShell을 남기던 경로를 수정했습니다. 버전 전환 실행기 역시 자기가 생성한 PowerShell의 완료를 기다리고, 시간 초과 시 해당 핸들만 정리합니다. 분리 실행된 정상 앱을 함께 종료하지 않습니다.
- 업데이트 시작 확인의 시간 초과·취소에서도 인계되지 않은 실행기를 정리합니다. 종료를 확인하지 못하면 재시도나 앱 종료를 성공 처리하지 않습니다. 이미 승인된 버전 인계는 유지합니다.
- 정리가 아직 끝나지 않은 경우 복구·재시도할 수 있도록 앱 창과 트레이를 유지합니다. 모든 정리가 확인된 뒤 창을 닫습니다.
- 파일 선택 창이 열려 있는 상태에서 앱을 완전 종료하면 선택 작업도 취소하여 종료 요청이 오래 대기하지 않게 했습니다.
- 예약 디스패처가 0.5초마다 모든 과거 업무에 대해 연결 가능 여부를 반복 계산하던 경로를 없앴습니다. 실제 대기 요청과 중간 지시가 있는 업무만 확인하며 예약 시각 검사 주기는 유지합니다.

## 검증

합성 CLI와 격리된 상태 폴더를 사용합니다. 개인 Claude 인증·프로필·MCP·Windows 보안 정책은 변경하지 않으며 실제 모델 요청을 보내지 않습니다.

- 실제 PowerShell 자식의 정상 완료 후 정리, 시간 초과, 취소, Job 배정 실패, 출력 제한, 커널 핸들 해제와 연속 확인 명령을 검사했습니다.
- 기존 파이프 대기 결함을 재현했습니다. 기존 방식은 1초 제한 후에도 3초 이상 대기했고, 수정된 방식은 소유 작업을 정리하고 반환했습니다.
- 실제 컴파일한 C# 실행기로 시간 초과 시 시작용 PowerShell 종료와 분리된 자식 보존을 확인했습니다.
- 저장된 업무가 3,000개인 합성 대기 상태에서 디스패처 1회 중앙값은 1,477.0759ms에서 0.0017ms로 줄었습니다. 이는 해당 대기 계산의 측정이며 전체 앱이 같은 비율로 빨라진다는 뜻은 아닙니다.
- 실제 PowerShell 래퍼와 합성 CLI로 8회 연결·작업·승인 모드 변경·중지·후속 요청·연결 종료를 반복했습니다. 매회 연결 종료 시 소유 프로세스 3개가 0개로 정리됐고 이전 연결까지 합산한 잔류 프로세스도 0개였습니다. 작업 중 `plan`/`auto` 변경과 중지 후 후속 요청은 PID·세션을 유지했습니다. 앱 완전 종료 후에도 소유 프로세스는 0개였습니다.
- 프로세스 도우미 13개, 예약·대기열·모드·중지/재개 132개, 업데이트·설치·라우트·GitLab 107개, 직전 반응성·승인 모드·단축키 76개 테스트가 각각 통과했습니다. 테스트군은 일부 범위가 겹치므로 단순 합산하지 않습니다.
- 스킬·선택적 하네스·조회 49개가 통과했고 외부 코어가 필요한 19개는 건너뛰었습니다. 실제 운영 PC의 외부 코어·보안 제품·사용자 프로필 조합은 이번 격리 시험에서 검증한 것으로 표시하지 않습니다.

## 적용

같은 버전의 수정본이므로 기존 앱을 트레이에서 **완전 종료**한 뒤 새 EXE를 실행합니다. 이미 열린 동일 버전 프로세스가 있으면 실행기는 기존 창을 재사용합니다. 운영 PC의 개인 프로필이 별도로 만든 프로세스까지 임의로 종료하지 않습니다.

이 문서는 로컬 구현·검증 결과입니다. 같은 버전의 공개 수정본은 [GitHub Release](https://github.com/bongG-moon/workspace_local/releases/tag/v0.23.20)의 변경 안내와 체크섬으로 확인합니다. 사내 GitLab 게시 자체는 사내 PC에서 별도로 진행해야 합니다.

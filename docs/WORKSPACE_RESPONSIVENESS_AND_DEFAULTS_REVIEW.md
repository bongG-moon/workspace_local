# 작업 목록 응답성과 승인 기본값 점검

검증일: 2026-10-22. 앱 버전은 **0.23.29**로 유지합니다. 이 문서는 소스 변경과 격리 검증 결과이며, 설치 파일 재배포 완료를 뜻하지 않습니다.

## 확인한 원인과 변경

| 항목 | 확인한 상태 | 변경 |
| --- | --- | --- |
| 일반 대화·업무 숫자 | 숫자가 레이블과 같은 흐름에 들어가 좁은 폭에서 줄바꿈될 수 있음 | 한 자리 숫자 공간 16px 예약, 한 줄 레이블, 접힌 사이드바 배지 별도 정렬 |
| 출력 중 목록 처리 | 닫힌 목록 관리 창의 큐·예약 행을 다시 생성함 | 창이 열렸을 때만 상세 행 생성, 닫으면 해제, 예약 내용이 같으면 노드 재사용 |
| 긴 응답 | 작은 출력 조각마다 전체 본문 교체 및 완료된 대화 배열 복제 | 기존 텍스트 노드에 추가, 완료 메시지에서 기록 제한 적용; 표시 제한은 그대로 유지 |
| 같은 버전의 새 EXE | 이전 서버가 살아 있으면 버전 번호만 보고 기존 창을 재사용 | 시작 시 한 번 계산한 소스 빌드 식별값 비교; 다른 빌드/식별 불가이면 WS-48로 완전 종료 후 새 EXE 실행 안내 |
| 폴더 확인 | 앱 재시작 때 승인 상태가 초기화됨 | 앱 전용 설정에 명시적 폴더 승인과 폴더 신원 보관, 사용 전 재확인 |
| 승인 기본값 | CLI의 Manual 기본값을 그대로 사용 | 지원되는 업무 연결은 첫 요청 전 실제 Auto 적용 응답을 확인; 직접 고른 일반 승인 모드는 재시작 후 복원 |

Test 앱과 기존 배포본의 큐 코드는 동일했지만 저장 공간·WebView 프로필은 분리되어 있었습니다. 새 Test 상태와 기존의 많은 기록, 살아 있는 이전 프로세스가 차이를 만들 수 있습니다. HTTP 정적 응답에는 이미 `Cache-Control: no-store`가 있고 단일 EXE 실행 자료도 아카이브 해시별로 분리되므로, 단순 캐시 오염을 확정 원인으로 판단하지 않았습니다. 회사 PC의 이벤트 자료 없이 현장 원인을 단정하지 않습니다.

## 유지하는 동작

- 대기 요청·예약·작성 중인 입력·대화 기록을 삭제하거나 초기화하지 않습니다.
- 일반 대화의 도구 제한, 회사 정책, Windows 권한, 개인 Claude 설정은 유지합니다.
- Auto를 지원하지 않거나 적용이 거절되면 실제 승인 모드를 표시하고 안내합니다. Bypass로 대체하지 않으며 Bypass 승인은 영구 보관하지 않습니다.
- 폴더 승인 기록이 없는 기존 업무는 다음 명시적 확인부터 기억합니다. 다른 폴더 또는 교체된 폴더에 승인을 넘기지 않습니다. OneDrive Cloud Files 업무 폴더는 기존 지원 범위를 유지합니다.
- 같은 버전의 다른 빌드를 강제로 종료하거나 업무를 자동 재실행하지 않습니다. 버전 증가를 기준으로 하는 기존 업데이트 정책은 유지하며, 설정의 빌드 표시로 실제 실행 소스를 구분합니다.
- 진단 로그 상시 수집이나 별도 백그라운드 폴더 탐색을 추가하지 않습니다. 빌드 식별은 시작 시 한 번만 계산합니다.

## 검증

- 실제 Edge: 1440/1000px, 라이트/다크, 숫자 0/1/9, 접힌 사이드바 레이아웃 확인.
- 실제 Edge의 격리 자료: 메시지 150개·대기 요청 100개·예약 100개를 넣고 스트리밍 중 삭제·지금 반영·드래그 확인. 남은 대기 요청 98개와 입력 초안 유지, 페이지 오류 없음.
- 클릭 위치 흔들림 0/4/7/10px, 아이콘/버튼 여백, 클릭 중 레이아웃 이동, 영역 밖 놓기, 키보드 실행 등 20개 포인터 시나리오 통과.
- 실제 로컬 HTTP 서버 + Edge + 테스트 Claude 연결: 삭제·재정렬·지금 반영, 선택 요청 정확히 한 번 전달, 나머지 요청 및 초안 유지 확인.
- 재시작·Auto 거부/미지원·지연 응답·저장 실패·폴더 교체·OneDrive·사용자 선택 유지·개인 Claude 설정 불변 회귀 검증.
- Python/PowerShell 빌드 식별값 일치 확인. 복사 위치/사용자 상태는 식별값에 영향 없음. 실제 실행기 복사본에서 동일 빌드 재사용, 다른/구형 빌드 거절, 더 높은 실행 버전 유지 확인.

동일한 큰 자료로 닫힌 목록 갱신 100회를 5회 측정한 중앙값은 기존 **198.6ms**, 수정본 **2.9ms**였습니다. 이 수치는 `WorkspaceWorkflow.render()` 경로의 비교이며 전체 앱·Claude 응답 시간이나 사내 VDI 성능 측정값은 아닙니다. 닫힌 큐/예약 상세 DOM은 각각 100개에서 0개로 줄고, 대화 표시 150개는 유지됩니다.

재현 스크립트: `scripts/test-lab/verify-workspace-queue-pointer.cjs --heavy`, `--heavy --benchmark`, 비교 기준은 변경 전 Git HEAD에 `--baseline`을 추가합니다. 전체 HTTP 경로는 `scripts/test-lab/verify-workspace-queue-http.py`입니다. 모두 개인 Claude 요청 대신 격리된 테스트 응답을 사용합니다.

## 기존 구현에서 정리한 부분

닫힌 창의 불필요한 행 생성, 출력 조각마다 같은 기록 복제, 실행기에서 사용되지 않던 동일 버전 플래그를 제거했습니다. 사용자 안내서의 말풍선 정렬·삭제된 경로 추가 버튼 설명도 현재 UI에 맞췄습니다. 지속 승인 검토 중 발견한 '현재 모드 사용' 후 오래된 모드 재복원 및 OneDrive 경로 거부 회귀도 수정했습니다. 캐시 전체 삭제와 운영판 상시 상세 진단은 이번 문제 해결에 추가하지 않았습니다.

# Company Workspace 0.14.0 — 이전 대화와 알림

0.14.0은 기존 Claude 대화를 업무 폴더와 함께 이어 열고, 다른 일을 하는 동안 완료·확인 요청을 확인하는 사용 흐름을 추가합니다. 승인 목록에는 명시적으로 선택하는 Bypass가 추가되며, 지원되는 Windows 앱 창의 제목 표시줄 색도 화면과 맞춥니다.

EXE·VBS 모두 기존 Python 3.11 이상과 Claude Code의 기존 인증을 사용합니다. Python을 설치하거나 다운로드하지 않으며 Company Agent는 필수 조건이 아닙니다. 창 닫기·트레이·후속 요청·예약은 [0.13.0 사용법](WORKSPACE_0.13.0_DESKTOP.md)을 따릅니다. 이 문서는 사용법과 구현 범위를 설명하며 공개 배포 완료나 모든 운영 PC의 검증 완료를 뜻하지 않습니다.

## 이전 Claude 대화 불러오기

1. 왼쪽의 **이전 Claude 대화 불러오기**를 누릅니다.
2. **최근 Claude 대화**에서 고르거나 **Claude 세션 ID**에 UUID를 넣고 **찾기**를 누릅니다.
3. 대화 미리보기와 **원래 작업 폴더**를 확인하고 **이 대화 불러오기**를 누릅니다.
4. 업무 폴더 확인을 거쳐 새 요청을 보내면 같은 Claude 세션 ID로 이어갑니다.

Company Agent로 만든 대화에 한정하지 않습니다. 일반 Claude Code에서 만든 대화도 현재 앱이 사용하는 Claude 설정 폴더에 기록이 있으면 대상입니다. 현재 `CLAUDE_CONFIG_DIR` 등으로 정해진 설정 위치만 확인하며 다른 계정·다른 설정 위치에서 기록을 자동으로 가져오지 않습니다. 가져온 후 설정 위치가 바뀌면 해당 업무의 연결·전송·원본 터미널 열기를 중단하고 안내합니다.

가져오기 자체는 Claude를 실행하거나 질문을 보내지 않습니다. 원래 작업 폴더를 앱 업무에 연결하고 표시 가능한 사용자·Claude 텍스트만 앱 기록에 복사합니다. 원본 JSONL·Claude 인증·개인 설정·기존 승인 규칙은 수정하지 않으며, 이전 기록에 있는 도구 실행 원문·도구 결과·생각 내용은 대화 화면에 가져오지 않습니다. 일반 대화 본문 자체에 사용자가 적은 내용은 그대로 포함될 수 있습니다.

원본 기록을 읽었다는 이유로 폴더를 자동 신뢰하지 않습니다. 가져온 업무에서 Claude를 연결하거나 실행하기 전에는 앱의 폴더 확인이 필요합니다. 같은 설정 위치에서 이미 가져온 같은 세션·폴더를 다시 선택하면 기존 업무를 엽니다. 원래 폴더가 사라졌거나 기록의 위치·중복 여부를 확인할 수 없으면 다른 폴더나 세션으로 대신 연결하지 않습니다.

**다른 터미널에서 같은 세션을 실행 중이라면 먼저 작업을 마친 뒤 이어가세요.** 앱은 외부 CLI의 실행 여부를 확정하지 못합니다. 같은 UUID를 여러 곳에서 동시에 실행하면 Claude 원본 기록에 서로의 메시지가 섞일 수 있습니다. 가져오기 단계의 원본 보존과 이후 Claude가 대화를 이어 쓰는 동작은 구분됩니다. UUID 재개와 동시 실행의 동작은 [Claude 공식 세션 안내](https://code.claude.com/docs/en/sessions)를 참고하세요.

### 목록과 미리보기의 범위

목록은 현재 설정 위치의 최근 기록 일부를 보여 줍니다. 목록에 없으면 UUID로 직접 찾을 수 있습니다. 화면은 최근 부모 연결을 따라 확인할 수 있는 일반 대화를 표시하며, 모든 도구 이벤트를 재현하는 원본 로그 뷰어는 아닙니다. 긴 기록·손상된 일부 줄·지원하지 않는 형식은 일부 표시 안내 또는 확인 불가 안내가 나올 수 있습니다. 깊게 중첩된 잘못된 JSON도 손상된 줄로 처리합니다.

개별 기록 확인은 32 MiB, 한 줄은 2 MiB 범위이며 앱에 복사하는 대화는 최대 150개·총 50만 자입니다. 불러오기 창은 그중 최근 6개 메시지의 일부를 미리 보여 줍니다. 실제 대화 재개에 사용하는 기록은 Claude가 자신의 UUID로 읽습니다. 앱은 화면 미리보기만을 새 프롬프트로 다시 전송하지 않습니다.

## 완료·승인·오류 알림

상단 **알림**에서 완료된 업무와 확인이 필요한 업무를 모아 봅니다. 항목을 누르면 해당 업무로 이동하고, **모두 읽음**으로 목록의 읽음 상태를 정리합니다. 진행 중인 승인·질문·선택 요청은 기존 **응답 대기**에서도 확인할 수 있습니다.

**설정 → PC 알림**에서 전체 알림과 **작업 완료 / 승인·질문·선택 대기 / 오류·확인 필요**를 각각 켜거나 끕니다. 다른 앱을 사용하거나 창을 닫아 백그라운드에 있을 때 Windows 트레이 알림을 요청하며, 해당 업무를 보고 있는 동안에는 같은 알림을 반복해서 띄우지 않습니다. 빠르게 이어진 알림은 배너 요청을 줄이고 앱 목록에 기록합니다. PC 알림을 꺼도 앱 안의 알림 기록은 남습니다.

알림에는 업무 이름과 짧은 상태 안내를 사용하며 실행 명령·파일 내용·오류 원문은 넣지 않습니다. 알림을 클릭하면 해당 업무를 열도록 요청합니다. Windows 알림 설정·집중 모드·트레이 지원 상태에 따라 배너나 클릭 동작이 달라질 수 있으므로 화면에 실제 배너가 나오는 것을 보장하지 않습니다. 표시되지 않은 결과도 앱의 **알림**에서 확인할 수 있습니다.

알림 설정과 최근 최대 50개 기록은 앱 상태 폴더의 `desktop-notifications.json`에 저장합니다. 앱을 다시 열 때 예전 알림 배너를 재발송하지 않습니다. Windows 알림 설정·브라우저 설정·Claude 설정은 바꾸지 않습니다. 기존 **브라우저 알림** 설정은 PC 트레이 알림과 별도이며 브라우저 권한을 따릅니다.

## Bypass 승인 모드

입력창의 **승인** 목록에서 현재 연결이 제공하는 **Bypass**를 직접 선택할 수 있습니다. 선택 시 위험 설명을 확인하고 **위험을 이해하고 Bypass 사용**을 눌러야 적용을 요청합니다. 취소하면 기존 모드를 유지합니다. 일반 **Shift+Tab** 순환에는 Bypass를 넣지 않습니다.

Bypass는 Claude의 파일 수정·명령 실행 승인 확인을 생략할 수 있는 모드입니다. 해당 업무 폴더와 연결 도구를 신뢰할 때만 선택하세요. 앱이 시작할 때 자동으로 켜거나, 반복 승인 때문에 대신 선택하거나, 개인 기본 설정으로 저장하지 않습니다. 적용 범위는 현재 앱 실행 중 해당 업무이며, 다른 업무에는 복사하지 않습니다. 앱을 완전히 종료하고 다시 시작하면 기존 Claude 설정을 상속합니다.

필요하면 같은 Claude 세션 ID로 연결을 다시 준비합니다. 이때 CLI가 제공하는 `--allow-dangerously-skip-permissions`로 모드 전환을 허용한 뒤 `set_permission_mode` 응답에서 실제 적용값을 확인합니다. 처음부터 실행을 무조건 우회 모드로 만드는 `--dangerously-skip-permissions`는 사용하지 않습니다. 재연결 시 기존 모델·Effort·승인 선택과 복원 기준을 이어받으며, 설정을 바꾸기 위해 업무 메시지를 보내지 않습니다.

현재 연결이 이 기능을 제공하지 않거나 회사 정책·CLI에서 거절하면 적용 완료로 표시하지 않습니다. 거절 규칙과 조직 정책은 CLI가 처리하며 앱은 그 정책을 변경하지 않습니다. 확인한 실제 모드를 표시하고, 재연결이나 설정 재적용이 실패하면 다음 업무를 자동으로 진행하지 않습니다. 다른 지원 모드를 고르거나 기존 설정 복원을 선택하면 해당 제어 요청의 실제 적용값을 다시 확인합니다.

## 제목 표시줄과 앱 화면

확인된 Company Workspace 앱 창에만 제목 표시줄·문자·테두리 색을 적용합니다. Windows 11의 지원되는 기본 제목 표시줄은 앱의 밝은 색상과 맞춰 표시됩니다. 창 이동·최소화·최대화·닫기 동작은 기존 창 기능을 유지합니다.

Windows 10이나 Edge가 직접 그리는 제목 표시줄에서는 색이 그대로 남을 수 있습니다. 고대비 모드에서는 사용자 가독성 설정을 우선합니다. 색상 적용 실패로 앱 실행을 막지 않으며 Windows 전체 테마·강조색·Edge 프로필 설정을 변경하지 않습니다. 창의 X는 계속 화면만 닫고, **트레이 → 완전 종료** 또는 **설정 → 완전히 종료**가 앱을 종료합니다.

## 구현과 확인 범위

세션 가져오기는 읽기 전용 parser와 인증된 앱 API를 사용합니다. 테스트는 임시 일반 Claude 기록으로 UUID 중복 처리·원래 폴더·신뢰 확인·설정 위치 변경 차단·원본 바이트 보존·손상 JSON 처리를 확인합니다. 알림은 앱 기록·중복 억제·설정·업무 이동을 검증하며 Windows가 실제 배너를 표시했다는 의미로 확대하지 않습니다.

Bypass 통합 테스트는 AI를 실행하지 않는 제어용 연결로 확인 취소·정책 거절·동일 UUID 재연결·모델/Effort/승인 복원과 메시지 미전송을 확인합니다. **이 테스트로 실제 Bypass 업무를 실행한 것은 아닙니다.** 각 배포본의 전체 회귀·실제 CLI·EXE·화면 검증 결과는 [0.14.0 검증 기록](https://github.com/bongG-moon/workspace_local/blob/main/docs/VALIDATION_0.14.0.md)에서 별도로 확인합니다.

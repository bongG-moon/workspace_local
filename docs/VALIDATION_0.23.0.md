# 0.23.0 — 사내 GitLab 배포와 업데이트

## 변경 내용

- Python 배포 도구에서 소스 반영, 원본 커밋을 보존한 별도 EXE/VBS 빌드, Generic Package 게시를 진행합니다.
- 앱에는 사내 서버 주소와 프로젝트 정보만 포함합니다. 게시 토큰과 SSH 개인키를 배포하지 않습니다.
- 버전별 파일의 익명 다운로드와 체크섬을 검증한 뒤 최신 버전 정보와 변경 내용을 게시합니다.
- 게시 실패 후 창을 다시 열어도 직전 빌드를 검증해 불러오며 같은 파일로 재시도할 수 있습니다.
- 앱은 배포본에 지정된 GitLab에서 업데이트를 받습니다. 설정 오류나 접속 실패로 공개 GitHub로 전환하지 않습니다. 기존 공개 배포본의 GitHub 업데이트는 유지합니다.

## 검증 기록

- 게시 도구 core 28개, GUI 24개, 업데이트 화면 21개, 시작 상태 검사 36개: 결합 109개 통과.
- 업데이터·설치기·경로·패키징 통합 검사 통과. 허용된 저장소 리디렉션, 공급자별 캐시, 잘못된 해시·서버 설정 차단을 포함합니다.
- Windows 실행기 회귀 50개 중 49개 통과, 환경 조건에 따른 1개 생략.
- 공개 배포용 EXE 빌드와 내장 파일 검증, VBS와 공통 124개 파일 일치 확인 완료.

- 전체 회귀 1,628개 실행: 1,594개 통과, 환경 조건·선택형 검증 34개 생략, 실패 없음.
- 이후 실제 빌드에서 발견한 Windows 긴 검증 경로와 부모 PowerShell의 모듈 경로 상속을 수정했습니다. 추가 검사를 포함한 게시 core 31개와 GUI 24개를 다시 실행해 통과했습니다. 실제 Windows PowerShell 자식에서 파일 해시·압축·해제도 확인했으며 부모 환경은 유지했습니다.
- 커밋 `052157b`에서 원본을 수정하지 않는 `Publisher.build()` 실제 실행 성공: 별도 Git archive, SDK 해시 확인, 설정을 포함한 EXE/VBS 생성, 공통 125개 파일 비교, ZIP 검사까지 완료했습니다.
- 위 실제 사내 설정 배포 파일을 모의 Registry에 게시하고, UpdateManager에서 익명 조회·체크섬·실제 파일 추출을 확인했습니다. 추출된 앱의 서버를 데모 모드로 실제 기동해 GitLab 공급자와 0.23.0 버전, 업데이트 포인터 승격, 정상 종료와 런타임 기록 제거를 확인했습니다.
- 내부 네트워크와 설치기의 Windows 실행기 호출은 모의 처리했습니다. 기존 실제 Workspace와 Claude 작업은 실행하거나 종료하지 않았습니다.

공개 배포용 VBS ZIP SHA256: `adf3ee5cd49bdeaf2abf4645f7af822534f15c2936443cec4ba3cf3c8a464eb0`.

사내 설정 예제 빌드는 검증용이며 실제 사내 주소를 포함하지 않습니다. 배포 담당자가 실제 서버 주소를 설정해 다시 빌드합니다. 공개 Release의 일반 EXE/VBS ZIP은 GitHub 업데이트를 사용하는 공개 배포본입니다.

## 현장 확인이 필요한 범위

사내 GitLab의 실제 주소·Project ID·게시 권한·인증서·중복 패키지 정책은 외부에서 접근할 수 없어 검증하지 않았습니다. 모의 서버와 임시 Git 저장소 검사는 실제 사내 접속을 대신하지 않습니다. [사내 배포 안내](WORKSPACE_GITLAB_PUBLISHER.md)의 현장 확인을 최초 배포 때 수행합니다.

새 배포 창은 자동 위젯 검사와 실제 core 호출을 검증했습니다. 컴퓨터 사용을 통한 화면 조작 검사는 앱 접근 승인 대기 시간이 지나 완료하지 못했습니다. 기존 사용 중인 Workspace 창과 개인 Claude 설정은 변경하지 않았습니다.

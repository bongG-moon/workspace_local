# AX Workspace: 작업표시줄, 설정 및 도움말 개선

대상: 0.23.22 동일 버전 수정 배포. 기존 사용자 상태와 Claude 환경은 유지합니다.

## 설계와 적용

1. **작업표시줄**: 외부 EXE와 실제 창을 표시하는 WebView2 호스트에 버전과 무관한 동일 AppUserModelID `AX.Workspace.Desktop`를 부여합니다. 창의 재실행 속성에는 원래 EXE 경로와 지정한 state/cache/Python/demo 옵션만 저장합니다. 임시 서버 URL·인증 토큰·관리자 권한 선택은 저장하지 않습니다. 기존 창 활성화와 단일 인스턴스 로직은 유지합니다. 주기적 탐색이나 프로세스는 추가하지 않습니다.
2. **설정**: 헤더와 스크롤 본문을 나누고 제목·닫기 버튼을 항상 표시합니다. 최신 실행기 바로가기 생성 버튼과 프런트엔드 다운로드/폴링 경로를 제거합니다. 구형 EXE를 이미 사용한 PC에는 최신 EXE로 교체하라는 간단한 안내를 남깁니다. 기존 업데이트 기능과 이미 만들어진 바로가기의 호환 처리는 유지합니다.
3. **도움말**: 상단을 `AX Workspace를 만든 이유` → `사용 안내서` 순서의 두 카드로 구성하고 그 아래 세 단계 시작 안내와 FAQ를 둡니다. 좁은 화면은 한 열, 밝게·어둡게는 기존 테마 색을 사용합니다. 전체 소개 HTML은 복제하지 않고 번들 원본으로 연결합니다. 도움말도 헤더를 고정합니다.
4. **문서 열기**: 실제 네이티브 클릭 검사에서 기존 허용 경로가 안내서 단일 주소만 받아 소개와 절 링크가 차단됨을 확인했습니다. 정확한 두 문서 경로와 안전한 안내서 절 이름만 허용하며, 다른 로컬 API·포트·쿼리·토큰·경로 이동은 계속 거부합니다.

## 실행 파일과 고정 아이콘

최신 EXE를 그대로 사용하면 됩니다. 별도 바로가기는 필수가 아닙니다. 옛 EXE에 저장된 부트스트랩 동작은 내부 앱 업데이트만으로 교체되지 않으므로, 이번 작업표시줄 수정은 새로 빌드한 EXE로 실행해야 합니다.

기존 고정 아이콘이 분리되면 옛 아이콘을 고정 해제한 뒤 새 EXE로 실행하고 **실행 중인 AX Workspace 창의 아이콘**을 다시 고정합니다. Windows의 기존 사용자 고정 목록을 자동 수정하지 않습니다. 고정 후 원래 EXE를 이동·삭제하면 연결이 끊길 수 있으므로 계속 사용할 위치에 두세요.

직접 실행한 개발용 호스트나 EXE 재실행 정보가 없는 VBS 창은 파이프 없이 단독 실행할 수 있는 프로그램이 아니므로 내부 호스트만 고정되지 않게 합니다. VBS는 기존 실행 파일로 계속 열 수 있습니다. 이번에 VBS용 별도 작업표시줄 설치 기능을 만들지는 않았습니다.

## 검증

- 동일 버전 배포 전 최종 회귀: 위 범위에 EXE 부트스트랩·배포 이력을 추가한 137개 검사 모두 통과. 로그: `build/qa-shell-release-tests-20261012.log`.

- 네이티브 창, 설정 권한 표시, 도움말 경로, 대화상자, 관리 실행기와 브랜드 패키지 회귀: 94개 통과.
- 실제 Windows Shell 속성 저장소 테스트: AppID·EXE 재실행·아이콘·이름·호스트 단독 고정 방지 확인. 같은 검사에서 소개·안내서 절 허용 및 API/쿼리/다른 포트/비사용자 호출 차단을 검증.
- 1440×900, 800×600, 480×640 × 밝게/어둡게 6개 화면 검사: 설정 최하단 스크롤에도 닫기 위치 유지, 소개 링크 열기, 너비 범위, Escape 닫기, JS 오류 0개.
- 실제 네이티브 창에서 설정 스크롤·닫기와 도움말 소개 카드 클릭을 확인했으며 소개 HTML이 기본 Chrome 브라우저에 열렸습니다. 개인 업무를 읽거나 Claude를 호출하지 않은 별도 데모였습니다.
- 사용자 작업표시줄의 기존 고정 아이콘을 실제로 지우고 다시 고정하는 검사는 하지 않았습니다. 해당 PC의 기존 핀 마이그레이션과 고정 후 재부팅까지 검증됐다고 주장하지 않습니다.

# Company Workspace 외부자 관점 재검토

검토일: 2026-09-28. 대상: 현재 `main`, Workspace 0.9.

## 판단

처음부터 만든다면 기존 Claude Code를 실행 엔진으로 사용하는 원칙은 유지하되, 현재 화면과 앱 운영 구조를 그대로 만들지는 않는다. 현재는 CLI와 연결된 채팅·파일 조회·하네스 관리가 구현된 상태다. 목표 제품은 명령어를 모르는 사람이 실행 준비부터 결과 확인과 실패 복구까지 끝낼 수 있는 업무 앱이다.

기능을 줄여 쉬워 보이게 만드는 것이 목표는 아니다. 터미널에서 사용하던 업무 기능에 대응하는 GUI 조작을 제공하고, 지원하지 못하는 기능은 개별적으로 명시해야 한다. 단순히 ‘고급 기능은 터미널’로 묶으면 해당 기능이 필요한 비개발자는 다시 막힌다.

## 검토 근거와 한계

- 제품 사용 흐름, 실행 구조, 공식 기능 지원을 세 관점에서 독립 검토했다.
- 현재 소스와 문서를 대조하고, 격리된 테스트 서버의 홈·업무 카드·폴더 선택 대화상자를 브라우저에서 확인했다.
- 테스트 서버는 저장소의 `scripts/test-lab/serve-workspace-fixture.py`와 가상 CLI를 사용하며, 실제 사용자 설정 대신 `.smoke/outsider-review-20260928`의 테스트 자료를 사용했다.
- 자동 승인 검토가 폴더 신뢰 확인과 업무 시작 조작을 거절하여 실행 이후 UI 클릭 검증은 진행하지 않았다. 승인·완료·복구에 대한 평가는 해당 소스의 동작을 읽어 내린 판단이다. 브라우저 자동화에서 일부 클릭이 반영되지 않은 현상은 키보드 조작으로 폴더 창이 열렸으므로 제품 결함으로 분류하지 않았다.
- 실제 모델 요청, 사내 HCP·DRM 업무, 새 사용자를 대상으로 한 사용성 실험은 수행하지 않았다. 이전 테스트 통과 수가 이번 제품 사용성 평가를 입증하지는 않는다.
- 구현 코드는 변경하지 않았다. 이 문서는 검토 결과이며 새 설계의 구현 완료 보고가 아니다.

## 처음부터 세울 사용자 흐름

1. 앱 아이콘을 열면 기존 회사 연결과 사용할 수 있는 기능이 확인된다. 사용자에게 Python 경로나 실행 명령을 입력시키지 않는다.
2. ‘새 업무’ 또는 ‘이전 업무 이어하기’를 고른다. 새 업무의 기본 저장 위치를 제공하고, 필요하면 사용자가 바꾼다.
3. 탐색기로 자료를 고른다. 원본 경로는 보존하고, 선택한 자료와 결과 저장 위치를 구분한다. 폴더 설정이 실행되는 경우에는 실제 영향에 대한 동의를 받는다.
4. 자유롭게 요청한다. 업무 카드는 예시이며 사용 가능한 업무의 제한 목록이 아니다.
5. 현재 진행 중인 일과 기다리는 이유를 보여 준다. 사용자 결정이 필요하면 질문 또는 영향 중심의 승인 화면으로 전환한다.
6. 이번 요청에서 생성·수정한 결과를 보여 준다. 결과 열기, 저장 위치 열기, 추가 수정 요청으로 이어진다.
7. 앱을 다시 열면 업무·자료·대화·결과를 찾아 계속한다. 연결 만료나 파일 이동도 앱에서 다음 행동을 고를 수 있어야 한다.

## 터미널 기능을 GUI로 바꾸는 기준

아래는 목표 대응이며 전부 구현됐다는 뜻이 아니다. 각 항목은 실제 설치된 버전과 회사 정책으로 가능 여부를 확인한다.

| 사용자가 하려는 일 | GUI에서 제공할 조작 |
| --- | --- |
| `cd`로 작업 위치 선택 | 업무 공간 선택·최근 업무·새 업무 만들기 |
| `dir`로 파일 확인 | 자료 목록·찾기·탐색기에서 열기 |
| 파일 경로를 붙여 요청 | 자료 선택과 요청에 포함할 파일 표시 |
| 이전 세션 재개 | 업무 목록에서 이어하기·이전 대화 찾아오기 |
| 모델 확인/선택 | 회사에서 허용한 모델 표시와 선택 |
| 스킬 호출 | 자연어 요청과 선택 가능한 작업 방식 메뉴 |
| MCP 확인/복구 | 업무 도구 연결 상태와 지원되는 재연결 조작 |
| 실행 계획과 승인 방식 선택 | 계획 먼저 보기·변경 확인 등 정책상 허용된 모드 |
| 문맥 상태 확인/관리 | 지원되는 범위의 대화 사용량·정리·분기 기능 |
| 중지·추가 지시·재개 | 수행된 작업을 구분하는 중지/후속 요청 동작 |
| 인증·연결 복구 | 기존 회사 인증 방식과 연결되는 갱신·진단 절차 |

TUI 전용 기능은 GUI 대체 경로, 별도 구현 필요, 현재 미지원으로 나눠 기록해야 한다. 모든 CLI 기능의 완전한 동등성을 약속하기 전에 이 표를 실제 기능 목록으로 확장하고 검증한다. 원본 터미널은 전문가용 선택지로 둘 수 있지만 필수 업무의 완료 조건으로 삼지는 않는다.

## 유지할 것과 바꿀 것

**유지:** 기존 Claude 실행 대상·회사 wrapper·모델·인증·스킬·후크·MCP 설정 보존, 원본 자료 경로 보존, 질문 폼, 승인 전달, CLI 세션 ID 재개, 개인 상태 보존, 소유 프로세스만 종료하는 경계.

**재구성:** 업무·자료·실행·산출물의 연결, 이해할 수 있는 승인, 실패 복구, 세션 탐색, 기능별 GUI 대응, 설치·종료·업데이트 경험.

**기술 선택:** 웹으로 UI를 작성하는 방식은 유지해도 된다. 새 배포 제품이라면 Windows 앱 셸과 실행 관리자를 검토하되, Edge에서 다른 셸로 옮기는 작업만으로 제품 문제가 해결되지는 않는다. 조직이 허용하는 런타임 배포와 업데이트 방식을 함께 설계해야 한다. EXE 포장만으로 기존 WS-33이 해결된다고 보장하지 않는다. UAC·보안 정책·사용자 계정 변경을 전제로 하지 않는다.

**SDK 선택:** 현재 CLI 어댑터를 즉시 버릴 이유는 없다. 전송 계층과 앱 상태 모델을 구분하고, 공식 SDK의 유지보수 이점과 기존 회사 실행 환경의 호환성을 비교해 결정한다. SDK 도입이 인증·설정·회사 wrapper 동일성을 자동 보장하지는 않는다.

## 공식 문서로 확인한 구현 가능 범위

- 프로그램 실행용 CLI도 Claude Code의 도구와 에이전트 실행 구조를 사용한다. 사용자 스킬 호출과 여러 내장 명령의 인수 지정 형태를 지원하지만 `/login` 같은 TUI 전용 명령은 구분해야 한다. 부분 응답 스트리밍 옵션도 제공한다. [Claude Code 프로그램 실행](https://code.claude.com/docs/en/headless)
- Python SDK 문서는 모델·권한 변경, 세션 조회, MCP 상태와 제어 등을 제공한다. 현재 설치 버전과 회사 정책에서 가능한지는 별도 검증 대상이다. [Python SDK 참조](https://code.claude.com/docs/en/agent-sdk/python)
- 승인과 사용자 질문은 앱이 콜백과 자체 UI로 처리할 수 있다. [승인·사용자 입력](https://code.claude.com/docs/en/agent-sdk/user-input)

따라서 ‘GUI에서는 불가능해서 터미널에 남겨둔 기능’과 ‘아직 GUI에 연결하지 않은 기능’을 구분해야 한다.

## 구현 순서와 완료 판정

1. 실제 터미널 사용 기능을 빠짐없이 정리하고 GUI 대응·버전 조건·미지원 이유를 명시한다.
2. 현재 회사 연결과 개인 상태를 보존하는 실행 계약을 고정한다.
3. 한 업무의 전체 흐름을 먼저 완성한다. 예: 자료 선택 → 보고서 요청 → 수정 영향 확인 → 결과 열기 → 앱 재시작 → 후속 수정.
4. 이 흐름에 인증 만료·연결 끊김·문서 이동·중지·재개·업데이트를 추가한다.
5. 모델/도구/스킬/세션/문맥 기능을 대응표에 따라 확장하고 관리 화면을 정리한다.

완료 판정은 테스트 통과 수와 별도로, 터미널을 모르는 사용자가 설명자의 도움 없이 다음 과제를 끝내는지로 한다.

- 앱 시작과 사용할 연결 확인
- 파일 선택과 원하는 결과 위치 확인
- 자연어 업무 요청과 필요한 질문 답변
- 승인 대상과 변경 영향을 이해한 선택
- 이번 작업의 결과 열기와 추가 수정

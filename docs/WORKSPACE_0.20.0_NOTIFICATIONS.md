# 0.20.1 앱 알림 카드

완료·승인·질문·선택 대기·오류 알림을 앱과 같은 밝은 배경과 보라색 강조의 카드로 표시합니다. 0.20.1은 **상태·업무명·결과/열기·닫기**만 남깁니다. 반복 안내문과 WORKSPACE 표기를 없애고 크기를 368×190에서 340×96 DIP로 줄였습니다. 높이는 약 49%, 면적은 약 53% 줄었습니다. 업무명과 정해진 상태 안내만 보내며 대화 본문·파일 내용·명령·인증 정보는 표시하지 않습니다.

## 사용법

- **설정 → PC 알림**에서 전체 알림과 완료·확인 요청·오류 알림을 각각 조절합니다. 기존 선택을 유지합니다.
- 다른 앱에서 일하거나 Workspace를 트레이로 숨긴 상태에서 알림을 받을 수 있습니다. 해당 업무를 이미 보고 있다면 같은 알림을 띄우지 않습니다.
- 카드가 나타나도 입력 포커스는 현재 앱에 남습니다. **결과 / 열기**를 누를 때 해당 업무를 열고 그 알림을 읽음 처리합니다.
- 닫기를 누르거나 표시 시간이 지나면 카드만 사라집니다. 알림함 기록은 남습니다. 상단 **알림**에서 확인할 수 있습니다.
- 카드는 12초 뒤 닫힙니다. 포인터가 카드 위에 있는 동안에는 표시 시간을 잠시 멈추되 최대 60초까지만 유지합니다.
- 동시에 한 장만 표시합니다. 겹치거나 짧은 시간에 이어진 알림은 쌓아 두었다가 뒤늦게 띄우지 않고 알림함에 기록합니다.

## 설계와 호환성

기존 알림은 Windows의 `Shell_NotifyIcon` 기본 배너였으므로 앱의 CSS를 적용할 수 없었습니다. 이번 카드는 기존 `Workspace.Desktop.exe` 안의 가벼운 WinForms 창입니다. 알림마다 새 프로세스나 WebView2를 만들지 않습니다. 닫힐 때 타이머·창·그리기 자원을 정리하고 클릭 연결도 해제합니다.

앱이 위치한 모니터의 작업 영역과 배율을 기준으로 우측 하단에 배치합니다. 작업 표시줄을 피하고 표시 영역을 벗어나지 않게 조절합니다. Windows 배율·테마·알림 설정은 변경하지 않습니다.

0.20.1에서는 시스템 그림자와 직접 그린 경계가 겹치던 구조를 정리해 하나의 10 DIP 모서리를 사용합니다. Windows 10·11에서 동일한 경계를 사용하며, 작은 화면에서는 알림 크기를 작업 영역 안에 맞춥니다. Region 기반 모서리는 픽셀 단위 실루엣이며 반투명 그림자나 알파 경계를 추가하지 않습니다.

글꼴은 웹 화면에 이미 사용하는 Noto Sans KR에서 실제 400·600 굵기를 생성했습니다. 전체 문자 범위와 한글 11,172자를 유지한 압축 글꼴을 네이티브 EXE에 포함하고, 알림을 처음 표시할 때 프로세스 내부에서만 불러옵니다. 카드마다 글꼴을 다시 읽거나 Windows에 설치하지 않습니다. 시스템 정책 등으로 읽지 못하면 맑은 고딕 계열로 대체합니다. 상세 원본·해시·라이선스·재생성 방법은 소스의 `deploy/fonts`에 있습니다.

구성은 [Fluent 2 Toast](https://fluent2.microsoft.design/components/web/react/core/toast/usage)의 짧은 핵심 제목과 최소 행동 원칙을 참고했습니다. 상태와 업무명 두 줄, 작은 행동 버튼으로 줄이되 기존 색감과 알림 기록을 유지합니다.

표시 전에 Windows의 `SHQueryUserNotificationState`를 확인하고 알림 허용 상태일 때만 요청합니다. 전체 화면·발표·잠금 등 제한 상태나 조회 실패 시에는 카드 대신 알림함 기록을 유지합니다. 이 API의 반환값을 따르는 것이며 모든 Windows 버전의 방해 금지 설정과 동일하게 연동된다고 보장하지는 않습니다. 이미 켜 둔 브라우저 알림은 별도 설정입니다.

카드를 지원하지 않는 이전 데스크톱 호스트나 호스트가 없는 실행에서는 사용 가능한 기존 트레이 알림으로 되돌아갑니다. 카드가 바쁨·표시 제한으로 거절한 경우에는 다른 채널로 다시 띄우지 않습니다. 알림 수락 응답은 실제로 사용자가 화면을 보았다는 증거가 아닙니다.

기존 알림함 파일 형식·최대 50개 기록·중복 방지·재시작 시 재발송 금지를 유지합니다. 알림 클릭은 처음 발행한 알림 ID에만 연결되며 늦게 도착한 클릭을 새 업무에 연결하지 않습니다. Claude 인증·모델·승인·플러그인 설정은 변경하지 않습니다.

## 검증 기준

Python 전달 경로에서 카드 수락·거절·지원 없음, 기본 배너 대체 조건, 정확한 업무 이동, 닫은 알림과 종료된 호스트의 늦은 이벤트를 검증합니다. 기존 알림 설정·중복·전경 억제·읽음·보관 한도 회귀도 실행합니다. 네이티브 빌드 후 격리된 고정 예제 알림으로 표시·닫기·업무 열기를 확인합니다. 실제 확인 결과와 미확인 환경은 별도 검증 기록에 남깁니다.

참고: [Microsoft 알림 표시 상태 API](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shqueryusernotificationstate), [포커스를 바꾸지 않는 알림 창](https://learn.microsoft.com/dotnet/api/system.windows.forms.form.showwithoutactivation).

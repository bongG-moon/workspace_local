# 0.23.2 — 간편한 사내 배포와 액세스 토큰 호환

## 변경 내용

- 기본 입력을 HTTPS 서버 주소, 숫자 프로젝트 ID, 게시 토큰으로 줄였습니다. **배포하기** 한 번으로 소스 확인, EXE/VBS 생성, 게시와 다운로드 검증을 진행합니다.
- SDK가 준비되면 준비 영역을 접습니다. 추가 다운로드 서버, 토큰 종류와 Git 소스 반영은 고급 설정에 두었습니다.
- `glpat-` 액세스 토큰은 `PRIVATE-TOKEN`으로 전송합니다. 이전 버전에서 `deploy`로 저장한 설정도 인식합니다. Deploy Token과 CI Job Token도 유지합니다.
- 게시 오류에 HTTP 응답 코드와 토큰별 권한 안내를 표시합니다. `write_registry`는 컨테이너용 권한임을 구분하고, 서버 응답 본문과 토큰은 표시하지 않습니다.
- 검토한 릴리스 기록을 소스 ZIP에 포함해 현재 변경 내용과 이전 이력을 오프라인으로 읽습니다. 제목과 본문은 수정할 수 있으며 같은 버전의 편집 내용을 유지합니다. 사내에서 GitHub를 실시간 조회하는 방식이 아닙니다.
- 게시 실패 뒤에는 기존 파일과 기록을 검증해 같은 파일로 재시도합니다. 손상된 기록이나 파일을 같은 버전의 새 빌드로 조용히 대체하지 않습니다.

## 검증 기록

- 게시 도구 검사 155개 실행: 153개 통과, Windows 심볼릭 링크 조건 2개 생략. GUI 작업 흐름, 변경 내용 편집, 소스 ZIP, SDK, 게시와 재시도 검사를 포함합니다.
- 이후 `PRIVATE-TOKEN` 결과 키 제거 보완은 GUI 43개를 다시 실행해 모두 통과했습니다.
- GitLab 업데이트와 시작 진단 검사 34개 실행: 33개 통과, 환경 조건 1개 생략.
- 별도 검토자가 토큰·워크플로·게시 코어 49개, CLI·릴리스 기록 31개를 독립 실행해 모두 통과했습니다.
- 공개용 EXE/VBS를 실제 생성하고 EXE 내장 파일 추출 검증과 공통 앱 파일 124개 일치를 확인했습니다.
- `.git` 없는 소스 ZIP에서 SDK를 가져와 사내 설정을 포함한 EXE/VBS를 실제 생성했습니다. 공통 앱 파일 125개와 원본 소스 확인값이 유지됐고 Git 호출은 0회였습니다.
- 실제 생성 파일로 모의 서버의 첫 게시에 HTTP 403을 반환시킨 뒤, 재시작한 게시 도구가 파일을 다시 만들지 않고 복원해 게시했습니다. 이전 `deploy` 설정과 `glpat-` 조합이 `PRIVATE-TOKEN`을 사용하는지, 읽기 요청에는 인증을 넣지 않는지, 파일 4개와 마지막 최신 정보 게시 및 앱의 최신 정보 해석을 확인했습니다.

공개용 VBS ZIP SHA256: `0838a26e488bc22803490cf88efd40618be364c1bd50020d7d85158b27ace48e`.

## 현장 확인

사내 GitLab에는 외부에서 접속하지 않았습니다. 실제 토큰의 유효성·만료·`api` 권한, 프로젝트 역할, 인증서와 패키지 정책은 사내에서 확인해야 합니다. 액세스 토큰의 접두사만으로 사용 권한이나 유효성을 보장하지 않습니다.

HTTPS Package Registry 게시에는 SSH 키가 필요하지 않습니다. Git 소스 자체를 SSH로 반영할 때만 별도의 SSH 인증이 사용됩니다. 사용자 앱에는 게시 토큰과 SSH 개인키를 포함하지 않습니다.

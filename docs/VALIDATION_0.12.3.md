# Workspace 0.12.3 자동완성 표시 검증

검증일: 2026-09-29. 사용자 증상은 `/skill`을 입력해도 입력창 위에 후보가 나타나지 않는 것이었습니다.

## 원인과 수정

0.12.2의 입력 처리는 업무를 선택하지 않은 홈에서 즉시 종료됐습니다. 입력창의 `/` 안내와 실제 동작이 달랐습니다. 또한 첫 Claude 연결은 수동으로 명령 불러오기를 눌러야 했습니다. 이전 UI 회귀 검사도 모두 업무가 선택된 상태에서 시작했습니다.

0.12.3은 홈에서도 입력 패널을 열어 실제 설치 메타데이터의 공통 후보를 보여줍니다. 신뢰한 업무의 첫 `/` 입력은 AI 질문 없이 Claude 초기화를 자동 진행하며, 설치 발견 후보를 실제 연결이 보고한 후보로 대체합니다. 이름·설명·검색 강조·키보드와 클릭 선택을 유지합니다. 초기화 중 입력 변경, 다른 업무 선택, 포커스 이동, Esc 닫기, 초기화 실패를 별도로 처리합니다. 신뢰하지 않은 폴더는 자동 실행하지 않습니다.

실제 CLI와 대조하면서 기존 사용자 명령 `commands/sc/task.md`의 `sc`가 빠지는 문제를 추가 발견했습니다. 경로 접두사를 보존해 `/sc:task`, `/sc:estimate`, `/sc:spawn`으로 삽입하도록 수정했습니다. 내장 명령은 임의로 만들지 않으며, 설치 정보와 실행 연결의 보고를 구분합니다.

## 검증 결과

- 전체 Workspace 회귀: 497개 실행, 490개 통과, 7개 환경 조건 건너뜀, 실패·오류 0. 마지막 경로 접두사 보정 전의 전체 실행입니다.
- 접두사 보정과 신규 회귀 추가 후 영향을 받는 입력 UI·추천·발견·설치 메타데이터 검사 95개 재실행: 94개 통과, 심볼릭 링크 조건 1개 건너뜀, 실패·오류 0.
- 입력 UI 검사 26개는 홈 `/sk`, 홈 `@` 안내, 자동 초기화 중 최신 검색 유지, 신뢰 전 자동 실행 금지, 실패 후 명시 재시도, 다른 업무의 늦은 응답 무시, 포커스 유지, Esc 이후 늦은 응답 억제 등을 포함합니다.
- 실제 브라우저의 격리된 가상 CLI/설치 환경: 홈에서 `/sk`만 입력해 입력창 위 세 후보와 설명 표시, Tab으로 `/company-agent:skills` 삽입, 새 신뢰 업무에서 `/te`만 입력해 실제 연결의 `/test-skill` 후보 자동 표시를 확인했습니다. 불러오기 버튼을 누르거나 질문을 전송하지 않았습니다.
- 최종 ZIP과 실제 로그인 계정의 Claude Code **2.1.284**: 실행·재실행의 같은 PID 사용 확인. 홈 `/sk`에서 설치 후보 11개, 연결 이후 검색 후보 25개, `/sc:task` 정확한 전체 이름 보존, 대화 메시지 0개를 확인했습니다. 검색은 이름 앞부분 우선이며 설명 일치도 포함하므로 숫자는 CLI 화면의 접두사 후보 개수와 동일하다는 뜻이 아닙니다.
- 초기화 전 홈 조회는 CLI를 시작하지 않았습니다. 초기화는 기존 시작 후크와 MCP를 실행할 수 있으나 AI 질문은 보내지 않았습니다. 테스트 서버는 종료하고 기존 개인 설정 5개 파일의 존재/해시가 동일함을 확인했습니다.

건너뛴 전체 검사 7개는 심볼릭 링크 권한 3개, 실제 사용자 토큰 조건 3개, WSH 환경 1개입니다. 모든 Windows 정책이나 VBS 더블클릭 성공을 이번 검사만으로 보장하지 않습니다. 실제 ZIP 실행 경로는 PowerShell 실행기를 통해 검증했습니다.

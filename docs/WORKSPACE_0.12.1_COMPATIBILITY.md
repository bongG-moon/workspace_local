# Company Workspace 0.12.1 사용 범위와 호환성

2026-09-29 기준입니다. **앱은 별도 로그인 없이 열고, AI 업무는 기존 Claude Code의 인증과 설정을 사용합니다.** Claude CLI의 질문·승인·모델·스킬 기능을 GUI로 전달하며, 터미널 전용 화면까지 모두 같은 방식으로 제공한다는 의미는 아닙니다.

## 실행과 인증

| 구분 | 동작 |
| --- | --- |
| 앱 실행 | Windows와 Python 3.11 이상이 필요합니다. ZIP을 완전히 풀고 `Company-Workspace.vbs`를 더블클릭합니다. Python이 동봉된 독립 실행 파일은 아닙니다. |
| 앱 로그인 | 새 계정·앱 전용 로그인·API 키 입력은 없습니다. CLI 탐색에 실패해도 앱 화면에서 연결 확인 안내를 볼 수 있습니다. |
| AI 업무 | 같은 사용자의 기존 Claude 호출 경로·인증·회사 연결·모델·MCP·스킬을 사용합니다. Claude를 확인하지 못하면 AI 요청을 보류하며 다른 실행 파일·계정으로 자동 전환하지 않습니다. |
| 로컬 HTTP 보호 | 앱이 매 실행 생성한 내부 연결 토큰으로 화면과 서버 사이 접근을 확인합니다. 이 값은 Claude 인증이나 사용자가 입력할 API 키와 다릅니다. |
| 인증 만료 | 실제 Claude 인증 오류가 확인되면 기존 Claude 인증을 갱신한 뒤 다시 요청합니다. 앱이 새 인증 저장소를 만들거나 실패 요청을 자동 재전송하지 않습니다. |

앱 화면이 열린 것, Claude 실행 파일을 찾은 것, 인증된 실제 모델 응답을 받은 것은 서로 다른 확인 단계입니다. 별칭·프로필 함수·회사 호출 스크립트를 건너뛰고 다른 CLI를 대신 실행하지 않습니다.

## 실행 정책 변경 범위

0.12.1은 시작·진단·재실행·직접 Python 진입의 권한 확인·파일 선택·CLI 호출용 PowerShell에 `-ExecutionPolicy Bypass`를 전달합니다. **이번 실행의 PowerShell 프로세스와 그 자식 프로세스 계열에만 적용**하며 사용자나 컴퓨터의 영구 정책을 저장하지 않습니다. `MachinePolicy`·`UserPolicy`로 지정된 조직 그룹 정책이 우선합니다.

이 옵션은 UAC 권한 상승과 다릅니다. 기존 사용자·세션·프로필 검사, 일반 권한 linked token 우선 경로, 허용된 UAC-off 환경의 제한 토큰 복사 및 자식 검증을 유지합니다. 검증 실패 시 관리자 원본 권한으로 업무를 계속하지 않습니다.

다른 PC에서 프로세스 한정 옵션으로 VBS `exit 1`이 해결된 사례는 수정 후보를 검토한 근거입니다. 같은 종료 코드만으로 현재 PC의 실패 원인이 실행 정책이라고 확정하지 않습니다. 그룹 정책·AppLocker·WDAC·WSH 실행 차단이나 Python 부재까지 이 옵션으로 해결된다고 보장하지 않습니다. 다운로드 표시를 일괄 삭제하거나 Windows 정책을 영구 변경하지 않습니다.

시작 실패 시 같은 ZIP의 `Check-Workspace.cmd`로 읽기 전용 진단을 실행할 수 있습니다. `ws33-4` 진단은 실행 정책 5개 범위와 다운로드 표시(Mark-of-the-Web) 유무, 스크립트 구문 확인 상태를 구분합니다. 다운로드 표시 원문, 인증 정보, 환경변수 원문은 보고서에 넣지 않습니다. 진단 자체가 원래 VBS 실행·제한 토큰 생성·실제 Claude 업무를 모두 시험한 것은 아닙니다. 자세한 항목은 [시작 진단 안내](WORKSPACE_STARTUP_DIAGNOSTIC.md)를 참고하세요.

## 이번만 허용과 항상 허용

기본 선택은 **이번만 허용**입니다. 반복 허용 선택지는 현재 CLI가 승인 요청과 함께 제공한 `addRules`의 `allow` 후보에 한해 표시합니다. 앱이 명령 이름만 보고 새 허용 규칙을 만들지 않습니다.

| 선택 범위 | 의미 | 저장 영향 |
| --- | --- | --- |
| 이번만 허용 | 지금 대기 중인 요청 한 번에 답합니다. | 지속 허용 규칙을 추가하지 않습니다. |
| 이 연결에서 허용 (`session`) | CLI가 제안한 표시 범위만 현재 연결에서 허용합니다. | 새 연결에는 적용하지 않습니다. |
| 이 프로젝트에서 항상 허용 · 나만 (`localSettings`) | 현재 프로젝트의 개인 설정 범위입니다. | 선택한 규칙을 CLI에 전달해 해당 범위에 저장하도록 요청합니다. 다음 연결에도 적용하는 범위입니다. |
| 이 프로젝트에서 항상 허용 · 공유 설정 (`projectSettings`) | 프로젝트 설정에 기록되는 범위입니다. | 설정 파일을 공유하면 다른 사용자에게도 적용될 수 있습니다. 앱이 Git 커밋·공유까지 수행하지 않습니다. |
| 모든 프로젝트에서 항상 허용 · 내 설정 (`userSettings`) | 현재 Claude 사용자 설정의 공통 범위입니다. | 다른 프로젝트와 다음 연결에도 적용하는 범위입니다. 선택한 규칙만 CLI에 저장하도록 요청합니다. |

**항상 허용은 표시한 도구·규칙·저장 범위에 대한 선택**입니다. 규칙에 세부 조건이 없는 경우에는 해당 도구 전체 범위임을 표시합니다. CLI가 저장 범위를 제안하지 않으면 앱이 항상 허용을 만들어 제공하지 않습니다. 회사 deny 규칙·관리 정책을 해제하거나 모든 승인을 자동 생략하는 선택지는 추가하지 않습니다.

사용자가 범위를 고른 뒤 승인해야 브라우저가 후보 ID를 보내고, 서버는 그 승인 요청에 CLI가 제공한 규칙을 확인하여 원본 업데이트를 반환합니다. 선택지만 바꾸는 것으로 저장하지 않습니다. 사용자가 지속 허용을 명시적으로 고른 해당 규칙만 CLI에 저장하도록 요청하며, 앱이 개인 설정 파일을 직접 쓰지 않습니다. 거절하거나 질문에 답하는 경우에 승인 규칙을 함께 저장하지 않습니다. 실제 저장·적용은 CLI의 처리 결과와 이후 동작을 확인해야 합니다.

모델·승인 모드 변경은 계속 현재 연결에만 적용합니다. **기존 설정으로 돌아가기**는 그 연결의 모드를 복원하는 기능이며, 사용자가 별도로 저장한 지속 허용 규칙을 삭제하는 기능은 아닙니다. 저장한 규칙을 바꾸려면 기존 Claude의 해당 설정 범위를 확인합니다.

## 기존 기능과 Company Agent 코어

0.12.0의 공통/폴더 카탈로그, 실제 바탕화면 기본 위치, Noto Sans KR, 대기 배지, `/`·`@` 입력 보조, 외부 앱 열기를 유지합니다. 저장소의 `docs/WORKSPACE_0.12.0_COMPATIBILITY.md`는 당시 기록이며, 현재 실행과 승인 저장 범위는 이 문서를 기준으로 합니다. 과거 문서를 내려받거나 웹에 연결하지 않아도 현재 사용 절차를 확인할 수 있습니다. 목록에 보이는 항목이 실제 CLI에 로드됐거나 실행 권한을 얻었다는 뜻은 아닙니다.

**이번 작업에서 확인한 개인 Company Agent 설치는 1.4.23이며 업데이트하지 않았습니다.** Workspace와 코어는 별도 배포입니다. Workspace 0.12.1 ZIP은 설치된 코어·스킬·후크를 교체하지 않습니다. 소스의 코어 개선이나 과거 1.4.28 문서가 현재 개인 설치에 적용됐다고 판단하지 마세요.

HTML 디자인 카드의 `workspaceChoice` schema 1, 정확한 선택 대기의 Stop 보정 구분, 등록된 하네스 도움말 조회 예외는 해당 기능이 적용된 코어가 필요합니다. 지원하지 않는 설치에서는 기존 텍스트 선택·후크 동작을 유지할 수 있습니다. 모델 목록·모드 변경·항상 허용 후보도 설치 Claude가 실제 제공하는 범위를 따릅니다.

새 ZIP을 적용할 때는 기존 앱의 **설정 → 앱 종료**를 누른 뒤 새 폴더에서 실행하세요. 기존 업무·대화·기억·개인 설정은 자동 이동하거나 삭제하지 않습니다. 앱 창의 X는 서버 종료와 다릅니다.

## 검증 범위

새 버전의 확정 시험 결과는 저장소의 `docs/VALIDATION_0.12.1.md`에 기록합니다. 가상 CLI·임시 설정 시험과 실제 회사 PC의 UAC-off 실행·모델 인증·Office·DRM·Windows 알림은 구분합니다. 앱이 열리거나 모의 승인 응답이 통과한 것을 실제 회사 업무 성공으로 취급하지 않습니다.

# 0.18.0 검증 기록 — 전용 Windows 창

2026-09-30 현재 개발 PC의 Windows 로그인 사용자 환경에서 확인한 결과입니다. 모든 회사 PC·보안 정책 조합에서의 실행 보장은 아닙니다.

## 자동 회귀

- 최종 전체 시험: **989개 중 959개 통과, 30개 건너뜀, 실패·오류 0개** (209.588초).
- 현재 사용자 명령 해석·실행기 재사용 `ResolutionTests`: 별도 9개 통과.
- 건너뜀: 선택적 Company Agent 소스 연동, 심볼릭 링크 권한, 명시적으로 선택해야 하는 네이티브 토큰/알림/트레이 시험 등. Company Agent 소스가 없어도 현재 일반 Claude 앱은 동작합니다.
- 새 시험은 전용 파이프 통신, 중복 창 방지, 호스트 종료·재열기, 잘못된 PID/HWND 거부, Runtime 미발견, 브라우저 알림 중복 방지 및 구버전 서버 호환을 포함합니다. 기존 입력·자동완성·Shift+Tab·모델/effort·첨부·승인·이전 대화 관련 회귀도 함께 실행했습니다.

앞선 샌드박스 전체 시험 두 회에서는 각각 임시 기록 파일 교체 `WinError 5`, 로컬 업로드 연결 `WinError 10053`이 서로 다른 시험에 한 건씩 발생했습니다. 해당 묶음의 단독 재실행은 통과했고 최종 실제 사용자 환경 전체 재실행도 통과했습니다. 새 창 구현이 이 두 간헐 오류의 근본 원인을 해결했다고 주장하지 않으며 관련 기존 기록/업로드 코드는 이번 변경으로 수정하지 않았습니다.

## 실제 전용 창

`verify-workspace-desktop.py`의 별도 가짜 업무 상태로 다음을 확인했습니다. 실제 Claude나 개인 브라우저 프로필을 사용하지 않았습니다.

- WebView2 Runtime **154.0.4258.37**에서 호스트 초기화와 localhost 페이지 로드 완료.
- 창 소유 프로세스·PID·HWND·실행 파일·사용자·세션·생성 시각 검증.
- 반복 열기 네 번에서 같은 프로세스와 창 재사용.
- 제목 표시줄 X 명령으로 숨기고 같은 창 복원. 완전 종료 시 호스트 프로세스 종료.
- Windows가 앱 제목 표시줄 색상 요청을 수락. 실제 화면의 색상·배율을 모든 OS에서 육안 확인한 것은 아닙니다.
- 별도 자식 프로세스에서만 Runtime 경로를 존재하지 않는 위치로 지정했을 때 WS-46 반환 및 호스트 정리. 설치된 Runtime이나 전역 환경 변수는 변경하지 않았고 브라우저 대체 실행도 없었습니다.

## 실제 EXE와 Claude

- 한글·공백이 포함된 폴더에 EXE 한 개만 복사한 뒤 실행했습니다. 최종 EXE SHA256은 아래 표와 같습니다.
- 기존 **Python 3.13.5**를 확인해 사용했습니다. 앱 캐시에 Python 실행 파일은 없습니다.
- bootstrap에 `window.mode=desktop`, `engine=WebView2`가 확인됐으며 EXE 재실행과 창 열기 API가 같은 서버/창을 재사용했습니다.
- 기존 **Claude Code 2.1.285**의 인증과 명령 경로로 초기화했습니다. 모델 `claude-sonnet-5-5`, effort `medium`, 명령 141개를 확인했습니다.
- 같은 배포 소스의 서버 API로 검증 대화 한 번을 요청해 `WORKSPACE_EXE_OK` 응답을 확인했습니다. 대기 도구 0개, 모델·effort·승인 상태 유지. 마지막 C# 저장 창 deferral 보정 후 최종 EXE는 시작/재열기/정상 종료를 다시 확인했습니다.
- 기존 개인 설정 5개 경로의 실행 전후 해시가 같았습니다. 새 검증용 Claude 대화 기록은 생성되며 개인 기본 설정을 초기화하지 않습니다.

## 패키지

## 한계와 현장 확인

- **WebView2 Evergreen Runtime 및 .NET Framework 4.6.2 이상이 필요합니다.** 앱은 자동 설치하거나 회사의 실행 정책을 변경하지 않습니다. 기존 Python 3.11 이상 조건도 유지합니다.
- 다른 PC의 WDAC/AppLocker·UAC 비활성화·화면 배율·다중 모니터 조합에서 이번 호스트를 모두 검증하지 않았습니다. 기존 제한 토큰/DACL 수정은 유지했습니다.
- 일반 폴더/파일 선택, 실제 탐색기 드래그, 저장 대화상자, IME와 단축키의 모든 네이티브 입력 조합 및 화면 엔진 장애 복구는 운영 PC에서 추가 확인이 필요합니다. 관련 웹 동작 자동 회귀와 기본 네이티브 창 수명 검증을 수동 UI 전수 검사로 표현하지 않습니다.
- 별도 검증 브라우저로 로컬 인증 URL을 전달하는 추가 화면 검증은 자동 승인 검토에서 차단되어 수행하지 않았습니다. 다른 방식으로 이 차단을 우회하지 않았습니다.
- WebView2는 여러 하위 프로세스와 별도 메모리를 사용합니다. 브라우저 방식보다 항상 메모리가 적다는 성능 주장은 하지 않습니다.

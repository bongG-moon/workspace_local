# 0.23.36 동일 버전 갱신 검증 — 2026-10-28

## 이전 초안 알림

업데이트 복원 시 목록에 없는 업무의 초안까지 현재 초안 Map에 복사하던 경로를 재현했다. 사용자가 보관 기록을 지워도 복사본이 다음 업데이트 snapshot에 포함되어 같은 내용의 복원 안내가 다시 나타날 수 있었다.

- 업데이트 복원에서 사용할 수 없는 업무의 초안은 원본 보관 기록에 두고 사용자의 복원·정리 선택을 따른다.
- 선택했던 업무가 사라진 경우 빈 홈 입력창으로 복원하되, 사라진 업무 ID의 복사본을 만들지 않는다. 일반 대화 홈도 동일하게 처리한다.
- 초안 저장소를 정상 로드한 경우, 이미 저장되어 있는 숨긴 업무의 초안·임시 보관 입력은 새 업데이트 snapshot에 중복 포함하지 않는다. 저장소의 내용 자체는 삭제하지 않는다.
- 전환 전 저장소 flush가 실패하면 기존과 같이 전환을 완료하지 않는다. 화면만 다시 로드하는 복원 동작은 기존의 전체 snapshot을 유지한다.
- 새로 작성하거나 직접 복원한 입력, 첨부, 다른 업무의 초안은 유지한다. 요청 자동 전송은 없다.

실제 프런트엔드 초안 저장 모듈을 사용한 연속 2회 업데이트 시나리오를 포함해 아래 6개 파일의 **206개 테스트 통과**:

`test_workspace_upgrade_frontend.py`, `test_workspace_startup_health_frontend.py`, `test_workspace_drafts_frontend.py`, `test_workspace_upgrade_handoff.py`, `test_workspace_upgrade_launcher.py`, `test_workspace_drafts.py`.

서로 다른 이전 보관 기록이 여러 건 있으면 한 건을 정리한 뒤 다음 기록이 안내될 수 있다. 사용자의 실제 과거 업데이트 상태를 재현한 것은 아니며, 합성 초안과 격리된 로컬 저장소로 반복 경로를 검증했다.

## 설정 창 제작자 표기

기존 설정 하단 메뉴 아래 왼쪽에 `Designed by 2069026`을 배치했다. Noto Sans KR 12px, 보통 굵기, 테마의 보조 글자 색상, 위 메뉴와 12px 간격을 사용한다. 링크나 추가 실행 동작은 없다.

실제 배포 HTML/CSS를 Edge에서 열어 라이트·다크 모드 각각 1280px 및 420px 창 너비로 검증했다. 네 조합 모두 글자·버튼 겹침과 가로 잘림이 없고 브라우저 스크립트 오류가 없었다. 정적 표기이므로 네트워크 요청·폴링·상주 작업자는 추가하지 않았다.

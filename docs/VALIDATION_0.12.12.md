# Company Workspace 0.12.12 — 제한 권한 재실행과 WS-38

검증 기준일: 2026-09-30. 네이티브 회귀, 공개 소스 전체 회귀, 현재 사용자 실행기 및 로컬 산출물·실제 EXE 연결 검증을 완료했습니다. 공개 게시와 다운로드 대조는 아직 하지 않았습니다. **운영 진단으로 확인한 실패 원인, 개발 PC의 인공 재현, 수정본의 운영 PC 재실행을 구분합니다.** 아래 대기 항목은 성공으로 처리하지 않습니다.

## 운영 진단으로 확인한 내용

사용자가 전달한 0.12.11 비교 진단 JSON에서 다음을 확인했습니다. 원본 JSON에는 운영 계정 경로가 있어 이 문서나 공개 저장소에 복사하지 않습니다.

| 비교 항목 | 원래 PowerShell 실행 조건 | 앱의 제한 권한 자식 |
| --- | --- | --- |
| UAC·권한 조건 | UAC 비활성화, High 무결성 | 앱이 만든 제한 복사 토큰 |
| Python | 기존 Python 3.11.5와 기본 모듈 정상 | 검사 시작 단계 접근 거부 |
| 기본 DACL | 사용자 직접 허용 ACE 없음, Administrators·SYSTEM 허용 | 위 기본 DACL을 상속 |
| 자기 프로세스 핸들·파이프 | 원래 조건과 비교 가능 | 접근 거부, Windows 코드 5 |
| 출력 리디렉션을 사용하는 Python | 원래 조건에서 정상 | 접근 거부, Windows 코드 5 |
| 출력 리디렉션 없는 Python | 원래 조건과 비교 가능 | 종료 코드 `0xC0000142` |

기존 실행기는 관리자 권한을 제한하면서 원본 기본 DACL을 그대로 이어받았습니다. 이 운영 환경에서는 제한 자식이 자신의 프로세스 및 새 출력 통로를 사용할 수 없어 Python 시작이 실패했습니다. **이번 WS-38은 앱의 권한 전환 과정에서 발생한 결함으로 확인했습니다.** Python 재설치나 PATH 변경으로 해결해야 한다는 근거는 없습니다. 이 진단이 모든 코드 5·WS-38의 원인을 동일하게 확정하는 것은 아닙니다.

## 수정 경계

수정 대상은 앱 실행을 위해 새로 만드는 제한 토큰 복사본의 기본 DACL입니다. 동일 사용자가 그 복사본으로 만드는 새 프로세스·통로를 사용할 수 있도록 준비합니다. 원본 토큰, Windows UAC·영구 정책, 기존 파일·폴더 ACL, 계정과 Claude·Company Agent 개인 설정을 바꾸지 않습니다. 관리자 원본 권한으로 앱을 계속 실행하는 예외를 추가하지 않습니다.

현재 구현은 제한 복사본의 사용자 SID를 다시 확인한 뒤, 기존 기본 DACL의 ACE·거부 항목·순서를 보존하고 동일 사용자의 새 객체용 GENERIC_ALL 허용 ACE가 없으면 추가합니다. 이미 해당 허용이 있으면 중복 추가하지 않으며 NULL DACL은 기존 의미를 유지합니다. 토큰 소유자·SACL과 프로세스/스레드의 명시적 보안 설명자는 바꾸지 않습니다. 저장한 기본 DACL을 다시 읽어 바이트 일치까지 확인하지 못하면 중단합니다. 이 변경은 기존 파일 접근권이나 관리자 그룹·권한을 복구하는 기능이 아닙니다.

기존 일반 권한 UAC 연결 토큰 우선 경로와 사용자·세션·프로필 검증, 관리자 권한·무결성 및 실제 자식 프로세스 검증을 유지합니다. 아래 결과 표의 개발 PC 인공 재현과 네이티브 회귀로 효과를 별도 확인합니다.

EXE와 VBS 모두 앱 파일만 배포하며 이미 설치된 Python 3.11 이상을 사용합니다. Python 런타임·설치 프로그램을 포함하거나 다운로드·자동 설치하지 않습니다. AI는 기존 Claude 인증을 사용합니다.

전체 공개 소스 회귀의 생략 28개는 선택적 Company Agent 코어 20개, 심볼릭 링크 권한 3개, 별도 선택 실행 토큰 검사 4개, WSH 환경 1개입니다. 토큰 검사 중 제한 복사본·자식·신규 기본 DACL 3개는 위 별도 네이티브 14개 실행에서 통과했습니다. 시험 범위가 겹치므로 전체 회귀·네이티브·순수 ACL·버전 검사 수를 누적 합산하지 않습니다. 현재 사용자 실행기 3개는 전체 회귀 실행기에서 제외해 별도로 확인했습니다. 전체 보고서는 `build/qa-workspace-0.12.12-tests.json`에 보관합니다.

VBS ZIP의 격리 데모 검사는 별도 압축 해제한 서버 진입점의 시작·API·종료 확인입니다. VBS 더블클릭 자체나 운영 PC 재실행의 검증으로 확대하지 않습니다. 실제 EXE 검사는 기존 CLI 연결 초기화까지이며 모델에 업무 메시지를 보내 답변 품질을 시험한 것은 아닙니다.

순수 ACL 검사는 원래 ACE 바이트·거부 순서 보존, 정확한 사용자 허용과 중복 방지, 조건부·상속 전용 ACE의 오인 방지, NULL 유지 및 잘못된 ACL 거절을 확인했습니다. 네이티브 시험의 수정 전 기준은 임의로 실패하도록 편집한 코드가 아니라 커밋 `806183a`와 정규화 해시가 같은 0.12.11 전체 네이티브 소스입니다.

수정 전 시험은 파이프 코드 5 및 `child_session` 코드 5를 재현했습니다. **운영 JSON의 모든 실패 경로나 `0xC0000142`까지 동일하게 재현한 것은 아닙니다.** 수정 후 시험은 권한이 낮아진 Medium 자식 검증, 원본 토큰 수정 시도의 거절 및 후속 Python 실행을 확인했습니다. 시험은 현재 비승격 Medium 계정에서 만든 제한 복사 토큰 호스트를 사용했으며 운영 PC의 UAC 비활성·High 계정 환경 자체를 변경·복제하지 않았습니다.

개발 PC에서 운영 조건을 인공적으로 재현하는 시험은 변경의 효과와 경계를 확인하는 근거입니다. 실제 운영 PC의 보안 제품·그룹 정책·인증 환경 전체를 재현했다는 뜻은 아닙니다. 수정본의 해당 PC 재실행 결과를 받기 전까지 운영 해결 완료라고 표시하지 않습니다.

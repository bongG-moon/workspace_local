# Company Workspace 0.13.0 검증 기록

검증 기준일: 2026-09-30. Windows 앱 사용 흐름 변경을 대상으로 합니다. 회사 운영 PC에서 이전 0.12.12가 실행된다는 사용자 확인과 이번 0.13.0 신규 기능 검증을 구분합니다.

## 코드·화면 검증

| 범위 | 결과 |
| --- | --- |
| 공개 소스 전체 회귀 | 715개 실행, 686개 통과, 29개 조건부 생략, 실패·오류 0 |
| 현재 로그인 사용자 실행기 | 3개 통과: 기존 호출 환경, 동일 버전 재실행, 다른 버전 충돌 처리 |
| Windows 트레이 네이티브 및 단위 검사 | 10개 통과: 임시 아이콘, 중복 방지, Shell 재시작 메시지 후 복구, 정리 |
| 창 표시·숨김 및 소유권 | 11개 통과; 다른 사용자·프로세스·변경된 창을 조작하지 않음 |
| 대기·예약 엔진 | 28개 통과, 전체 회귀에 포함 |

전체 회귀는 Company Agent 외부 코어 없이 실행했습니다. 29개 생략은 선택적 Company Agent 통합 20개, 심볼릭 링크 권한 3개, 실제 Windows 사용자·토큰·트레이 opt-in 5개, 해당 시험 프로세스에서 실행되지 않은 Windows Script Host 1개입니다. 네이티브 트레이와 현재 사용자 실행기는 별도 실행했습니다. 이 표의 부분 시험은 전체 수와 중복되므로 합산하지 않습니다.

브라우저 시험은 격리된 가상 CLI의 결정적 응답을 사용했습니다. 실제 모델의 품질·회사 인증·외부 시스템 동작을 검증한 것은 아닙니다. 탐색기의 파일을 실제 Windows UI에서 끌어오는 동작은 이 환경에서 직접 조작하지 못했으며, HTTP 업로드와 브라우저 파일 이벤트 계약을 각각 검사했습니다. 앱 내부 원본 경로 드래그는 실제 화면에서 수행했습니다.

## 설계 경계

- 일반 Claude Code와 기존 인증을 사용합니다. 후속·예약 경로는 Company Agent 설치, Cron 도구, OS 작업 스케줄러에 의존하지 않습니다.
- 현재 요청이 승인·질문을 기다릴 때 다음 요청을 보내지 않습니다. 기존 거절·승인 규칙을 완화하지 않습니다.
- 보내기 직전의 중지/연결 재설정 경쟁을 확인합니다. 전송 기록이 불확실하면 자동 재전송하지 않습니다.
- 한 번·매일·매주 예약, 재시작 복원, 손상된 상태 파일, 저장 실패, 같은 발생 회차 중복, 설정 변경, 지연·놓친 회차를 시험했습니다.
- 외부 드래그는 로컬 앱 관리 복사본에 저장하며 크기 제한·경로 검증·원자적 저장·업무 전환 중 잘못된 첨부 방지를 적용합니다.
- 응답은 40ms 단위로 모아 프레임 갱신하고 마지막 완료 메시지와 중복되지 않게 합니다. 위로 스크롤한 읽기 위치를 유지합니다.
- UAC·Windows 정책·개인 Claude 설정을 수정하지 않습니다. 0.12.12의 권한 토큰 수정 코드는 유지합니다.

0.13.0 운영 회사 PC의 직접 실행, 모든 CLI 버전·기업 보안 제품·Office·DRM 조합, 긴 시간의 절전/로그오프/실제 Explorer 재시작은 별도 현장 확인 범위입니다. 트레이 복구 시험은 실제 Explorer 종료 대신 해당 Windows 메시지를 전송한 시험입니다.

개인 경로·실행 토큰·원시 업무 상태는 공개 저장소와 ZIP에서 제외합니다. 로컬 원시 기록은 `build/qa-workspace-0.13.0-tests.json`, `build/qa-workspace-0.13.0-browser.json` 등에 보관합니다.

# LLM 사용량 표시

왼쪽 하단 앱 메뉴 위에 `LLM 토큰 사용량`을 표시합니다. 서비스에서 제공하는 수치는 **팀 사용 금액/예산**입니다. 실제 토큰 개수로 변환하지 않으며 상세 패널에 기준을 설명합니다.

운영자는 **사내 배포 프로그램의 `LLM 사용량 MCP 주소 (선택)`**에 HTTP/HTTPS 서버 주소와 MCP 경로를 입력한 뒤 빌드합니다. 주소는 `workspace-llm-usage.json`으로 EXE와 업데이트 ZIP에 함께 포함됩니다. 일반 앱에는 주소 편집 기능이 없으며, 개인 KEY는 패키지에 포함하지 않습니다. 주소를 변경했다면 새로 빌드해야 하며 이전 주소로 만든 파일을 게시하지 않도록 검사합니다.

배포 주소가 없는 앱에 한해 `LLMOPS_MCP_URL` 환경변수를 사용할 수 있습니다. 배포 주소가 있으면 환경변수보다 우선합니다. 기본 팀 별칭은 `hcp-pro-tier`이고 `LLMOPS_TEAM`으로 변경할 수 있습니다. 사내 주소는 운영자의 배포 설정에서만 입력하고 공개 소스에는 넣지 않습니다. 환경변수 변경 후 앱을 완전히 종료하고 다시 실행하세요.

KEY는 `SK_BUDGET_HUD_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY`, 사용자 `.claude/settings.json`의 `env.ANTHROPIC_AUTH_TOKEN` 또는 `env.ANTHROPIC_API_KEY`, `OPENAI_API_KEY` 순서로 읽습니다. `CLAUDE_CONFIG_DIR`이 있으면 해당 폴더의 `settings.json`을 사용합니다. 스토어 연결 KEY와 별개이며 브라우저·로그·업무 요청에 전달하지 않습니다. 인증 헤더를 다른 주소로 리디렉션하지 않습니다.

## 연결 테스트 EXE

`python scripts/test-lab/build-usage-test.py --output <새 출력 폴더>`로 별도 테스트 EXE를 만듭니다. 기존 앱 설치를 변경하지 않고 `%LOCALAPPDATA%/CompanyAgent/llm-usage-test`에 자체 실행 자료와 상태를 저장합니다. 자동 업데이트는 꺼져 있습니다. 사용량 조회에는 실제 사용자 Claude KEY를 사용하며 예시 값으로 대체하지 않습니다.

테스트 앱의 왼쪽 아래 **LLM 토큰 사용량**을 열고 서버 주소 입력 후 **저장하고 연결 확인**을 누릅니다. KEY 입력란은 없습니다. 주소는 테스트 앱 재실행 후에도 유지됩니다. 실패 시 상세의 진단 코드, 단계, HTTP 번호로 DNS/연결/인증/팀 조회/예산 응답 문제를 구분합니다. KEY나 서버 응답 원문은 표시하지 않습니다.

2차 테스트 앱에는 **기본 연결 / 서버에 직접 연결** 선택과 최근 조회 경로 표시가 있습니다. 기본 연결은 Python의 환경변수·Windows 프록시 설정 및 예외를 따릅니다. 같은 PC에서 기존 조회는 정상인데 앱만 초기화 단계에서 503을 받으면, 허용된 사내 직접 접속 경로로 비교할 수 있습니다. 직접 연결은 사용자가 선택한 경우에만 사용량 클라이언트에 적용하며, 시스템 설정 변경이나 실패 후 자동 우회는 하지 않습니다. 정식 앱은 기존 기본 연결 방식을 유지합니다. 503만으로 서버 장애나 프록시 장애를 확정하지 않습니다.

`--revision 2` 빌드는 파일 이름과 앱 이름, 저장 경로, 실행 식별자를 분리합니다. 이전 테스트 앱이 실행 중이어도 새 테스트 화면으로 열립니다.

- 앱의 `--demo` 실행 또는 명시적 `LLMOPS_DEMO=1`에서만 예시 수치를 표시합니다. 실제 조회 실패를 예시나 0으로 대체하지 않습니다. 운영 환경에서는 이 변수를 해제하세요.
- 조회는 별도 스레드에서 수행하며 대화 처리 잠금을 사용하지 않습니다. 5분 캐시, 동시 조회 합치기, 수동 새로고침 최소 15초 간격, 실패 후 1분 대기를 적용합니다. 화면은 서버가 반환한 `pollAfterMs`를 따라 재조회하므로 실패 복구를 5분 동안 미루지 않습니다.
- 502/503/504, 연결 오류와 시간 초과에는 같은 연결 경로로 최대 2회 재시도합니다(기본 2초, 5초 대기). 각 조회는 약 9초로 제한하며, 대기 중 잠금을 잡지 않습니다. 인증/권한/응답 형식 오류에는 즉시 반복 호출하지 않습니다. `Retry-After`가 있으면 이를 따르고, 15초보다 긴 대기는 작업 스레드를 끝낸 뒤 다음 갱신 시점으로 넘깁니다(대기 해석 상한 24시간). 업무 요청·설치 명령은 재실행하지 않습니다.
- 화면이 보이는 동안 주기적으로 갱신하며 업무가 끝날 때마다 별도 호출하지는 않습니다. 테스트 주소를 저장하면 캐시를 지우고 즉시 조회합니다.
- MCP initialize/session-id/initialized/tool 호출을 사용하며 JSON과 여러 이벤트를 포함한 SSE를 처리합니다. 응답 크기는 512 KiB로 제한합니다.
- 80%는 주의, 95%는 한도 임박으로 표시합니다. 색상과 문구를 함께 사용하고 작업을 강제로 중단하지 않습니다. 한도 0은 비율을 계산하지 않고 `한도 미설정`으로 표시합니다.
- 조회가 실패하면 `사용량을 조회하지 못했어요.`를 표시하고 이전 금액·잔액·사용률·사용량 막대·초기화 시각을 숨깁니다. 빈 막대를 0%로 보여주지도 않습니다. 자동 재시도 중에도 이전 수치를 보여주지 않으며, 정상 조회에 성공하면 새 수치를 표시합니다. 상세에는 인증 오류의 `LLM Key 확인이 필요합니다.` 등 원인과 재시도 횟수를 안내합니다. 내부 캐시는 팀 선택 등에만 이용하며 실패 시 잔액으로 노출하지 않습니다.
- 초기화 시각은 API `reset_at` 값을 사용하고 한국 시간(KST), 24시간제로 표시합니다. 명시된 `Z`/오프셋을 우선하며, 시간대가 없는 값은 운영 기준(한국 시간 09시 초기화)에 맞춰 UTC로 해석합니다. 이는 실서버 원문 확인 전의 배포 해석 규칙이며 서버 응답 계약이 확정되면 대조해야 합니다. 화면에 시간대가 생략되었음을 안내하고 시각에 마우스를 올리면 서버 원문을 확인할 수 있습니다. `2026-10-28T00:00:00` 또는 `...00:00:00Z`는 `10월 28일 09:00 KST`, `...00:00:00+09:00`는 `00:00 KST`입니다. 특정 시각으로 강제 고정하거나 이미 변환된 값에 다시 9시간을 더하지 않습니다.

검증: `tests/test_llm_usage*.py`의 로컬 MCP HTTP/프록시/오류 복구 시험, `scripts/test-lab/verify-llm-usage-ui.cjs`의 화면 시험. 사내 MCP 실제 연결과 `reset_at` 원문은 사내망에서 별도로 확인해야 합니다. TEST1/TEST2가 모두 다시 연결되었다는 운영 확인만으로 최초 503의 원인을 프록시 또는 서버로 확정하지 않습니다.

# 일반·관리자 실행 권한 선택

0.23.20부터 **설정 → 앱과 Claude 실행 권한**을 사용합니다. 이전 공개 0.23.19에는 이 기능이 없으므로 0.23.20 실행 파일을 사용하세요. 실제 UAC 승인 후 관리자 실행·일반 권한 복귀의 왕복은 아직 미검증이며 [검증 기록](VALIDATION_0.23.20.md)을 확인하세요.

1. **실행 권한**에서 일반 또는 관리자를 선택합니다.
2. **선택한 권한으로 다시 시작**을 누릅니다. 관리자는 앱의 확인창에서 한 번 더 선택합니다.
3. Windows 승인창이 나오면 본인이 직접 확인합니다. 계정에 관리자 권한이 없거나 다른 계정으로 승인한 경우에는 실행이 거절될 수 있습니다. 다른 계정의 Claude 설정은 사용하지 않습니다.
4. 진행 중인 작업과 승인·질문을 마치면 앱이 작성 중인 입력과 첨부를 보관하고 모든 Claude 연결을 종료한 뒤 다시 시작합니다. 기다리는 동안 전환을 취소할 수 있습니다.
5. 설정의 **현재: 일반 권한 / 관리자 권한**으로 적용 결과를 확인합니다. 새 앱이 준비된 뒤에만 선택을 저장합니다. Windows 승인을 취소하거나 전환 전 검사가 실패하면 기존 앱과 선택을 유지합니다. 기존 앱 종료 후 새 창 준비에 문제가 생기면 실행 파일을 다시 열어 보관된 초안을 복원하세요.

0.23.20 수정본은 **Windows 권한 확인 → 전환 연결 → 작업 완료 대기 → 작성 내용 보관 → 앱 재시작**을 구분해 표시합니다. 다른 업무의 승인·답변·결과 확인도 먼저 마쳐 주세요. 보관 단계가 되면 설정 창은 자동으로 닫히며, 다시 열어 확인해도 전환을 막지 않습니다. 전환 연결이 실패하면 준비 중 표시를 해제하고 기존 입력을 유지합니다.

이전 0.23.20 ZIP을 사용했다면 수정 ZIP을 다시 받아 새 폴더에서 실행하세요. 버전이 같아 자동 업데이트 알림은 뜨지 않습니다. 진행 중인 전환이 있다면 메인 화면의 전환 안내에서 마치거나 취소한 뒤 수정본을 실행합니다. 업무가 남아 있다면 작업·응답을 마친 뒤 초안을 보관해 수정본으로 교체합니다.

**다시 일반 권한으로 돌아오려면** 같은 위치에서 일반을 선택하고 재시작하세요. 처음 실행할 때는 일반 권한이며, 선택한 권한은 이 앱의 상태 폴더 안 `execution-mode.json`에만 보관합니다. 다음 EXE·VBS 실행에서도 선택을 읽습니다. EXE의 `--execution-mode normal` 또는 `--execution-mode administrator` 옵션으로 이번 실행의 권한을 직접 지정할 수도 있습니다.

관리자 앱이 이미 열려 있을 때 일반 권한으로 돌아오려면 앱 설정에서 전환하세요. 일반 터미널이나 일반 브라우저가 관리자 앱의 작업·종료를 대신 요청하도록 허용하지 않습니다.

일반 모드는 기존처럼 같은 계정의 일반 UAC 토큰 또는 검증된 제한 토큰을 사용합니다. 관리자 모드는 같은 계정·로그인 세션의 실제 관리자 토큰이 확인된 경우에만 유지합니다. 프로그램이 Windows UAC·계정·그룹 정책·파일 권한을 바꾸거나 Windows 승인을 우회하지 않습니다.

관리자 모드에서 Claude와 그 도구·명령도 관리자 권한을 상속합니다. Claude의 auto·manual·bypass 승인 모드와 모델·Effort는 별개이며, 기존 업무의 선택과 개인 인증·MCP·스킬·메모리 설정을 보존합니다. 재시작 뒤 이어 할 일과 예약은 내용을 확인하고 재개하세요. 중단된 요청은 자동으로 다시 보내지 않습니다.

버전 업데이트도 선택한 권한을 유지합니다. 이번 권한 선택이 없는 같은 버전의 앱이 열려 있어도 작업·초안을 보존하는 기존 전환 절차로 교체합니다. 현재 실행 중인 앱보다 오래된 파일을 실행하면 최신 앱을 우선하며 낮은 버전으로 교체하지 않습니다.

## 관리자 연결 보호와 메모리 사용

관리자 모드의 API는 연결 토큰 외에 실제 요청 프로세스의 Windows 사용자·세션·관리자 권한도 확인합니다. 일반 프로세스에는 새 창을 찾는 최소 정보와 같은 계정의 창 열기만 허용합니다. WebView2의 샌드박스는 유지하고 전용 창이 같은 출처의 인증된 요청만 중계합니다. 다른 웹사이트·출처의 요청이나 임의 서버 주소를 중계하지 않습니다.

중계는 동시에 최대 4개, 응답당 최대 32MiB로 제한하며 응답을 별도 캐시에 보관하지 않습니다. 요청 본문 길이가 제공되지 않으면 256KiB까지 메모리에 읽고 큰 첨부는 독점적으로 연 임시 파일로 넘겨 사용 후 삭제합니다. 앱의 기존 첨부 제한은 파일당 50MiB입니다.

관련 근거: [Windows TCP 소유 프로세스 조회](https://learn.microsoft.com/en-us/windows/win32/api/tcpmib/ns-tcpmib-mib_tcptable_owner_pid), [WebView2 요청과 지연 응답](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2webresourcerequestedeventargs). WebView2 요청에는 네트워크 계층이 나중에 붙이는 일부 헤더가 없을 수 있어 본문 길이 대체 처리를 포함합니다.

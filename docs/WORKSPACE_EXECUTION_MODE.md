# Windows에서 일반·관리자 권한으로 실행하기

현재 0.23.21 소스와 로컬 수정본은 **프로그램을 열어 준 Windows 프로세스의 권한을 그대로 사용**합니다. EXE의 실행 선언은 `asInvoker`이며, 설정의 현재 권한 표시는 시작 시 검사한 실제 Windows 토큰을 기준으로 합니다. 설정에서 권한을 전환하는 선택칸과 버튼은 제거했습니다. 아래 안내는 현재 구현 기준이며 [최초 공개 0.23.20 검증 기록](VALIDATION_0.23.20.md)의 설정 전환 방식은 이전 구현에 대한 기록입니다.

## 실행 방법

| 원하는 실행 | 방법 |
| --- | --- |
| 일반 권한 | 일반 Windows 환경에서 `Company-Workspace-0.23.21.exe`를 더블클릭합니다. |
| 관리자 권한 | EXE를 우클릭해 **관리자 권한으로 실행**을 누르고 Windows 승인창이 나오면 본인이 확인합니다. |
| 터미널에서 실행 | 해당 터미널의 현재 권한을 앱·Claude가 상속합니다. 관리자 PowerShell에서 실행하면 관리자 권한으로 열립니다. |
| VBS로 실행 | VBS를 실행한 Windows 환경의 권한을 그대로 상속합니다. 관리자 실행은 EXE의 우클릭 메뉴가 가장 간단합니다. |

앱과 Claude, Claude가 호출하는 도구·명령은 같은 권한으로 실행됩니다. 일반 권한으로 열린 앱이 도구 호출 때문에 자동으로 관리자 권한을 얻거나, 관리자 앱을 자동으로 일반 권한으로 낮추지 않습니다. UAC가 꺼져 있거나 회사 정책에 따라 처음부터 관리자 토큰을 사용하는 PC에서는 더블클릭도 관리자 실행일 수 있습니다. 앱은 그 토큰을 확인해 사용하고 Windows 정책을 바꾸지 않습니다.

Windows의 같은 로그인 사용자·세션·프로필과 실제 토큰을 확인합니다. 다른 계정으로 관리자 인증한 경우나 SYSTEM·서비스 세션 등은 허용하지 않습니다. 개인 Claude 인증·모델·MCP·스킬·메모리와 회사 정책을 유지합니다.

## 다른 권한으로 다시 열기

1. 필요한 작성 내용을 보관하고 **설정 → 앱 종료**, 또는 트레이 아이콘 우클릭의 **완전 종료**를 선택합니다.
2. 작업 중이면 표시되는 종료 확인을 읽고 종료를 결정합니다. 종료는 진행 중 작업을 중지하며 이미 변경된 파일은 그대로 남습니다.
3. 트레이 아이콘까지 종료된 뒤 원하는 Windows 권한으로 EXE를 다시 엽니다. 창의 **X는 트레이로 숨기는 기능**이므로 이것만으로 권한이 바뀌지 않습니다.
4. 새 연결에서 현재 실행 권한을 확인합니다. 대화·업무 폴더는 유지하며 이어 할 일과 예약은 내용을 확인하고 재개하세요. 중단된 요청은 자동으로 다시 보내지 않습니다.

동일한 권한의 앱이 이미 실행 중이면 그 창을 활성화합니다. 일반 프로세스가 관리자 앱의 작업·종료를 대신 요청하도록 허용하지 않으므로 관리자 앱에서 직접 완전 종료하세요. 관리자 터미널에서 다시 여는 것만으로 일반 권한이 되는 것은 아닙니다.

이전 `execution-mode.json` 선택 파일은 실행 권한을 결정하는 데 사용하지 않고 다시 저장하지도 않습니다. 파일을 직접 삭제하거나 개인 설정을 초기화할 필요가 없습니다. 개발자용 `--execution-mode normal|administrator`는 **현재 권한 일치 검사**이며 UAC 호출이나 토큰 변경 옵션이 아닙니다. 기본 `auto`는 검증된 실제 권한을 확인합니다.

## 새로 받아도 관리자 표시가 유지될 때

밝게·어둡게 설정은 `%LOCALAPPDATA%\CompanyAgent\local-ui\appearance.json`에 따로 저장합니다. 새 실행 파일에서도 화면 모드가 유지되는 것은 정상이며, 관리자 권한이 저장되었다는 뜻은 아닙니다. 현재 앱은 관리자 권한을 선택 파일이나 실행 캐시에서 복원하지 않습니다.

1. **설정 → 앱과 Claude 실행 권한**에서 현재 권한과 앱·실행기 버전을 확인합니다.
2. 트레이에서 **완전 종료**했는지 확인합니다. X로 숨긴 기존 프로세스는 처음 실행한 권한을 유지합니다.
3. 앱을 연 터미널이 관리자 상태였는지, 바로가기의 **속성 → 바로 가기 → 고급**이나 EXE의 **속성 → 호환성**에 관리자 실행이 지정되어 있는지 확인합니다. 해당 지정은 앱의 저장 설정과 별개의 Windows 실행 조건입니다.
4. UAC가 꺼져 있거나 회사 정책상 현재 로그인 환경이 관리자 토큰을 사용하는 경우에는 일반 더블클릭도 관리자 실행일 수 있습니다. 이 경우 앱 캐시를 지워도 권한이 바뀌지 않습니다. 기존 보안 정책은 유지하고 필요한 실행 조건을 담당자와 확인하세요.

관리자 표시를 없애려고 `local-ui`, `workspace-runtime` 또는 개인 Claude 설정을 통째로 삭제하지 마세요. 업무·예약·첨부를 잃거나 다시 준비해야 할 수 있으며 권한 문제의 해결 방법도 아닙니다. 오래된 `execution-mode.json`이 있는 경우에도 삭제할 필요는 없습니다.

## 작업 중 승인 모드 변경

작업 중에도 **승인** 목록이나 **Shift+Tab / Alt+M**으로 현재 연결이 지원하는 승인 모드를 바꿀 수 있습니다. 변경 응답을 확인한 뒤 이후 도구 호출에 적용합니다. 이미 화면에 나온 승인·질문은 사라지거나 자동으로 허용되지 않으므로 직접 답하세요. 연결된 CLI가 실시간 변경을 거절하거나 제공하지 않으면 현재 모드를 유지하고 이유를 안내합니다. 모델·Effort 변경과 Windows 관리자 실행은 이 기능과 별개입니다.

Windows 관리자 권한과 Claude의 Manual·Auto·Plan·Bypass 승인 모드는 서로 다른 설정입니다. Bypass를 고를 때는 기존 위험 확인을 거치며 Windows 권한을 높이지 않습니다. 개인 기본 설정을 임의로 변경하지 않습니다.

## 관리자 연결 보호와 메모리 사용

관리자 앱의 API는 연결 토큰 외에 실제 요청 프로세스의 Windows 사용자·세션·관리자 권한도 확인합니다. 일반 프로세스에는 새 창을 찾는 최소 정보와 같은 계정의 창 열기만 허용합니다. WebView2 샌드박스를 유지하고 전용 창이 같은 출처의 인증된 요청만 중계합니다. 다른 웹사이트·출처의 요청이나 임의 서버 주소를 중계하지 않습니다.

앱 설정의 권한 전환 제어기·전환 준비 폴링·선택 파일 읽기·쓰기 경로를 제거했습니다. 버전 업데이트의 작업 대기·초안 보관 기능은 유지하며, 업데이트 후 프로세스도 Windows에서 실행된 권한을 상속합니다.

## 구형 EXE를 계속 누르고 있던 경우

업데이트는 앱 파일과 처음 실행하는 EXE가 별개입니다. 0.23.19 등 구형 EXE는 새 앱으로 연결하기 전에 일반 권한으로 바꾸는 코드가 있어, 최신 앱을 설치해도 원래 EXE로 관리자 실행하면 일반 권한이 전달될 수 있습니다.

0.23.21에서는 설정에 앱·실행기 버전과 실제 앱 권한을 표시합니다. **최신 실행기 바로가기 만들기**는 현재 앱과 같은 버전의 EXE를 기존 배포 경로에서 받아 SHA256 확인 후 앱 소유 위치에 보관하고, 전용 **Company Workspace (최신)** 바로가기를 만듭니다. 원래 다운로드 EXE나 알 수 없는 바로가기를 덮어쓰지 않습니다. 기존 앱을 완전 종료한 뒤 이 새 바로가기를 관리자 권한으로 실행하세요.

향후 업데이트도 EXE 자산이 있으면 함께 확인하고 새 앱의 시작 확인 후 준비된 실행기로 연결합니다. 현재 배포에 EXE가 없거나 아직 게시되지 않았으면 준비 실패를 표시하며 현재 실행기를 유지합니다. Windows UAC·정책·계정과 Claude 개인 설정은 변경하지 않습니다. 실제 운영 PC의 권한 결과는 해당 PC에서 확인해야 합니다.

# 0.21.2 모델·Effort 재연결 복구

검증일: 2026-10-01. 0.21.1 사용성 검토서에서 보고한 모델 기본값 복원 → 작업 취소 → 재연결 시 Effort 충돌 경로를 보완했습니다.

## 변경 내용과 범위

- 명시적으로 **기존 설정 사용**을 선택한 기록을 삭제하지 않습니다. 같은 앱 실행 중 최초 연결에서 CLI가 실제 보고한 모델·승인 기준값과 모델별 Effort 기준값을 별도로 유지합니다. 앱 완전 재시작 후에는 현재 PC의 Claude 설정을 다시 따릅니다.
- 새로운 CLI 프로세스가 이전 완료 턴의 모델을 복원하더라도 앱에서 확인한 모델 선택을 먼저 적용하고 응답을 확인합니다. 그다음 현재 모델의 Effort를 복원합니다.
- 지원되지 않거나 거절된 설정은 연결의 실제 모델·Effort 목록과 함께 안내합니다. 설정 메뉴는 계속 열 수 있으며, 유효한 항목 선택이나 기본값 복원으로 회복합니다. CLI가 변경 기능 자체를 지원하지 않는 경우에는 확인된 현재 값을 사용하겠다는 명시적 선택을 제공합니다. Bypass 위험 확인을 생략하는 경로는 제공하지 않습니다.
- 입력 중인 초안·첨부는 보존합니다. 설정 변경·복구만으로 업무 요청을 보내지 않습니다. `/effort`와 클릭 선택은 같은 제어 경로를 사용합니다.
- 설정 복원 때문에 전송 전에 차단된 대기·예약 요청은 보존하고 일시정지합니다. 설정을 고친 뒤 사용자가 **이어 실행**을 눌러 현재 설정을 확인해야 진행합니다. 전송 여부가 불명확한 요청은 여전히 자동 재전송하지 않습니다.
- 인증·전송 실패는 설정 선택 문제와 구분합니다. 연결 오류를 정상 연결로 처리하거나 자동 로그인·재전송하지 않습니다.
- 예약/대기 편집창에도 기존 제어 명령 검사를 적용했습니다. `/effort` 같은 즉시 설정 명령을 업무 프롬프트로 예약하지 않으며 입력한 편집 내용은 남깁니다.

기존 계정, UAC·보안 정책, 개인 Claude 인증·모델·MCP·스킬·하네스 설정은 수정하지 않습니다. 새 백그라운드 프로세스나 반복 조회 타이머는 추가하지 않습니다.

## 재현 검사

중립적인 두 모델 이름을 사용하는 기록용 가짜 CLI를 추가했습니다. 마지막 완료 턴의 모델만 재개하고, 취소한 턴의 제어 변경은 재개 기록에 반영하지 않는 조건을 만듭니다. 수정 전에는 보고서와 같은 `effort_invalid`가 발생했습니다. 특정 회사 endpoint나 공급자 모델 이름에 의존하지 않습니다.

재현 범위는 다음과 같습니다.

- 모델 선택 → 응답 완료 → 기본값 복원 → Effort 선택 → 취소 → 같은 세션 재개 → 후속 요청 한 번
- 모델·Effort·승인의 명시적인 기본값 복원, 반복 재연결, 다른 업무와의 분리
- 유효하지 않은 Effort, 거절된 모델, 지원 중단된 제어 기능에서의 명시적 복구
- 모델 복원이 거절되면 Effort를 먼저 적용하지 않음
- 인증·전송 실패, 복구 중 업무 변경, 대기열의 중지 경합과 불확실한 전송
- 제어 변경 시 업무 요청·대화 기록·실행 ID·파일 변경 관찰을 만들지 않음
- 개인 설정과 저장 대화에 앱 실행 중 복원 상태를 기록하지 않음

실제 EXE 시나리오는 `scripts/test-lab/verify-workspace-standalone.py`로 별도 상태를 만들고 `scripts/test-lab/verify-workspace-control-restore.py`의 단계별 동작으로 확인합니다. 테스트 모델은 현재 CLI가 제공한 목록에서 선택합니다.

실행기 검사 3개는 샌드박스 계정에서 기존 본인 계정 검증에 의해 WS-31로 중단됐습니다. 보안 검증을 약화하지 않고 실제 로그인 사용자로 재실행해 모두 통과했습니다. 첫 통합 실행의 테스트 모듈 검색 경로 오류도 검사 도구에서 수정했고, 위 323개는 최종 재실행 결과입니다.

실제 EXE 검증은 앱의 인증된 로컬 API로 제어·전송·중지 순서를 실행했습니다. 이번 PC에서 CLI가 제공한 Haiku로 짧은 응답을 받은 다음, 처음 관찰한 `claude-sonnet-5-5`로 **기존 설정 사용**을 적용했습니다. 중지 후에도 모델과 low, 기존 default 승인 모드가 유지됐습니다. 질문 3개 중 2개는 응답 완료, 1개는 의도적으로 중지했으며 추가 질문은 없었습니다. 이 모델명은 테스트 관찰값이며 운영 기본값이 아닙니다.

Computer Use로 최종 전용 창에서 복원 후 Effort 목록 열기, medium 클릭 변경, `/effort low` 적용과 입력 비움, 완료 응답 표시를 확인했습니다. 모델 메뉴의 12개 항목은 이 연결의 초기화 보고값과 표시명·설명·순서가 일치했습니다. 기존 설정 복원과 직접 입력은 별도 항목으로 표시됐습니다. 사내 대화형 `/models`와 비교한 것은 아닙니다.

VBS ZIP 검증은 압축을 푼 서버 진입점을 실행한 검사이며 VBS 아이콘을 Computer Use로 다시 더블클릭한 검사는 아닙니다. 공통 실행기 검사는 별도로 수행했습니다. 지원 중단된 제어 기능, 거절·인증·시간 초과와 초안·첨부 보존은 가짜 CLI 및 프런트엔드 회귀 검사로 확인했으며 실제 인증을 만료시키거나 회사 정책을 변경하지 않았습니다.

로컬 근거: `build/qa-workspace-0.21.2-controls-tests.json`, `build/qa-standalone-0.21.2-controls-release/`, `build/workspace-release-0.21.2.json`. 실제 상태·대화·개인 설정 검사 파일은 Git과 배포 ZIP에 포함하지 않습니다.

## 운영 모델 목록과 검증 한계

앱의 모델 목록은 CLI 초기화 응답을 그대로 사용합니다. 공급자 목록을 새로 고정하거나 테스트 환경의 모델을 운영 기본값으로 강제하지 않습니다. 기존 설정 복원·직접 입력은 모델 카탈로그와 구분합니다.

사내 운영 endpoint와 대화형 `/models` 화면의 직접 비교는 이번 개발 PC에서 수행할 수 없습니다. 동일 운영 PC·계정·CLI 버전에서 표시명·선택값·순서·현재/기본 모델을 비교하고 각 허용 모델의 실제 적용 응답을 확인해야 합니다. 현재 동적 목록 구현을 사내 목록 일치의 완료 증거로 간주하지 않습니다.

네트워크 단절·인증 만료의 실제 재현, PC 절전·재부팅, 주간 예약의 장기간 실행은 이번 변경의 검증 범위에 포함하지 않습니다. 인증 오류 처리는 격리된 제어 응답 주입 검사로 확인합니다. 기존 사용성 보고서에서 통과한 다른 기능을 이번에 모두 재검증했다고 주장하지 않습니다.

# Company Agent 핸드북

회사 공통 / 개인 전체 / 이 프로젝트를 먼저 구분하는 사용 설명서입니다. 각 범위 안에서 기억·지식과 업무 구성(스킬·도구·규칙)을 확인합니다.

## 1. 처음이라면 여기부터

**먼저 [시작하기](ONBOARDING_COURSE.md)에서 작은 가상 업무 하나를 해보세요.** 기능의 뜻과 바꾸는 방법이 궁금할 때는 아래 설명을 찾아보세요.

회사에서 준비한 것은 업무 절차와 설정입니다. Claude Code와 승인된 Python, 필요한 Office·MCP는 별도 준비물입니다. “스킬이 목록에 있다”와 “업무를 실제로 성공했다”는 다릅니다.

| 하고 싶은 일 | 시작할 곳 | 직접 확인할 것 |
| --- | --- | --- |
| 자료 내용 확인 | 원본 첨부 → 자료 읽고 정리하기 | 페이지·표·수치와 미확인 범위 |
| 보고서나 PPT | 보고서 만들기 / 발표 자료 준비하기 | 디자인 확인 후 제작, 결과 파일 열기 |
| 내 표현 방식·업무 지식 저장 | 기억·하네스 관리 → 개인 전체 / 이 프로젝트 → 기억·지식 | 저장 내용·사용 상태·적용 범위 |
| 함께 참고할 지식 보기 | 회사 공통 → 기억·지식 | 회사·팀이 배포한 출처와 기준일 |
| 공통 절차와 자동 처리 확인 | 회사 공통 → 업무 구성 | 공통 기준·스킬·후크, 읽기 전용 |
| 내 스킬·도구·폴더 지침 확인 | 개인 전체 / 이 프로젝트 → 업무 구성 | 출처·관리 주체·적용 범위 |
| 현재 폴더의 전체 구성 비교 | 기억·하네스 관리 → 구성 한눈에 | 세 영역의 상태·실제 위치·공유 여부, HTML 저장 |
| 속도·사용량 확인 | 사용 현황 · 결과 확인 | CLI 보고값과 사용자 대기 구간 |

## 2. 용어를 쉽게 이해하기

| 용어 | 여기서의 의미 | 오해하기 쉬운 점 |
| --- | --- | --- |
| CLI | 기존 Claude Code 실행 프로그램 | Workspace는 이를 대체하는 별도 AI가 아니라 입력·확인 창 |
| 하네스 | AI의 업무 절차·도구·설정·검증을 연결하는 틀 | 모델 자체를 더 똑똑하게 학습시키는 기능은 아님 |
| 스킬(Skill) | 업무별 처리 설명서 | 설치된 프로그램·실행 권한과는 별개 |
| 후크(Hook) | 요청 시작·도구 실행·종료 시 자동으로 호출되는 처리 | 모든 후크가 차단 장치인 것은 아님 |
| MCP | 외부 도구를 CLI에 연결하는 방식 | 연결만으로 관련 스킬이 자동 활성화되는 것은 아님 |
| 작업자(Agent) | 조율자가 맡긴 업무를 수행하는 별도 실행 역할 | 이름이 표시됐다고 실제 실행이 증명되는 것은 아님 |
| 기억(Memory) | 다음 업무에 참고할 내용. 공통 지식과 내 선호·업무 지식을 관리 주체로 구분 | 원본 문서·대화 전체를 저장하는 창고가 아님 |
| 지식(Knowledge) | 기억 중 출처를 확인할 용어·계산식·업무 자료 | 별도 관리 영역이 아님. 참고 자료가 명령이나 권한이 되는 것도 아님 |

## 3. 세 범위, 두 종류의 내용

| 범위 | 내용과 저장 위치 | 누가 바꾸나요? | 어디에서 이어지나요? |
| --- | --- | --- | --- |
| **회사 공통** | 설치에 연결된 배포 지식과 공통 기준·스킬·후크 | 담당자가 검토·배포. 사용자 화면은 읽기 전용 | 같은 배포본과 연결 설정을 사용하는 환경 |
| **개인 전체** | 로컬 개인 저장소의 선호·지식·개인 스킬·도구 | 나. 저장 전 범위와 내용 확인 | 같은 사용자 설치·저장소를 쓰는 여러 작업 폴더 |
| **이 프로젝트** | 로컬 개인 저장소의 프로젝트별 기억·자산. 폴더 지침은 실제 프로젝트 파일 | 내 자산은 나. 공유 프로젝트 파일은 작성·공유 주체 확인 | 저장한 프로젝트 경로와 연결된 설치에서 사용 |

‘회사 공통’은 회사가 관리하는 내용이며 ‘개인 전체/이 프로젝트’는 내 자료를 적용할 범위입니다. 각 화면에서 **기억·지식 / 업무 구성**을 선택합니다.

새 기억·지식·스킬·도구를 저장할 때는 **어디에 저장할까요? → 개인 전체 / 이 프로젝트**를 선택합니다. 이미 요청에 범위를 명시했다면 재질문하지 않습니다. 기존 항목 수정은 원래 범위를 유지하고, 회사 공통은 직접 저장 선택지에서 제외합니다. ‘내 것’이라고만 말하면 두 범위 중 하나를 물어봅니다. 화면에서도 새 저장 범위는 미선택으로 시작합니다.

실제 저장 경로는 **구성 한눈에**에서 확인합니다. 같은 PC의 새 대화라도 같은 설치·저장소를 사용해야 기억을 다시 조회할 수 있습니다. 다른 PC나 계정으로 자동 동기화하지 않으며, 옮겨 쓰려면 담당자와 백업·이전·연결 설정을 확인한 뒤 다시 조회합니다. 프로젝트 폴더 복사나 이름 변경만으로 프로젝트 개인 기억이 따라오지는 않습니다. ‘개인 전체’에 저장할 수 없다는 안내가 나오면 담당자에게 설치 범위를 확인하세요.

Claude 자체 자동 기억은 이 화면의 Company Agent 기억과 별도로 관리합니다. 원래 CLI에서 해당 기억의 경로·설정을 확인하며, 두 저장소를 자동 합치지 않습니다. 프로젝트 폴더를 공유해도 Company Agent 개인 자료가 동료에게 자동으로 전달되지는 않습니다.

| 확인할 저장소 | 일반적인 위치 또는 구분 |
| --- | --- |
| Company Agent 개인 전체 | 현재 User 설치 기본값은 `%LOCALAPPDATA%\CompanyAgent\states\user`. 기존 설치 등록·사용자 지정 위치가 우선 |
| User 설치의 프로젝트 개인 자료 | 위 저장소의 `project-scopes/<폴더 식별자>/`. 현재 작업 폴더의 절대경로로 구분 |
| 별도 Project 설치 | 기본값은 `%LOCALAPPDATA%\CompanyAgent\states\projects\<폴더 식별자>`. 해당 설치의 등록된 `stateRoot`가 우선 |
| Claude Code 자체 설정·기억 | 별도 Claude 설정 루트. 일반적으로 `%USERPROFILE%\.claude`를 사용하지만 실제 설정·기억 위치는 원래 CLI에서 확인 |

각 Company Agent 저장소 안에서 기억은 `memory/items/`, 개인 스킬은 `personal-root/.claude/skills/`, 학습 이력은 `learning/state.json`에 있습니다. 프로젝트 폴더 안의 지침 파일과는 다른 위치입니다. User 설치의 프로젝트별 저장소와 별도 Project 설치를 혼동하거나, 같은 폴더 이름·상위·하위 관계만으로 같은 기억을 쓴다고 가정하지 마세요. 예전 설치의 다른 경로를 위 기본값으로 수동 이동하지 않습니다. 이 경로는 확인용이며 기억 변경·중지·복구는 관리 화면이나 해당 명령으로 요청합니다.

부서 기준도 회사 영역에 포함합니다. 프로젝트는 “어느 폴더에 적용할지”이지 세 번째 정책 소유자가 아닙니다. 회사 필수 기준, 개인화 가능한 기본값, 참고 지식은 구분합니다. `required`라는 표시만으로 운영체제 권한이 강제되는 것은 아닙니다.

User 설치와 Project 설치는 적용 범위·개인 저장소가 다를 수 있습니다. 다른 범위의 기억이 보이지 않는다고 삭제됐다고 단정하거나 자동으로 합치지 마세요. 회사 업데이트는 개인 기억·지식·스킬과 기존 모델·MCP 설정을 임의로 초기화하지 않습니다.

**‘공통’과 ‘전역 설치’는 다릅니다.** 공통은 관리 주체, User/Project는 적용 범위입니다. ‘내 사용자 설치’는 내 여러 폴더에, ‘이 프로젝트’는 해당 설치 범위에 적용됩니다. User 설치 하나로 다른 직원에게 배포되거나 개인 기억이 공유되지는 않습니다. ‘폴더에 있으니 내 것’이라고도 판단하지 마세요. 함께 받은 프로젝트 파일은 공유 구성일 수 있습니다.

프로젝트 `CLAUDE.md`는 목적·단위·완료 조건을 적는 설명서입니다. 공통 스킬·후크·연결·검증을 포함하는 하네스 전체와 같지 않습니다. 작은 규칙은 짧은 프로젝트 지침으로 시작하고, 반복 업무에 여러 역할이 필요할 때 프로젝트 하네스를 생성하세요. 기존 `CLAUDE.md`를 생성기가 교체하지 않습니다. [시작하기](ONBOARDING_COURSE.md) 7단계에서 A/B 폴더로 차이를 시험합니다.

**새 작업 폴더의 첫 시작:** 파일 읽기·작성·수정 같은 작업 요청이 들어오면 지침이 없는 작업 폴더에 짧은 기본 `CLAUDE.md`를 한 번 생성합니다. 기존 파일·`.claude/CLAUDE.md`·부모 프로젝트 지침이 있으면 보존합니다. 홈·시스템·설치/설정 폴더, 계획 모드, 변경 금지 요청에서는 생성하지 않습니다. 별도 AI 호출이나 전체 폴더 탐색 없이 시작 안내만 만들므로 `/init`의 코드 분석과 동일하지 않습니다. 실행법·프로젝트 지식은 확인 후 별도로 보완합니다. 단순히 폴더를 여는 것만으로는 생성하지 않습니다.

**질문과 피드백 언어:** Company Agent의 질문 제목·선택지·설명·추천 표시·승인 안내는 기본 한국어입니다. 흔한 영문 선택 문구는 추가 AI 호출 없이 바꾸고, 알 수 없는 영문 설명의 재작성은 제한된 횟수만 요청합니다. 대화 언어를 따로 요청하면 그 범위를 따르며, 영어 보고서 요청만으로 선택 질문까지 영어로 바꾸지는 않습니다. 코드·파일명·제품명과 Claude 자체 메뉴·권한 버튼·Windows/Office 화면은 원래 표기를 유지할 수 있습니다.

## 4. 기본 스킬 11개와 이전 이름 1개

**이 폴더의 구성 지도:** Workspace의 **기억·하네스 관리 → 구성 한눈에**에서 회사 공통 / 개인 전체 / 이 프로젝트를 나란히 볼 수 있습니다. 이름·상태·파일 위치를 펼쳐 확인하고 HTML로 저장할 수 있습니다.

설정 켜짐, 사용 가능, 정의 발견, 꺼짐, 미확인을 구분합니다. 스킬의 **본문 로드 기록**은 현재 폴더와 대화의 동일 본문 기록을 대조한 경우에만 표시하며 업무 적용·성공 증거가 아닙니다. MCP는 연결을 시도하지 않고 등록 상태만 보여줍니다. 저장한 HTML에는 경로와 이름이 포함되므로 공유 전 확인하세요. 전체 서버/OS 정책·실행 옵션·원격 도구나 다른 프로젝트 기억을 모두 탐색한 결과가 아닙니다.

아래는 기본 제공 스킬입니다. 추가로 설치한 항목은 PC마다 다를 수 있습니다. 실제 목록은 Claude Code의 `/skills`, `/company-agent:skills` 또는 Workspace의 **준비·결과 확인 → 발견한 스킬**에서 확인하세요.

호출명에는 `company-agent:`가 붙습니다. `company`는 이 플러그인의 스킬 호출명이 아닙니다. 평소에는 이름 대신 자연어로 요청하며, 자동 선택을 점검할 때만 정확한 이름을 지정해 비교하세요.

| 스킬 | 언제 쓰나요? | 준비물·한계 |
| --- | --- | --- |
| `company-agent:html-report` | HTML 보고서 만들기 | 디자인 또는 첨부한 HTML 양식 선택. 참고 양식의 코드·외부 링크를 무조건 실행하지 않음 |
| `company-agent:presentation` | HTML 초안 확인 후 편집 가능한 PPT 만들기 | 정적 HTML 배치 변환, 카드·그림자·태그·자유 배치 지원. 새 디자인/참고 캡처/기존 PPTX/저장한 HTML → 초안 승인 → PPT. 기존 그림 크기만 수정하는 작업은 별도 제작 질문 없이 처리 |
| `company-agent:file-organizer` | 폴더 정리안 작성, 승인 후 이동 | 삭제·덮어쓰기 없는 계획. 되돌리기는 기록과 이후 파일 상태가 맞는 이동만 대상 |
| `company-agent:outlook-assistant` | 메일 찾기·요약·답장 초안·보관 계획 | 승인된 회사 연결 우선. 선택적 로컬 Outlook 조회는 읽기 전용; 새 발송/이동 연결을 자동 설치하지 않음 |
| `company-agent:personal-memory` | 개인 선호·지속적인 업무 맥락 저장/조회 | 이번 수정과 장기 저장을 구분. Company Agent 저장소와 Claude 자체 기억을 자동 합치지 않음 |
| `company-agent:personal-knowledge` | 용어·지표 정의·업무 지식 정리 | 회사 원본 보존, 출처·개인 적용 상태 구분 |
| `company-agent:asset-factory` | 개인 스킬·도구·MCP 제작·수정·연결 | 새 도구는 회사 표준 `tools.py`, 스킬은 연결된 도구 재사용. 생성·시험·현재 세션 호출·전사 배포는 구분. 기존 스크립트는 유지 |
| `company-agent:project-harness` | 폴더별 업무 절차·작업자·검증 구조 구성 | 기존 파일 충돌·백업 확인. 회사 MCP 서버 자체를 대신 구현하는 기능은 아님 |
| `company-agent:company-agent` | 작업 선택·위임·결과 확인 조율 | 지원 역할. 모든 요청에서 별도로 실행할 업무 스킬은 아님 |
| `company-agent:karpathy-guidelines` | 코드·스크립트·실행형 도구 개발 지침 | 작은 범위·명확한 근거·검증을 위한 지원 역할. 일반 요약에 불필요하게 호출하지 않음 |
| `company-agent:self-learning` | 업무 후 재사용할 교훈과 개인 개선 검토 | 조건을 만족하는 개인 영역만. 회사 정책·인증·모델 가중치를 자동 변경하지 않음 |

이전 제작 스킬 이름 `company-agent:platform-mcp-builder`는 호환용으로만 남아 있습니다. 새 스킬이나 도구를 만들 때 둘 중 하나를 고를 필요 없이 자연어로 요청하면 됩니다.

### 어떤 개발·설명 원칙을 사용하나요?

아래 원칙은 기존 스킬의 필요한 부분에 반영했습니다. 외부 플러그인 전체를 설치한 것이 아니며 별도로 이름을 입력할 필요가 없습니다.

이름이 비슷한 별도 ADHD 병렬 추론 프로젝트는 도입하지 않았습니다. 여러 모델 호출이 필요한 방식을 기본 업무에 추가하거나 검증하지 않은 성능·토큰 절감률을 약속하지 않습니다.

**자동 선택의 실제 흐름:** 사용 가능한 목록의 용도 비교 → 필요한 경우 후보 선택 → 선택한 본문 전체 로드 → 필요한 업무 실행. 정확한 명시 호출을 먼저 따르며, 명확한 한 업무 영역·한 역할의 후보가 겹치면 기존 우선 선택 또는 사용자 답변을 반영한 뒤 진행합니다. 이름이 같아도 출처가 다르면 구분합니다. 선택 질문에 답한 뒤에는 모델이 해당 선택을 현재 요청에 기록해야 하며, 시스템이 번호 답변만 보고 임의로 고르지는 않습니다. 읽기와 제작처럼 서로 다른 단계는 중복이 아닙니다. 맞는 스킬이 없거나 후보 관계가 불명확하면 허용된 일반 방식으로 진행하며, 임의의 모든 스킬을 정확히 의미 분석해 선택을 강제한다고 보장하지는 않습니다.

목록은 모든 스킬의 본문이 아닙니다. 목록을 전달했다는 로그만으로 모델이 이를 적용했다고 볼 수 없습니다. 로컬 목록도 모든 원격·동적·기본 내장 스킬을 완전히 열거한다고 보장하지 않습니다.

작업자 대화에서 읽은 스킬은 메인 대화에서도 읽었다고 표시하지 않습니다. 작업자에게 지침을 전달한 것, 본문을 읽은 것, 결과를 확인한 것은 각각 다른 단계입니다. 로드 기록은 실제 반환된 전체 본문과 버전을 대조하며, 실패·일부분·다른 본문은 완료 근거가 아닙니다. 나눠 읽기는 같은 요청과 같은 파일 버전 안에서 전체 범위를 확인해야 합니다.

`context: fork`, 모델 지정, `allowed-tools`, 동적 실행 지침처럼 원본 CLI의 기능이 필요한 스킬은 현재 요청에서 정확한 `Skill` 호출이 성공해야 합니다. 파일을 `Read`로 읽는 것은 본문 확인일 뿐 해당 실행 기능의 대체가 아닙니다. 이름 충돌이나 미등록으로 정확히 호출하지 못하면 제한을 안내합니다. 일반 본문 스킬의 재사용과 이 실행 요건을 구분합니다.

HTML/PPT는 한 요청에 최종 파일 한 개가 기본입니다. 초안·수정본·검사용 이미지는
내부 임시 작업 공간에 보관하고, 확인한 최종 후보만 한 번 전달합니다. 다음 요청이나
명시적인 복수 산출물은 별도로 만들 수 있고 기존 파일은 보존합니다. 이 규칙은 코드
프로젝트의 여러 소스 파일을 하나로 합치라는 뜻이 아닙니다. 최종 전달 확인 뒤에는
제작기가 생성 시 기록한 변경 없는 중간 파일만 자동 정리합니다. 원본·최종 파일·대표
양식·기억·스킬, 수정되거나 미등록인 파일, 이전 버전의 중간물, 최종 결과의 참조 파일은
보존합니다. 작업 기록은 중복 전달 방지를 위해 남깁니다. 잠긴 파일은 보존하고 반복
재시도하지 않습니다. 임의 도구가 만드는 모든 파일을 추적·정리하는 보안 장치는 아닙니다.

## 5. 자동으로 동작하는 후크 7개

후크는 별도 버튼 없이 CLI 이벤트에 따라 실행됩니다. **안내, 실행 관찰, 정책 판단, 완료 검토를 구분해서** 읽어주세요. 모델의 지침 준수와 운영체제 권한을 모두 보장하는 장치는 아닙니다.

| 이벤트 | 언제 / 무엇을 하나요? | 사용자에게 중요한 한계 |
| --- | --- | --- |
| `SessionStart` | 시작·재개 시 현재 설치와 실행 경로·스킬 목록·업무 맥락 준비 | 준비 출력은 모델 적용·업무 성공 증거가 아님 |

| `PreToolUse` | 위험 명령 확인, 이번 업무의 스킬 준비와 대상 회사 MCP 정책 확인, 회사 작업자에 실행 정보 전달 | 명확히 겹치는 같은 역할의 후보는 선택 후 본문 준비. 이전 목록·다른 스킬·재시도만으로 생략하지 않음. 후보가 없거나 불명확한 업무는 안내만 전달 |

| `Stop` | 변경 작업의 완료 확인과 의미 있는 시점의 학습 검토 | 질문·승인·작업자 대기는 완료가 아님. 확인에 진전이 없으면 반복을 멈추고 미확인 범위를 유지 |

완료 확인 기록이 빠졌다고 이미 만든 결과를 다시 만들거나 같은 업무를 반복하지 않습니다. 확인이 막힌 경우 학습은 보류하고, 실제 결과와 확인하지 못한 부분을 구분해 전달합니다.

“아직 실행하지 않았습니다”라고 나오면 해당 동작은 실행되지 않은 것입니다. 반대로 내부 참고 안내가 표시됐다는 사실만으로 파일 권한 오류라고 단정하지 마세요. 같은 안내가 반복되면 멈추고 해당 요청·버전·실제 상태를 담당자에게 전달합니다. 샌드박스를 끄거나 성공 기록을 꾸며서 통과시키지 않습니다.

**위험 명령 보호:** 작업 중인 변경을 지우는 `git reset --hard`, 폴더 전체 강제 삭제, 강제 push 같은 직접 명령을 실행 전에 막습니다. 필요한 경우 사용자가 대상과 명령을 직접 검토합니다. 다른 명령으로 우회하지 않습니다. 모든 스크립트 내부 동작을 검사하는 샌드박스는 아니며, 기존 Claude 승인과 운영체제 권한은 계속 적용됩니다. 후크를 끄면 이 보호도 동작하지 않습니다.

기본 제작기의 안전한 중간 파일 정리는 이 보호를 끄지 않고 수행합니다. 해당 작업의 기록·내용·실제 위치를 코드로 확인한 뒤 등록된 파일만 개별 정리하며, 폴더 전체를 지우지 않습니다. 작업 기록과 빈 내부 폴더는 남을 수 있습니다. 이름이 `temp`이거나 Git에 등록되지 않았다는 이유로 삭제하지 않습니다. 정상 정리는 추가 모델 호출이나 매 파일별 질문이 없으며, Claude 자체 권한과 회사 정책은 유지합니다.

완료 검토는 알려진 실행 명령과 도구 결과에서 변경 가능성을 확인합니다. 명시적으로 실행되지 않은 거절은 새 변경으로 세지 않지만, 그 전에 만든 파일까지 검증 완료로 바꾸지는 않습니다. 오류가 났어도 일부 변경은 남을 수 있으므로 실제 파일을 확인합니다.

## 7. 범위별 기억과 업무 구성을 다듬는 방법

### 회사 공통 → 기억·지식 — 함께 참고, 담당자가 갱신

**회사 공통 → 기억·지식**에서 회사·팀이 배포한 지식을 읽습니다. 회사 필수 규정과 실행 절차는 **회사 공통 → 업무 구성**에서 봅니다. 팀원이 실시간으로 공동 편집하는 공간은 아니므로, 수정할 내용은 담당자에게 제안하세요. 프로젝트 `CLAUDE.md`나 일반 문서가 이 목록에 자동 등록되지는 않습니다.

### 개인 전체 / 이 프로젝트 → 기억·지식 — 선호와 업무 지식을 한곳에서

Workspace **기억·하네스 관리 → 개인 전체 / 이 프로젝트 → 기억·지식 → 내 기억 추가 → 변경안 확인 → 확인하고 저장** 순서입니다. 제목과 짧은 선호만 적고 원본 문서·계정 정보는 넣지 마세요. 사용 안 함, 수정, 이전 내용 복원안을 지원합니다. 저장 위치와 적용 범위가 같아야 새 대화에서도 비교할 수 있습니다. Claude Code 자체 자동 기억은 별도 관리하며 자동으로 합치거나 덮어쓰지 않습니다.

요청에 참고할 기억은 허용된 개인 전체·현재 프로젝트에서 관련도 순으로 고르고, 같은 관련도일 때 프로젝트 항목을 먼저 봅니다. 중복을 제외하고 합계 최대 5개를 참고 대상으로 고릅니다. 프로젝트 기억이 많아도 더 관련 있는 개인 기억을 무조건 뒤로 밀지 않습니다. 이는 검색 순서이지 회사 정책이나 저장 범위를 바꾸는 규칙이 아닙니다. 목록에 없는 기억도 남아 있을 수 있으므로 범위와 제목을 지정해 조회하세요.

```text
앞으로 내 보고서는 결론부터 짧게 설명하고 확인한 범위와 미확인 부분을 구분해줘.
이 표현 선호만 개인 기억에 저장하고 문서 본문은 저장하지 마.
```

자동 학습은 User 설치에서는 개인 전체, Project 설치에서는 해당 설치 저장소에서만 작동합니다. 명시적 저장 범위 선택은 학습 설정을 바꾸지 않습니다. 진행 중인 교정은 임시 후보로 모으고, 의미 있는 업무가 완료·검증된 시점에 선호나 전체 본문을 실제 로드한 개인 스킬의 제한된 점검 항목을 개선합니다. 단순 조회, 재사용할 교훈이 없는 답변, 질문·승인 대기는 학습 완료가 아닙니다. User 설치의 프로젝트 전용 자산은 자동 수정하지 않습니다.

장기적으로 쓸 명시적 교정은 조건을 만족하면 기억 요청 없이 반영할 수 있습니다. 추정한 선호는 독립된 업무에서 반복 확인해야 하며, 같은 업무의 재답변·재시도를 독립된 반복 근거로 늘리지 않습니다. 같은 범위·같은 항목을 A → B → A로 고치면 마지막 교정을 사용합니다. 개인 스킬의 같은 점검 항목은 새 문장으로 교체하며 서로 모순되는 문장을 계속 덧붙이지 않습니다. 수동 편집과 충돌하거나 과거 항목의 식별자를 이력에서 복원할 수 없으면 해당 자동 개선만 보류하고 기존 스킬을 보존합니다.

**새 스킬 생성은 별도입니다.** 기존 개인 스킬의 점검 항목 개선은 조건부 자동 처리하지만, 새로운 업무 절차를 스킬로 만드는 일은 생성 요청이나 제안에 대한 동의 후 제작 스킬로 진행합니다. 공통 스킬을 쓰다가 자동으로 개인 복제본을 만드는 기능은 없습니다. 명시적인 “기억해줘” 요청은 완료 학습을 기다리지 않고 선택한 범위에 저장합니다.

본문 전체 로드는 개선 대상의 근거이며 실제 적용·업무 성공의 증명은 아닙니다. 모든 교정을 즉시 영구 저장하지 않습니다. 매 요청마다 별도 학습 모델을 자동 호출하거나 종료 후 백그라운드 학습하지 않지만, 완료 시 교정 정리와 검토에는 현재 대화의 모델 처리 비용이 들 수 있습니다. 복잡한 개선을 별도 작업자에게 검토하게 하면 그 처리 비용도 포함됩니다. 공통 자료·회사 정책·프로젝트 `CLAUDE.md`·도구 코드를 자동 수정하지 않고 현재 요청을 덮어쓰지 않습니다.

자동 학습 카드나 `/company-agent:learning`에서 관찰·적용 내역을 확인하고 일시 중지·재개·선택한 변경 되돌리기를 요청합니다. 중지해도 기존 기억을 지우거나 사용을 멈추지는 않습니다. 되돌리기는 자동 선호의 사용 중단 또는 스킬 점검 영역의 이전 상태 복원이며, 업무 파일이나 발송 메일의 취소가 아닙니다.

출처가 있는 용어·계산식은 같은 화면의 **내 업무 지식 초안**에서 저장하고, 직접 검토 후 사용으로 바꿉니다. 개인 초안을 만들었다고 공통 기억이 바뀌지 않습니다. **공통 기억 검토용 내보내기**는 로컬 ZIP 생성이며 자동 업로드·회사 반영이 아닙니다. 전달 전 민감 내용을 검토하세요. 공통 자료로의 반영은 담당자의 검토·배포 단계입니다.

### 회사 공통 → 업무 구성 — 실행 방식과 공통 규정

**공통 하네스**는 회사 업무 기준·공통 스킬·후크 정의를 확인하는 화면입니다. 목록이 있다는 사실과 현재 CLI에서 실제 실행됐다는 사실은 다릅니다. 화면에 수정·삭제 버튼을 두지 않으며 개인 선호로 회사 필수 기준을 해제하지 않습니다.

### 개인 전체 / 이 프로젝트 → 업무 구성 — 내 추가 구성과 폴더별 지침

**개인 전체 / 이 프로젝트 → 업무 구성**에서 개인·사용자 설치·프로젝트·외부 플러그인의 스킬 출처와 개인 도구 등록 기록을 확인합니다. 이는 모든 외부 도구의 연결 상태 목록이 아닙니다. 외부 설치 원본과 MCP 자격증명을 편집하지 않습니다. 등록·활성화 기록만으로 실행 성공을 판정하지 마세요.

같은 화면의 **이 폴더에만 적용할 업무 지침**에 목표·입력·결과물·완료 기준을 적습니다. 저장 파일은 `.claude/rules/company-workspace-brief.md`이며 기존 `CLAUDE.md`와 다릅니다. 기존 또는 직접 수정한 지침은 덮어쓰지 않습니다. 회사 공통 규정을 개인 폴더에 복사해 별도 정책 계층으로 만들 필요는 없습니다.

#### 개인 스킬·도구 만들기

반복하는 처리 순서는 스킬, 계산·조회처럼 재사용할 실행 코드는 도구입니다. 둘 다 같은 제작 스킬로 요청합니다. 새 업무 도구는 회사 표준 `tools.py`로 만들고 내 PC에서는 가벼운 stdio 연결로 실행합니다. 별도 웹 서버를 켜거나 회사 서버에 배포할 필요가 없습니다. 글쓰기 스킬이나 일회성 작업까지 도구로 만들지는 않습니다. 같은 기능이 있으면 재사용하고 기존 스크립트 도구는 그대로 유지합니다.

저장할 때 **개인 전체 / 이 프로젝트**를 한 번 선택합니다. 선택 저장소의 `personal-root/.claude/skills`에는 스킬, `mcp/servers`에는 새 도구를 보관합니다. 회사 플러그인 캐시는 수정하지 않습니다. 도구는 후보 생성 → 정상·잘못된 입력 시험 → 검증 기록 → 연결 등록 → Claude 재시작 후 실제 호출 순서입니다. 스킬은 필요한 도구를 연결해 사용하고, 없는 도구를 임의 코드로 대신하지 않습니다. 도구의 코드·입력 형식이 바뀌면 재시험하고 연결된 스킬도 확인합니다.

도구 연결 확인은 필요한 스킬을 처음 쓸 때 수행하며 LLM이나 서버를 새로 띄우지 않습니다. 현재 대화에서 바뀌지 않은 확인 결과는 재사용합니다. 다른 저장소·외부 MCP도 연결된 실제 도구로 재사용할 수 있지만, 같은 저장소에서 만든 도구에 적용하는 소스·스키마 검증과는 구분합니다. 등록 여부만으로 현재 세션의 연결 성공을 보장하지 않습니다.

**기존 도구가 재시험을 요청하면:** 과거 검사 기록으로 새 검사 기준을 통과했다고 보지 않습니다. 해당 도구가 원래 저장된 범위에서 정상 입력과 잘못된 입력을 다시 시험하고, 통과한 현재 기록으로 활성화·연결을 확인하세요. JSON 입력·출력은 선언한 형식·필수 값·범위 등을 검사하며, 지원하지 않는 조건은 무시하지 않고 알립니다. 검사 조건을 지워 통과시키지 않습니다. 재시험 안내가 소스 삭제나 이미 별도 등록된 MCP의 자동 해제를 뜻하지는 않습니다.

[시작하기](ONBOARDING_COURSE.md) 8단계에서 회의 메모 정리 스킬과 달성률 계산 도구를 만들어 봅니다. 이름 없는 자동 선택과 명시 사용을 따로 시험하고, 목표 0·누락 입력도 확인합니다. 생성된 코드는 내 Windows 계정 권한으로 실행되므로 외부 연결·파일 변경 여부도 확인하세요. 시험 통과가 모든 상황의 안전성을 보장하지는 않습니다.

**관리자 참고:** 현재 같은 미완료 업무에서 한 개인 스킬의 서로 다른 교정을 연이어 모으면 앞선 후보가 남지 않을 수 있습니다. 여러 항목의 자동 보존·반영을 보장하지 말고 실제 적용 내역을 확인하세요. 저장·조회 성공만으로 사내 모델의 실제 적용 품질까지 입증되는 것은 아닙니다.

## 8. 느리거나 토큰을 많이 쓰면

1. 요청에 대상 파일·확인 범위·완료 기준을 한 번에 적습니다.
2. 디자인·양식 등 이미 답한 내용은 유지해 달라고 요청합니다.
3. 새 주제는 새 대화로 나누고, 긴 자료는 필요한 범위부터 읽습니다.
4. 표시 인코딩만 깨졌다면 파일 생성·발송 등 원래 업무부터 반복하지 않습니다.
5. 문서 읽기·계산 등은 실제로 사용 가능한 스킬·도구와 지원 범위를 확인합니다.

새 폴더의 기본 `CLAUDE.md` 생성은 3장의 조건에서 지원합니다. `/revise-claude-md`라는 별도 명령, 업무 종료마다 강제 `/compact`, 자동 후속 질문 전송은 제공하지 않습니다. 개인 자동 학습과 CLI 자체 대화 압축은 프로젝트 지침의 자동 수정이나 공통 기억 공유가 아닙니다. 대화 압축과 기억 저장은 다른 일입니다.

Workspace **사용 현황**은 CLI가 실제 제공한 토큰과 앱이 관찰한 실행·질문·승인 대기를 구분합니다. 빠진 값은 0이 아니라 미제공입니다. 요청 값이 세션 누적일 수 있으므로 서로 더하지 않습니다. 사내 모델 단가를 모르면서 청구 금액이나 절감률을 만들지 않습니다.

토큰 알림은 다음 요청부터의 안내이며 강제 예산 제한이 아닙니다. 과거 로그 분석은 사용자가 고른 파일만 대상으로 하며 자동으로 대화 전체를 검색하지 않습니다. **준비·결과 확인**의 평가는 사용자가 직접 확인해 기록한 표본이지 모델 전체 성능 점수가 아닙니다.

## 9. 무엇을 빼거나 바꿀 수 있나요?

| 의견 또는 변경 | 현재 방법 | 주의점 |
| --- | --- | --- |
| 보고서 표현·분량·디자인 변경 | 해당 요청 또는 개인 선호 | 이번 결과만 바꿀지 지속 적용할지 구분 |
| 특정 개인 기억 사용 중단 | 기억 화면의 사용 안 함 | 삭제·과거 이력 제거와 다름 |

| 겹친 스킬 중 하나 사용 | skills 명령으로 후보·범위 선택 | 원본을 삭제하거나 Claude 전체 우선순위를 바꾸는 것은 아님 |
| 회사 스킬/후크 자체 제거·수정 | 담당자에게 영향 검토와 새 배포 요청 | 현재 앱에는 회사 스킬/후크 개별 켜기·끄기 기능이 없음 |
| 회사 필수 정책 변경 | 회사 정책 담당자 | 개인 선호로 해제하지 않음 |

설치 캐시의 SKILL.md나 후크 파일을 직원마다 직접 수정하면 업데이트 시 사라지거나 버전별 동작이 갈릴 수 있습니다. 원본 소스에서 변경·검증하고 새 배포로 전달하는 방식이 좋습니다. 유지/교체/업데이트 시에는 실제 설치 범위와 백업 내용을 확인하세요.

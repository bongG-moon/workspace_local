# Company Workspace 0.11.4 UI 검토

## 확인한 문제와 수정

| 항목 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 확인창 | 6개 경로에서 브라우저 기본 확인창 사용 | 앱 디자인의 공통 확인창. 취소 기본 초점, Esc 취소, 호출 버튼으로 초점 복귀 |

| 탭 상태 | 자료의 고정 active 클래스 때문에 결과와 동시 강조 | aria-selected 상태로 선택 탭 하나만 강조 |
| 시작 경고창 | DPI 처리가 없는 MessageBox | HWND 생성 전 PMv2와 시각 스타일 설정, 보조 코드 오류 시 원래 경고 유지 |
| 재실행 | Edge 탐색 위치가 첫 실행과 다름 | 시스템 x86, 시스템 x64, 사용자 설치 위치를 같은 순서로 확인 |

## 실제 화면 검증

개인 Claude 설정이나 실제 업무 대신, 별도 설정·상태 폴더와 가짜 CLI를 사용하는 로컬 fixture에서 검사했다. 모델 호출은 하지 않았다.

- 긴 파일명: 수정 전 233px 행에서 873px로 넘침. 수정 후 행 clientWidth/scrollWidth가 모두 231px이며 파일명은 177px 안에서 줄바꿈, 글자 크기 13px.
- 결과 탭 선택 시 자료 탭은 aria-selected=false, box-shadow=none이고 결과 탭만 강조됨.
- 이름에 공백만 입력하면 오류가 열린 rename-dialog 안에서 보임.
- 앱 종료 확인의 초기 초점은 취소. Esc 뒤에는 설정 창과 앱 종료 버튼 초점 유지.
- 예문 적용 취소 뒤 도우미와 기존 초안이 유지되며, 비활성화됐던 호출 버튼이 다시 활성화되고 초점 복귀.
- 390×844 창에서 6개 업무 중 최근 4개 밖의 업무 1을 검색해 열었고, 페이지 가로 넘침 없음.
- 독립 코드 검토에서 전체 업무 연속 선택 응답 경합을 추가 발견해 보완. 긴 업무 경로는 390px 브라우저의 실제 스타일이 white-space:normal이며 clientWidth/scrollWidth가 모두 272px로 확인됨.

## 검증 범위

Windows 경고창은 실제 DPI API와 시각 스타일 초기화, 보조 코드 실패 시 경고 유지, Edge 경로 및 오류 처리 테스트로 검증했다. Windows 기본 경고창의 최종 외관은 직접 눈으로 확인하지 않았다.

사용자 계정, UAC, Claude 모델·MCP·Skills·Memory·폴더 신뢰 설정은 변경하지 않았다.

## 자동 테스트 및 적용 결과

- UI 상태·카탈로그·종료·확인창: 31개 통과. 새 확인창/전체 업무 테스트 8개 포함. 독립 리뷰에서 이 8개를 별도로 재실행해 통과.
- 서버·실행기 연결·종료·진단: 64개 중 62개 통과, 환경 조건에 따른 2개 건너뜀. 이 중 실제 사용자 계정이 필요한 실행기 테스트 3개는 격리 계정의 WS-31 차단을 확인한 뒤 정상 로그인 계정에서 재실행하여 모두 통과.
- 시작/재실행 및 새 경고창 표시 테스트: 27개 중 26개 통과, 호스트 WSH 조건으로 1개 건너뜀.
- 합계: 서로 다른 테스트 122개, 최종 119개 통과 / 3개 건너뜀. 반복 실행은 합계에 중복 포함하지 않음.

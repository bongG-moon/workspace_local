## Windows 카드 구현

`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-lab/test-notification-card.ps1`로 실제 네이티브 호스트 빌드를 불러와 검사했습니다.

- 완료·응답 대기·오류 3종, 96/144/192 DPI 레이아웃과 렌더링
- 음수 좌표 모니터와 320×160 작업 영역 내 카드·컨트롤 배치
- Unicode 제목·제어 문자·잘못된 surrogate·길이 검증
- 비활성화 표시 스타일과 포커스를 받지 않는 버튼 스타일
- 접근성 열기·닫기 동작과 반복 종료에서 콜백 한 번만 발생
- 카드 생성·DPI 변경·dispose 64회 후 GDI 32→32, USER 20→20

격리된 네이티브 실행에서 완료·응답 대기·오류 카드 3개 요청이 수락되었고 표시 전후 foreground HWND가 유지됐습니다. 메인 창을 숨긴 상태에서 동작했으며 자동 닫기 후 자원 수는 두 번째·세 번째 카드 사이에서 GDI 60, USER 32로 유지됐습니다. 이 실물 실행은 마지막 버튼 포커스·dispose 보완 전 빌드이며, 최종 빌드는 위 컴파일·접근성·반복 해제 검사로 확인했습니다.

알림 카드는 작업 표시줄에 나타나지 않는 tool window라 Windows 자동화 도구의 창 목록에서 선택되지 않았습니다. 따라서 실제 포인터로 최종 알림의 열기·닫기 버튼을 누르는 검증과 실제 다중 모니터 이동·혼합 배율·방해 금지 조합은 미확인입니다. 클릭 경로는 Python IPC 회귀와 네이티브 접근성 동작 검사로 확인했으며 이를 실제 마우스 클릭 검증으로 간주하지 않습니다.

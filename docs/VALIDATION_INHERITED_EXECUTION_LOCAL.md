# 0.23.20 수정 배포 검증: Windows 권한 상속과 작업 중 승인 변경

검증일: 2026-10-06. 이번 기록은 Windows 권한 상속 방식으로 바꾼 0.23.20 수정 배포의 검증 결과입니다. 기존 GitHub v0.23.20 자산을 같은 버전의 수정 파일로 교체합니다. 과거 관리자 전환 검증 문서는 당시 구현의 기록으로 남깁니다.

## 적용한 변경

- 설정의 일반·관리자 전환 선택, 재시작 버튼, 반복 확인과 앱 권한 선택 파일 읽기·쓰기를 제거했습니다. 설정에는 이번 실행의 확인된 권한만 표시합니다.
- EXE·VBS·직접 Python 실행은 로그인 사용자·세션·실제 Windows 토큰을 검증하고 상속합니다. EXE의 Windows **관리자 권한으로 실행**을 선택하면 그 권한을 앱·Claude·도구가 사용합니다. 일반 터미널에서는 일반 권한을, 관리자 터미널에서는 관리자 권한을 상속합니다. UAC를 끈 PC에서는 더블클릭도 관리자 토큰일 수 있습니다. 정책·계정·ACL·개인 Claude 설정을 바꾸지 않습니다.
- 다른 권한의 앱이 열려 있으면 창 재사용·권한 변경·강제 종료를 시도하지 않고 완전 종료 안내를 표시합니다. 같은 권한의 이전 수정본은 유휴·초안 보관 절차를 거쳐 교체하며, 동일한 최신 실행은 기존 창을 활성화합니다.
- 초기화가 끝난 지원 CLI에서는 실행·승인·질문 대기 중 승인 모드를 클릭, Shift+Tab, Alt+M으로 변경합니다. 확인 응답을 받은 모드를 이후 도구 요청에 사용합니다. 이미 나타난 승인·질문은 직접 답해야 합니다.
- 변경은 사용자 작업을 전송하거나 실행 상태를 바꾸지 않습니다. 늦은 응답은 작업과 확인창을 유지하고, 한 개의 미확인 제어만 보관합니다. 새 요청·대기열·다른 설정 제어는 순서가 확정될 때까지 기다립니다. Bypass는 기존 위험 확인을 유지하며, 아직 준비하지 않은 연결은 작업 중 재시작하지 않습니다.
- 모드 변경 도중 결과가 도착해도 완료 상태를 유지합니다. 늦은 성공 응답은 해당 승인 모드 복원 오류만 해소하고 다른 설정 오류를 보존합니다.

## 느려짐 확인과 개선

이전 관리자 WebView2 중계는 진행 내용의 긴 요청과 짧은 API 요청이 같은 4개 처리 슬롯을 사용했습니다. 실제 WebView2의 격리 테스트에서 진행 요청 4개를 각각 3초간 유지한 뒤 버튼 API를 요청해 병목을 재현했습니다.

| 항목 | 수정 전 | 수정 후 |
|---|---:|---:|
| 버튼 요청 응답 시간 | 2,871.6ms | 16.3ms |
| 동시에 유지한 진행 요청 | 4 | 4 |

진행 요청과 버튼·설정 요청의 제한된 처리 슬롯을 분리했습니다. 버퍼 크기 제한·파일 기반 대용량 업로드·응답 후 자원 해제를 유지하고, 권한 전환용 반복 조회를 제거했습니다. Windows TCP 소유자·토큰 검사는 100회 측정에서 평균 0.67ms였으므로 검증을 생략하거나 토큰을 캐시하지 않았습니다.

이 결과는 특정 병목을 재현한 측정이며 모든 PC의 전체 성능 향상률이나 메모리 감소량을 뜻하지 않습니다. 실제 관리자 토큰 대신 테스트 창에서 관리자 중계 경로를 활성화했습니다. 사용자 앱·작업·Claude·개인 설정은 사용하지 않았습니다.

## 실행·기능 검증

| 검증 | 결과 |
|---|---|
| 프런트엔드 회귀: 클릭·Shift+Tab·Alt+M, 실행/승인/질문 상태, 늦은 결과, 초안·카드 유지 | 246개 통과 |
| 실행·토큰·재실행·권한 불일치·업데이트 인계 | 초기 140개 통과, 조건부 3개 제외; 최종 관련 90개 통과 |
| 제어·Bypass·모델/Effort 전송 규약 | 103개 통과; 최종 서버·제어 41개 통과 |
| 최종 서버 종합 회귀 | 203개 실행: 202개 통과, 일반 사용자 환경의 명시적 opt-in 검증 1개 제외 |
| 최종 단일 EXE 실제 실행 | 일반 권한, protocol 3, 전용 창 준비, launcher exit 0 |
| 반복 실행 | 같은 서버 PID와 창 재사용 |
| 완전 종료 | closed=true, runtime 삭제 확인 |
| 이전 0.23.20 protocol 2 → 수정본 protocol 3 | 같은 버전 교체, 다른 프로세스로 전환, 완료 후 종료 |
| 예전 관리자 선택 파일 | 일반 권한으로 실행되고 선택 파일은 원래 바이트 유지 |
| EXE/VBS ZIP | 126개 소스 + 7개 고정 빌드 자산 검증, 양쪽 133개 동일 |
| 실제 관리자 UAC 승인 후 앱·Claude 실행 | 수행하지 않음 |

실제 UAC 승인이나 보안 대화상자를 자동으로 누르지 않았습니다. 현재 PC의 실제 일반 토큰과 관리자·다른 계정·다른 세션·혼합 토큰의 검증 행렬을 확인했습니다. 실제 사용자 Claude에 작업을 보내거나 인증·설정·MCP·모델·Effort·스킬을 변경하지 않았습니다.

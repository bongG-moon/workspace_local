# Company Workspace 0.12.1 검증 기록

검증일: 2026-09-29. 현재 상태: **전체 회귀·최종 ZIP·독립 소스 검토·기존 인증의 실제 CLI 최소 요청 확인 완료**. 확정된 결과만 아래에 기록하며, 0.12.0의 통과 수치를 새 버전의 재검증 결과로 사용하지 않는다. 사용자 경로·업무 내용·인증 정보는 포함하지 않는다.

38건의 범위는 `test_workspace_app_without_cli`, `test_workspace_direct_startup`, `test_workspace_picker`, `test_workspace_picker_integration`, `test_workspace_transport_product`다. 실제 Windows 시험은 `test_workspace_execution_policy`다. 서로 겹치는 부분 실행과 최종 전체 실행 수치를 더해 고유 시험 수로 계산하지 않는다.

승인 관련 명령 `python -B -m unittest tests.test_workspace_permissions tests.test_workspace_controls_frontend tests.test_workspace_frontend_state`는 42건 모두 통과했다. 권한 시험은 개인 프로필·도구·네트워크·LLM 없이 메모리 상태만 가진 가상 CLI 자식 프로세스를 실제 실행해 session과 3개 지속 저장 범위의 정확한 `updatedPermissions` 전송, 1회 승인·거절·후보 재사용 방지·모드 ACK를 확인했다. UI 시험은 Node의 모의 DOM에서 실제 `app.js`를 실행했다. 실제 Claude 설정 파일 저장이나 새 Claude 연결에서의 지속 적용까지 검증한 것은 아니다.

실제 사용자 실행기 7건의 결과는 `build/qa-workspace-0.12.1-native-launcher-tests.json`의 `run=7`, `success=true`, 실패·오류·생략 빈 목록으로 확인했다. 회사 PC의 UAC-off 원본 환경에서 실제 Claude 업무를 실행한 결과와 구별한다.

전체 결과는 `build/qa-workspace-0.12.1-tests.json`의 `run=446`, `success=true`, 실패·오류 빈 목록으로 확인했다. 생략 7건 중 opt-in 진단·제한 토큰 복사·자식 검증·VBS 안내 4건은 위의 별도 native 7건에 포함하여 통과했다. 실제 심볼릭 링크 생성 권한 3건만 생략 상태로 남으며 합성 reparse/junction 차단 시험은 통과했다. 현재 사용자 실행기 3건은 전체 실행에서 제외하고 별도로 실행했다. 부분 시험·별도 재실행과 전체 결과를 합산하지 않는다.

브라우저에서는 **이번만 허용**이 기본 선택이며 **이 프로젝트에서 항상 허용 · 나만**과 실제 규칙 2개가 표시되는 것을 확인했다. 해당 범위를 고른 뒤 승인하자 가상 CLI 응답 **설정 범위 전달됨: localSettings**가 한 번 표시되고 대기 배지가 해제됐다. `build/qa-workspace-0.12.1-permission-ui-result.json`에 기본값·선택 범위·응답 1회·대기 0·가상 CLI 사용을 기록하고 시험 서버와 탭을 종료했다. 이는 제어 메시지 전달과 UI 흐름의 증거이며 개인 Claude 설정 파일에 규칙을 저장한 시험은 아니다.

## 기존 인증의 실제 CLI 확인

최종 ZIP을 새로 압축 해제하고 demo가 아닌 실제 실행기를 `-NoBrowser`로 실행했다. 앱 버전 0.12.1과 추출 경로, 실제 CLI 2.1.283, 재열기 시 동일 서버 PID를 확인했다. 기존 Claude 인증으로 지정한 한 줄 확인 문구만 요청했고 응답 1회를 받아 `state=done`, `markerReceived=true`, 대기 도구 없음으로 완료했다. 문서 읽기·도구 실행·설정 변경은 요청하지 않았다.

실제 CLI가 명령 139개·도구 43개·스킬 81개와 승인 모드 `default`, 모델 정보를 보고했다. 이 수치는 해당 연결이 제공한 목록이며 설치 메타데이터 후보 수나 모든 항목의 호출 성공 수가 아니다.

결과는 `build/qa-workspace-0.12.1-live-final/cli-result.json`과 `finish-result.json`에 기록했다. 종료 결과는 `serverClosed=true`, `personalSettingsUnchanged=true`, `changedConfigFileCount=0`이다. 기존 설정 파일 5개의 해시만 전후 비교했고 인증값은 출력하지 않았다. 이 비교를 모든 개인 상태 파일의 전수 검증으로 확대하지 않는다.

이 시험은 실제 인증·모델 응답의 최소 왕복을 확인했다. VBS 더블클릭이나 문제가 발생한 회사 PC의 UAC-off 환경에서 실행한 시험은 아니며, 실제 업무 문서의 처리·결과 품질·지속 허용 저장까지 검증한 것은 아니다.

실행 정책 시험의 최초 정책 조회는 PowerShell 모듈 자동 로드 충돌로 시험 코드 오류가 났다. 절대 Windows PowerShell 모듈 경로를 사용하도록 시험을 수정한 뒤 재실행하여 통과했다. 최초 오류를 제품 성공이나 실행 정책 차단의 증거로 사용하지 않는다.

## 자동 검증과 수용시험의 경계

- 앱 전용 로그인 없이 화면 시작, 기존 Claude 인증으로만 AI 요청. 로컬 HTTP의 내부 연결 토큰은 계속 별도로 검증.
- 정상 별칭·프로필 함수·회사 호출 스크립트 상속 유지. CLI 미탐지 시 다른 실행 파일·계정·설정 루트로 자동 전환하지 않음.
- CLI가 제공한 session/localSettings/projectSettings/userSettings 후보의 정확한 규칙·저장 범위 표시. 이번만 허용·거절·질문 응답에 지속 허용 추가 없음.
- 위조·오래된 후보 ID, 다른 승인 요청의 ID, 잘못된 규칙·destination 거절. 회사 deny나 전체 권한 생략으로 확대하지 않음.
- 모델·승인 모드의 연결별 적용과 지속 규칙 저장 구분. 모드 복원이 저장 규칙 삭제라고 표시되지 않음.
- 실행기·진단·권한 재실행·직접 Python·picker·CLI wrapper의 일관된 프로세스 범위와 그룹 정책 우선. 기존 UAC·사용자·토큰 검증 유지.
- 새 ZIP에서 Python 3.11 이상 요구, 버전·자산·인증 경계·API 종료·임시 runtime 정리와 소스 일치 확인.

위 항목은 검증 기준이다. 자동 시험·최종 묶음 확인의 통과와 아래에 명시한 실제 회사 PC·개인 Claude 설정 적용의 미시험 범위를 구분한다.

## 보존 조건과 확인하지 않은 범위

다른 PC에서 프로세스 한정 Bypass로 VBS `exit 1`이 해결된 사례는 수정 후보다. 현재 PC의 원인을 확정한 증거가 아니며, 그룹 정책·AppLocker·WDAC·WSH 차단 또는 Python 부재를 모두 해결한다는 보장도 아니다. 전역 실행 정책과 UAC·계정 설정, 다운로드 표시를 자동 변경하지 않는다.

앱 전용 로그인은 없고, AI는 기존 Claude 인증을 사용하며, 로컬 HTTP는 앱의 내부 연결 토큰으로 보호한다. 사용자 개인 모델·MCP·스킬·기억·인증을 자동 덮어쓰지 않는다. 사용자가 지속 허용을 명시적으로 고른 경우에만 CLI가 제공한 해당 규칙과 범위를 저장 요청에 포함한다. 시험용 허용 규칙은 격리 환경에서 검증하며 개인 설정에 시험 규칙을 추가하지 않는다.

확인한 개인 Company Agent 설치는 **1.4.23이며 이번 작업에서 업데이트하지 않았다**. Workspace ZIP과 코어는 별도 배포다. 소스의 HTML 선택·Stop 후크 개선이 기존 설치에 적용됐다는 뜻이 아니다.

문제가 발생한 회사 PC의 VBS → 실제 Claude 업무 전체 흐름, UAC-off 실행, 실제 지속 규칙의 회사 정책 적용, Office·DRM·작업표시줄 점멸·복수 모니터 DPI는 별도 현장 확인이다. 현재 PC의 실제 한 줄 응답과 로컬 가상 CLI 통과를 해당 환경의 성공으로 대체하지 않는다.

## 배포 묶음

최종 파일: `dist/company-workspace-preview-0.12.1-20260929-205708.zip`

크기: 5,844,418 bytes

SHA-256: `7dfbeccf539cb43c8dbe5e034028e74586f571c132321647ec60819f0efccc92`

허용 파일 59개의 현재 소스 일치, 진단 helper 고정 해시 4개, 상태 파일 미포함 검사를 통과했다. 다른 임시 폴더에 압축을 풀고 실제 로그인 사용자로 추출된 앱의 demo 서버를 실행해 다음을 확인했다.

- 앱 버전 0.12.1, 실행 앱 루트가 새 추출 경로, 격리된 초기 상태.
- 인증 없는 API의 403 응답과 인증된 API 동작.
- HTML·JavaScript·전체 한글 글꼴·HTML 안내서를 포함한 자산 8개.
- 임시 업무·파일 생성과 파일 목록·catalog·attention API.
- API 종료와 runtime 파일 정리.

결과는 `build/qa-workspace-0.12.1-bundle.json`의 `success=true`와 위 SHA-256으로 확인했다. 추출 demo 시험은 회사 PC에서 VBS부터 실제 Claude 업무까지 수행한 시험이 아니다.

최초 `205536` 묶음은 HTML 안내서 누락으로 패키지 검사와 추출 실행 확인에 실패했다. 빌더의 UTF-8 BOM을 복원하고 복사 전후 파일 존재 검사를 추가한 뒤 새 묶음으로 다시 제작해 통과했다. 실패 ZIP은 배포 폴더에서 분리했으며 검증 통과 묶음으로 취급하지 않는다.

이 기록은 커밋·푸시·공개 업로드·메일 발송 완료를 의미하지 않는다.

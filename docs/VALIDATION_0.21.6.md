# 0.21.6 단축키 검증

검증일: 2026-10-01. 비교 기준은 이 PC에 설치된 Claude Code 2.1.286의 기본 입력 동작과 [공식 키 설정](https://code.claude.com/docs/en/keybindings), [대화형 사용 안내](https://code.claude.com/docs/en/interactive-mode)입니다. 개인 keybindings.json은 이 PC에서 발견되지 않았습니다. 다른 PC의 사용자 정의 키 설정을 자동으로 읽어 적용한다는 의미는 아닙니다.

## 반영한 동작

- Enter 전송, Shift+Enter/Alt+Enter/Ctrl+J 줄바꿈. 자동완성에서는 Enter·Tab 선택이 먼저이며, 한글 조합과 키를 누른 채 반복되는 Enter는 전송하지 않습니다.
- Shift+Tab/Alt+M 승인 모드, Alt+P 모델 선택. 기존 연결의 지원 범위와 적용 확인을 유지합니다.
- Ctrl+X 다음 Enter는 자동완성 선택보다 우선해 대기 요청을 등록합니다. 연속키의 대기 시간은 3초입니다.
- Esc/Ctrl+C 중지. 입력창에 선택한 글이 있는 Ctrl+C는 복사로 유지하며, 자동완성·선택 목록을 닫는 Esc가 중지보다 먼저입니다.
- 현재 업무의 이전 요청 탐색, Ctrl+R 검색, Ctrl+S 임시 보관. 전송 확인 후 초안을 복원하며 새 입력·첨부는 덮어쓰지 않습니다. 일반 한 줄 입력의 끝에서 ↑로 이력을 불러옵니다. 자동 줄바꿈을 측정할 수 없으면 기본 방향키 이동을 유지하고 Ctrl+P/N은 논리적 줄을 기준으로 이동합니다.
- Ctrl+A/E/F/H/K/U/W/Y, Alt+B/F/D/Y, Ctrl+Backspace, Ctrl+_ 편집. 입력 이력은 최대 100개, 삭제한 글 보관은 20개·64,000자입니다.
- Ctrl+O로 받은 도구·실행 상세를 펼칩니다. 앱의 빠른 실행은 충돌을 피하도록 Ctrl+Shift+P로 이동했습니다.
- 임시 보관한 초안은 화면 복구와 새 버전 전환에 함께 보관합니다. 총 저장 한도를 넘거나 이전 기록과 충돌하면 저장·전환을 중단하고 양쪽 내용을 보존합니다. 복원할 업무가 없어도 별도 복원 목록에서 복사할 수 있습니다.

## 자동 검사

- 관련 회귀 검사 643건: 640건 통과, 환경 조건에 따른 3건 건너뜀. 시작 권한의 실제 사용자 검사, 심볼릭 링크 생성 권한 검사, Windows 알림 표시 선택 검사가 해당됩니다.
- 이후 추가한 대기열 응답 검사를 포함한 단축키 통합 검사 29건 별도 통과. 위 숫자와 중복되므로 합산하지 않습니다.
- 실제 앱의 입력 처리·자동완성·인라인 선택·전송 함수와 대기열 전송 함수를 연결해 확인했습니다. 전송 실패, 늦은 응답, 업무 전환, 첨부만 수정한 경우와 한글·이모지 경계를 포함합니다.
- 정적 파일 HTTP 검사 45건 정상 응답. ZIP의 110개 소스 파일과 7개 네이티브 빌드 파일을 원본·빌드 해시로 검증했습니다.
- 새 VBS ZIP을 별도 폴더에 압축 해제한 뒤 격리된 데모 상태로 실행해 초기화·자료 목록·카탈로그·인증 경계·정상 종료를 확인했습니다. VBS 아이콘의 실제 더블클릭 검사를 의미하지는 않습니다.

## 실제 EXE 확인

- 실제 로그인한 Windows 사용자에서 EXE만 있는 한글 경로로 실행했습니다. 기존 Python 3.13.5를 찾았으며 Python·설치 프로그램을 묶거나 내려받지 않았습니다.
- EXE 재실행 시 같은 서버를 사용했고, WebView2 독립 앱 창을 확인했습니다.
- 기존 Claude 인증으로 초기 연결: Claude Code 2.1.286, 명령 141개 확인. 개인 설정 파일 해시 변경 없음.
- Computer Use로 실제 입력창에서 Shift+Enter가 전송 없이 줄바꿈하는 것과 Enter가 요청을 한 번 보내는 것을 확인했습니다. 도구를 쓰지 않는 고정 문장 요청 1건에 SHORTCUT_OK 응답을 받았습니다.
- Ctrl+S로 보관한 초안이 전송 확인 후 자동으로 돌아왔습니다. Ctrl+A → Ctrl+K로 현재 줄을 지운 뒤 Ctrl+Y로 복원했습니다. Ctrl+R 검색에 방금 전송한 요청이 표시되고, Esc로 닫을 때 기존 초안이 유지됐습니다. Alt+P 모델 선택도 열렸습니다.
- 한글 실제 IME 조합 입력과 모든 Windows 배율·키보드 배열을 수동으로 재현한 것은 아닙니다. 조합 이벤트와 문자 경계는 자동 검사로 검증했습니다.

## 명확히 구분한 범위

작업 중 Enter는 앱 대기열에 넣고 현재 요청이 끝난 뒤 실행합니다. 터미널 CLI가 도구 경계에서 입력을 반영하는 동작과 동일하지 않습니다. 작업 중 Ctrl+Enter 또는 Ctrl+X 다음 Ctrl+S의 즉시 반영은 현재 앱 연결에서 지원하지 않아 입력을 보존하고 안내합니다. 기존 '지금 반영'의 중지·재개를 이 키에 연결하지 않았습니다.

Ctrl+B/D/G/T/L, Alt+T/O 등 프로세스·외부 편집기·터미널 화면·기능 전환 전용 키는 입력창에서 다른 작업으로 바꾸지 않고 안내합니다. Esc 두 번으로 대화 되감기, 사용자 키 재지정, Vim 입력 모드는 이번 변경에서 구현하지 않았습니다. Ctrl+O도 앱이 받은 실행 기록 표시이며 원본 CLI의 전체 원시 로그 화면은 아닙니다.

PC 보안 정책, UAC, Claude 인증·모델 기본값·승인 정책·스킬·MCP·후크 개인 설정은 변경하지 않았습니다.

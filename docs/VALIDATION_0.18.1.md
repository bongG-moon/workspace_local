# 0.18.1 트레이 메뉴 위치·배율 수정

## 원인과 수정

트레이의 우클릭 메뉴가 아이콘에서 떨어져 표시되는 구현 결함을 수정했습니다. 본창은 WebView2 호스트의 DPI manifest를 사용하지만, 별도 Python 트레이 스레드는 DPI 인식을 설정하지 않았습니다. 또한 `WM_CONTEXTMENU` 콜백의 `wParam`을 무조건 화면 좌표로 해석했습니다. 이 메시지는 버전 4 알림 아이콘 문서에서 좌표가 보장되는 이벤트 목록에 포함되지 않습니다.

- 숨겨진 트레이 소유 창을 만들기 전부터 해당 스레드에만 Per-Monitor V2를 적용합니다. 지원되지 않으면 Per-Monitor V1을 시도합니다. 소유 창과 메뉴가 같은 좌표계를 사용하며 종료·초기화 실패 시 이전 스레드 상태를 복원합니다.
- `Shell_NotifyIconGetRect`로 이 앱의 HWND와 아이콘 ID에 해당하는 현재 위치를 확인합니다. 마우스·키보드 호출 모두 아이콘 아래 모서리에 메뉴를 붙이고 화면 가장자리 배치는 Windows 메뉴 기능에 맡깁니다.
- 아이콘 위치를 얻지 못하면 같은 DPI 문맥의 커서 위치를 사용합니다. 두 조회 모두 실패하면 임의의 `(0, 0)`에 메뉴를 띄우지 않습니다. 보조 모니터의 음수 좌표를 그대로 유지합니다.
- PC 배율·해상도·UAC·보안 정책과 Claude 인증·모델·승인 모드·개인 설정은 변경하지 않습니다. 새 반복 타이머·프로세스·외부 라이브러리를 추가하지 않습니다.

기술 근거: [알림 아이콘 콜백 계약](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-notifyicondataw), [창 생성 시 DPI 문맥과 메시지 처리](https://learn.microsoft.com/en-us/windows/win32/hidpi/high-dpi-improvements-for-desktop-applications), [Per-Monitor V2 메뉴 배율](https://learn.microsoft.com/en-us/windows/win32/hidpi/dpi-awareness-context), [아이콘 위치 조회](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shell_notifyicongetrect).

## 검증 기록

- 트레이·알림·전용 창·진단·EXE 회귀 검사: **81개 실행, 77개 통과, 4개 명시적 생략, 실패 0**.
- 현재 Windows 사용자로 트레이 네이티브 검사: **17개 통과**. 임시 아이콘의 중복 방지, 열기 이벤트, Explorer 재시작 메시지 복구, 종료·재시작과 네이티브 HWND/메뉴 콜백의 Per-Monitor V2 문맥을 확인했습니다. 호출자 스레드 DPI 상태도 유지됐습니다.
- 좌표 회귀 검사는 확대 배율에 해당하는 서로 다른 크기의 사각형, 음수 모니터 좌표, 불명확한 콜백 값, 위치 조회 실패를 포함합니다. 네이티브 메뉴 콜백 검사는 실제 창 메시지를 사용하되 차단되는 팝업 표시 자체는 가로채므로 시각 검증을 대신하지 않습니다.
- 전용 창 통합 검사: 페이지 로드, 기존 창 4회 재사용, X로 숨김·재표시, 정상 종료 통과. 별도 데모 상태를 사용했습니다.
- 실제 0.18.1 EXE를 한글·공백 경로에서 실행: 기존 Python 3.13.5와 Claude Code 2.1.285 탐지, 반복 실행 시 동일 서버 재사용, 기존 Claude 인증 연결 초기화와 명령 141개 수신, 정상 종료 통과. 사용자 업무 메시지는 보내지 않았으며 검사한 개인 설정 파일 5개의 해시는 동일했습니다.
- EXE와 VBS ZIP의 앱 파일 91개 일치: 소스 84개와 고정된 WebView2 호스트 빌드 파일 7개. 런타임 상태·인증 파일이 포함되지 않았음을 확인했습니다. VBS ZIP 압축 해제 후 데모 API 시작·종료 검사도 통과했습니다. 실제 VBS 더블클릭에 의한 메뉴의 시각 검사는 별도입니다.
- 공개 다운로드 해시 검증: 배포 후 결과를 기록합니다.

단일 EXE SHA-256: `cda2c623161fa42df260e03ab044d6a974ddfbb8b048d29daf56aefb5fb8ee0a`.

기존 UI 전체 및 모든 모니터 배율 조합의 시각 검증을 완료했다는 의미는 아닙니다. 문제 화면의 실제 트레이 펼침 상태에서 수정본으로 우클릭하여 최종 위치를 확인해야 합니다.

## 업데이트

기존 트레이 아이콘에서 **완전 종료**한 뒤 0.18.1 EXE 또는 VBS 묶음을 실행합니다. 창의 X는 백그라운드로 숨기므로 업데이트를 위해서는 완전 종료가 필요합니다. Python·WebView2 등 실행 조건은 0.18.0과 같으며 자동 설치하지 않습니다.

# Company Workspace 0.23.21 로컬 구현·검증

검증일: 2026-10-07. Windows 로컬 소스와 실제 EXE/VBS 패키지를 사용했습니다. 이 문서는 GitHub 게시 전 로컬 검증 기록입니다. 최종 배포 파일과 게시 상태는 [0.23.21 Release](https://github.com/bongG-moon/workspace_local/releases/tag/v0.23.21)를 기준으로 확인하세요. 사내 GitLab 재게시를 수행하지 않았습니다.

## 반영한 내용

1. GitLab 구성 파일 게시: 기존 기본 브랜치에 새 브랜치용 `start_sha`를 보내지 않습니다. `force=False`, 파일별 `last_commit_id`, 게시 직전 HEAD 확인과 게시 후 SHA 확인은 유지합니다. README만 있는 프로젝트의 생성·갱신 요청과 동시 변경 실패를 시험했습니다.
2. 관리자 실행 진입점: 내부 앱과 처음 실행한 EXE 버전을 구분합니다. 업데이트 시 검증된 EXE를 함께 준비하고 시작 확인 후 전용 실행기로 연결합니다. 설정에서 같은 버전 EXE를 검증해 **Company Workspace (최신)** 바로가기를 만들 수 있습니다. 기존 EXE를 덮어쓰지 않으며 지정 Python 경로·상태 위치를 유지합니다. 일시적인 바로가기 실패는 복원·재시도합니다.
3. 이어 할 일: 선택한 기존 항목 ID·본문·첨부로 **지금 반영/지금 실행**합니다. 중지 확인 후 같은 대화를 재개하며 다른 항목의 상대 순서를 유지합니다. 중복 클릭·응답 유실·편집/취소·자동 실행 경합과 없어진 첨부를 검사했습니다. 폴더 신뢰, 승인·질문, 설정 확인, 전송 미확인 경계는 유지합니다.
4. 화면 모드: 밝게·어둡게·시스템 설정 따르기, 저장/재시작, 첫 화면 깜빡임 방지, 제목 표시줄·PC 알림과 WebView 컬러스킴을 연결했습니다. 밝은 모드의 기존 색상 값은 그대로 보존합니다. 이미지·HTML 문서 자체의 색상은 반전하지 않습니다.

## 자동 검증

서로 겹치는 테스트가 있어 아래 숫자를 합산해 고유 검사 수로 해석하지 않습니다.

| 범위 | 결과 |
|---|---|
| GitLab 소스 게시 | 18개 통과 |
| 사내 게시 도구 전체 | 204개 중 201개 통과, 호스트 기능 조건 3개 생략 |
| 실행기·업데이트·권한·GitLab 자산·실제 Windows COM 직렬화 | 관련 192개 통과 |
| 이어 할 일·중지 후 재개 | 122개 통과 |
| 프런트엔드 전체 회귀 | 519개 통과 |
| 서버·화면 모드·네이티브 창·시작 진단 통합 | 106개 중 105개 통과, 조건부 1개 생략 |
| 마지막 화면 모드·대기 목록 UI | 48개 통과 |
| 네이티브 알림·창 테마 | 105개 중 103개 통과, opt-in 2개 생략 |

- 합성 CLI 프로세스에서 interrupt ACK와 result 순서 두 경우 모두 같은 PID·세션·승인 모드로 선택 항목→나머지 항목 실행을 확인했습니다.
- 실제 Windows COM으로 임시 바로가기 데이터를 직렬화했습니다. 사용자 바탕화면·기존 EXE·개인 Claude 설정은 변경하지 않았습니다.
- C# 창·알림 검증: 테마 초기 배경, 최대화·최소화·트레이 복원, 알림 3종×4 DPI, 한글 글꼴·배치·밝게/어둡게 전환을 확인했습니다. 카드 64회 생성·해제 후 GDI 20→20, USER 22→22로 누적이 없었습니다.
- 테마는 저장된 작은 JSON과 단일 미디어/Windows 설정 이벤트를 사용합니다. 추가 상시 PowerShell·테마 폴링은 없습니다. 실행기 준비 진행 조회도 사용자가 요청했을 때만 유한하게 수행합니다.
- 본문·보조·안내 글자 대비는 약 12.98/9.42/7.00:1, 주요 버튼 흰 글자는 4.80:1입니다. 진행 링크는 밝은 강조색으로, 업데이트 hover는 진한 배경으로 보완했습니다.

## 실제 화면 검증

computer-use로 개인 앱과 분리된 체험 창에서 확인했습니다.

- 밝은 기본 화면, 설정의 다크 선택 및 저장 안내, 어두운 제목 표시줄, 새 업무 선택창, 대화·표·코드·응답 대기 화면을 확인했습니다.
- 배경 지정이 없는 HTML 문서를 열어 흰 문서 바탕과 검은 글씨가 유지되는 것을 확인했습니다. 바깥 미리보기 팝업은 다크 모드입니다.
- 대기 목록 두 번째 항목의 **지금 실행**을 실제 클릭했습니다. 선택 항목이 체험 대화로 먼저 전달되고 남은 첫 번째·세 번째 항목의 상대 순서가 유지되는 것을 API 상태와 함께 확인했습니다.
- 검증 화면은 가상 자료입니다. 실제 모델 호출과 사용자 진행 중 업무는 사용하지 않았습니다.

로컬 증거: `build/qa-0.23.21/`의 `frontend-tests.log`, `integration-tests-final.log`, `last-ui-tests.log`, `queue-ui-proof.json`, 화면 PNG와 `packaged-check/packaged-proof.json`. 작업 중 발견한 테스트 대역의 이벤트 API 누락과 이전 버전 고정 기대값은 보완 후 통과했습니다.

## 최종 패키지

- EXE·VBS의 공통 파일 **138개 일치**. 직접 소스 131개와 생성된 네이티브 파일 7개를 확인했습니다.
- 최종 EXE 직접 실행: 앱/실행기 0.23.21, 실제 일반 권한, 이전 관리자 설정 파일 무시·보존, 재실행 시 같은 인스턴스 재사용, 정상 종료, 다크 저장 후 재시작 첫 HTML부터 적용을 확인했습니다.
- 모든 패키지 시험 종료 후 격리 `runtime.json`이 제거됐습니다. EXE ZIP/VBS ZIP에 Python은 포함하지 않습니다.
- 전달 폴더: `hermes/dist/workspace-release-0.23.21`. 정확한 파일 해시는 그 폴더의 `SHA256SUMS.txt`를 기준으로 합니다.

## 운영 환경에서 남은 확인

- 사내 GitLab은 외부에서 접근할 수 없어 실제 프로젝트 재게시를 수행하지 않았습니다. 사내에서 **구성 파일만 올리기**로 재시험해야 합니다.
- 실제 운영 PC의 UAC 승인·보안 제품·관리자 토큰 조합은 원격으로 재현하지 않았습니다. 최신 EXE를 완전 종료 후 관리자 실행하고 설정의 실제 권한을 확인해야 합니다.
- 이 로컬 검증 당시에는 0.23.21 원격 게시 전이어서 실제 배포 서버의 실행기 다운로드는 확인하지 않았습니다. 미게시·출처 불일치·파일 오류 시 기존 실행기를 유지하고 오류를 안내하는 경로를 시험했습니다.

## 상단 화면 모드 빠른 전환 추가 검증

- 상단 재시작·자료 패널 버튼 옆에 같은 크기의 해·달 아이콘 버튼을 추가했습니다. 달은 어두운 모드로, 해는 밝은 모드로 전환합니다.
- 설정의 선택값과 같은 저장 API를 사용하며 시스템 따르기 상태에서 누르면 현재 화면의 반대 모드를 명시적으로 저장합니다. 저장 중 중복 클릭을 막고 실패 시 기존 모드를 유지하며 토스트로 안내합니다.
- 관련 appearance/layout/frontend 검사 28개 통과. 시스템 변경, 설정 동기화, 저장 실패, 중복 입력을 포함합니다 (`build/qa-0.23.21/topbar-tests.log`).
- 개인 앱과 분리된 체험 창에서 달→다크·해→라이트 실제 클릭, 아이콘 중앙 정렬, 설정의 어둡게 선택 동기화, 제목 표시줄 전환과 저장 파일을 확인했습니다.
- 새 EXE/VBS의 138개 파일 일치 및 현재 소스 차이 없음, 격리 EXE 재실행·테마 보존·정상 종료 검증을 다시 통과했습니다. 전달 폴더의 0.23.21 파일을 갱신했습니다. 이 항목은 원격 게시 전 로컬 검증 결과입니다.

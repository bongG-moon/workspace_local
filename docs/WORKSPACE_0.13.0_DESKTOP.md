# Company Workspace 0.13.0 — 창을 닫아도 이어지는 업무

이 문서는 0.13.0에 구현한 기능의 사용법과 설계 범위를 설명합니다. 실제 시험 결과와 확인 범위는 [0.13.0 검증 기록](https://github.com/bongG-moon/workspace_local/blob/main/docs/VALIDATION_0.13.0.md)에 정리합니다. 사용법 문서와 공개 배포 여부는 별개이며, 이미 받은 이전 실행 파일에는 자동 적용되지 않습니다.

## 실행 환경과 기존 설정

앱 전용 로그인은 없습니다. EXE와 VBS 모두 이미 설치된 **Python 3.11 이상**을 사용하며, AI 업무에는 같은 Windows 계정의 **Claude Code와 기존 인증**이 필요합니다. EXE는 앱 파일을 담은 실행기이며 Python·Claude를 설치하거나 다운로드하지 않습니다. **Company Agent 설치는 필수가 아닙니다.** 회사 스킬·기억 관리처럼 Company Agent가 제공하는 기능은 해당 설치가 있는 범위에서 사용합니다.

기존 Claude 호출 경로·인증·모델·MCP·개인 설정을 유지합니다. 예약을 위해 Windows 작업 스케줄러를 등록하거나 Company Agent 스킬·Claude Cron을 호출하지 않습니다. Windows 로그인 때 앱을 자동 실행하도록 등록하지도 않습니다. 실행 방법과 기존 Python 경로 지정은 [단일 EXE 안내](WORKSPACE_STANDALONE_EXE.md)를 참고하세요.

## 창 닫기와 완전 종료

| 조작 | 동작 |
| --- | --- |
| 창의 **X** | 화면을 닫습니다. 앱 서버가 살아 있으면 진행 중인 업무와 예약은 계속됩니다. |
| 설정의 **트레이로 보내기** | 연결된 앱 창을 숨길 수 있을 때 표시됩니다. 작업 표시줄 알림 영역의 아이콘으로 돌아올 수 있습니다. |
| 트레이 메뉴 **앱 열기** | 실행 중인 앱 화면을 다시 엽니다. |
| 트레이 메뉴 **완전 종료**, 또는 설정의 **완전히 종료** | 앱이 시작한 업무 연결을 정리하고 로컬 앱을 종료합니다. 이후 예약은 실행하지 않습니다. |

트레이에는 진행 중인 업무와 승인·질문 대기의 개수를 표시합니다. 아이콘이 보이지 않으면 Windows 알림 영역의 숨겨진 아이콘 목록을 확인할 수 있습니다. 트레이를 사용할 수 없는 환경에서도 같은 실행기를 다시 열어 앱으로 돌아갈 수 있습니다. 새 버전으로 교체할 때에는 기존 앱을 완전히 종료한 뒤 새 실행기를 사용합니다.

PC가 꺼지거나 절전 상태가 되면 앱이 업무나 예약을 계속 수행할 수 없습니다. 트레이 실행은 PC를 깨우는 기능이 아닙니다. 완전 종료·작업 중지는 이미 만든 파일이나 끝난 외부 작업을 되돌리지 않습니다.

## 응답을 읽는 위치 유지

답변은 수신되는 동안 순서대로 표시합니다. 여러 작은 응답 조각을 묶어 화면을 갱신하여 긴 답변을 받을 때 반복적인 화면 변경을 줄입니다. 이 처리는 모델 응답 속도나 결과 품질을 바꾸는 기능이 아닙니다.

대화 맨 아래를 읽고 있으면 새 응답을 따라갑니다. 위로 이동해 이전 내용을 읽으면 위치를 유지하고 **최신 응답으로 이동 ↓** 버튼을 표시합니다. 이 버튼을 누르거나 다시 맨 아래로 이동하면 최신 응답을 따라갑니다. 다른 업무로 이동한 뒤 이전 업무의 늦은 응답이 새 업무 화면에 섞이지 않도록 구분합니다.

## 자료 추가와 파일 끌어 놓기

| 방법 | Claude에 연결되는 자료 | 원본과 복사본 |
| --- | --- | --- |
| **자료 추가**, **경로 추가**, `@` 파일 참조 | 사용자가 고른 원본 경로 | 이 단계에서 별도 파일을 복사하지 않습니다. |
| 앱의 자료·결과 항목을 입력창으로 끌기 | 해당 항목의 원본 경로 | 다시 복사하지 않습니다. |
| 파일 탐색기의 파일을 입력창으로 끌기 | 앱 관리 공간에 저장한 복사본 경로 | 원본을 이동하거나 변경하지 않습니다. 이후 원본을 수정해도 복사본에 자동 반영하지 않습니다. |

먼저 업무를 선택하고 아래 입력창으로 파일을 끌어 놓습니다. 문서·이미지·소스 파일 중 지원하는 형식을 받을 수 있으며, 폴더는 **경로 추가**를 사용합니다. 한 요청에는 자료를 최대 **12개** 첨부할 수 있습니다. 드래그 복사는 **파일마다 50 MiB**, 앱 관리 복사본 전체는 **512 MiB**까지입니다. 큰 자료는 원본 경로로 연결할 수 있으며 실제 읽기 가능 여부는 Claude 도구·권한·파일 형식에 따릅니다.

복사본은 기본 `%LOCALAPPDATA%\CompanyAgent\local-ui\attachments` 아래에 보관합니다. 사용자 지정 상태 폴더를 사용하면 그 폴더의 `attachments`를 사용합니다. 첨부에서 제거하거나 대기 요청을 취소해도 원본과 저장된 복사본을 삭제하지 않습니다. 일부 파일만 복사된 뒤 오류가 나면 추가된 개수를 안내하며 이미 추가한 자료를 확인할 수 있습니다.

파일을 끌어 놓는 단계는 이 PC 안의 앱 저장입니다. 실제 AI 요청을 보내면 자료 처리는 기존 Claude 연결과 회사 정책을 따릅니다.

## 실행 중 후속 요청

현재 업무가 진행 중일 때도 다음 요청을 작성하고 자료를 붙일 수 있습니다.

| 선택 | 실행 시점과 의미 |
| --- | --- |
| **끝나고 이어서** | 대기 목록에 등록합니다. 현재 요청이 정상 완료되면 같은 업무에서 다음 요청으로 보냅니다. |
| **지금 반영** | 현재 요청의 중지를 요청하고, 그 연결의 정리가 확인되면 같은 Claude 대화를 이어 새 요청을 보냅니다. 대기 목록에서는 이 요청을 앞으로 옮깁니다. |

**지금 반영은 중지 후 같은 대화 재개 방식입니다.** 실행 중인 Claude 내부 작업에 메시지를 끼워 넣어 즉시 지침만 바꾸는 동작을 보장하지 않습니다. 이미 수행한 파일 변경·외부 작업은 남습니다. 중지를 확인하지 못하거나 오류가 발생하면 자동으로 새 요청을 계속 보내지 않습니다. 체험 모드에서는 끝나고 이어서만 사용할 수 있습니다.

**이어 할 일**에서 아직 보내지 않은 요청의 문구를 수정하고 **위로 / 아래로** 순서를 바꾸거나 취소합니다. 이미 전송한 요청은 목록 편집으로 바꾸지 않으며 현재 작업의 중지 기능을 사용합니다. 등록 실패 때는 작성 중인 내용과 첨부를 유지합니다.

## 실행 예약

1. 업무를 선택하고 작업 폴더를 확인합니다. 입력창에 실행할 내용을 작성하고 필요한 자료를 추가합니다.
2. **실행 예약**을 누릅니다. **한 번**은 날짜·시간, **매일**은 시간, **매주**는 요일·시간을 고릅니다. 여러 요일을 선택할 수 있습니다.
3. 요청과 첨부 자료를 확인하고 저장합니다. 시각은 **이 PC의 현재 시간대**를 기준으로 합니다.
4. **이어 할 일 → 실행 예약**에서 다음 실행과 최근 상태를 확인하고 수정·일시 정지·재개·삭제합니다.

예약 시각이 되면 같은 업무의 대기 요청으로 등록하고 실행 가능한 차례에 보냅니다. 해당 업무가 이미 진행 중이면 기다립니다. 예약을 삭제하거나 일시 정지하면 해당 예약에서 아직 보내지 않은 대기 요청도 취소하지만, 이미 전송한 요청은 멈추지 않습니다.

예약은 **PC가 깨어 있고 앱이 실행 중인 동안** 동작합니다. 앱을 완전히 종료했다가 다시 실행하면 대기 요청과 활성 예약을 일시 정지한 채 복원합니다. 업무 폴더와 내용을 확인한 뒤 **이어 실행**을 선택해야 합니다. 재시작 전에 놓친 예약을 몰아서 실행하지 않습니다.

실행 중 짧은 지연은 예약 시각으로부터 최대 5분까지 처리할 수 있습니다. 그보다 늦게 발견한 실행은 건너뛰고, 반복 예약은 다음 미래 시각으로 넘깁니다. 같은 예약의 이전 요청이 아직 대기·진행·확인 필요 상태라면 새 회차를 쌓지 않습니다. 앱 재시작 후에는 5분 안의 지난 예약도 건너뜁니다. 이는 정확한 시각 실행이나 PC 종료 중 실행을 보장하는 스케줄러가 아닙니다.

## 승인·오류·설정 변경을 만났을 때

| 상태 | 다음 요청과 예약의 처리 |
| --- | --- |
| 승인·질문·디자인 선택 대기 | 현재 응답을 기다립니다. 답변 후 현재 요청이 정상 완료되면 대기 요청을 이어 실행합니다. 예약이 승인을 대신하지 않습니다. |
| 수동 중지 또는 오류 | 해당 업무의 대기 실행을 멈춥니다. 결과를 확인하고 **이어 실행**을 선택합니다. |
| 앱 재시작 | 업무 폴더와 대기·예약 내용을 다시 확인할 때까지 일시 정지합니다. |
| 모델·Effort·승인 모드가 등록 때와 달라짐 | 자동 실행을 멈추고 안내합니다. **이어 실행**을 선택하면 아직 보내지 않은 요청과 활성 예약이 현재 선택한 설정을 사용합니다. 이미 보냈거나 전송 여부가 불확실한 요청은 바꾸지 않습니다. |
| 전송 여부를 확인할 수 없음 | **전송 확인 필요**로 남기고 자동 재전송하지 않습니다. 대화·결과를 확인한 뒤 해당 항목을 **대기에서 제거**하고 필요한 요청만 새로 등록합니다. |

예약은 등록한 업무 폴더와 앱에서 선택한 모델·Effort·승인 설정을 기준으로 합니다. 지정하지 않은 값은 기존 Claude 설정을 상속합니다. 개인 설정 파일이나 인증 정보를 예약 데이터에 복사하지 않습니다. 완전 종료 후에는 연결 설정의 메모리 선택을 자동 복원하지 않으므로, 이전 예약과 현재 선택이 다르면 확인이 필요합니다. 기존의 거절 규칙과 승인 절차를 유지하고 예약·후속 요청용 자동 승인 예외를 추가하지 않습니다.

대기·예약은 앱 상태 폴더의 `work-queue.json`에 저장합니다. 요청 문구·첨부 경로·일정·앱에서 선택한 실행 설정이 포함됩니다. 손상되거나 저장을 확인할 수 없으면 원본을 임의로 초기화하거나 요청을 반복 전송하지 않고 자동 실행을 멈춥니다. 대기 취소와 예약 삭제는 이미 수행한 작업을 되돌리지 않습니다.

## 이렇게 설계한 이유

창을 닫는 것과 업무를 끝내는 것을 분리하여 다른 앱에서 일하는 동안에도 요청을 이어갈 수 있게 했습니다. 원본 경로 첨부는 기존 업무 파일과 연결하고, 드래그는 복사본임을 표시해 브라우저의 파일 취급 방식과 사용자의 기대를 맞춥니다. 후속 요청은 순서를 사용자가 정하고, 예약도 동일한 업무 전송·승인 경로로 보내도록 했습니다. 전송이 불확실할 때 자동 재시도하지 않는 것은 같은 파일 작업이나 외부 요청이 중복 실행되는 것을 막기 위해서입니다.

후속 요청의 대기와 방향 수정, 대화 맥락을 유지한 보조 질문, 변경 내용 검토의 분리는 [OpenAI의 원격 업무 사용 안내](https://developers.openai.com/blog/mastering-codex-remote-for-engineering)를 참고했습니다. 업무·자료·명령·예약을 한 화면 흐름에서 찾기 쉽게 하는 구성은 [ChatGPT 기능 안내](https://learn.chatgpt.com/docs/features)를 참고했습니다. 두 문서는 UX 참고 자료이며, Workspace의 Claude 연결이 해당 제품의 실행 프로토콜이나 클라우드 기능을 동일하게 제공한다는 근거는 아닙니다.

## 추가로 권장하는 기능 — 이번 버전 미구현

| 제안 | 기대하는 사용 흐름 |
| --- | --- |
| 전 업무 알림 모음 | 기존 대기 배지에 더해 완료·실패·승인 이력을 한 목록에서 읽고 해당 업무로 이동 |
| 명령 팔레트 | 키보드로 업무·설정·결과·스킬을 한 번에 찾아 실행 |
| 결과 변경 비교·되돌리기 미리보기 | 바뀐 파일의 차이와 되돌릴 범위를 먼저 확인하고 명시적으로 적용 |
| 대화 분기 | 원래 업무를 유지하면서 특정 시점의 맥락으로 별도 질문·다른 접근을 비교 |

이 제안은 현재 구현된 메뉴나 동작을 의미하지 않습니다. 특히 되돌리기는 파일 변경 외의 메일 발송·외부 시스템 작업까지 복구하는 기능으로 표현하지 않아야 합니다.

# Company Workspace 0.12.11 — Python 탐색 및 WS-38 진단

검증일: 2026-09-30.

운영 PC의 PowerShell에서는 Python 3.11.5가 실행되지만 0.12.10 EXE는 WS-38을 표시한다는 보고를 기준으로 검사했습니다. 개발 PC의 Python 절대 경로가 EXE에 고정되지 않았음을 확인했습니다. **그 운영 PC의 정확한 실패 원인과 수정본 재실행 결과는 아직 미확인**입니다.

## 재현과 변경

기존 실행기는 PATH의 첫 Python이 부적합하면 뒤에 있는 정상 Python을 놓칠 수 있습니다. `py`가 없는 이 조건에서 기존 함수가 WS-38을 반환하는 것을 격리된 fixture로 재현했습니다.

0.12.11은 실제 실행 파일을 가리키는 별칭과 PATH의 여러 후보, `py -0p`의 설치 목록, 현재 사용자·머신의 PEP 514 등록 경로를 확인합니다. 등록 키는 읽기만 하며 다른 사용자 프로필이나 임의 디렉터리를 탐색하지 않습니다. 후보 수·검사 시간이 제한되므로 PC 전체 설치를 완전히 검색한 결과라는 의미는 아닙니다.

검사 결과는 표식이 있는 ASCII JSON 한 줄로 구분합니다. 앞뒤 안내 출력은 허용하지만 중복·잘못된 응답을 정상으로 처리하지 않습니다. 실행·환경 준비·시간 초과·버전·모듈 오류를 구분하며, 함수와 `.cmd/.bat` 래퍼를 검사 목적으로 실행하지 않습니다. EXE의 `--python` 옵션은 기존 절대 `.exe` 경로만 허용하고 명시한 설치가 실패하면 다른 설치로 전환하지 않습니다.

실패 진단은 앱 상태 폴더의 `diagnostics/python-check-*.json`에 저장합니다. 후보 경로·버전·상태·허용된 모듈 이름·오류 번호와 앱 경로·실행 시도 ID를 기록합니다. 부모는 시작 시각, 앱 경로, 실행 시도 ID, WS 코드가 모두 맞는 자식 기록만 표시합니다. 표준 오류 원문·프로필 본문·인증·환경변수 값은 기록하지 않습니다. **로컬 경로는 포함**하므로 공유할 때 이를 확인해야 합니다. 기록 실패가 원래 오류를 가리지 않으며, 이 파일은 공개 저장소의 제외 목록에 있습니다.

환경 준비 오류 분류는 충돌 예외를 주입한 회귀로 검증했습니다. 시험 도구 환경의 Path/PATH 중복 관찰을 운영 PC의 원인으로 단정하지 않습니다.

# Workspace 0.21.4 검증 결과

검증일: 2026-10-01. 변경 범위: 현재 도구·스킬과 수행 동작 표시, 요청별 활동 기록.

## 구현

- 입력창 위 상태 줄에 동작·도구명·안전하게 축약한 대상을 표시합니다. 여러 도구가 겹치면 다른 호출 개수도 표시합니다.
- 채팅의 ‘도구·스킬 활동’은 요청별로 모아 기본적으로 접습니다. ‘활동 N’을 누르면 해당 기록으로 이동해 펼칩니다.
- 승인·질문 대기와 CLI의 대화 정리 등 명시 상태 안내가 오래된 도구 정보보다 우선합니다. 설정 변경을 업무 실행으로 표시하지 않습니다.
- 요청됨 / 실행 중 / 결과 수신 / 오류 / 결과 미확인을 구분합니다. 결과 수신은 도구의 응답을 받았다는 의미이며 전체 업무나 백그라운드 작업의 성공을 뜻하지 않습니다.
- 최근 80건·문자열 합계 48,000자로 제한하고, 상세 DOM은 펼칠 때만 만듭니다. 추가 타이머·네트워크 폴링은 없습니다. 원본 입력·출력·명령·스킬 인자를 새로운 활동 기록에 복제하지 않습니다.

중복 요청·결과, 부모 호출 불일치, 실행 ID 불일치, 종료된 연결과 초기 연결의 미요청 기록, 하위 작업, 결과 미수신, 기록 상한, 입력 문자열의 안전한 표시를 검사했습니다. 답변 없이 중지된 옛 요청의 활동이 다음 요청 뒤에 붙는 문제를 검토에서 발견해 수정하고 회귀 검사했습니다.

## 실제 화면과 Claude 연결

Computer Use로 실제 WebView2 창에서 다음을 확인했습니다.

1. 가상 Skill·Read·Glob 기록에서 현재 파일과 도구, 동시 호출 개수가 표시됨.
2. 활동 버튼으로 스킬명·파일명·각 상태를 펼쳐 확인 가능.
3. 승인 카드가 나오면 상태 줄이 ‘실행 전 확인이 필요해요’로 바뀜.
4. 최종 응답 후 활동은 남고 현재 작업 표시가 종료됨. 다른 업무에서는 이전 활동 상태가 사라지고, 완료 업무를 다시 열면 기록이 복원됨.
5. 최종 배포 EXE에서도 실제 Read 기록을 펼쳐 파일명과 ‘결과 수신’을 확인함.

별도 한글 경로의 EXE만 있는 폴더에서 실행했습니다. 설치된 Python 3.13.5와 Claude Code 2.1.285를 자동 인식했고, 초기 연결에서 모델 claude-sonnet-5-5·effort medium·명령 141개를 확인했습니다. 두 번째 실행은 동일 서버와 창을 재사용했습니다.

실제 AI 요청은 격리된 검증 폴더의 activity-probe.txt를 한 번 읽도록 요청한 1건입니다. Read 호출 1건의 결과 수신과 파일 안의 확인 문자열 응답을 확인했습니다. 모델·effort·승인 모드는 요청 전후 같았으며, 종료 후 기존 개인 설정 파일 5개의 비교에서 변경은 0개였습니다. 검증용 서버·창·Claude 연결은 종료했습니다. 실제 Skill·MCP·장시간 도구 heartbeat는 이번 실사용 검증에서 호출하지 않았으며 해당 경로는 가상 프로토콜 테스트 범위입니다.

## 배포 검증과 한계

EXE와 VBS ZIP은 동일한 소스 103개 및 검증된 네이티브 자산 7개를 포함합니다. ZIP CRC·파일 목록·소스 동일성·네이티브 해시·실행 진단 핀을 검사했습니다. 압축 해제한 VBS 묶음의 서버·인증 API·화면 자산·한국어 폰트·안내서·정상 종료도 검사했습니다. 실제 VBS 더블클릭은 이 서버 검사와 별개입니다. Python 설치 파일·개인 인증·사용자 대화·검증 기록은 배포에 포함하지 않습니다.

활동은 CLI가 실제로 제공한 메시지의 표시입니다. 내부 사고 과정이나 진척률을 만들어 보여주지 않습니다. 과거 버전에서 수집하지 않은 도구 기록은 복원할 수 없습니다. 원래 실행 ID를 가진 콜백, 이미 관찰한 호출 ID와 하위 호출의 부모는 이전 실행과 혼동하지 않도록 처리합니다. CLI가 실행 식별 정보 없이 완전히 새로운 최상위 호출을 뒤늦게 보낸다면 원래 실행을 완벽히 역추적할 수는 없습니다. 기존 직렬 요청 처리와 연결 종료 가드를 유지합니다.

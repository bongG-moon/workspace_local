# Workspace 0.16.0 검증 기록

검증일: 2026-09-30. 기존 Claude Code를 사용하는 일반 Windows GUI 앱의 통합 알림함·명령 팔레트·파일 변경 비교·대화 분기와 자원 사용 개선을 대상으로 합니다.

## 자동 검사

- 전체 회귀 검사: 960개 중 929개 통과, 31개 건너뜀, 실패·오류 0개(215.956초). 건너뛴 검사는 선택적 Company Agent 어댑터 19개, 심볼릭 링크 권한 4개, 별도 동의가 필요한 Windows 네이티브 검사 7개, 이 호스트에서 실행 불가한 WSH/VBS 검사 1개입니다.
- 현재 로그인한 Windows 사용자 환경의 실행기 검사: 9개 통과. 설치 경로·별칭, 재실행 재사용, 다른 버전 충돌 방지 경로를 포함합니다.
- 추가 검사: 알림별 읽음 ID와 현재 대기 상태 구별, 오래된 HTTP 응답, 분기 중복 클릭·원본 변경, 제한된 파일 스냅샷·부분 관찰·원본 무변경, UI 버퍼와 기록 캐시의 제한, 저장 실패 후 최신 결과 보존.

## 실제 화면 확인

개인 데이터가 없는 격리된 CLI·대화·문서 fixture를 사용했습니다. 1280×720 화면에서 다음을 직접 조작했습니다.

- Ctrl+K로 팔레트를 열고 검색·Enter·Esc로 이동. 기존 `/re` 자동완성은 입력창 위에 그대로 표시.
- 통합 알림함에서 질문 알림을 읽음 처리해도 `응답 필요 1`과 실제 질문 대기가 유지됨.
- 파일 변경 비교에서 HTML 생성과 Markdown 수정의 이전/이후 줄이 구분되고 원본 HTML 스크립트는 실행되지 않음.
- 분기 만들기 후 원본·분기 업무가 각각 존재하며 준비 상태, 공유 폴더 안내, 원래 대화로 이동이 표시됨.
- 원래 대화로 돌아오면 작성하던 초안이 유지됨. 관찰한 화면의 브라우저 오류 로그 없음.

## 실제 EXE와 CLI 연결

최종 EXE만 있는 한글 경로에서 별도 상태·캐시 폴더를 사용해 실행했습니다.

- EXE 0.16.0 시작, 기존 Python 3.13.5 탐색 및 서버 실행 성공. Python 포함·다운로드·설치 없음.
- 설치된 Claude Code 2.1.285 연결, 실제 모델 `claude-sonnet-5-5`, Effort `medium`, 명령 141개 수신.
- 초기화와 설정 조회만 수행했으며 사용자 AI 메시지는 0개. 재실행 시 동일 캐시·서버 재사용 확인.
- 검증 서버와 Claude 연결 정상 종료. 개인 설정 파일 5개에 대한 전후 해시 비교에서 변경 0개.
- 분기 옵션은 별도 격리 프로필의 설치 CLI에서 `--resume`·`--fork-session`·`--session-id` 초기화를 확인했습니다. 원본 해시는 같고, 첫 사용자 요청 전에는 자식 대화 파일이 아직 없음을 확인했습니다.

실제 AI 응답을 받는 분기 후속 요청은 이번 검증에서 실행하지 않았습니다. 분기 요청·응답·ID 검증은 가상 CLI와 회귀 검사로 검증했으며, 회사 운영 PC의 실제 모델 응답까지 확인했다는 뜻은 아닙니다. 지원 범위는 [Claude CLI 분기 옵션](https://code.claude.com/docs/en/cli-reference)에 근거한 마지막 대화 기록에서의 분기입니다.

## 자원 사용 확인

동일한 합성 대화 100개를 읽는 Python `tracemalloc` 비교입니다. 운영 데이터나 전체 프로세스 RSS 측정이 아닙니다.

| 기록 읽기 방식 | 유지된 기록 객체 | 관찰한 최대 할당 | 읽기 시간 |
| --- | ---: | ---: | ---: |
| 기존 방식, 본문 모두 적재 | 83.190 MiB | 90.402 MiB | 0.804초 |
| 지연 로딩, 본문은 선택 시 적재 | 0.084 MiB | 16.011 MiB | 0.449초 |

유휴 본문 캐시는 최근 8개를 유지하며 실행·미저장·정리 중인 업무는 제외합니다. 빈 대기열 확인을 두 번 실행해도 기록 본문을 다시 읽지 않는 회귀 검사를 포함합니다. 저장 실패 뒤 본문이 오래된 디스크 내용으로 대체되지 않도록 보호합니다.

파일 비교는 4개의 128 KiB HTML을 전후 수집하는 10개 요청으로 시험했습니다. 최근 8개 보관 시 추적 메모리 최대 6.01 MiB, 최종 유지 0.52 MiB, 디스크 8.01 MiB를 관찰했습니다. 최대 저장 정책은 기록당 4 MiB·8개이며 쓰는 동안 임시 파일이 하나 더 존재할 수 있습니다. 이 수치는 현재 PC의 합성 시험 결과이며 모든 문서의 성능 보장이 아닙니다.

화면은 대화 150개·50만 자, 메시지당 10만 자를 제한하고 초과 표시를 안내합니다. 숨겨진 창에서 애니메이션 프레임이 멈춰도 스트림 처리 버퍼가 무제한 쌓이지 않습니다. 팔레트·비교 기능은 상시 감시기나 반복 조회 타이머를 추가하지 않습니다.

## 배포 묶음

- EXE와 VBS ZIP의 앱 파일 76개가 소스와 일치함을 확인했습니다.
- VBS ZIP은 새 폴더에 압축 해제하여 포함된 서버 진입점·인증 경계·화면·글꼴·오프라인 안내서·파일 목록·알림·목록 조회·종료를 확인했습니다.
- VBS 더블클릭 자체는 이 호스트의 WSH 시험 제한으로 확인하지 못했습니다. EXE 실행 검증과 구분합니다.
- 최종 EXE SHA-256: `1c48e3102ecfbd1607f05582084f40f049624e0a3f4a01ef6a288048fefef5ef`
- 최종 VBS ZIP SHA-256: `757686bac1657176094e223f3d182ce8a9dbc7b3645f0e6fe7d4229d70eab36c`
- 배포 소스 커밋: `66a9b12f936c856c1e6ad8cb03222f4389eab049`. 원격 `main`의 동일 커밋과 [v0.16.0 Release](https://github.com/bongG-moon/workspace_local/releases/tag/v0.16.0)를 확인했습니다.
- 공개한 EXE ZIP·VBS ZIP·SHA256SUMS.txt를 인증 없이 다시 내려받아 모두 로컬 파일과 같은 SHA-256임을 확인했습니다. EXE ZIP: `0ece72b437d82097e498b75b597bd2f3f62ba4e4d180e7736e32dd0e0f6ac351`.
- 배포 직전 별도 코드 검토에서 분기 식별자·원본 검증, 파일 수집 경계, 기록 캐시·저장 실패 보호, 늦게 도착한 화면 응답 처리를 확인했고 추가 차단 결함은 발견하지 못했습니다.

Windows 알림 배너의 실제 표시 여부, 모든 회사 보안 정책·Python 설치 조합, Office 문서 내부 비교·자동 복구는 이번 검증 완료 범위가 아닙니다. 기존 인증·UAC·회사 정책·개인 Claude 설정을 변경하지 않았습니다.

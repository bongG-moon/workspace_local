# Company Workspace — 로컬 업무 화면 0.12.10

## 0.12.10 기존 실행 환경 확인

EXE와 VBS 모두 **이미 설치된 Python 3.11 이상**을 확인하여 사용합니다. Python 실행 환경·설치 프로그램을 포함하거나 다운로드·자동 설치하지 않습니다. 조건이 맞지 않으면 확인한 이유를 안내하고 중단합니다. 앱 전용 로그인은 없으며 AI 업무에는 같은 Windows 사용자의 기존 Claude Code와 인증을 사용합니다. 기존 PATH·개인 설정·회사 보안 정책은 자동으로 바꾸지 않습니다.

## 0.12.9 승인 카드 정리

승인 카드의 요청 요약·범위 선택·버튼을 간결하게 정리했습니다. 실행 원문과 허용 규칙은 계속 확인할 수 있습니다. 기본은 **이번만 허용**이며, 연결·지속 허용은 현재 Claude가 제공한 선택지와 정확한 저장 범위를 확인한 뒤 직접 선택합니다. 화면을 간결하게 바꿔도 Claude의 승인 의미·회사 정책·규칙 전달 방식은 유지합니다.

## 0.12.8 왼쪽 안내 문구 정리

왼쪽의 고정 안내 문구 ‘나의 PC와 연결 / 내 업무가 이어지는 공간’을 제거했습니다.

## 0.12.7 모델·Effort·승인 모드 사용법

입력창 아래 **모델 / Effort / 승인**에서 현재 Claude 연결이 보고한 값을 확인하고 변경합니다. 선택 목록을 열거나 설정을 바꾸는 것은 업무 요청 전송이 아닙니다. 연결이 없으면 먼저 기존 Claude를 초기화하고, 업무 폴더 확인이 필요하면 해당 확인을 거칩니다. 입력 중인 요청이나 첨부 자료를 이 과정에서 자동 전송하지 않습니다.

### Effort 버튼과 `/effort`

Effort 버튼과 입력 명령은 같은 설정 경로를 사용합니다. 실제 수준을 확인하지 못하면 **미확인**, 요청값만 있으면 **요청 high**처럼 구분하며, 업무를 아직 선택하지 않았을 때는 **기존 설정**으로 표시합니다.

| 입력·조작 | 동작 |
| --- | --- |
| **Effort** 클릭 또는 `/effort`만 입력 후 보내기 | 입력창 위에 Effort 선택 목록을 엽니다. AI 질문은 보내지 않습니다. |
| `/effort low`, `/effort medium`, `/effort high`, `/effort xhigh`, `/effort max` | 현재 모델이 제공한 수준만 적용하고 CLI의 실제 적용값을 다시 확인합니다. 모든 모델에서 다섯 수준을 전부 지원하는 것은 아닙니다. |
| `/effort auto` 또는 Effort 목록의 **auto** | 현재 모델에서 변경 전에 관찰한 Effort로 복원합니다. 개인 설정 파일의 Effort를 삭제하거나 다른 모델·승인 모드를 초기화하지 않습니다. |

변경 전 값을 확인하지 못하면 auto로 복원했다고 표시하지 않고 안내합니다. Effort를 바꾼 뒤 다른 모델로 이동하여 새 모델의 변경 전 값을 모르는 경우도 해당합니다. 이때 임의 값으로 바꾸거나 다른 설정을 초기화하지 않습니다. 지원하지 않는 수준·적용 거절·시간 초과·적용값 확인 실패도 성공으로 처리하지 않습니다. 잘못된 명령이나 실패한 명령은 수정할 수 있도록 입력창에 남깁니다. 명령 또는 열린 목록에서 선택이 성공하면 해당 `/effort` 명령 텍스트만 지우며 첨부 자료는 유지합니다. 대화 기록에 새 업무 요청을 만들지 않습니다.

`ultracode`는 Effort 단계와 별개입니다. Effort를 바꿀 때 기존 값을 보존하며 앱이 임의로 켜거나 끄지 않습니다. 모델을 바꾸면 새 모델이 제공한 Effort 목록과 적용값을 다시 확인합니다.

### 승인 모드와 Shift+Tab

승인 버튼은 연결에서 확인한 모드를 아래처럼 표시합니다.

| 화면 표시 | 모드 | 의미 |
| --- | --- | --- |
| `manual mode on` | `default` 또는 설치 CLI의 `manual` | Claude의 기존 승인 규칙에 따라 필요한 작업을 확인합니다. |
| `accept edits on` | `acceptEdits` | Claude의 파일 편집 허용 모드를 사용합니다. |
| `plan mode on` | `plan` | 실행 전에 계획을 검토합니다. |
| `auto mode on` | `auto` | Claude가 제공하는 자동 판단 모드를 사용합니다. 회사 정책이나 모든 확인을 해제하는 모드는 아닙니다. |

**입력창에 커서가 있을 때 Shift+Tab**을 누르면 현재 연결이 지원하는 모드만 **Manual → Accept edits → Plan → Auto** 순서로 순환합니다. 지원하지 않는 모드는 건너뛰며, 현재 모드나 순환 가능 여부를 확인하지 못하면 목록에서 확인하도록 안내합니다. 다른 입력 필드·창의 Shift+Tab은 기존 키보드 이동을 유지합니다. 일반 Tab은 자동완성 선택에 사용합니다. 요청·질문·승인·설정 변경이 진행 중일 때는 모드를 함께 바꾸지 않습니다.

앱이 시작할 때 기본 모드를 임의로 Auto로 바꾸지 않습니다. 개발 환경에서 관찰한 Claude CLI 2.1.284의 SDK/`-p` 연결은 `default`를 상속했습니다. 대화형 터미널과 SDK의 시작 모드는 다를 수 있으므로 터미널의 Auto 표시를 앱에 복사하지 않습니다. 실제 연결값을 표시하며, 설치 버전·모델·설정에 따라 지원 모드가 달라질 수 있습니다. [Claude 공식 승인 모드 안내](https://code.claude.com/docs/en/permission-modes).

### 설정 변경과 재연결

모델·Effort·승인 모드는 각각 적용하고 CLI 응답을 확인합니다. 요청값과 실제 응답값이 다르면 실제 값을 우선 표시합니다. 하나를 바꾼 것만으로 다른 설정을 기본값으로 되돌리거나 기존 업무 요청을 다시 실행하지 않습니다. 실패 시 실제 반영 여부를 안내하며 확인하지 못한 값을 적용 완료로 표시하지 않습니다. 승인 모드의 변경 전 값을 모르면 복원할 수 없다고 안내하며, 임의로 Default를 선택하거나 연결 전체를 초기화하지 않습니다.

같은 앱 실행 중 같은 업무가 새 Claude 연결을 준비하면, 그 업무에서 선택한 모델·Effort·승인 모드를 메모리에서 다시 적용한 뒤 다음 요청을 진행합니다. 재적용을 확인하지 못하면 기본값으로 조용히 업무를 시작하지 않습니다. 다른 업무에는 복사하지 않으며 앱을 완전히 종료·재시작하면 이 선택은 영구 저장되지 않아 기존 Claude 설정을 다시 상속합니다. 승인 카드의 **항상 허용**으로 명시적으로 저장한 규칙은 이 연결 설정과 별개입니다.

새 기능의 실제 검증 결과는 저장소의 `docs/VALIDATION_0.12.7.md`에 기록합니다. 이 사용법 문서만으로 모든 CLI·회사 PC에서 검증이 끝났다고 판단하지 않습니다.

## 함께 제공하는 입력창

자료 추가·경로 추가·모델·Effort·승인 모드를 입력창 하단의 같은 줄에서 사용합니다. `/ 스킬·명령`과 `@ 파일`은 작은 안내 문구로 표시하고, 입력 중 후보 표시와 Tab/Enter 선택은 유지합니다. 좁은 창에서는 겹치지 않도록 실행 설정만 다음 줄로 정렬합니다.

`Company-Workspace-0.12.10.exe`는 앱 파일을 담은 실행기이며, 이미 설치된 Python 3.11 이상으로 앱을 시작합니다. EXE ZIP을 받았다면 먼저 풀고 실행하세요. Python을 동봉하거나 설치하지 않습니다. 기존 Claude PowerShell 프로필과 인증을 이어서 사용하며, VBS 배포 방식도 유지합니다. [단일 EXE 사용 안내](WORKSPACE_STANDALONE_EXE.md)를 참고하세요.

## 0.12.3 입력창 개선

`/sk`·`@rep`처럼 앞부분을 입력하면 입력창 바로 위에 후보와 설명이 나타나고 **Tab / Enter**로 선택할 수 있습니다. 홈에서는 설치된 공통 스킬을, 업무에서는 해당 폴더의 후보를 표시합니다. 신뢰한 업무는 첫 `/` 입력 때 기존 Claude를 자동 초기화해 실제 명령 목록을 갱신하며 AI 질문은 전송하지 않습니다. 문장 중간의 스킬 호출, 공백이 있는 한글 파일 참조, 소스 파일 추천도 지원합니다. [0.12.3 자동완성 안내](WORKSPACE_0.12.3_AUTOCOMPLETE.md)와 [입력 문법·터미널 전용 기능의 경계](WORKSPACE_0.12.2_INPUT.md)를 확인하세요.

## 이어서 제공하는 0.12.1 사용 흐름

**앱 화면은 먼저 열고, AI 업무는 기존 Claude 인증을 사용합니다.** 앱 전용 로그인이나 API 키는 없습니다. Claude 호출 대상을 아직 확인하지 못해도 화면에서 원인을 볼 수 있으며, 다른 CLI나 계정으로 자동 전환하지 않습니다. EXE·VBS·소스 실행 모두 Windows와 이미 설치된 Python 3.11 이상이 필요합니다. 실행기는 기존 설치를 확인할 뿐 Python을 다운로드하거나 설치하지 않습니다. AI 요청에는 정상적으로 사용할 수 있는 기존 Claude Code가 필요합니다.

승인 카드는 **이번만 허용**을 기본으로 합니다. CLI가 제공하면 **이 연결에서 허용** 또는 저장 범위를 표시한 **항상 허용**을 직접 선택할 수 있습니다. 항상 허용은 표시된 규칙만 CLI에 전달해 저장하도록 요청하며, 모든 도구를 일괄 허용하거나 기존 설정 파일을 통째로 바꾸지 않습니다. 모델·Effort·승인 모드 선택은 개인 기본 설정에 저장하지 않습니다.

앱이 시작하는 PowerShell에는 `-ExecutionPolicy Bypass`를 사용하며 이번 실행의 PowerShell 프로세스와 그 자식 프로세스 계열에만 적용합니다. 사용자·컴퓨터의 영구 실행 정책이나 UAC를 바꾸지 않으며 조직의 그룹 정책이 우선합니다. 다른 PC에서 이 옵션으로 해결된 사례만으로 현재 PC의 `exit 1` 원인을 확정하지 않습니다. [0.12.1 사용 범위와 호환성](WORKSPACE_0.12.1_COMPATIBILITY.md)에 시작 조건과 승인 저장 범위를 정리했습니다.

### 함께 제공하는 업무 화면

새 업무의 기본 위치는 Windows가 알려 준 실제 **바탕화면 아래 Company Workspace**입니다. 저장 위치를 바꿀 수 있으며 기존 업무·대화·개인 설정은 이동하지 않습니다. 앱에 Noto Sans KR을 동봉해 인터넷 폰트 다운로드 없이 한글을 표시하고, 파일·폴더 선택 응답은 별도 JSON 파일로 받아 PowerShell 안내 문구가 섞이는 오류를 방지합니다.

**스킬·도구**는 업무와 독립적으로 **공통 / 선택 폴더**를 조회합니다. 설치 메타데이터와 실제 CLI 보고를 구분하고, 출처가 다른 동명 스킬을 보존합니다. 승인·질문·디자인 선택 대기는 전체 업무 배지에서 모아 확인합니다. 확인된 Windows Edge 앱 창에는 작업표시줄 강조를 요청하고, 브라우저 알림은 사용자가 켠 경우에만 요청합니다.

**폴더별 스킬 → 업무 폴더** 드롭다운에서 현재 앱의 업무 목록에 등록된 디렉토리를 바로 선택합니다. 별도 폴더 탐색 창은 열리지 않으며, 같은 디렉토리는 한 번만 표시하고 전체 경로로 구분합니다. 처음에는 현재 업무 폴더(선택한 업무가 없으면 가장 최근 업무 폴더)를 사용하며 이후 조회 폴더 선택을 유지합니다. 조회 폴더를 바꿔도 진행 중인 업무·대화·입력 초안은 바뀌지 않습니다. 등록된 업무가 없으면 새 업무를 만든 뒤 선택할 수 있습니다.

입력창의 `@`는 현재 업무 폴더와 직접 선택한 파일을 추천합니다. `/`는 연결 전 설치 메타데이터와 실제 연결의 명령을 구분하고, 연결이 보고한 뒤에는 그 목록을 기준으로 표시합니다. `/effort`는 위의 앱 설정 명령으로 처리합니다. 모델·Effort·승인 모드는 해당 업무 연결에 적용하며 개인 기본 설정은 유지합니다. 결과 미리보기에서 **기본 앱에서 열기 / 폴더에서 보기 / 메모장에서 열기**를 사용할 수 있으며 HTML도 직접 선택해 기본 앱으로 열 수 있습니다.

**Workspace와 Company Agent 코어는 별도 배포입니다.** Workspace를 바꿔도 설치된 하네스 후크·스킬은 바뀌지 않습니다. 이번 작업에서 확인한 개인 설치는 Company Agent **1.4.23**이며 업데이트하지 않았습니다. HTML 디자인 카드와 선택 대기의 Stop 보정, 정확한 하네스 도움말 조회 승인 개선은 해당 기능을 제공하는 코어가 필요합니다. 기존 설치에서는 텍스트 선택과 기존 후크가 계속 동작할 수 있습니다. 14개 요구사항의 0.12.0 기준은 저장소의 `docs/WORKSPACE_0.12.0_COMPATIBILITY.md`에 남깁니다. 기존 인증·지속 승인 저장의 경계는 [0.12.1 안내](WORKSPACE_0.12.1_COMPATIBILITY.md), 현재 실행 설정의 표시·복원은 위 0.12.7 안내를 따릅니다.

## 이전 버전 변경 기록

아래 0.10~0.11.4 항목은 당시 변경 기록입니다. 현재 동작은 위 0.12.7 안내와 이어서 제공하는 사용 절차를 기준으로 합니다.

### 0.11.4 화면 전반의 사용성 보완

앱 종료, 연결 변경, HTML 미리보기 등의 확인창을 앱 안의 같은 디자인으로 통일했습니다. 취소 또는 Esc를 누르면 기존 화면을 유지하며, 팝업 안에서 발생한 오류도 해당 팝업 앞에 표시합니다.

홈의 **전체 업무 보기**에서 모든 업무를 검색하고 열 수 있습니다. 창이 좁아 왼쪽 업무 목록이 숨겨져도 이전 업무에 접근할 수 있습니다. 자료 목록의 긴 파일명은 영역 안에서 줄바꿈하며, 자료·결과 탭은 선택한 탭 하나만 강조합니다.

시작 경고창에도 고해상도 배율과 시각 스타일을 적용했습니다. 기존 창을 다시 열 때는 첫 실행과 동일하게 시스템 및 사용자 설치 경로에서 Edge를 찾습니다.

### 0.11.3 선명한 파일·폴더 선택 창

**자료 추가**와 **폴더 찾아보기**는 Windows 공통 항목 선택 창을 사용합니다. 파일 선택에는 여러 파일 선택과 문서·이미지 필터를, 폴더 선택에는 주소창·검색·즐겨찾기를 갖춘 같은 방식의 탐색 창을 제공합니다. 앱에서 지정하는 제목·선택 버튼·파일 형식 안내를 한국어로 표시합니다. 탐색 영역의 언어와 밝고 어두운 테마는 Windows 설정을 따릅니다.

선택 창을 만들기 전에 모니터별 고해상도 배율 처리를 설정하여 확대된 비트맵으로 흐려지는 원인을 제거합니다. 지원되는 Windows에서는 Per-Monitor V2를 우선 사용합니다. Windows 전체 배율·해상도·호환성 설정은 바꾸지 않습니다. 선택 창의 앞뒤 순서, 취소, 원본 경로 반환과 여러 파일 선택은 기존 동작을 유지합니다.

### 0.11.2 스킬 분류·개수 수정

스킬 탭은 설치 정보와 현재 연결 정보를 호출 이름 기준으로 합쳐 표시합니다. 상단 스킬 개수는 검색어와 관계없이 확인된 일반 스킬 수를 표시하며, 설치에서 발견한 목록인지 현재 연결에서 보고한 목록인지 화면에 구분합니다. `user-invocable: false`인 내부 보조 스킬과 호출 이름이 없는 참조 자료는 별도로 접어 둡니다. `disable-model-invocation: true`인 직접 호출 전용 스킬은 일반 목록에 포함합니다. 같은 이름이어도 플러그인이 다르면 별도 항목입니다.

도구·연결 서버·명령은 첫 업무 요청 전에는 **연결 전**, 연결됐지만 CLI가 목록을 제공하지 않으면 **미확인**, 빈 목록을 실제로 보고했을 때만 **0**으로 표시합니다. 목록을 열거나 새로고침해도 AI 요청을 보내거나 Claude 설정을 변경하지 않습니다.

### 0.11.1 종료·재실행 수정

창의 **X**는 창만 닫고 업무 연결을 유지합니다. 앱을 완전히 종료하거나 새 버전을 적용하려면 **설정 → 앱 종료**를 누릅니다. 진행 중인 연결을 정리하는 동안은 **앱을 종료하고 있어요**를 표시하고 실제 정리가 끝난 뒤 완료를 안내합니다.

이전 버전이 남아 있으면 실행기가 해당 창을 다시 열어 **설정 → 앱 종료**로 돌아갈 수 있게 합니다. 진행 중인 업무를 임의로 종료하지 않습니다. 종료 처리가 진행 중이면 잠시 기다린 뒤 새 버전을 시작하며, 종료 여부가 불확실하면 새 서버를 겹쳐 시작하지 않습니다.

### 0.11 스킬·도구 탭

왼쪽 **스킬·도구**에서 선택한 업무에 연결된 Claude 기능을 확인합니다. **스킬 / 도구 / 연결 서버 / 명령**으로 나누고, 이름·설명·출처를 검색할 수 있습니다. 창이 좁을 때는 상단 메뉴의 스킬·도구 아이콘을 사용하세요.

- **현재 연결에서 확인:** 해당 Claude 연결이 실제로 전달한 스킬·기본 도구·MCP 도구·명령 목록입니다. 연결 서버의 연결 성공·실패 상태도 함께 표시합니다. 목록에 있다는 사실이 개별 실행 권한이나 성공을 보장하지는 않습니다.
- **설치에서 발견:** 신뢰한 작업 폴더에 등록된 Company Agent의 스킬 목록과 각 SKILL.md의 호출 속성을 읽어 확인한 설명·출처·범위입니다. 첫 AI 요청 전에도 확인할 수 있으며, 현재 Claude가 로드한 목록과 구분합니다. 설치 조회가 지원되지 않으면 확인 필요 안내를 표시합니다.
- **아직 연결 전 / 미제공 / 빈 목록 / 마지막 연결 정보**를 구분합니다. CLI가 항목을 보고하지 않은 상태를 0개로 표시하지 않으며, 연결 종료 후에는 마지막으로 확인한 목록임을 표시합니다.
- **새로고침**은 읽기 전용 조회입니다. 탭 열기나 조회만으로 AI·도구를 실행하지 않고 Claude 설정을 변경하지 않습니다. **업무로 돌아가기**를 누르면 작성 중인 초안과 대화로 돌아갑니다.

기존 앱을 **설정 → 앱 종료**로 종료한 뒤 새 실행기를 사용하세요. 0.10.1의 폴더 선택 창과 전용 아이콘 수정도 포함합니다.

### 0.10.1 폴더 선택·아이콘 수정

- **찾아보기**와 **자료 추가**의 Windows 선택 창이 실제 Workspace 창에 연결되도록 바꿨습니다. 보이지 않는 투명 부모 창을 제거하고, 선택 창을 한 번 앞으로 표시한 뒤 상시 최상위 상태를 해제합니다. 다른 앱으로 이동한 경우 반복해서 초점을 가져오지 않습니다.
- 폴더 선택 중에는 찾아보기 버튼에 **선택 창 열림…**을 표시하고 중복 클릭을 막습니다. 선택·취소·실패 후 창과 자원을 정리합니다.
- 전용 아이콘을 추가했습니다. ICO는 16/20/24/32/40/48/64/128/256px 각각 원본 도형에서 렌더링했고 SVG와 192/512px PNG를 함께 제공합니다. 앱 창은 해당 favicon을 읽습니다.
- 적용하려면 기존 앱을 **설정 → 앱 종료**로 종료한 뒤 새 소스 또는 새 ZIP의 실행기를 사용하세요. 작업표시줄에 예전 아이콘을 고정했다면 Windows의 고정 아이콘은 남을 수 있으므로 새 실행 창에서 다시 고정할 수 있습니다. 사용자 핀이나 브라우저 프로필을 자동 변경하지 않습니다.

소유 창 전달·취소·오류 자원 정리와 아이콘 응답/해상도는 자동 검증했습니다. 이 검증 환경에서는 실제 Windows 선택 창의 앞뒤 순서와 작업표시줄 아이콘을 직접 조작·촬영할 수 없어, 직원 PC의 실제 표시까지 확인했다고 주장하지 않습니다.

## 누구를 위한 화면인가요?

터미널에서 명령을 입력하는 것이 낯선 사용자를 위한 Company Agent의 별도 로컬 화면입니다. **기존 Claude Code CLI가 실제 작업을 수행**합니다. Claude Desktop을 설치하거나 회사 모델 연결을 교체하지 않습니다.

**앱 전용 로그인·API 키는 필요하지 않습니다.** 같은 Windows 사용자, 같은 실행 환경과 작업 폴더에서 `claude`를 실행했을 때 사용하는 로그인·모델·설정·스킬을 그대로 사용하고, 입력과 출력만 업무 화면으로 표시합니다. 기존 Claude가 로그인돼 있다면 앱을 위해 다시 로그인할 필요가 없습니다.

앱 화면과 로컬 서버 사이에는 매 실행 생성하는 내부 연결 토큰이 있습니다. 이것은 로컬 HTTP 접근을 보호하는 값이며 Claude 로그인 토큰이나 사용자가 입력할 API 키가 아닙니다. 앱이 열렸다는 사실과 실제 AI 인증·모델 응답 성공은 별도로 확인합니다.

이 버전은 로컬 시험용 소스 버전이며, 기존 공개 Release에 자동 반영되지 않습니다. 사내 HCP 서버·보안 프로그램·실제 DRM 문서에서의 최종 검증과 정식 배포 승인은 별도로 필요합니다. 모든 CLI 화면을 재구현했다는 의미가 아닙니다.

## 새 업무 화면 사용 순서

1. `Company-Workspace.vbs`를 더블클릭합니다. 기존 앱이 실행 중이면 먼저 종료하고 새 폴더에서 실행합니다.
2. **새 업무**에서 **새 업무 공간 만들기** 또는 **기존 폴더 사용하기**를 선택합니다. 새 공간은 실제 바탕화면의 `Company Workspace` 아래에 생성되며 화면에서 저장 위치를 바꿀 수 있습니다. OneDrive나 회사 정책으로 바탕화면이 이동된 경우에도 Windows의 실제 위치를 사용합니다. 기존 폴더는 **찾아보기**로 고릅니다. 바탕화면을 확인할 수 없으면 위치를 직접 선택합니다. 해당 폴더의 지침·도구 실행 범위를 읽고 확인합니다.
3. **자료 추가**로 파일을 고르고 자연어 요청을 입력한 뒤 **보내기**를 누릅니다. 단축키는 `Ctrl+Enter`입니다. 파일 선택은 경로 참조이며 클라우드로 미리 업로드하지 않습니다. 요청 시 실제 자료 처리는 기존 Claude 연결을 따릅니다.
4. 질문은 선택지로 답하고, 승인 카드에서 대상·변경 전후·실행 원문을 확인합니다. 기본은 **이번만 허용**입니다. CLI가 제안한 경우에만 표시된 규칙을 **이 연결에서 허용**하거나 저장 범위를 확인해 **항상 허용**할 수 있습니다. 폴더의 개인 설정·프로젝트 공유 설정·사용자 공통 설정은 적용 범위가 다릅니다. 다른 업무에서 대기가 생기면 전체 대기 배지에서 이동합니다.
5. **이번 결과**에서 요청 시작 전후 확인된 파일을 미리 보거나 **이 결과로 요청**해 수정합니다. 생성 주체를 확정한 기록이 아닌 로컬 파일 변경 관찰입니다. 문서 확장자·깊이·개수·시간 제한이 있어 모든 파일을 보여 주지는 않습니다.
6. **최근 업무**에서 검색·이어하기하고 제목 변경·고정을 사용할 수 있습니다. 화면 간 이동 중 초안은 메모리에 유지되며 앱 재시작 후에는 복구되지 않습니다.

**스킬·도구**에서는 공통 또는 직접 선택한 폴더의 기능을 검색합니다. 조회 범위는 업무 전환으로 자동 변경되지 않으며 목록 조회만으로 폴더 실행을 신뢰하지 않습니다. 등록된 Company Agent를 확인하지 못해도 확인 가능한 사용자·폴더·활성 플러그인 스킬 메타데이터는 표시하고 설치 진단 이유를 구분합니다. 호출 스크립트가 내부에서 `CLAUDE_CONFIG_DIR`을 바꿀 수 있으므로 서버 환경의 설치 목록을 실제 CLI 목록과 같다고 단정하지 않습니다.

입력창 아래 **모델 / Effort / 승인**에서 연결이 제공한 항목을 선택합니다. 모델은 이름 직접 입력도 지원합니다. 요청·질문·승인이 진행 중일 때는 변경하지 않으며 CLI의 적용 응답을 확인합니다. 개인 기본 설정은 수정하지 않고 같은 앱·업무의 재연결 선택만 메모리로 유지합니다. **기존 설정 사용**과 Effort의 **auto**는 확인한 변경 전 값을 복원하며, 복원값을 확인하지 못하면 안내합니다. **연결 다시 확인**은 실패한 업무 요청을 자동 재전송하지 않습니다.

화면이 좁으면 자료·결과는 **자료** 버튼으로 여는 패널에 표시합니다. 뉴모피즘의 부드러운 입체감에 테두리·텍스트 상태·키보드 초점을 함께 사용했습니다. 상세 설계와 검증 기록은 저장소의 `docs/WORKSPACE_REDESIGN_2026-09-28.md`에 있습니다.

## 처음 쓰는 사람을 위한 도우미

왼쪽의 **사용 도움말 → 첫 업무 따라 하기** 또는 **설정 → 나의 기억과 업무 방식 / 사용 현황과 결과 확인**으로 엽니다. 화면 열기·조회·통계에 별도 AI를 호출하지 않습니다.

1. **따라 하기:** 자료 읽기 → 결과 만들기 → 수정 → 선호 저장 → 새 대화 재사용의 5단계입니다. 예문 버튼은 입력창만 채우며 직접 보내야 실행됩니다. ‘직접 확인했어요’는 학습 진행 기록이지 업무 성공의 자동 판정이 아닙니다. 예문과 진행 확인은 기존 코스 JSON을 사용하며, 자세한 설명은 하나의 사용자 안내서에서 읽습니다.
2. **회사 공통 → 기억·지식:** 설치에 연결된 회사·팀의 배포 지식을 읽습니다. 사용자 화면에서는 수정하지 않습니다. 공동 쓰기·실시간 동기화 서버나 일반 프로젝트 문서 자동 수집 기능은 아닙니다.
3. **개인 전체 / 이 프로젝트 → 기억·지식:** 나의 선호·업무 맥락과 개인 업무 지식을 함께 관리합니다. 선호는 추가·수정·비활성화·이전 내용 복원안을 확인한 뒤 저장합니다. 지식은 출처·확인일을 붙여 초안으로 만들고 검토 후 활성화합니다. 검토용 내보내기는 로컬 ZIP이며 공통 반영·자동 전송이 아닙니다. 자동 학습 끄기·이력 복구를 지원하며 Claude 자체 기억과 합치지 않습니다.
4. **회사 공통 → 업무 구성:** 회사 기준·공통 스킬·후크 정의를 읽기 전용으로 확인합니다. 목록이나 정의 파일이 있다는 사실만으로 실제 CLI 실행을 보장하지 않습니다.
5. **개인 전체 / 이 프로젝트 → 업무 구성:** 개인·사용자·프로젝트·외부 플러그인 스킬은 출처별로, 내가 만든 도구는 등록 기록으로 확인합니다. 외부 설정·자격증명은 읽어 표시하거나 변경하지 않습니다. 폴더 지침 편집기는 목표·입력·결과·확인 기준만 `.claude/rules/company-workspace-brief.md`에 저장합니다. 기존 `CLAUDE.md`와 직접 수정한 지침은 보존하고 수정 전 버전은 개인 상태의 `workspace/brief-versions`에 남깁니다.
6. **사용 현황:** 현재 요청의 CLI 보고값과 사용자가 선택한 과거 JSONL 분석을 별도로 보여 줍니다. 누락은 ‘미제공’, 사내 모델 비용은 미추정입니다. 같은 메시지의 스트림 기록은 중복 제거하며 CLI 완료값·작업자·로그 합계를 서로 더하지 않습니다. CLI 버전에 따라 완료값이 누적일 수 있어 요청끼리 합산하지 않습니다. 다음 요청의 토큰 알림은 앱을 닫으면 해제되며 강제 비용 한도가 아닙니다.
7. **준비·결과 확인:** 설치·스킬 발견·지침 분량과 실제 업무 결과를 분리합니다. 사용자 확인 기록에서 실패·중지·차단·미확인을 빼고 성공률을 만들지 않습니다. 모델/평가 시 설치 버전별 관찰 그룹을 표시하되 전체 AI 성능 점수나 인과적 개선 증거라고 주장하지 않습니다. 실제 실행 당시 버전을 입증하지 못하면 평가 시 버전과 구별합니다.

이 소스의 Workspace 실행 코드 버전은 **0.12.10**이며 Company Agent 코어 버전과 별도로 관리합니다. 업무 중심 화면과 기존 기록을 유지하면서 실제 연결의 모델·Effort·승인 모드를 표시하고 설정 변경과 업무 전송을 구분합니다. 본인 계정·세션·프로필 검증과 일반 권한 재실행을 유지하며, UAC가 꺼진 환경에서는 검증된 제한 토큰 복사본을 사용하는 경로가 있습니다. 실제 문서 읽기는 설치된 스킬·도구의 지원 범위를 따릅니다.

Company Agent 코어의 [1.4.28 변경 안내](https://github.com/bongG-moon/claude_base_repo/blob/main/docs/UPDATE_1.4.28.md)와 [당시 배포 검증 범위](https://github.com/bongG-moon/claude_base_repo/blob/main/docs/VALIDATION_RELEASE_1.4.28.md)는 과거 배포 자료이며, 현재 개인 설치가 그 버전이라는 의미가 아닙니다. 이번 Workspace 0.12.7 안내와 구분해서 보세요. 검증 기록의 외부 링크는 인터넷 연결이 필요합니다.

Company Agent와 Workspace는 별도 배포 묶음이며 기존 설치·ZIP에 자동 적용되지 않습니다. 기존 앱을 종료한 뒤 승인된 새 Workspace ZIP을 별도 폴더에 풀어 실행하세요. Company Agent만 업데이트해도 이미 풀어 놓은 Workspace와 그 안의 안내서가 갱신되는 것은 아닙니다. 해당 기능이 없는 설치에서는 안내·일반 Claude 대화를 그대로 유지하고 설치 확인 필요만 표시합니다. UI가 임의로 다른 설치/상태 폴더를 선택하거나 플러그인을 설치하지 않습니다. 기존 memory/knowledge/brief API는 호환을 위해 유지합니다.

관리 화면은 기존 사용자 설치 등록과 Claude 설정 루트, 현재 작업 폴더에 맞는 프로젝트 등록을 확인합니다. 사용자 설치와 프로젝트 설치의 기억은 별개입니다. 터미널 호출 스크립트가 내부에서 환경변수를 다시 바꾸는 경우 시작 환경만으로 두 위치의 동일성을 보장하지 않으므로 등록을 확인해야 합니다. 모든 폴더에 스킬 파일을 복사할 필요는 없습니다.

**공통/내 것은 관리 주체, 기억/하네스는 내용의 역할, 프로젝트는 적용 범위**입니다. User 설치를 공통 소유로, 프로젝트 파일을 개인 소유로 추정하지 않습니다. 이번 화면 분리를 위해 기존 파일을 이동·복제·자동 공유하지 않습니다.

### 관리 화면의 자료는 어디에 있나요?

| 자료 | 기본 저장 위치와 범위 |
| --- | --- |
| 회사 공통 지식·스킬·후크 | 선택한 Company Agent의 버전 배포 폴더. 화면에서 읽기 전용으로 조회 |
| 개인 전체 | User 설치 등록의 상태 폴더. 기본값은 `%LOCALAPPDATA%/CompanyAgent/states/user` |
| 이 프로젝트 | User 설치는 위 상태의 `project-scopes/<폴더 해시>`, 별도 Project 설치는 해당 등록의 상태 폴더 |
| Workspace 자체 기록 | 기본 `%LOCALAPPDATA%/CompanyAgent/local-ui`. Company Agent 개인 기억 저장소나 Claude의 전체 기록과 별개 |

사용자 지정 상태 경로가 있으면 기본값 대신 설치 등록을 따릅니다. 같은 Claude 설정의 User 등록이 없는 Project 전용 환경에서는 개인 전체 저장을 사용할 수 없습니다. User의 프로젝트 저장은 정확한 작업 폴더별이며, 하위 폴더에서 자동 상속되거나 별도 Project 설치로 자동 이관되지 않습니다. 프로젝트 폴더를 동료와 공유해도 개인 상태 폴더가 함께 공유되는 것은 아닙니다.

명시적으로 저장하는 기억·지식·스킬·도구의 범위와 **자동 학습의 범위는 별개**입니다. 자동 학습은 현재 활성 설치의 상태에서 계속되며, 화면에서 프로젝트 항목을 한 번 저장했다고 이후 모든 학습이 그 범위로 바뀌지 않습니다. User 설치의 별도 프로젝트 자산은 자동 수정하지 않습니다. Company Agent 설치 전 선택 백업은 이 모든 폴더의 완전한 이사·복구 패키지가 아니므로 PC 교체 때는 담당자와 각 저장소를 따로 확인합니다.

공통 스킬은 작업 방법, 후크는 실행 시점의 안내·검사·기록을 담당합니다. 목록 표시·정의 조회·선택은 실제 도구 권한·회사 승인·실행 성공을 대신하지 않습니다. 세부 사용법은 화면에서도 연결되는 [사용자 안내서](Company-Agent-사용자-안내서.html)를 참고하세요.

저장은 **미리보기 → 명시 확인 → 현재 내용 해시 재확인**으로 진행합니다. 실행 중인 업무가 있으면 개인 기억/지침 변경을 잠시 보류합니다. 응답 시간 초과 때 저장 여부는 미확인으로 안내하며 원래 업무를 자동 재실행하지 않습니다. 외부 편집기의 동시 저장까지 전역 잠금하는 기능은 아닙니다.

관리 정보는 선택한 탭에서만 조회합니다. 따라 하기·현재 사용 현황은 하네스 조회 프로세스를 띄우지 않습니다. 공통·개인 지식은 저장소를 먼저 분리한 뒤 각 20개 단위로 조회합니다. 내 기억은 선호와 지식 각각 첫 페이지를 가져오며 ‘내용·출처 보기’ 또는 수정에서 선택한 본문을 표시합니다. 하네스 출처 목록은 해당 탭을 열 때만 확인합니다. 목록이 바뀌면 새로고침 안내를 하며, 확인 범위 한도에 도달하면 전체 목록이 아님을 표시합니다.

## 시작하기

1. Windows에서 사용합니다. EXE·VBS·소스 방식 모두 회사가 승인하여 이미 설치한 Python 3.11 이상이 필요합니다. Python이나 Claude 설치 프로그램은 제공하지 않으며 자동 설치하지 않습니다. 실제 AI 업무에는 기존 Claude Code와 그 인증이 필요하며 Company Agent 기능은 기존 코어 설치 범위를 따릅니다.
2. **`Company-Workspace-0.12.10.exe`를 더블클릭**합니다. VBS 방식은 ZIP 전체를 푼 Workspace 폴더의 `Company-Workspace.vbs`를 더블클릭합니다. 별도로 ‘관리자 권한으로 실행’을 선택할 필요는 없습니다. ZIP 미리보기 안에서 실행하지 마세요.
3. Edge가 있으면 독립 앱 모양의 창, 없으면 기본 브라우저가 열립니다. CLI 탐색에 실패해도 앱 화면을 열어 연결 확인이 필요하다고 안내하며 다른 CLI를 대신 실행하지 않습니다.
4. ‘작업 폴더’를 선택하고 해당 폴더의 설정 실행에 동의합니다.
5. 파일 선택 → 요청 입력 → 필요한 질문/승인 응답 → 결과 확인 순서로 진행합니다.
6. **설정 → 앱 종료**로 연결된 작업과 로컬 서버를 종료합니다. 창의 X만 닫으면 서버는 남아 있으므로 다시 실행해 열린 작업을 확인할 수 있습니다.

새 ZIP으로 교체할 때도 먼저 기존 앱의 **설정 → 앱 종료**를 눌러 종료하세요. 다른 버전/폴더의 앱이 살아 있으면 구버전을 조용히 재사용하거나 진행 중 업무를 강제 종료하지 않고 안내합니다.

### 관리자 권한으로 감지되거나 시작할 수 없을 때

`WS-33`이나 일반 시작 실패로 중단되면 실행한 0.12.10 묶음의 `Check-Workspace.cmd`로 읽기 전용 진단을 실행하세요. VBS는 `Company-Workspace.vbs` 옆에 있고, EXE는 [단일 EXE 사용 안내](WORKSPACE_STANDALONE_EXE.md)의 실행 캐시에서 찾을 수 있습니다. [결과 읽는 법](WORKSPACE_STARTUP_DIAGNOSTIC.md)을 참고하세요. `ws33-13` 진단은 실행 정책 5개 범위, 다운로드 표시(Mark-of-the-Web)의 유무, 스크립트 구문 확인 상태를 함께 구분합니다. 다운로드 표시 원문·인증 정보·환경변수 값을 보고서에 넣거나 보안 설정을 변경하지 않습니다.

시작·진단·재실행·직접 Python의 권한 확인·파일 선택·CLI 호출용 PowerShell은 `-ExecutionPolicy Bypass`를 이번 실행의 PowerShell 프로세스와 그 자식 프로세스 계열에만 적용합니다. `CurrentUser`·`LocalMachine` 정책을 저장하지 않고 `MachinePolicy`·`UserPolicy`의 조직 정책을 우선합니다. 이 옵션은 UAC 권한을 높이지 않으며 기존 사용자·토큰 검사를 대체하지 않습니다. 다른 PC의 `exit 1` 해결 사례는 참고 후보일 뿐이며, 같은 오류 코드의 원인이 항상 실행 정책인 것은 아닙니다.

평소처럼 더블클릭해도 PC의 실행 환경에 따라 관리자 권한으로 시작될 수 있습니다. 실행기는 Windows 사용자 식별자(SID), 로그인 세션, 프로필 경로가 현재 로그인한 본인과 일치하는지 먼저 확인합니다. 다른 계정, SYSTEM, 서비스 세션, 확인할 수 없는 사용자·프로필에서는 시작을 중단합니다. Claude 실행 파일이 발견됐다는 사실만으로 본인의 설정이라고 판단하지 않습니다.

본인 계정으로 관리자 권한이 감지된 경우에는 Windows가 제공하는 **같은 사용자의 일반 권한 UAC 연결 토큰**을 우선 사용합니다. UAC 비활성화와 같은 사용자·세션·프로필이 확인된 허용 원본 토큰에서는 관리자 권한을 제한한 복사본을 만들고 Medium 무결성으로 검증하는 대체 경로가 있습니다. 원본 토큰이나 PC 설정은 변경하지 않습니다. 관리자 SID·남은 권한·무결성과 실제 자식 프로세스를 확인한 뒤 한 번만 재실행하며, 검증에 실패하면 `WS-33` 등 확인된 이유로 중단합니다.

UAC·Windows의 영구 보안 정책·Claude 인증·모델·MCP·개인 설정은 자동 변경하지 않습니다. 사용자가 승인 카드에서 지속 허용을 직접 선택한 경우에만 해당 규칙과 저장 범위를 CLI에 전달합니다. 관리자 원본 권한을 그대로 허용하는 예외는 추가하지 않았습니다. 회사 정책이 토큰 생성이나 자식 실행을 막으면 재실행을 반복하지 않고 진단 결과를 안내합니다. **문제가 발생한 회사 PC에서 VBS → 실제 Claude 업무까지의 성공은 아직 검증하지 못했습니다.** 현재 PC의 제한 토큰·자식 프로세스 시험은 그 대상 환경의 성공을 대신하지 않으며 제한 토큰은 완전한 샌드박스를 뜻하지 않습니다.

시작 실패 안내는 최초 실행기가 한 번 표시합니다. 이미 안내한 종료 코드 `20`은 VBS에서 다시 표시하지 않습니다. Python 버전·경로 검사가 실제로 실패한 경우에만 Python 안내를 표시하며, 다른 시작 실패를 Python 문제로 단정하지 않습니다. `-NoBrowser`로 실행할 때는 같은 이유를 콘솔 오류로 확인할 수 있습니다.

### 작업 중지와 종료 확인

작업 중지는 앱이 시작한 CLI 연결을 대상으로 합니다. 이미 만든 파일·완료된 외부 작업을 되돌리는 기능은 아닙니다. 종료를 확인하지 못하면 성공한 중지로 표시하지 않고 연결 상태 확인이 필요하다고 알립니다.

종료 시 입력 연결을 닫고 최대 0.3초 정상 종료를 기다립니다. 계속 실행 중이면 Windows에서 기존 소유 PID의 트리 종료를 시도하고, 실패하면 앱이 보유한 프로세스 핸들만 종료한 뒤 실제 종료를 기다립니다. 이름으로 프로세스를 검색하거나 다른 Claude·Office 프로그램을 찾아 종료하지 않습니다.

트리 종료가 실패한 경우에는 직접 시작한 CLI 프로세스의 종료만 확인할 수 있습니다. 모든 하위 프로그램까지 닫혔다고 보장하지 않으므로, 문서 프로그램이나 외부 작업이 남았다면 실제 상태를 확인하세요. 종료 실패 후 같은 쓰기 작업을 무조건 다시 보내지 않습니다.

### 원본 경로와 실행 환경

원본 파일을 복사하지 않고 정확한 경로를 전달합니다. 브라우저의 일반 파일 업로드처럼 원본을 임시 복사하지 않습니다. 경로 직접 입력도 지원하며, 웹 드래그 앤 드롭은 아직 지원하지 않습니다.

프로세스 한정 실행 정책 옵션만으로 조직의 그룹 정책·AppLocker·WDAC·WSH 차단이나 Python 부재를 해결할 수는 없습니다. 이런 경우 확인한 원인을 안내하며 보안 정책을 해제하거나 다른 계정으로 실행하지 않습니다. CLI 로그인이나 인증서·회사 게이트웨이 설정이 필요하면 기존 조직 안내를 따릅니다. 앱은 비밀번호/API 키를 새로 수집하지 않습니다.

개발자 실행(본인의 일반 권한 터미널에서 실행):

```powershell
python -X utf8 -m local_app.server
# 가상 화면 체험: 실제 AI/문서 작업 없음, 별도의 demo 기록 사용
python -X utf8 -m local_app.server --demo
```

직접 Python으로 시작해도 본인 계정과 일반 권한 검사를 수행합니다. 관리자 터미널에서 이 검사를 통과하지 못하면 VBS 실행기를 사용해 검증된 재실행 경로를 거칩니다. 직접 Python 실행이 높은 권한을 허용하는 우회 경로는 아닙니다.

더블클릭 실행기는 현재 사용자의 Windows PowerShell 시작 프로필을 적용한 뒤 `Get-Command claude`로 실제 호출 대상을 선택합니다. 별칭, 프로필 함수, `.cmd`/`.ps1` 실행 스크립트도 존중하며, 스크립트를 건너뛰고 별도의 npm 실행 파일을 선택하지 않습니다. 같은 사용자의 일반 권한으로 다시 실행할 때도 CLI 환경과 프로필 연결을 유지하고, 환경 전달은 메모리에서만 처리합니다. 다른 사용자 프로필이나 별도 Claude 인증 저장소는 만들거나 검색하지 않습니다. `CLAUDE_CONFIG_DIR`, 모델·회사 연결·인증 환경변수는 그대로 상속하고, 환경값이나 인증 파일을 앱의 상태 파일로 복사하지 않습니다. 기존 `COMPANY_AGENT_CLAUDE` 명시 지정은 호환용으로 유지하지만 일반 사용자가 새로 설정할 항목은 아닙니다.

호출 대상을 확인하지 못하면 앱 화면에서 연결 문제를 안내하고 AI 요청을 보류합니다. 자동으로 다른 실행 파일·계정·인증 저장소를 골라 업무를 시작하지 않습니다. 앱의 로컬 화면을 여는 것과 Claude를 실제 사용할 수 있는지는 구분합니다.

Windows PowerShell과 다른 실행 환경(WSL/Linux, Git Bash 전용 프로필, VS Code 전용 환경, 특정 터미널에서만 임시로 만든 변수·함수)은 자동으로 동일하다고 가정할 수 없습니다. 해당 환경만 정상이라면 재로그인부터 요구하지 말고 CLI 경로·설정 위치·실행 환경 차이를 확인해야 합니다. 화면의 ‘연결 상태와 작업 기록’에서 실행 경로와 상속한 설정 위치를 확인할 수 있습니다. 기존 호출 스크립트가 그 안에서 설정 위치를 변경할 수도 있으므로 이 값은 시작 환경 기준입니다.

OAuth 만료 등 실제 인증 오류가 발생하면 앱이 소유한 실패 연결만 종료합니다. 터미널에서 기존 인증을 갱신한 후 사용자가 다시 보내면 새 CLI 프로세스가 같은 로그인 저장소를 다시 읽습니다. 앱 재설정, 별도 로그인, 요청 자동 재전송, 반복 인증 확인용 모델 호출은 하지 않습니다. ‘기존 Claude 사용’ 표시는 실행 파일 확인이며 모델 응답/인증 성공의 증거가 아닙니다.

## 보안 및 기록

### 현재 폴더의 구성 한눈에 보기

작업 폴더 선택 후 **기억·하네스 관리 → 구성 한눈에**를 누르면 **회사 공통 / 개인 전체 / 이 프로젝트**를 나란히 표시합니다. 각 영역의 스킬·지침·후크·도구(MCP)·에이전트·기억·학습 저장소를 펼쳐 이름, 저장 위치, 공유 여부를 확인합니다. 목록은 이 버튼 또는 새로고침을 누를 때만 읽으며 모델 호출과 설정 변경은 없습니다.

- **설정 켜짐**: 로컬 활성 설정이 확인됨. CLI가 실제로 로드했다는 뜻은 아닙니다.
- **사용 가능**: 스킬 후보 또는 사용 상태의 기억. 현재 요청에서 실제로 사용했다는 뜻은 아닙니다.
- **정의 발견**: 파일이나 MCP/후크 등록 정보만 확인됨. 연결·인증·실행은 미시험입니다.
- **꺼짐 / 제외**, **초안 / 미적용**, **선택 필요**, **확인 필요**: 확인된 설정과 불확실성을 별도로 표시합니다.
- **본문 로드 기록**: 현재 대화 ID·현재 폴더·스킬 식별자·본문 해시가 모두 맞는 기존 기록만 표시합니다. 별도 작업자가 읽은 본문을 부모 대화가 읽은 것으로 합치지 않습니다. 적용 성공이나 결과 정확성을 뜻하지 않습니다. [스킬 본문 확인 범위](SKILL_PRIORITY.md#본문-로드와-실제-적용의-구분)를 참고하세요.

**구성 지도 HTML 저장**으로 조회 시점의 화면을 보관할 수 있습니다. 파일에는 로컬 경로와 항목 이름이 포함되므로 공유 전에 검토하세요. 대화 원문·기억 본문·MCP 명령·토큰·환경변수는 내보내지 않습니다. 저장한 HTML은 자동 갱신되지 않습니다.

구성 지도는 1.4.16부터 지원합니다. 현재 배포 조합을 함께 적용하면 앱에서 사용할 수 있습니다. 구버전 코어는 업데이트 안내만 표시하며 설정을 고치거나 대신 설치하지 않습니다. CLI에서는 등록된 진입점 뒤에 `context map --project "현재 폴더의 절대경로" --output "새 지도.html의 절대경로"`를 붙여 만들 수 있습니다. 출력 폴더는 이미 존재해야 하며 같은 파일을 덮어쓰지 않습니다. Company Agent 등록이 없으면 일반 Claude 파일 정의만 표시하고 회사 기능을 활성으로 꾸미지 않습니다.

서버/OS 관리 정책, 세션 실행 옵션, 다른 프로필, 원격·동적 도구와 전체 내장 스킬, CLAUDE.md의 참조 확장, 다른 프로젝트의 자동 기억은 조회 범위 밖입니다. 최종 적용은 해당 CLI의 `/status`, `/skills`, `/hooks`, `/mcp`, `/memory`와 실제 업무로 확인합니다. [공식 설정 범위](https://code.claude.com/docs/en/settings)와 [MCP의 개인·프로젝트 범위](https://code.claude.com/docs/en/mcp)를 기준으로 파일 발견과 실제 연결을 구분했습니다.

### 대화와 자료 보호

- `127.0.0.1` 임의 포트에만 바인딩하며 외부 공개/릴레이 기능이 없습니다.
- 매 실행 시 생성한 토큰으로 모든 API를 인증합니다. 브라우저 접속 후 주소의 토큰은 지우고 탭 저장소에만 보관합니다.
- Host/Origin/cross-site 확인, CSP 적용. 모델 출력은 HTML로 실행하지 않습니다.
- 파일 열기는 선택한 작업 폴더 또는 사용자가 첨부한 정확한 경로의 문서 확장자만 허용합니다. GUI 파일 접근 범위는 CLI 자체의 권한/샌드박스를 대체하지 않습니다.
- 실행 파일/스크립트·HTML의 자동 실행은 지원하지 않습니다. 재분석만 위해 원본을 덮어쓰거나 인코딩을 손실 변환하지 않습니다.
- HTML의 **기본 앱에서 열기**는 명시적인 원본 열기 요청입니다. 기존 Windows 연결 프로그램에 따라 원본 스크립트·외부 연결이 동작할 수 있습니다. 정적 미리보기에서는 계속 차단하며, 앱 연결 설정을 자동 변경하지 않습니다.
- 알림 집계에는 업무 제목·대기 종류·식별자만 사용합니다. 실행 명령·자료 본문은 브라우저 알림에 넣지 않습니다. 작업표시줄 강조는 인증된 화면과 연결한 정확한 Edge 창에서만 시도하며 다른 앱의 포커스를 가져오지 않습니다. 다른 브라우저나 인앱 브라우저는 배지와 선택한 브라우저 알림을 사용합니다.
- `%LOCALAPPDATA%\CompanyAgent\local-ui\history-sessions\<대화 ID>.json`에 대화별로 저장하고 `history-index.json`에는 최근 최대 500개 대화 목록만 둡니다. 갱신된 대화만 저장하며 각 대화는 최대 150개 메시지·본문과 파일 경로 합계 50만 자로 제한합니다. 기존 `history.json`은 다음 정상 저장 때 이전하되 원본은 삭제하지 않습니다. 목록에서 오래되어 빠진 대화 파일도 자동 삭제하지 않습니다. 손상된 기록은 덮어쓰지 않고 새 앱 기록 저장 중지 안내를 표시합니다. CLI 자체 기록은 별개이며, 업무 원문의 이중 보존은 조직 보존 정책에서 검토해야 합니다.
- 승인 요청 원문과 표준 오류, 인증 정보, 전체 도구 결과를 별도의 앱 로그에 저장하지 않습니다. 모델의 일반 답변에 포함된 정보는 대화 기록에 남습니다.
- 새 사용량 스냅샷과 선택 로그 분석은 메모리에만 두며, 기존 대화 보존 정책을 바꾸지 않습니다. 사용자가 직접 확인한 코스 단계/결과만 `local-ui/learning-progress/<폴더 해시>.json`에 최대 100건 보관합니다. 원문·파일 경로·토큰 로그는 이 기록에 저장하지 않습니다. 모델 이름과 평가 시 설치 범위의 해시/버전은 로컬 비교용으로 남습니다.
- ‘확인 기록만 비우기’는 해당 폴더의 학습 진행과 자기 평가만 초기화합니다. 대화 이력·기억·지식·산출물은 보존됩니다. 먼저 원문 없는 확인 기록을 내려받을 수 있습니다. 내려받은 기록은 외부로 자동 전송되지 않습니다.
- 로컬 UI라는 것은 **모델 추론도 오프라인이라는 뜻이 아닙니다.** 기존 Claude/HCP 연결로 요청이 전달됩니다.
- 앱 상태 저장은 현재 사용자의 LOCALAPPDATA 권한을 상속합니다. 공유 계정/공유 프로필 배포는 지원 대상이 아닙니다.

## 검증

왼쪽의 **사용자 안내서**와 따라 하기 화면은 `Company-Agent-사용자-안내서.html` 한 파일로 연결됩니다. 시작하기·업무별 사용법·기억/스킬/후크·CLI 명령어 안내를 로그인·AI 호출 없이 읽습니다. 첫 예문은 참고 파일 없이 가상 MD를 만들고 다음 요청에서 읽습니다. 안내서 Markdown 원본들을 수정하면 `scripts/build-manuals.mjs`로 이 파일을 생성합니다. 별도의 Guide·Handbook·Onboarding·첫 업무 HTML은 배포하지 않습니다. Workspace의 `/manual/guide`는 이 파일을 제공하고, 기존 안내 URL은 명시된 호환 경로만 같은 안내서의 해당 구역으로 연결합니다. 이번 소스 변경은 기존 설치본이나 게시 ZIP을 자동으로 갱신하지 않습니다.

이번 도우미의 실제 구현 범위, 측정값, 남은 사내 확인은 [Workspace 0.3 구현·검증 기록](https://github.com/bongG-moon/claude_base_repo/blob/main/docs/VALIDATION_BEGINNER_WORKSPACE_2026-09-19.md)을 참고하세요. 검증 기록은 UI 미리보기 ZIP에 포함하지 않으며 저장소 링크로 별도 열람합니다.

이후 외부 감사에서 지적된 대기·양식 확인·미리보기·조회 및 저장 비용 보완은 [감사 후 수정·검증 기록](https://github.com/bongG-moon/claude_base_repo/blob/main/docs/VALIDATION_AUDIT_FIXES_2026-09-19.md)에 정리했습니다.

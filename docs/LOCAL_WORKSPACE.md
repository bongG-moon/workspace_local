# Company Workspace — Claude Code 업무 화면 0.23.20

0.23.20에서는 **설정 → 앱과 Claude 실행 권한**에서 일반·관리자를 선택하고 앱을 다시 시작할 수 있습니다. 기본값은 일반이며, 성공한 선택은 앱 자체 설정에만 저장됩니다. 관리자 모드에서 Claude와 도구도 관리자 권한을 사용합니다. 수정본은 권한 확인·작업 대기·작성 내용 보관·재시작 단계를 구분하며, 설정을 다시 열어도 보관 단계에서 닫고 전환을 이어갑니다. 같은 버전의 수정 ZIP을 새로 받아 실행해야 하며 자동 업데이트 알림은 뜨지 않습니다. [실행 권한 선택 안내](WORKSPACE_EXECUTION_MODE.md)를 참고하세요.

입력창 위의 진행 표시가 회전 스피너로 바뀝니다. 준비·실행·중지 처리 중에는 회전하며 승인·답변 대기와 완료 시에는 멈춥니다. 움직임 줄이기 설정을 따릅니다. 실제 UAC 승인 후 관리자 실행과 일반 권한 복귀의 왕복은 아직 미검증이며 [검증 기록](VALIDATION_0.23.20.md)에서 확인 범위를 확인하세요.

0.23.19은 시간 설정 방식을 확장하고 예약 입력 디자인을 통일한 버전입니다. 실행 예약에서 **한 번·평일(월~금)·매일·매주·매월·간격 반복**을 선택합니다. 매주는 요일을 여러 개 고를 수 있고, 매월은 1~31일 중 선택하며 해당 날짜가 없는 달은 건너뜁니다. 간격 반복은 합계 1분~24시간의 시간·분과 매일의 시작·종료 시각을 지정합니다. 시작 시각을 기준으로 종료 시각 전까지 예약하며 자정을 넘는 구간은 지원하지 않습니다. 예를 들어 8시간 간격, 07:00~23:59는 07:00·15:00·23:00에 예약됩니다. 화면에 입력한 시간 방식과 예약 시각을 요약해서 표시합니다.

기존 예약의 대기·승인·일시 정지·수정·삭제·중복 방지 기능은 유지합니다. 앱이 켜져 있고 PC가 깨어 있을 때 기존 업무 연결로 요청을 전달하며, 앱을 다시 연 뒤에는 내용을 확인하고 이어 실행합니다. 시간을 지정하는 것은 실제 업무 종료 시각을 보장하지 않으며, 실행 중인 요청이 있으면 기존 대기 규칙을 따릅니다. 시간·날짜·간격 입력은 예약 방식 선택칸과 같은 높이·글꼴·여백·테두리를 사용합니다.

0.23.18은 작업 중 트레이의 **완전 종료**를 누르면 **“작업 중인 내용이 있습니다. 그래도 종료하시겠습니까?”**를 표시합니다. **취소**하면 작업을 유지하며, **종료**를 선택하면 이 앱에서 실행한 모든 작업과 승인·답변 대기를 중지하고 앱을 종료합니다. 숨겨진 창도 종료 확인을 위해 다시 표시됩니다. Claude 실행 프로세스가 정상 종료되는 시점과 종료 확인이 겹쳐 실패로 남는 문제도 보완합니다. 앱에서 시작한 CLI와 그 하위 프로세스의 종료를 확인하며, 확인되지 않은 상태를 완료로 표시하지 않습니다. 다른 앱이나 Claude 개인 설정을 변경하지 않습니다.

0.23.17은 작업 중지 뒤 같은 대화에서 이어서 요청할 수 있도록 개선합니다. Claude가 중지를 확인하면 현재 연결과 세션·모델·Effort·승인 모드를 유지합니다. 중지 확인 중에는 입력을 보존하고 전송을 기다리며, 확인이 끝나면 새 요청을 직접 보낼 수 있습니다. 연결을 완전히 닫으려면 설정의 **업무 연결 종료**를 사용합니다. 이전 요청은 자동 재전송하지 않습니다.

0.23.16은 종료 실패 뒤 재시도와 재실행을 보완합니다. 종료가 끝나지 않은 앱은 준비 상태로 표시하지 않고, **종료 다시 시도**와 **상태 확인**을 제공합니다. 실행 파일을 다시 열 때도 기존 앱에 종료를 한 번 재요청하고 실제 종료를 확인한 뒤 시작합니다. 하위 프로그램의 종료가 확인되지 않으면 성공으로 처리하지 않습니다. 기존 업무 기록과 Claude 개인 설정은 유지합니다.

기존 Claude Code를 Windows 앱 화면에서 사용하는 도구입니다. 터미널 명령이나 `cd` 대신 업무 폴더를 선택하고, 질문·첨부·승인·결과 확인을 화면에서 진행합니다. 앱 전용 로그인은 없으며 AI 업무에는 현재 Windows 사용자의 기존 Claude Code와 인증을 사용합니다.

0.23.15부터 스킬·기능 화면에는 기능 목록만 표시합니다. 진행 내용·결과 확인·승인·선택·분기 안내는 업무 대화에서 확인하세요. 목록을 보는 중에도 업무 실행과 알림은 계속되며, **업무로 돌아가기**를 누르면 최신 대화와 작성 중인 입력을 이어갑니다. 펼친 진행 상세는 화면 전환 시 접고 임시 표시 데이터를 정리하며, 저장된 기록은 다시 펼쳐 볼 수 있습니다.

0.15.0은 Claude Code의 일반 기능을 중심으로 정리했습니다. Company Agent 전용 학습·기억 관리·설치 등록 화면과 실행 연동은 이번 런타임·배포 묶음에서 제외합니다. 사용자의 기존 Company Agent 설치나 설정을 삭제하지 않으며, Claude 설정에 활성화된 플러그인은 다른 플러그인과 같은 방식으로 조회합니다. [0.15.0 변경 범위](WORKSPACE_0.15.0_CLAUDE.md)를 참고하세요.

0.16.0은 통합 알림함·빠른 실행·파일 변경 비교·대화 분기를 추가합니다. 사용법과 보관 범위는 [0.16.0 변경 안내](WORKSPACE_0.16.0_PRODUCTIVITY.md)에 정리했습니다.

자세한 창 재사용·이전 대화 이어가기·도구 연결 방식은 [0.17.0 변경 안내](WORKSPACE_0.17.0_RELIABILITY.md)를 확인하세요.

0.18.0은 WebView2 전용 Windows 창으로 실행합니다. [실행 조건과 전환 안내](WORKSPACE_0.18.0_NATIVE_WINDOW.md)를 확인하세요.

0.18.1에서는 트레이 우클릭 메뉴의 위치와 배율 처리를 수정했습니다. 아이콘의 실제 위치를 기준으로 표시하며 PC 화면 배율은 변경하지 않습니다.

0.19.0에서는 대화 영역을 넓히고 좌우 패널 접기를 추가했습니다. 좌측 상단 버튼으로 업무 목록을 아이콘 레일로 접고, 우측 상단 버튼으로 자료·결과를 펼칩니다. 넓은 창에서 선택한 상태는 앱 화면에 저장됩니다. 좁은 창의 임시 패널은 바깥 클릭이나 Esc로 닫습니다. 이어 할 일·실행 예약은 입력창 위 버튼으로 엽니다. 기존 고정·업무 순서 변경·자동완성·모드 전환은 유지됩니다.

좌측 업무 목록과 우측 자료·결과 패널은 라벤더 적용 전의 기본 색상을 사용합니다. 자료 목록, 파일 확장자 표시, 결과 카드, 탭, 접힌 아이콘 레일과 좁은 창의 패널도 원래 색상을 유지합니다. 색상 복원은 0.21.10부터 반영했으며, 파란색 화면의 0.21.9가 백그라운드에 남아 있어도 새 버전 전환 경로를 사용합니다.

이전 Claude 대화는 **새 업무 → 기존 세션 활용하기**에서 엽니다. 세션을 선택하거나 ID로 찾은 뒤 **업무에 추가하고 이어가기**를 누르면 같은 세션과 원래 작업 폴더를 업무로 등록합니다. 팝업을 여는 것만으로 새 업무를 만들거나 AI 요청을 보내지 않습니다.

0.20.2부터 새 앱 창은 최대화된 상태로 열립니다. 이미 열려 있는 창을 다시 부르면 사용자가 조절한 크기와 일반/최대화 상태를 유지합니다. 상단 **Claude 실행 준비됨**은 실행 파일 확인 완료, **업무 연결됨**은 선택한 업무의 실제 연결, **업무 연결 종료**는 다음 요청 시 재연결을 뜻합니다. 준비 상태에서 스킬·도구의 **연결하고 목록 확인**으로 AI 질문 없이 해당 업무의 목록을 확인할 수 있습니다.

## 대화에서 이미지·표·코드 확인

HTML 결과물의 미리보기를 열면 **화면**에서 보고서의 정적인 배치를 먼저 볼 수 있습니다. **코드**를 누르면 원문을 확인하고 복사할 수 있으며, 코드 표시는 최대 10만 자입니다. 앱 안에서는 HTML의 스크립트와 외부 연결을 실행하지 않습니다. 클릭 동작이나 외부 자료를 포함한 원본의 전체 동작은 **기본 앱에서 열기**로 확인하세요. 화면과 코드 사이를 바꾸어도 원본 파일은 수정하지 않습니다.

0.21.0부터 첨부 이미지와 결과 파일을 대화 안에서 확인하고 눌러 확대할 수 있습니다. 로컬 Markdown 이미지도 업무 폴더와 명시적으로 첨부한 파일 범위에서 표시합니다. 외부 이미지 주소는 자동으로 불러오지 않고 링크로 표시합니다.

표에는 복사 버튼이 있으며 CSV/TSV 파일도 표로 미리 볼 수 있습니다. 코드는 문법 색상·복사·접기를 지원합니다. Bash/PowerShell 실행 카드는 Claude가 보고한 명령과 결과를 보여주며, 제안 코드의 표시만으로 실행하지 않습니다. 결과를 받지 못하면 완료로 표시하지 않습니다. 일반 코드 파일은 읽기 전용 미리보기와 복사를 제공합니다.

이미지는 PNG·JPEG·WebP, 파일당 8 MiB·1,600만 화소까지 표시합니다. 애니메이션은 원래 앱에서 확인합니다. 표는 최대 100행·30열, 코드는 10만 자, 실행 기록은 최근 40개·명령 8천 자·결과 1만2천 자까지 보관합니다. 잘린 내용은 화면에 안내하며 전체 원본은 변경하지 않습니다. 실행 기록 수집 이전의 과거 세션에는 새 실행 카드가 없습니다.

## 0.21.1 안정성 개선

첫 실행에서 화면 일부가 준비되지 않으면 안내를 표시합니다. 화면 복구를 누르면 현재 업무와 보내지 않은 초안·첨부를 같은 탭에서 최대 10분 동안 보존해 다시 표시합니다. 로딩 중 새로 입력하거나 지운 초안은 이전 복구 기록보다 우선합니다. 진행 중인 요청을 다시 보내거나 승인을 대신 처리하지 않습니다. 자료 업로드·전송 등 저장 동작 중에는 복구를 기다립니다.

화면 준비·모듈 오류·앱 창 엔진 상태는 앱 상태 폴더의 `ui-diagnostics.json`에 제한된 코드로 기록합니다. 기록에는 대화·초안·파일 경로·인증 토큰·오류 원문을 넣지 않습니다. 최근 240개 기록, 분당 300회, 파일 256 KiB 한도를 적용합니다. 새 진단 파일은 실행 문제 확인용이며 개인 Claude 설정을 바꾸지 않습니다.

사용 안내는 기본 브라우저에서 열립니다. Markdown 표 복사는 화면에 보이는 텍스트를 사용하며 CSV 원문은 그대로 유지합니다. 재시작 후 예약을 이어 실행할 때 폴더 확인창을 엽니다. 완료된 일회성 예약을 미래로 수정하면 다시 활성화하되, 사용자가 직접 정지한 예약은 유지합니다. 연결 3개가 사용 중이면 다음 예약은 자리가 생길 때까지 기다립니다. 전송 여부가 불명확한 요청은 자동 재전송하지 않습니다.

검증한 범위와 남은 제한은 [0.21.1 검증 결과](https://github.com/bongG-moon/workspace_local/blob/main/docs/VALIDATION_0.21.1.md)를 확인하세요. 이 검증 기록은 인터넷 연결이 필요합니다.

## 0.21.2 모델·Effort 재연결 복구

모델의 **기존 설정 사용**은 같은 앱 실행 중 최초 연결에서 실제 확인한 기준 모델로 돌아갑니다. 작업을 중지하고 같은 업무에서 다시 연결해도 이 복원 선택을 유지합니다. 모델의 실제 적용 응답을 확인한 다음 Effort를 복원하며, 앱 완전 재시작 시에는 현재 PC의 기존 Claude 설정을 다시 따릅니다.

CLI가 이전 설정을 더 이상 지원하지 않으면 입력창의 모델·Effort·승인 선택에서 현재 제공된 항목을 확인하고 고칠 수 있습니다. `/effort`도 같은 선택 기능을 사용합니다. 초안·첨부는 보존되며 설정 변경은 업무 요청으로 전송되지 않습니다. 설정을 고친 뒤 보내기를 누르세요. 대기·예약 요청은 별도로 **이어 실행**을 눌러 현재 선택한 설정을 확인합니다.

모델 목록은 연결된 CLI의 동적 보고값입니다. 앱의 기존 설정 복원·직접 입력 기능은 별도 제어 항목입니다. 회사별 대화형 `/models`와 같은 목록을 제공하는지는 해당 운영 CLI·계정·endpoint에서 확인해야 합니다. 특정 공급자 모델이나 승인 모드를 강제하지 않습니다.

검증 범위는 [0.21.2 검증 결과](VALIDATION_0.21.2.md)를 확인하세요.

## 0.21.3 업무 정리·자료 선택·백그라운드 알림

업무 목록의 삭제 버튼은 확인창을 거쳐 앱의 표시 기록만 별도 저장합니다. 실제 Claude 세션, 앱 대화 미러, 업무 폴더와 결과 파일은 삭제하지 않습니다. 진행 중인 업무·응답 대기·대기 요청·미완료 예약은 먼저 정리해야 하며 앱이 자동으로 작업을 취소하지 않습니다. 기존 세션을 다시 가져오면 숨긴 업무를 다시 표시할 수 있습니다.

자료 추가와 폴더 찾아보기는 앱 내부 선택창을 사용합니다. 현재 폴더의 메타데이터만 최대 250개(최대 2,000개 검사) 읽으며 재귀 탐색·파일 내용 읽기·폴더 신뢰 변경은 하지 않습니다. 큰 폴더는 일부 표시 안내와 이름 검색, Windows 탐색기로 선택 기능을 제공합니다. 최종 첨부 검증과 폴더 사용 동의는 기존 규칙을 유지합니다.

X로 창을 숨겨도 트레이가 정상 동작 중이면 서버·Claude 작업·대기 요청·예약이 유지됩니다. 알림 간격 제한과 기존 카드 표시 중에 도착한 새 알림은 최대 50건·60초의 메모리 대기열에서 재시도합니다. 응답 완료·읽음·업무 숨김·알림 끄기는 대기 배너를 취소합니다. 앱 재시작 시 과거 배너는 다시 보내지 않습니다. 표시 불가·만료된 알림도 앱 알림함에서 확인할 수 있습니다. 네이티브 카드의 명시적 사용 불가만 트레이 알림으로 전환하며 불명확한 응답이나 OS 표시 억제는 중복 알림을 피하기 위해 재시도하지 않습니다.

[쉬운 사용자 안내서](WORKSPACE_USER_GUIDE.html)는 세 시작 방식과 자료 넣기, 이어 하기·분기, 실행 예약, 창 닫기·알림, 업무 정리를 단계별로 설명합니다. [검증 결과](VALIDATION_0.21.3.md)를 함께 확인하세요.

## 0.21.4 도구·스킬 활동 표시

입력창 위 상태 줄에 현재 도구와 동작, 파일 이름 또는 스킬 이름을 표시합니다. 대화의 ‘도구·스킬 활동’에는 주요 호출을 여러 줄로 표시하고, **입력·결과 자세히 보기**에서 요청별 상세 내용을 확인합니다. 승인·질문 대기는 실행 정보보다 우선하며, 설정 변경만으로 작업 중 상태가 되지 않습니다.

완전한 CLI tool_use 메시지는 ‘요청됨’, 일치하는 tool_progress 메시지는 ‘실행 중’, tool_result는 ‘결과 수신’ 또는 ‘오류’로 표시합니다. 결과 수신은 도구 응답을 받았다는 뜻이며 백그라운드 작업이나 전체 업무 성공을 보장하지 않습니다. 중단·종료·기록 복원 시 끝을 확인하지 못한 호출은 ‘결과 미확인’으로 남깁니다. 내부 추론이나 백분율을 만들어 표시하지 않습니다. 설치된 CLI가 제공하지 않는 진행 정보는 표시할 수 없습니다.

요약 표시는 최대 80건·문자열 합계 48,000자에 제한한 메타데이터로 유지합니다. 파일 도구는 파일 이름, Skill은 스킬 이름, 명령·위임 도구는 제공된 짧은 설명만 사용합니다. 이 요약에는 입력·출력·명령·스킬 인자를 넣지 않고 URL·인증 정보 형태를 걸러냅니다. 0.23.5의 별도 상세 기록에서는 실제 수신한 입력과 결과를 아래 범위로 확인할 수 있습니다. 기존 명령 실행 카드의 명령·출력 열람은 유지합니다. 하위 작업은 부모 호출에 연결하며 하위 응답을 주 대화의 답변으로 바꾸지 않습니다. 짧은 요약 행은 최근 활동을 여러 개 보여 주며, 바뀐 행만 갱신합니다. 상세 본문은 펼칠 때만 불러옵니다.

[검증 결과](VALIDATION_0.21.4.md)를 확인하세요.

## 0.23.7 사용자 중지 안내

질문·승인 대기 중에도 직접 중지할 수 있습니다. 현재 연결의 알려진 중단 응답은 실패 경고나 오류 알림으로 표시하지 않고, 앱이 소유한 Claude 연결의 종료가 확인되면 중지 상태를 표시합니다. 이미 만들어진 결과 파일은 유지됩니다. 후속 요청은 같은 대화에서 보내면 됩니다.

실제 인증·연결 종료 실패나 중지하지 않은 작업의 오류는 계속 알려드립니다. 이전 요청은 자동 재실행하지 않으며, 중단 응답을 구분하기 위한 추가 AI 호출도 없습니다.

## 0.23.6 주요 활동과 상세 진행 기록

주요 중간 설명과 도구·스킬 호출은 대화에서 계속 확인할 수 있습니다. 도구 요약은 진행·대기 중인 호출을 우선해 최근 활동을 최대 6개 보여 주며, 더 이전 기록은 상세 보기에서 확인합니다. 입력창 위 상태는 실제로 전달받은 도구 호출 준비, 실행 보고, 답변 작성 등을 구분합니다. 준비 표시는 실행 확인과 다릅니다.

**입력·결과 자세히 보기** 또는 **진행 내용**을 펼치면 현재 업무에서 Claude가 실제로 전달한 설명, 도구·스킬 호출과 입력, 실행 결과 및 하위 작업 기록을 시간순으로 확인합니다. 도구 활동에서 열면 해당 요청을, 오른쪽 **진행 기록 보기**에서는 업무 전체를 볼 수 있습니다. 설정 변경만으로 업무를 새로 시작하거나, 상세 기록의 내용을 다시 실행하지 않습니다.

기록은 앱의 로컬 보관 영역에 저장하고 펼칠 때 50개씩 읽습니다. 한 번에 화면에 유지하는 기록은 최대 250개이며, 앞부분을 더 읽거나 최신 내용으로 돌아갈 수 있습니다. 상세 본문은 건당 최대 64 KiB, 업무당 데이터베이스는 최대 32 MiB로 제한하며 오래된 기록을 정리한 경우 안내합니다. 진행 중인 공개 텍스트는 기존 대화에서 계속 표시하고, 상세 기록에는 완성된 블록을 보관합니다. 접으면 상세 목록을 화면과 메모리에서 비우며 백그라운드의 기록 수집은 계속됩니다. **이전 기록**과 **최신 기록**으로 이동하고 긴 항목은 펼쳐 봅니다. 연결이 끊기거나 업무를 바꿔도 이미 보관된 기록을 다시 읽을 수 있습니다.

과거 버전에서 수집하지 않은 상세 내용이나 CLI가 전달하지 않는 터미널 전용 출력은 복원하지 않습니다. 내부 추론·인증 제어 메시지·이미지의 바이너리 본문은 기록하지 않으며, 알려진 인증 값 형태를 가립니다. 보관 범위를 넘긴 오래된 기록과 길이가 제한된 항목은 화면에 생략 안내를 표시합니다. 일반 파일 내용과 도구의 업무 입력·결과는 로컬 기록에 포함될 수 있습니다.

[0.23.6 검증 범위](VALIDATION_0.23.6.md)와 [Claude 출력 스트림 설명](https://code.claude.com/docs/en/agent-sdk/streaming-output)을 참고하세요.

## 새 버전으로 자동 전환

새 실행기를 더블클릭하면 같은 버전이나 더 최신 버전이 실행 중인 경우 기존 창을 엽니다. 더 새 버전이면 Python과 앱 창의 실행 조건을 먼저 확인합니다. 기존 업무의 실행·승인·질문·결과 확인이 끝나면 앱을 정상 종료하고 새 버전을 엽니다. 현재 작업을 강제로 중지하지 않습니다.

0.21.5 이상에서 다음 버전으로 전환할 때는 현재 업무와 보내지 않은 입력·첨부 경로를 앱의 상태 폴더에 잠시 보관합니다. 새 화면이 복원을 확인하면 이 임시 기록을 지웁니다. 입력이 너무 크거나 화면 응답·저장·종료를 확인하지 못하면 전환을 멈추고 기존 내용을 보존합니다. 대기 중 **전환 취소**를 누르면 현재 버전을 계속 사용할 수 있습니다.

0.21.4 이하 버전에는 초안 보관 기능이 없습니다. 이 버전에서 처음 넘어올 때는 작성 중인 내용을 따로 보관하고 안내의 **확인**을 선택하세요. 직접 설정에서 종료하거나 실행 아이콘을 다시 누를 필요는 없습니다. 확인 대화상자가 열린 사이 작업이 시작되면 전환을 중단합니다. 이 구버전은 화면 없는 실행에서는 자동 전환하지 않습니다.

전환 후 기존 업무와 대화는 그대로 남습니다. 대기열·예약은 일반 재시작과 같이 확인한 뒤 이어 실행합니다. 앱 연결에만 적용한 모델·승인 설정은 재시작 확인 절차를 따르며, 개인 Claude 설정과 Windows 설정은 변경하지 않습니다. 기존 배포 파일을 자동으로 삭제하지 않습니다. [검증 범위](VALIDATION_0.21.5.md)를 확인하세요.

## 실행과 업데이트

Windows 10/11 x64, Windows PowerShell, .NET Framework 4.6.2 이상, **WebView2 Evergreen Runtime**, **이미 설치된 Python 3.11 이상**이 필요합니다. VBS 방식은 Windows Script Host도 필요합니다. EXE와 VBS 모두 Python 실행 환경·설치 프로그램을 포함하거나 다운로드·자동 설치하지 않습니다.

1. 받은 ZIP을 새 폴더에 압축 해제합니다.
2. EXE 묶음은 `Company-Workspace-0.23.20.exe`, VBS 묶음은 `Company-Workspace.vbs`를 실행합니다.
3. **새 업무**에서 폴더를 선택하고 작업 위치를 확인한 뒤 요청을 입력합니다.

새 업무의 기본 위치는 Windows가 알려 준 실제 **바탕화면 아래 Company Workspace**입니다. 기존 폴더를 선택하거나 저장 위치를 바꿀 수 있습니다. 기존 업무 폴더와 Claude 설정을 자동으로 이동하지 않습니다.

Claude 호출 대상을 확인하지 못해도 앱 화면에서 연결 문제를 확인할 수 있습니다. 다른 계정·CLI·인증으로 자동 전환하지 않습니다. EXE 실행 조건과 옵션은 [단일 EXE 안내](WORKSPACE_STANDALONE_EXE.md), 오류 확인은 [시작 진단](WORKSPACE_STARTUP_DIAGNOSTIC.md)에 정리했습니다.

## 질문·파일·결과

- **자료 추가·경로 추가**는 선택한 원본 경로를 연결합니다. 우측 업무 파일이나 결과물을 입력창으로 끌어 놓아도 원본 경로를 첨부합니다.
- 문서·이미지·소스와 함께 **EXE, ZIP, 7z, RAR, TAR, GZ/TGZ, BZ2, XZ, ZST, CAB, ALZ, EGG** 등의 파일을 첨부할 수 있습니다. 파일 선택·경로 입력·`@파일`·드래그 모두 같은 형식 목록을 사용합니다. 첨부는 파일을 요청에 연결하는 동작이며, 이 단계에서 실행하거나 압축을 풀지 않습니다. 내부 자료를 읽거나 프로그램을 실행하는 일은 이후의 별도 요청과 기존 Claude 도구·승인 방식에 따릅니다.
- 파일 탐색기에서 끌어 놓은 파일은 앱이 관리하는 복사본으로 첨부합니다. 파일당 50 MiB, 앱 전체 복사본 512 MiB 한도이며 첨부 해제로 원본이나 복사본을 삭제하지 않습니다. 업로드 전에 형식·크기·저장 한도를 확인하며, 연결 중단이나 지원하지 않는 형식은 한국어 안내로 표시합니다.
- **Enter**로 요청을 보내고 **Shift+Enter**로 줄을 바꿉니다. 작업 중에 Enter로 보내면 현재 요청이 끝난 뒤 이어서 실행하도록 대기열에 추가합니다.
- `@`는 현재 업무 폴더와 첨부 파일에서 후보를 찾습니다. `/`는 설치 메타데이터의 후보와 실제 Claude 연결이 보고한 명령을 구분합니다. 후보가 열려 있으면 Tab 또는 Enter는 후보를 선택합니다. 선택 후 Enter를 한 번 더 눌러 요청을 보냅니다.
- 응답을 읽으려고 위로 스크롤하면 읽던 위치를 유지합니다. **최신 답변으로 이동**으로 다시 따라갈 수 있습니다.
- 결과 미리보기의 **기본 앱에서 열기 / 폴더에서 보기 / 메모장에서 열기**를 사용할 수 있습니다. HTML도 기본 연결 앱으로 열 수 있으며, 외부에서 원본 HTML을 열면 그 파일의 스크립트가 실행될 수 있습니다.

자동완성이나 설정 목록을 위해 Claude 연결을 준비하는 것은 AI 질문 전송이 아닙니다. `/` 후보를 불러오는 중 Shift+Tab을 눌러도 같은 업무의 연결 준비를 공유하며, 작성 중인 질문과 첨부를 자동으로 보내지 않습니다. 터미널 전용 대화형 명령은 앱에서 동일하게 동작한다고 가정하지 않고 제공되는 안내를 따릅니다.

### 입력창 단축키

좌측의 **단축키**를 누르면 키 조합과 사용 방법을 검색할 수 있는 안내가 열립니다. 좌측을 접었을 때도 단축키 아이콘으로 열 수 있습니다. **빠른 실행(Ctrl+Shift+P)**에서 **단축키**를 검색해 열어도 같은 안내를 볼 수 있습니다. 이 메뉴는 안내만 제공하며 기존 단축키 동작을 바꾸지 않습니다.

Claude Code의 기본 입력 단축키를 기준으로 합니다. 한글을 조합하는 중에는 Enter를 눌러도 글자 입력만 확정하며 요청을 보내거나 후보를 선택하지 않습니다. 열린 자동완성·선택창의 키 동작이 우선하고, 입력창 밖의 검색칸이나 문서 선택창에는 아래 편집 동작을 적용하지 않습니다.

| 단축키 | 입력창에서 하는 일 |
| --- | --- |
| Enter | 요청 보내기. 작업 중에는 끝나고 이어서 실행할 대기열에 추가 |
| Shift+Enter / Alt+Enter / Ctrl+J | 줄바꿈 |
| Ctrl+X 다음 Enter | 이어서 실행할 요청을 대기열에 추가 |
| Ctrl+Enter / Ctrl+X 다음 Ctrl+S | 작업 중이 아니면 요청 보내기. 작업 중의 즉시 입력 반영은 현재 연결에서 지원하지 않아 입력을 보존하고 안내 |
| Tab / Enter | 자동완성 후보 선택. 이 키를 누른 것만으로 동시에 전송하지 않음 |
| ↑ / ↓ / Ctrl+P / Ctrl+N | 자동완성이 열려 있으면 후보 이동. 그 외에는 현재 업무에서 보낸 요청 탐색 |
| Ctrl+R | 현재 업무에서 보낸 요청 검색 |
| Ctrl+S | 작성 중인 텍스트·첨부 잠시 보관 또는 복원. 업무별로 구분 |
| Shift+Tab / Alt+M | 현재 연결이 지원하는 승인 모드 순환 |
| Alt+P | 모델 선택 |
| Esc | 열린 후보·선택창 닫기. 입력창에서 열린 선택창이 없으면 현재 요청 중지 |
| Ctrl+C | 선택한 글자가 있으면 복사. 선택한 글자가 없으면 현재 요청 중지 또는 입력 지우기 |
| Ctrl+O | 앱의 도구 활동 기록 펼치기·접기 |
| Ctrl+Shift+P | 앱의 빠른 실행 열기 |

텍스트를 빠르게 고칠 때는 아래 키를 사용합니다. **Ctrl+K는 빠른 실행이 아니라 글자 삭제**입니다.

| 단축키 | 편집 동작 |
| --- | --- |
| Ctrl+A / Ctrl+E | 현재 줄의 처음·끝으로 이동 |
| Ctrl+F / Ctrl+H | 한 글자 뒤로 이동 / 앞 글자 삭제 |
| Alt+B / Alt+F | 단어 단위로 앞·뒤 이동 |
| Ctrl+K / Ctrl+U | 커서부터 현재 줄 끝·처음까지 삭제 |
| Ctrl+W / Ctrl+Backspace | 앞 단어 삭제 |
| Alt+D | 뒤 단어 삭제 |
| Ctrl+Y | 위 삭제 단축키로 지운 내용 붙여넣기 |
| Alt+Y | Ctrl+Y로 붙인 내용을 앞서 지운 내용으로 교체 |

Ctrl+S로 보관한 입력은 같은 업무에서 입력창이 비어 있을 때 Ctrl+S로 꺼낼 수 있습니다. 다른 요청을 보낸 뒤에도 입력창이 비어 있으면 보관한 입력을 다시 보여 줍니다. 전송이 실패했거나 새로운 내용을 쓰고 있다면 덮어쓰지 않습니다. 업무별 임시 보관은 한 개이며, 다른 내용을 적고 Ctrl+S를 다시 누르면 그 내용으로 교체합니다.

터미널 자체가 관리하는 **Ctrl+B**(작업 백그라운드 전환), **Ctrl+T**(터미널 작업 목록), **Ctrl+G**(외부 편집기), **Ctrl+D**(CLI 종료), **Esc 두 번**(되감기)은 앱의 다른 기능에 임의로 연결하지 않습니다. 해당 기능이 필요하면 **설정 → 고급 기능 → 원본 Claude Code 열기**를 사용하세요. 앱의 트레이 실행·이어 할 일·대화 분기는 이 키들의 대체 동작이 아닙니다.

사용자가 따로 만든 Claude 단축키 설정 파일을 수정하거나 앱으로 자동 가져오지 않습니다. 사용자 정의 키나 터미널별 설정은 원본 Claude Code에서 확인하세요.

## 모델·Effort·승인

입력창 아래 **모델 / Effort / 승인**에는 실제 Claude 연결이 제공한 값과 선택지를 표시합니다. 확인하지 못한 값은 미확인으로 구분하며 기본 모드를 임의로 Auto로 바꾸지 않습니다. 터미널과 앱의 SDK 연결은 시작 모드가 다를 수 있습니다.

**Effort** 버튼이나 `/effort`로 수준을 선택합니다. `/effort high`처럼 현재 모델이 지원하는 값을 지정할 수도 있습니다. `/effort auto`는 현재 모델에서 변경 전에 관찰한 값으로 복원하며, 그 값을 모르면 복원 불가를 안내합니다. 개인 설정을 삭제하거나 다른 모델·승인 모드를 초기화하지 않습니다.

입력창에서 **Shift+Tab 또는 Alt+M**을 누르면 지원되는 Manual → Accept edits → Plan → Auto를 순환합니다. 현재 모드를 모르면 임의로 순환하지 않습니다. Bypass로 들어갈 때는 **승인** 목록에서 직접 선택하고 위험 확인을 거칩니다. Bypass는 일반 순환에서 제외되지만, 이미 Bypass인 경우 같은 단축키로 지원되는 일반 모드에 돌아올 수 있습니다. **Alt+P**로 모델 선택을 열 수 있습니다.

승인 카드는 **이번만 허용**이 기본입니다. 현재 CLI가 제공한 경우에만 연결 또는 저장 범위가 표시된 **항상 허용**을 선택할 수 있습니다. 사용자가 선택한 정확한 규칙만 CLI에 전달합니다. Bypass도 CLI와 회사 정책이 허용하고 실제 적용 응답을 확인했을 때만 적용된 것으로 표시합니다.

모델·Effort·승인 선택은 같은 앱 실행 중 해당 업무에 유지하며 재연결 때 다시 적용을 확인합니다. 앱을 완전히 종료하면 기존 Claude 설정을 다시 상속합니다. **항상 허용**으로 사용자가 명시적으로 저장한 규칙은 이 임시 선택과 별개입니다.

## 스킬·도구와 연결 출처

**공통 스킬**은 사용자 공통 설정의 설치 메타데이터를 조회합니다. 같은 화면의 **연결 기준 업무**에서 도구·연결 서버·명령 목록의 출처를 선택합니다. 공통 범위라는 이유로 업무 연결 정보를 버리지 않으며, 특정 업무에서 보고된 도구를 모든 폴더의 공통 도구로 표시하지 않습니다.

**폴더별 스킬 → 업무 폴더**는 등록된 업무 디렉토리의 설치 후보와 그 폴더에 속한 연결 보고를 확인합니다. 출처가 다른 동명 스킬은 별도로 유지합니다. 조회 대상을 바꿔도 현재 업무·대화·초안·첨부·폴더 신뢰는 바뀌지 않으며 목록 조회만으로 Claude나 플러그인을 실행하지 않습니다.

숫자는 확인한 목록의 개수입니다. 연결이 끝난 기록은 **마지막 연결 정보**, 목록을 받지 못한 경우는 **미확인**, 실제 빈 배열을 보고받은 경우는 **0**으로 구분합니다. 설치 발견과 실제 연결의 로드 여부·실행 권한·성공은 서로 다른 정보입니다.

## 최근 업무와 이전 Claude 대화

최근 업무의 이동 손잡이를 끌어 순서를 바꾸거나 손잡이에 초점을 둔 상태에서 **Alt+↑ / Alt+↓**를 사용합니다. 고정한 업무끼리, 고정하지 않은 업무끼리 이동하며 고정 여부는 핀 버튼으로 바꿉니다. 업무 순서는 앱 상태에 저장하고 대화 내용이나 실행 폴더는 바꾸지 않습니다.

**이전 Claude 대화 불러오기**에서 현재 Claude 설정 위치의 일반 대화를 고르거나 세션 UUID로 찾습니다. 미리보기와 가져오기 자체는 원본 대화 파일을 수정하거나 AI 요청을 실행하지 않습니다. 원래 업무 폴더 확인은 별도로 거칩니다. 다른 터미널에서 같은 대화를 실행 중이라면 그 작업을 마친 뒤 이어가세요.

## 이어 할 일·예약·알림

진행 중에는 **끝나고 이어서**로 후속 질문을 대기시키거나, **지금 반영**으로 현재 요청을 중지한 뒤 같은 대화에서 새 요청을 이어갑니다. 지금 반영은 이미 수행한 작업을 되돌리지 않습니다. 대기 요청은 **이어 할 일**에서 수정·취소·정렬합니다.

**실행 예약**은 한 번·매일·매주를 지원합니다. PC가 깨어 있고 앱이 실행 중일 때 동작하며 기존 승인·질문이 있으면 기다립니다. 오류·직접 중지·앱 재시작 뒤에는 내용을 확인하고 **이어 실행**합니다. 지나간 예약을 몰아서 실행하지 않습니다.

왼쪽 **전체 예약**에서 모든 업무의 요청 요약·반복 주기·다음 실행·현재 상태를 모아 봅니다. 업무 이름·폴더·요청으로 검색하거나 실행 예정·일시정지·확인 필요·완료로 좁힐 수 있습니다. **예약 관리**는 해당 업무의 기존 관리 화면을 열며, 조회만으로 실행하거나 재개하지 않습니다. 최대 100개 예약 메타데이터를 15개씩 표시하고, 열린 동안에만 기존 4초 갱신을 사용합니다. 창을 닫으면 진행 중인 조회와 화면 목록을 해제합니다.

상단 **알림**에서 완료·확인 요청·오류와 해당 업무를 확인합니다. **설정 → PC 알림**에서 종류별 알림을 조절합니다. 다른 작업 중에는 앱 색감의 전용 알림 카드가 표시되고 **결과 / 열기**로 해당 업무로 이동합니다. 화면 표시가 제한되거나 알림이 겹쳐도 앱의 알림 목록에 기록이 남습니다. [알림 카드의 표시·보관 기준](WORKSPACE_0.20.0_NOTIFICATIONS.md)을 확인하세요.

검색칸은 안쪽 글자가 아닌 둥근 입력 영역을 얇게 강조합니다. Tab으로 이동할 때 현재 위치를 계속 표시하고, 팝업을 닫거나 업무를 삭제한 뒤 다른 입력칸의 포커스를 빼앗지 않도록 복원합니다.

응답 대기 알림에는 업무명 아래 진한 회색으로 질문·선택 문구 또는 승인 작업 설명을 최대 100자·두 줄로 표시합니다. 설명이 없으면 도구 종류에 맞는 짧은 안내를 사용합니다. 요약이 없는 이전 알림 기록이나 직접 호출도 기본 안내를 표시하며, 지난 알림을 다시 발송하지 않습니다. 명령 원문과 파일 본문을 가져오지 않으며 알려진 인증정보 형태를 가립니다. 같은 요약을 알림함과 브라우저 대체 알림에도 표시합니다. 기존 완료 알림의 크기와 응답 완료 후 지연 알림 취소 동작은 유지합니다.

창의 X는 화면을 닫으며, 지원되는 창에서는 **트레이로 보내기**로 숨길 수 있습니다. **트레이 → 앱 열기**로 돌아오고 **완전 종료**로 앱과 업무 연결을 종료합니다. Windows 로그인 자동 시작은 등록하지 않습니다.

## 기존 데이터와 설정

호환성을 위해 실행 이름 **Company-Workspace**와 기본 앱 상태 경로 `%LOCALAPPDATA%\CompanyAgent\local-ui`를 유지합니다. EXE 실행 캐시는 `%LOCALAPPDATA%\CompanyAgent\workspace-runtime`을 사용합니다. 이 이름이 Company Agent의 필수 설치나 전용 관리 기능을 뜻하지 않습니다.

앱은 기존 Claude 인증·`CLAUDE_CONFIG_DIR`·모델·MCP·플러그인·메모리 설정을 자동으로 덮어쓰지 않습니다. Windows UAC·영구 실행 정책·사용자 계정·기존 파일 ACL도 바꾸지 않습니다. 실행기의 PowerShell 실행 정책 옵션은 이번 프로세스 계열에만 적용하며 조직의 그룹 정책이 우선합니다. 로컬 HTTP 연결 토큰은 앱 내부 연결 보호용이며 새 Claude 인증 정보가 아닙니다.

## 확인 범위

이 문서는 0.23.20 사용법과 구현 범위입니다. 소스 변경만으로 배포 파일이 갱신되거나 모든 회사 PC에서 검증이 끝난 것은 아닙니다. 0.23.20 빌드·실제 실행·공개 배포 결과는 별도 검증 기록으로 확인해야 합니다. 이전 버전의 검증 기록은 그 버전에 대한 기록으로 유지합니다.

사내 배포 담당자는 [GitLab 배포 도구 안내](WORKSPACE_GITLAB_PUBLISHER.md)에 따라 소스 수정 없이 사내 배포본을 만들 수 있습니다. 일반 사용자는 제공받은 사내 ZIP을 처음 한 번 실행합니다. GitLab의 Releases 목록이 비어 있어도 Package Registry의 최신 정보와 설치 파일로 업데이트할 수 있습니다.

0.23.4부터 앱을 열 때 새 버전이 있으면 변경 내용과 **업데이트하기 / 다음에 하기**를 표시합니다. **업데이트하기**를 누를 때만 다운로드와 전환을 시작하며, **다음에 하기**나 닫기를 누르면 같은 창에서는 반복해서 안내하지 않습니다. 다시 앱 창을 열면 재안내할 수 있습니다. 요청을 보내거나 승인·답변을 처리 중이면 안전하게 안내할 수 있을 때까지 기다립니다. **설정 → 앱 업데이트 → 새 버전 자동 확인**을 끄면 자동 확인과 시작 팝업을 표시하지 않습니다. **지금 확인**으로 직접 확인할 수 있습니다.

기존 0.23.2/0.23.3에는 시작 팝업이 없으므로 사내에 새 버전을 배포한 뒤 **설정 → 앱 업데이트 → 지금 확인**으로 먼저 업데이트하세요. 그다음 실행부터 시작 안내를 사용할 수 있습니다. 사내망 연결이 안 되거나 확인에 실패해도 기존 앱을 계속 사용할 수 있습니다.

### MCP 변경 후 현재 업무의 Claude Code 재시작

상단 연결 상태 옆 또는 **설정 → 업무 연결 → Claude Code 재시작**으로 현재 업무의 CLI 연결을 다시 엽니다. 기존 앱 업무·Claude 세션 ID·폴더와 보내지 않은 입력·첨부를 유지하고, 앱이 시작한 해당 연결만 종료합니다. 개인 Claude 인증·설정·MCP 구성과 별도 터미널은 수정하지 않습니다.

진행 중인 작업이나 응답 대기가 있으면 중지 확인을 받은 뒤 재시작합니다. 이미 변경된 파일은 유지되며 이전 요청은 자동 재전송하지 않습니다. 대기 요청·예약은 재시작 동안 자동 실행을 보류하고, 일시정지가 남은 경우 안내에 따라 이어 실행합니다. 현재 업무에서 선택했던 모델·Effort·승인 모드는 기존 복원 절차로 확인하며, 적용할 수 없으면 성공으로 가정하지 않고 선택을 요청합니다.

이 기능은 `연결 다시 확인`의 설치 경로 점검과 다릅니다. CLI를 실제로 다시 준비하지만 새 MCP의 인증·도구 실행 성공까지 보장하지는 않습니다.

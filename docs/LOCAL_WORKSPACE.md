# Company Workspace — 로컬 업무 화면 0.11.4

## 0.11.4 화면 전반의 사용성 보완

앱 종료, 연결 변경, HTML 미리보기 등의 확인창을 앱 안의 같은 디자인으로 통일했습니다. 취소 또는 Esc를 누르면 기존 화면을 유지하며, 팝업 안에서 발생한 오류도 해당 팝업 앞에 표시합니다.

홈의 **전체 업무 보기**에서 모든 업무를 검색하고 열 수 있습니다. 창이 좁아 왼쪽 업무 목록이 숨겨져도 이전 업무에 접근할 수 있습니다. 자료 목록의 긴 파일명은 영역 안에서 줄바꿈하며, 자료·결과 탭은 선택한 탭 하나만 강조합니다.

시작 경고창에도 고해상도 배율과 시각 스타일을 적용했습니다. 기존 창을 다시 열 때는 첫 실행과 동일하게 시스템 및 사용자 설치 경로에서 Edge를 찾습니다.

## 0.11.3 선명한 파일·폴더 선택 창

**자료 추가**와 **폴더 찾아보기**는 Windows 공통 항목 선택 창을 사용합니다. 파일 선택에는 여러 파일 선택과 문서·이미지 필터를, 폴더 선택에는 주소창·검색·즐겨찾기를 갖춘 같은 방식의 탐색 창을 제공합니다. 앱에서 지정하는 제목·선택 버튼·파일 형식 안내를 한국어로 표시합니다. 탐색 영역의 언어와 밝고 어두운 테마는 Windows 설정을 따릅니다.

선택 창을 만들기 전에 모니터별 고해상도 배율 처리를 설정하여 확대된 비트맵으로 흐려지는 원인을 제거합니다. 지원되는 Windows에서는 Per-Monitor V2를 우선 사용합니다. Windows 전체 배율·해상도·호환성 설정은 바꾸지 않습니다. 선택 창의 앞뒤 순서, 취소, 원본 경로 반환과 여러 파일 선택은 기존 동작을 유지합니다.

## 0.11.2 스킬 분류·개수 수정

스킬 탭은 설치 정보와 현재 연결 정보를 호출 이름 기준으로 합쳐 표시합니다. 상단 스킬 개수는 검색어와 관계없이 확인된 일반 스킬 수를 표시하며, 설치에서 발견한 목록인지 현재 연결에서 보고한 목록인지 화면에 구분합니다. `user-invocable: false`인 내부 보조 스킬과 호출 이름이 없는 참조 자료는 별도로 접어 둡니다. `disable-model-invocation: true`인 직접 호출 전용 스킬은 일반 목록에 포함합니다. 같은 이름이어도 플러그인이 다르면 별도 항목입니다.

도구·연결 서버·명령은 첫 업무 요청 전에는 **연결 전**, 연결됐지만 CLI가 목록을 제공하지 않으면 **미확인**, 빈 목록을 실제로 보고했을 때만 **0**으로 표시합니다. 목록을 열거나 새로고침해도 AI 요청을 보내거나 Claude 설정을 변경하지 않습니다.

## 0.11.1 종료·재실행 수정

창의 **X**는 창만 닫고 업무 연결을 유지합니다. 앱을 완전히 종료하거나 새 버전을 적용하려면 **설정 → 앱 종료**를 누릅니다. 진행 중인 연결을 정리하는 동안은 **앱을 종료하고 있어요**를 표시하고 실제 정리가 끝난 뒤 완료를 안내합니다.

이전 버전이 남아 있으면 실행기가 해당 창을 다시 열어 **설정 → 앱 종료**로 돌아갈 수 있게 합니다. 진행 중인 업무를 임의로 종료하지 않습니다. 종료 처리가 진행 중이면 잠시 기다린 뒤 새 버전을 시작하며, 종료 여부가 불확실하면 새 서버를 겹쳐 시작하지 않습니다.

## 0.11 스킬·도구 탭

왼쪽 **스킬·도구**에서 선택한 업무에 연결된 Claude 기능을 확인합니다. **스킬 / 도구 / 연결 서버 / 명령**으로 나누고, 이름·설명·출처를 검색할 수 있습니다. 창이 좁을 때는 상단 메뉴의 스킬·도구 아이콘을 사용하세요.

- **현재 연결에서 확인:** 해당 Claude 연결이 실제로 전달한 스킬·기본 도구·MCP 도구·명령 목록입니다. 연결 서버의 연결 성공·실패 상태도 함께 표시합니다. 목록에 있다는 사실이 개별 실행 권한이나 성공을 보장하지는 않습니다.
- **설치에서 발견:** 신뢰한 작업 폴더에 등록된 Company Agent의 스킬 목록과 각 SKILL.md의 호출 속성을 읽어 확인한 설명·출처·범위입니다. 첫 AI 요청 전에도 확인할 수 있으며, 현재 Claude가 로드한 목록과 구분합니다. 설치 조회가 지원되지 않으면 확인 필요 안내를 표시합니다.
- **아직 연결 전 / 미제공 / 빈 목록 / 마지막 연결 정보**를 구분합니다. CLI가 항목을 보고하지 않은 상태를 0개로 표시하지 않으며, 연결 종료 후에는 마지막으로 확인한 목록임을 표시합니다.
- **새로고침**은 읽기 전용 조회입니다. 탭 열기나 조회만으로 AI·도구를 실행하지 않고 Claude 설정을 변경하지 않습니다. **업무로 돌아가기**를 누르면 작성 중인 초안과 대화로 돌아갑니다.

기존 앱을 **설정 → 앱 종료**로 종료한 뒤 새 실행기를 사용하세요. 0.10.1의 폴더 선택 창과 전용 아이콘 수정도 포함합니다.

## 0.10.1 폴더 선택·아이콘 수정

- **찾아보기**와 **자료 추가**의 Windows 선택 창이 실제 Workspace 창에 연결되도록 바꿨습니다. 보이지 않는 투명 부모 창을 제거하고, 선택 창을 한 번 앞으로 표시한 뒤 상시 최상위 상태를 해제합니다. 다른 앱으로 이동한 경우 반복해서 초점을 가져오지 않습니다.
- 폴더 선택 중에는 찾아보기 버튼에 **선택 창 열림…**을 표시하고 중복 클릭을 막습니다. 선택·취소·실패 후 창과 자원을 정리합니다.
- 전용 아이콘을 추가했습니다. ICO는 16/20/24/32/40/48/64/128/256px 각각 원본 도형에서 렌더링했고 SVG와 192/512px PNG를 함께 제공합니다. 앱 창은 해당 favicon을 읽습니다.
- 적용하려면 기존 앱을 **설정 → 앱 종료**로 종료한 뒤 새 소스 또는 새 ZIP의 실행기를 사용하세요. 작업표시줄에 예전 아이콘을 고정했다면 Windows의 고정 아이콘은 남을 수 있으므로 새 실행 창에서 다시 고정할 수 있습니다. 사용자 핀이나 브라우저 프로필을 자동 변경하지 않습니다.

소유 창 전달·취소·오류 자원 정리와 아이콘 응답/해상도는 자동 검증했습니다. 이 검증 환경에서는 실제 Windows 선택 창의 앞뒤 순서와 작업표시줄 아이콘을 직접 조작·촬영할 수 없어, 직원 PC의 실제 표시까지 확인했다고 주장하지 않습니다.

## 누구를 위한 화면인가요?

터미널에서 명령을 입력하는 것이 낯선 사용자를 위한 Company Agent의 별도 로컬 화면입니다. **기존 Claude Code CLI가 실제 작업을 수행**합니다. Claude Desktop을 설치하거나 회사 모델 연결을 교체하지 않습니다.

**앱 전용 로그인·API 키는 필요하지 않습니다.** 같은 Windows 사용자, 같은 실행 환경과 작업 폴더에서 `claude`를 실행했을 때 사용하는 로그인·모델·설정·스킬을 그대로 사용하고, 입력과 출력만 업무 화면으로 표시합니다. 기존 Claude가 로그인돼 있다면 앱을 위해 다시 로그인할 필요가 없습니다.

이 버전은 로컬 시험용 소스 버전이며, 기존 공개 Release에 자동 반영되지 않습니다. 사내 HCP 서버·보안 프로그램·실제 DRM 문서에서의 최종 검증과 정식 배포 승인은 별도로 필요합니다. 모든 CLI 화면을 재구현했다는 의미가 아닙니다.

## 새 업무 화면 사용 순서

1. `Company-Workspace.vbs`를 더블클릭합니다. 기존 앱이 실행 중이면 먼저 종료하고 새 폴더에서 실행합니다.
2. **새 업무**에서 **새 업무 공간 만들기** 또는 **기존 폴더 사용하기**을 선택합니다. 새 공간은 Workspace 상태 폴더의 `workspaces` 아래에 생성되며 실제 위치를 화면에 표시합니다. 기존 폴더는 **찾아보기**으로 고릅니다. 해당 폴더의 지침·도구 실행 범위를 읽고 확인합니다.
3. **자료 추가**로 파일을 고르고 자연어 요청을 입력한 뒤 **보내기**를 누릅니다. 단축키는 `Ctrl+Enter`입니다. 파일 선택은 경로 참조이며 클라우드로 미리 업로드하지 않습니다. 요청 시 실제 자료 처리는 기존 Claude 연결을 따릅니다.
4. 질문은 선택지로 답하고, 승인 카드에서 대상·변경 전후·실행 원문을 확인합니다. 뜻을 자동 해석할 수 없는 명령은 원문을 함께 표시합니다.
5. **이번 결과**에서 요청 시작 전후 확인된 파일을 미리 보거나 **이 결과로 요청**해 수정합니다. 생성 주체를 확정한 기록이 아닌 로컬 파일 변경 관찰입니다. 문서 확장자·깊이·개수·시간 제한이 있어 모든 파일을 보여 주지는 않습니다.
6. **최근 업무**에서 검색·이어하기하고 제목 변경·고정을 사용할 수 있습니다. 화면 간 이동 중 초안은 메모리에 유지되며 앱 재시작 후에는 복구되지 않습니다.

**스킬·도구**에서는 현재 업무에 연결된 기능을 검색하고, **설정**에서는 연결·모델, 첫 업무 안내와 관리 기능을 확인합니다. 실행 파일 확인과 실제 모델 응답 성공은 구분해 표시합니다. 지원하는 CLI가 연결된 뒤 대기가 되면 **현재 연결의 모델**을 변경할 수 있으며 영구 모델 설정은 수정하지 않습니다. 연결을 중지하거나 다시 시작하면 기본 모델로 돌아갑니다. **연결 다시 확인**은 실행 환경만 다시 확인하며 실패한 요청을 자동으로 재전송하지 않습니다.

화면이 좁으면 자료·결과는 **자료** 버튼으로 여는 패널에 표시합니다. 뉴모피즘의 부드러운 입체감에 테두리·텍스트 상태·키보드 초점을 함께 사용했습니다. 상세 설계와 검증 기록은 저장소의 `docs/WORKSPACE_REDESIGN_2026-09-28.md`에 있습니다.

## 처음 쓰는 사람을 위한 도우미

왼쪽의 **사용 도움말 → 첫 업무 따라 하기** 또는 **설정 → 나의 기억과 업무 방식 / 사용 현황과 결과 확인**으로 엽니다. 화면 열기·조회·통계에 별도 AI를 호출하지 않습니다.

1. **따라 하기:** 자료 읽기 → 결과 만들기 → 수정 → 선호 저장 → 새 대화 재사용의 5단계입니다. 예문 버튼은 입력창만 채우며 직접 보내야 실행됩니다. ‘직접 확인했어요’는 학습 진행 기록이지 업무 성공의 자동 판정이 아닙니다. 예문과 진행 확인은 기존 코스 JSON을 사용하며, 자세한 설명은 하나의 사용자 안내서에서 읽습니다.
2. **회사 공통 → 기억·지식:** 설치에 연결된 회사·팀의 배포 지식을 읽습니다. 사용자 화면에서는 수정하지 않습니다. 공동 쓰기·실시간 동기화 서버나 일반 프로젝트 문서 자동 수집 기능은 아닙니다.
3. **개인 전체 / 이 프로젝트 → 기억·지식:** 나의 선호·업무 맥락과 개인 업무 지식을 함께 관리합니다. 선호는 추가·수정·비활성화·이전 내용 복원안을 확인한 뒤 저장합니다. 지식은 출처·확인일을 붙여 초안으로 만들고 검토 후 활성화합니다. 검토용 내보내기는 로컬 ZIP이며 공통 반영·자동 전송이 아닙니다. 자동 학습 끄기·이력 복구를 지원하며 Claude 자체 기억과 합치지 않습니다.
4. **회사 공통 → 업무 구성:** 회사 기준·공통 스킬·후크 정의를 읽기 전용으로 확인합니다. 목록이나 정의 파일이 있다는 사실만으로 실제 CLI 실행을 보장하지 않습니다.
5. **개인 전체 / 이 프로젝트 → 업무 구성:** 개인·사용자·프로젝트·외부 플러그인 스킬은 출처별로, 내가 만든 도구는 등록 기록으로 확인합니다. 외부 설정·자격증명은 읽어 표시하거나 변경하지 않습니다. 폴더 지침 편집기는 목표·입력·결과·확인 기준만 `.claude/rules/company-workspace-brief.md`에 저장합니다. 기존 `CLAUDE.md`와 직접 수정한 지침은 보존하고 수정 전 버전은 개인 상태의 `workspace/brief-versions`에 남깁니다.
6. **사용 현황:** 현재 요청의 CLI 보고값과 사용자가 선택한 과거 JSONL 분석을 별도로 보여 줍니다. 누락은 ‘미제공’, 사내 모델 비용은 미추정입니다. 같은 메시지의 스트림 기록은 중복 제거하며 CLI 완료값·작업자·로그 합계를 서로 더하지 않습니다. CLI 버전에 따라 완료값이 누적일 수 있어 요청끼리 합산하지 않습니다. 다음 요청의 토큰 알림은 앱을 닫으면 해제되며 강제 비용 한도가 아닙니다.
7. **준비·결과 확인:** 설치·스킬 발견·지침 분량과 실제 업무 결과를 분리합니다. 사용자 확인 기록에서 실패·중지·차단·미확인을 빼고 성공률을 만들지 않습니다. 모델/평가 시 설치 버전별 관찰 그룹을 표시하되 전체 AI 성능 점수나 인과적 개선 증거라고 주장하지 않습니다. 실제 실행 당시 버전을 입증하지 못하면 평가 시 버전과 구별합니다.

이 소스의 Workspace 실행 코드 버전은 **0.11.4**입니다. 기존 0.9의 화면을 업무 중심 뉴모피즘 화면으로 교체하고 새 업무 공간, 업무 검색·고정·이름 변경, 부분 응답, 파일 변경 관찰, 연결 확인 및 연결별 모델 변경을 추가했습니다. Company Agent와 Workspace는 별도 배포 묶음이며 기존 설치·ZIP에 자동 적용되지 않습니다. 기존 앱을 종료한 뒤 승인된 새 Workspace ZIP을 별도 폴더에 풀어 실행하세요. Company Agent만 업데이트해도 이미 풀어 놓은 Workspace와 그 안의 안내서가 갱신되는 것은 아닙니다. 해당 기능이 없는 설치에서는 안내·일반 Claude 대화를 그대로 유지하고 설치 확인 필요만 표시합니다. UI가 임의로 다른 설치/상태 폴더를 선택하거나 플러그인을 설치하지 않습니다. 기존 memory/knowledge/brief API는 호환을 위해 유지합니다.

관리 화면은 기존 사용자 설치 등록과 Claude 설정 루트, 현재 작업 폴더에 맞는 프로젝트 등록을 확인합니다. 사용자 설치와 프로젝트 설치의 기억은 별개입니다. 터미널 호출 스크립트가 내부에서 환경변수를 다시 바꾸는 경우 시작 환경만으로 두 위치의 동일성을 보장하지 않으므로 등록을 확인해야 합니다. 모든 폴더에 스킬 파일을 복사할 필요는 없습니다.

**공통/내 것은 관리 주체, 기억/하네스는 내용의 역할, 프로젝트는 적용 범위**입니다. User 설치를 공통 소유로, 프로젝트 파일을 개인 소유로 추정하지 않습니다. 이번 화면 분리를 위해 기존 파일을 이동·복제·자동 공유하지 않습니다.

### 관리 화면의 자료는 어디에 있나요?

| 자료 | 기본 저장 위치와 범위 |
| --- | --- |
| 회사 공통 지식·스킬·후크 | 선택한 Company Agent의 버전 배포 폴더. 화면에서 읽기 전용으로 조회 |
| 개인 전체 | User 설치 등록의 상태 폴더. 기본값은 `%LOCALAPPDATA%/CompanyAgent/states/user` |
| 이 프로젝트 | User 설치는 위 상태의 `project-scopes/<폴더 해시>`, 별도 Project 설치는 해당 등록의 상태 폴더 |
| Workspace 자체 기록 | 기본 `%LOCALAPPDATA%/CompanyAgent/local-ui`. Company Agent 개인 기억 저장소나 Claude의 전체 기록과 별개 |

사용자 지정 상태 경로가 있으면 기본값 대신 설치 등록을 따릅니다. 같은 Claude 설정의 User 등록이 없는 Project 전용 환경에서는 개인 전체 저장을 사용할 수 없습니다. User의 프로젝트 저장은 정확한 작업 폴더별이며, 하위 폴더에서 자동 상속되거나 별도 Project 설치로 자동 이관되지 않습니다. 프로젝트 폴더를 동료와 공유해도 개인 상태 폴더가 함께 공유되는 것은 아닙니다.

명시적으로 저장하는 기억·지식·스킬·도구의 범위와 **자동 학습의 범위는 별개**입니다. 자동 학습은 현재 활성 설치의 상태에서 계속되며, 화면에서 프로젝트 항목을 한 번 저장했다고 이후 모든 학습이 그 범위로 바뀌지 않습니다. User 설치의 별도 프로젝트 자산은 자동 수정하지 않습니다. Company Agent 설치 전 선택 백업은 이 모든 폴더의 완전한 이사·복구 패키지가 아니므로 PC 교체 때는 담당자와 각 저장소를 따로 확인합니다.

공통 스킬은 작업 방법, 후크는 실행 시점의 안내·검사·기록을 담당합니다. 목록 표시·정의 조회·선택은 실제 도구 권한·회사 승인·실행 성공을 대신하지 않습니다. 세부 사용법은 화면에서도 연결되는 [사용자 안내서](Company-Agent-사용자-안내서.html)를 참고하세요.

저장은 **미리보기 → 명시 확인 → 현재 내용 해시 재확인**으로 진행합니다. 실행 중인 업무가 있으면 개인 기억/지침 변경을 잠시 보류합니다. 응답 시간 초과 때 저장 여부는 미확인으로 안내하며 원래 업무를 자동 재실행하지 않습니다. 외부 편집기의 동시 저장까지 전역 잠금하는 기능은 아닙니다.

관리 정보는 선택한 탭에서만 조회합니다. 따라 하기·현재 사용 현황은 하네스 조회 프로세스를 띄우지 않습니다. 공통·개인 지식은 저장소를 먼저 분리한 뒤 각 20개 단위로 조회합니다. 내 기억은 선호와 지식 각각 첫 페이지를 가져오며 ‘내용·출처 보기’ 또는 수정에서 선택한 본문을 표시합니다. 하네스 출처 목록은 해당 탭을 열 때만 확인합니다. 목록이 바뀌면 새로고침 안내를 하며, 확인 범위 한도에 도달하면 전체 목록이 아님을 표시합니다.

## 시작하기

1. 기존 Company Agent와 Claude Code, 회사가 승인한 Python 3.11 이상이 설치된 Windows에서 사용합니다.
2. 저장소 또는 ZIP을 풀어 놓은 Workspace 폴더의 **`Company-Workspace.vbs`를 평소처럼 더블클릭**합니다. 별도로 ‘관리자 권한으로 실행’을 선택할 필요는 없습니다. ZIP 미리보기 안에서 실행하지 마세요.
3. Edge가 있으면 독립 앱 모양의 창, 없으면 기본 브라우저가 열립니다.
4. ‘작업 폴더’를 선택하고 해당 폴더의 설정 실행에 동의합니다.
5. 파일 선택 → 요청 입력 → 필요한 질문/승인 응답 → 결과 확인 순서로 진행합니다.
6. **설정 → 앱 종료**로 연결된 작업과 로컬 서버를 종료합니다. 창의 X만 닫으면 서버는 남아 있으므로 다시 실행해 열린 작업을 확인할 수 있습니다.

새 ZIP으로 교체할 때도 먼저 기존 앱의 **설정 → 앱 종료**를 눌러 종료하세요. 다른 버전/폴더의 앱이 살아 있으면 구버전을 조용히 재사용하거나 진행 중 업무를 강제 종료하지 않고 안내합니다.

### 관리자 권한으로 감지되거나 시작할 수 없을 때

`WS-33`으로 중단되면 **별도 Workspace ZIP을 푼 폴더**에서 `Company-Workspace.vbs` 옆의 `Check-Workspace.cmd`를 일반 더블클릭해 읽기 전용 진단을 실행하세요. [결과 읽는 법](WORKSPACE_STARTUP_DIAGNOSTIC.md)을 참고하며, 진단만으로 회사 정책이나 권한이 변경되지는 않습니다.

평소처럼 더블클릭해도 PC의 실행 환경에 따라 관리자 권한으로 시작될 수 있습니다. 실행기는 Windows 사용자 식별자(SID), 로그인 세션, 프로필 경로가 현재 로그인한 본인과 일치하는지 먼저 확인합니다. 다른 계정, SYSTEM, 서비스 세션, 확인할 수 없는 사용자·프로필에서는 시작을 중단합니다. Claude 실행 파일이 발견됐다는 사실만으로 본인의 설정이라고 판단하지 않습니다.

본인 계정으로 관리자 권한이 감지된 경우에는 Windows가 제공하는 **같은 사용자의 일반 권한 UAC 연결 토큰**을 확인하고, 사용자·세션·프로필과 일반 권한 상태가 검증된 경우에만 한 번 다시 실행합니다. 재실행한 프로세스도 본인 계정과 일반 권한을 확인한 뒤 서버와 CLI를 시작합니다. 관리자 권한 상태에서 AI 업무를 계속하지 않으며, UAC·Windows 정책·Claude 인증·모델·MCP 설정을 변경하지 않습니다.

UAC가 꺼져 있거나 분리된 일반 권한 토큰이 없는 환경, 회사 정책이 필요한 Windows 기능을 차단하는 환경에서는 자동 재실행이 불가능할 수 있습니다. 이때 재실행을 반복하지 않고 **실제로 확인된 이유를 한국어로 안내하고 중단**합니다. 회사 담당자에게 해당 안내 내용을 전달해 승인된 일반 권한 실행 환경을 확인하세요. 모든 Windows·보안 정책 조합에서 자동 복구된다는 의미는 아닙니다.

시작 실패 안내는 최초 실행기가 한 번 표시합니다. 이미 안내한 종료 코드 `20`은 VBS에서 다시 표시하지 않습니다. Python 버전·경로 검사가 실제로 실패한 경우에만 Python 안내를 표시하며, 다른 시작 실패를 Python 문제로 단정하지 않습니다. `-NoBrowser`로 실행할 때는 같은 이유를 콘솔 오류로 확인할 수 있습니다.

### 작업 중지와 종료 확인

작업 중지는 앱이 시작한 CLI 연결을 대상으로 합니다. 이미 만든 파일·완료된 외부 작업을 되돌리는 기능은 아닙니다. 종료를 확인하지 못하면 성공한 중지로 표시하지 않고 연결 상태 확인이 필요하다고 알립니다.

종료 시 입력 연결을 닫고 최대 0.3초 정상 종료를 기다립니다. 계속 실행 중이면 Windows에서 기존 소유 PID의 트리 종료를 시도하고, 실패하면 앱이 보유한 프로세스 핸들만 종료한 뒤 실제 종료를 기다립니다. 이름으로 프로세스를 검색하거나 다른 Claude·Office 프로그램을 찾아 종료하지 않습니다.

트리 종료가 실패한 경우에는 직접 시작한 CLI 프로세스의 종료만 확인할 수 있습니다. 모든 하위 프로그램까지 닫혔다고 보장하지 않으므로, 문서 프로그램이나 외부 작업이 남았다면 실제 상태를 확인하세요. 종료 실패 후 같은 쓰기 작업을 무조건 다시 보내지 않습니다.

### 원본 경로와 실행 환경

원본 파일을 복사하지 않고 정확한 경로를 전달합니다. 브라우저의 일반 파일 업로드처럼 원본을 임시 복사하지 않습니다. 경로 직접 입력도 지원하며, 웹 드래그 앤 드롭은 아직 지원하지 않습니다.

조직에서 VBS 또는 PowerShell 실행을 차단하면 이를 우회하지 말고 승인된 배포 방식으로 실행기를 배포해야 합니다. CLI 로그인이나 인증서·회사 게이트웨이 설정이 필요하면 기존 조직 안내를 따릅니다. 앱은 비밀번호/API 키를 새로 수집하지 않습니다.

개발자 실행(본인의 일반 권한 터미널에서 실행):

```powershell
python -X utf8 -m local_app.server
# 가상 화면 체험: 실제 AI/문서 작업 없음, 별도의 demo 기록 사용
python -X utf8 -m local_app.server --demo
```

더블클릭 실행기는 현재 사용자의 Windows PowerShell 시작 프로필을 적용한 뒤 `Get-Command claude`로 실제 호출 대상을 선택합니다. 별칭, 프로필 함수, `.cmd`/`.ps1` 실행 스크립트도 존중하며, 스크립트를 건너뛰고 별도의 npm 실행 파일을 선택하지 않습니다. 같은 사용자의 일반 권한으로 다시 실행할 때도 CLI 환경과 프로필 연결을 유지하고, 환경 전달은 메모리에서만 처리합니다. 다른 사용자 프로필이나 별도 Claude 인증 저장소는 만들거나 검색하지 않습니다. `CLAUDE_CONFIG_DIR`, 모델·회사 연결·인증 환경변수는 그대로 상속하고, 환경값이나 인증 파일을 앱의 상태 파일로 복사하지 않습니다. 기존 `COMPANY_AGENT_CLAUDE` 명시 지정은 호환용으로 유지하지만 일반 사용자가 새로 설정할 항목은 아닙니다.

Windows PowerShell과 다른 실행 환경(WSL/Linux, Git Bash 전용 프로필, VS Code 전용 환경, 특정 터미널에서만 임시로 만든 변수·함수)은 자동으로 동일하다고 가정할 수 없습니다. 해당 환경만 정상이라면 재로그인부터 요구하지 말고 CLI 경로·설정 위치·실행 환경 차이를 확인해야 합니다. 화면의 ‘연결 상태와 작업 기록’에서 실행 경로와 상속한 설정 위치를 확인할 수 있습니다. 기존 호출 스크립트가 그 안에서 설정 위치를 변경할 수도 있으므로 이 값은 시작 환경 기준입니다.

OAuth 만료 등 실제 인증 오류가 발생하면 앱이 소유한 실패 연결만 종료합니다. 터미널에서 기존 인증을 갱신한 후 사용자가 다시 보내면 새 CLI 프로세스가 같은 로그인 저장소를 다시 읽습니다. 앱 재설정, 별도 로그인, 요청 자동 재전송, 반복 인증 확인용 모델 호출은 하지 않습니다. ‘기존 Claude 사용’ 표시는 실행 파일 확인이며 모델 응답/인증 성공의 증거가 아닙니다.

## 보안 및 기록

### 현재 폴더의 구성 한눈에 보기

작업 폴더 선택 후 **기억·하네스 관리 → 구성 한눈에**를 누르면 **회사 공통 / 개인 전체 / 이 프로젝트**를 나란히 표시합니다. 각 영역의 스킬·지침·후크·도구(MCP)·에이전트·기억·학습 저장소를 펼쳐 이름, 저장 위치, 공유 여부를 확인합니다. 목록은 이 버튼 또는 새로고침을 누를 때만 읽으며 모델 호출과 설정 변경은 없습니다.

- **설정 켜짐**: 로컬 활성 설정이 확인됨. CLI가 실제로 로드했다는 뜻은 아닙니다.
- **사용 가능**: 스킬 후보 또는 사용 상태의 기억. 현재 요청에서 실제로 사용했다는 뜻은 아닙니다.
- **정의 발견**: 파일이나 MCP/후크 등록 정보만 확인됨. 연결·인증·실행은 미시험입니다.
- **꺼짐 / 제외**, **초안 / 미적용**, **선택 필요**, **확인 필요**: 확인된 설정과 불확실성을 별도로 표시합니다.
- **본문 로드 기록**: 현재 대화 ID·현재 폴더·스킬 식별자·본문 해시가 모두 맞는 기존 기록만 표시합니다. 별도 작업자가 읽은 본문을 부모 대화가 읽은 것으로 합치지 않습니다. 적용 성공이나 결과 정확성을 뜻하지 않습니다. [스킬 본문 확인 범위](SKILL_PRIORITY.md#본문-로드와-실제-적용의-구분)를 참고하세요.

**구성 지도 HTML 저장**으로 조회 시점의 화면을 보관할 수 있습니다. 파일에는 로컬 경로와 항목 이름이 포함되므로 공유 전에 검토하세요. 대화 원문·기억 본문·MCP 명령·토큰·환경변수는 내보내지 않습니다. 저장한 HTML은 자동 갱신되지 않습니다.

구성 지도는 1.4.16부터 지원합니다. 현재 배포 조합을 함께 적용하면 앱에서 사용할 수 있습니다. 구버전 코어는 업데이트 안내만 표시하며 설정을 고치거나 대신 설치하지 않습니다. CLI에서는 등록된 진입점 뒤에 `context map --project "현재 폴더의 절대경로" --output "새 지도.html의 절대경로"`를 붙여 만들 수 있습니다. 출력 폴더는 이미 존재해야 하며 같은 파일을 덮어쓰지 않습니다. Company Agent 등록이 없으면 일반 Claude 파일 정의만 표시하고 회사 기능을 활성으로 꾸미지 않습니다.

서버/OS 관리 정책, 세션 실행 옵션, 다른 프로필, 원격·동적 도구와 전체 내장 스킬, CLAUDE.md의 참조 확장, 다른 프로젝트의 자동 기억은 조회 범위 밖입니다. 최종 적용은 해당 CLI의 `/status`, `/skills`, `/hooks`, `/mcp`, `/memory`와 실제 업무로 확인합니다. [공식 설정 범위](https://code.claude.com/docs/en/settings)와 [MCP의 개인·프로젝트 범위](https://code.claude.com/docs/en/mcp)를 기준으로 파일 발견과 실제 연결을 구분했습니다.

### 대화와 자료 보호

- `127.0.0.1` 임의 포트에만 바인딩하며 외부 공개/릴레이 기능이 없습니다.
- 매 실행 시 생성한 토큰으로 모든 API를 인증합니다. 브라우저 접속 후 주소의 토큰은 지우고 탭 저장소에만 보관합니다.
- Host/Origin/cross-site 확인, CSP 적용. 모델 출력은 HTML로 실행하지 않습니다.
- 파일 열기는 선택한 작업 폴더 또는 사용자가 첨부한 정확한 경로의 문서 확장자만 허용합니다. GUI 파일 접근 범위는 CLI 자체의 권한/샌드박스를 대체하지 않습니다.
- 실행 파일/스크립트·HTML의 자동 실행은 지원하지 않습니다. 재분석만 위해 원본을 덮어쓰거나 인코딩을 손실 변환하지 않습니다.
- `%LOCALAPPDATA%\CompanyAgent\local-ui\history-sessions\<대화 ID>.json`에 대화별로 저장하고 `history-index.json`에는 최근 최대 500개 대화 목록만 둡니다. 갱신된 대화만 저장하며 각 대화는 최대 150개 메시지·본문과 파일 경로 합계 50만 자로 제한합니다. 기존 `history.json`은 다음 정상 저장 때 이전하되 원본은 삭제하지 않습니다. 목록에서 오래되어 빠진 대화 파일도 자동 삭제하지 않습니다. 손상된 기록은 덮어쓰지 않고 새 앱 기록 저장 중지 안내를 표시합니다. CLI 자체 기록은 별개이며, 업무 원문의 이중 보존은 조직 보존 정책에서 검토해야 합니다.
- 승인 요청 원문과 표준 오류, 인증 정보, 전체 도구 결과를 별도의 앱 로그에 저장하지 않습니다. 모델의 일반 답변에 포함된 정보는 대화 기록에 남습니다.
- 새 사용량 스냅샷과 선택 로그 분석은 메모리에만 두며, 기존 대화 보존 정책을 바꾸지 않습니다. 사용자가 직접 확인한 코스 단계/결과만 `local-ui/learning-progress/<폴더 해시>.json`에 최대 100건 보관합니다. 원문·파일 경로·토큰 로그는 이 기록에 저장하지 않습니다. 모델 이름과 평가 시 설치 범위의 해시/버전은 로컬 비교용으로 남습니다.
- ‘확인 기록만 비우기’는 해당 폴더의 학습 진행과 자기 평가만 초기화합니다. 대화 이력·기억·지식·산출물은 보존됩니다. 먼저 원문 없는 확인 기록을 내려받을 수 있습니다. 내려받은 기록은 외부로 자동 전송되지 않습니다.
- 로컬 UI라는 것은 **모델 추론도 오프라인이라는 뜻이 아닙니다.** 기존 Claude/HCP 연결로 요청이 전달됩니다.
- 앱 상태 저장은 현재 사용자의 LOCALAPPDATA 권한을 상속합니다. 공유 계정/공유 프로필 배포는 지원 대상이 아닙니다.

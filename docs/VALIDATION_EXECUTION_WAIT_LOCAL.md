# 관리자 전환 대기 보완 — 0.23.20 동일 버전 수정 배포

2026-10-06. 초기 `v0.23.20`의 관리자 전환 대기를 보완한 동일 버전 수정 기록입니다. 수정 커밋·태그·EXE/VBS ZIP·체크섬·사내 배포 이력을 함께 갱신합니다. 초기 0.23.20 파일과 수정 파일은 해시와 내부 실행 권한 프로토콜로 구분합니다.

## 재현과 변경

- PowerShell `Start-Process -Wait`는 하위 프로세스 종료도 기다립니다. 권한 전환 담당자가 후속 앱을 시작하거나 기존 업무를 기다리면 호출자가 계속 `requesting`으로 남을 수 있어, 담당 프로세스만 `WaitForExit()`로 기다리도록 변경했습니다. Windows 승인·같은 계정·세션·실제 토큰 검증은 유지합니다. [Microsoft 설명](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/start-process?view=powershell-5.1)
- UAC 경계만 가상으로 바꾼 자체 부모·자식 프로세스 검사에서 이전 코드가 자식이 살아 있는 동안 제한 시간을 넘겼고, 수정 코드가 부모 종료 코드 17을 반환하면서 자식의 생존을 확인했습니다. 실제 관리자 프로세스는 시작하지 않았습니다.
- 전환 중 설정 창을 다시 열면 기존 초안 보관의 `dialog[open]` 조건이 전환을 막았습니다. 서버가 초안 보관 단계에 도달하면 설정 창만 닫아 보관을 이어갑니다. 다른 질문·승인·파일 선택창의 우선순위는 유지합니다.
- Windows 권한 확인·전환 연결·작업 완료 대기·작성 내용 보관·앱 재시작을 구분해 표시합니다. 해당 요청의 전환 실패 기록은 원래 호출자의 대기가 끝나기 전에도 반영하며, 다른 요청의 결과로 현재 전환을 취소하지 않습니다.

## 확인 결과

- 권한 전환·화면·진단 34개 검사: 33개 통과, 실제 사용자 진단 옵트인 1개 생략.
- 초안 보관 통합·기존 업데이트·시작 100개 검사 통과. 설정을 다시 열어도 입력·첨부를 보관하고, AI 요청 없이 전환 캡처가 이어지는지 확인했습니다.
- 이전 동작을 이용한 대조 검사에서 하위 프로세스 대기를 재현했습니다. 증거는 로컬 `build/qa-execution-wait/negative-control.json`입니다.
- 시작 헬퍼 변경에 맞춰 로컬 진단 표기 `ws33-56`과 고정 소스 해시를 함께 갱신했습니다. 공개 0.23.20의 `ws33-55` 기록과 혼동하지 마세요.
- 같은 버전의 초기 프로토콜 1 앱을 수정 프로토콜 2 앱으로 교체합니다. 이미 수정된 같은 버전과 더 높은 버전·프로토콜은 우선하며, 이전 파일로 다시 낮추지 않습니다. 버전은 0.23.20이며 자동 업데이트는 버전 비교를 사용하므로 기존 사용자는 새 ZIP을 직접 받아 실행해야 합니다.

동일 버전 수정 배포 검사 232개 중 230개 통과, 환경 조건부 2개 생략. 실제 초기 프로토콜 1 EXE를 수정 프로토콜 2 EXE로 교체하고 수정 EXE의 일반 권한 전용 창·재실행 재사용·정상 종료를 확인했습니다. 별도 상태·캐시와 체험 모드를 사용했고 실제 AI 호출은 0회입니다. 배포 파일 해시는 [현재 검증 기록](VALIDATION_0.23.20.md)에 있습니다.

실행 중인 문제 앱은 이 검증 PC에서 발견되지 않아, 해당 PC의 실제 전환 단계와 UAC 이후 오류 기록을 직접 확인한 것은 아닙니다. 실제 UAC 승인 → 관리자 앱·Claude 실행 → 일반 권한 복귀의 전체 왕복도 아직 미검증입니다. Windows·Claude 개인 설정을 변경하거나 사용자 업무를 종료하지 않았습니다.

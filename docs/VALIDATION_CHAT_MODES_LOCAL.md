# 일반 대화·업무 전환 로컬 검증 — 2026-10-16

이 문서는 2026-10-16 당시 0.23.26 소스에 적용한 로컬 수정의 검증 기록입니다. 당시에는 버전·Git 커밋·원격 Release를 변경하지 않았습니다. 이후 변경을 포함한 0.23.27 배포 검증은 [0.23.27 검증 기록](VALIDATION_0.23.27.md)을 참고하세요.

## 반영 범위

- A2 색상: 기존 좌우 패널과 뉴트럴 중앙 화면, 라이트·다크 동시 적용.
- 일반 대화/업무 선택, 종류별 목록·검색·선택·초안, 간결한 사이드바와 이름 수정.
- 일반 대화는 폴더 선택 없이 대화별 소유 공간을 생성. 첨부한 사본의 내용만 전달.
- 일반 대화의 도구·MCP·스킬·슬래시 실행 기능 제한. 기존 업무의 CLI 설정·인증·도구 동작 유지.
- 확인 후 대화 연결 중지 및 앱 기록·초안·알림·전용 폴더·추출 캐시·첨부 사본 삭제. 원본과 다른 업무 보존.
- 소유권·경로 검증, 진행 중 파일 처리와 삭제의 경합 방지, 잠긴 파일의 다음 실행 정리.
- 기존 연결 풀을 공유하고 추가 폴링·파일 감시·설정 동기화 프로세스를 만들지 않음.

## 실제 실행 검증

현재 PC의 Claude Code **2.1.296**과 기존 인증을 사용했습니다. 사용자 자료 대신 생성한 작은 테스트 자료만 전달했습니다.

1. 실제 `LocalApp`에서 일반 대화 생성 → 파일 사본 업로드 → 내용 준비 → Claude 전송을 수행했습니다.
2. TXT·PNG·PDF·DOCX·PPTX·XLSX 각각에만 넣은 검증 문구 6개를 응답에서 확인했습니다. 처리 시간은 해당 테스트에서 4.51초였습니다.
3. 초기화에서 tools·MCP·skills 목록이 비어 있고 승인 모드 변경이 비활성임을 확인했습니다.
4. 별도 실제 CLI 검사에서 `/model`과 `!` 시작 입력이 텍스트로 전달되고 로컬 명령 파일이 생성되지 않는 것을 확인했습니다.
5. 삭제 확인 후 자식 연결 종료, 앱 기록·전용 공간·캐시·업로드 사본 제거, 원본 SHA256 유지, 정리 대기 목록 비움을 확인했습니다.

실제 브라우저와 격리된 demo HTTP 서버에서도 생성·업로드·읽기 범위 표시·화면 전환·삭제를 검증했습니다. 이 화면 테스트의 AI 응답은 명시적인 체험 응답이며, 실제 모델 검증은 위 과정으로 따로 수행했습니다. 브라우저 오류는 없었습니다.

## 회귀·경계 검증

- 새 일반 대화 저장/복원과 기존 기록의 업무 기본값.
- 다른 대화의 사본·임의 파일 경로·변조된 소유 정보·정션 접근 거부.
- 실행 중 해당 연결만 종료, 다른 업무 연결과 원본 보존.
- 잠긴 파일 정리 보류 및 다음 앱 실행 재시도.
- 유휴 연결 회수 후 일반 대화 재연결. 업무용 승인 모드를 복원하지 않음.
- 삭제·첨부 준비 중인 대화를 연결 교체 후보에서 제외.
- 파일·XML·ZIP·이미지·요청 전체 크기 제한, 첨부 실패·일부 읽음 표시.
- 전환 시 신규 Claude 연결을 자동 생성하지 않음. 홈 초안과 업데이트 복원 모드 분리.
- 삭제된 대화의 늦은 초안 저장 응답이 기록·오류 표시를 다시 만들지 않음.
- 일반 대화 중지·오류는 업무 대기열에 기록하지 않음. 앱 종료 후 늦은 연결 콜백의 파일 쓰기 차단.
- 라이트·다크, 작은 창, 사이드바 이름 변경, 기존 폴더 정리 동작.

전체 회귀 2,706건을 먼저 실행했고 45건은 선택적 설치·회사 플러그인·Windows 심볼릭 링크 권한 등 실행 조건에 따라 제외되었습니다. 이 과정에서 오래된 테스트 모의 데이터·인코딩 문제, `.markdown` 파일 선택기 누락, 종료 직후 콜백의 기록 쓰기 경합을 발견했습니다. 해당 항목을 수정하고 실패한 검사 그룹 전체와 새 대화·첨부·초안 경계를 최종 소스로 다시 검증했습니다. 최초 실행 결과와 최종 재검사 결과는 각각 `build/qa-chat-modes-regression-current-user.json`, `build/qa-chat-modes-recheck.json`에 구분해 보관합니다.

최종 통합 재검사는 **191건 중 190건 통과, 1건 제외**, 실패·오류 0건입니다. 제외된 검사는 Windows 토큰의 심볼릭 링크 생성 권한이 필요한 항목이며, 별도 NTFS 정션 경계 검사는 통과했습니다. 화면 검증은 최종 소스 기준으로 UI 12항목과 실제 HTTP·파일 처리 7항목이 통과했으며 브라우저 오류가 없었습니다. 첨부·연결 풀·대기열 등 관련 검사도 별도로 수행했습니다. 위 수치는 중복 검사를 합산한 총 통과 수가 아닙니다.

## 배포·사용 범위

로컬 ZIP·EXE에 새 모듈과 가이드를 포함하고 번들 목록 및 EXE 내장 자료의 해시를 검사합니다. 같은 버전 수정본을 시험할 때는 기존 앱을 트레이에서 완전히 종료한 뒤 새 로컬 EXE를 실행하세요.

일반 대화는 기존 인증·회사 연결을 사용하지만 개인 프로젝트 도구·설정은 실행하지 않도록 CLI 제한을 적용합니다. 회사의 필수 관리 정책은 유지되며 OS 수준의 샌드박스는 아닙니다. PDF 지원은 연결된 모델·서버에도 의존합니다. 앱이 관리하는 기록 삭제와 Claude 자체 세션 기록 삭제는 별개입니다.

사용 안내: [일반 대화와 업무](WORKSPACE_CHAT_MODES.md), [화면 사용 안내서](WORKSPACE_USER_GUIDE.html).

## 일반 대화 홈과 승인 흐름 추가 확인

일반 대화 홈에 브랜드 심볼·은은한 배경, 네 가지 시작 질문, 최근 대화 카드를 구성했습니다. 업무용 시작 제목이 일반 대화에 남던 선택자 오류를 수정하고 카드와 입력창의 너비를 맞췄습니다. 효과는 CSS·기존 SVG만 사용하며 추가 상주 프로세스·폴더 감시·네트워크 요청을 만들지 않습니다.

- 공유 UI·업데이트·재시작 복원·초안·모드 관련 회귀 **104건 통과**.
- 실제 Edge에서 라이트·다크, 1440·680·420px 화면, 긴 제목, 빈 목록, 최근 대화 열기, 업무 화면 보존 등 **12항목 통과**, 브라우저 오류 0건.
- 시작 질문은 입력창에만 추가하며 작성 중인 글과 첨부를 보존합니다. 선택만으로 생성·연결·전송하지 않는 것을 확인했습니다.
- 일반 대화 실행·첨부·폴더 정리 검사는 **59건 중 58건 통과, Windows 심볼릭 링크 권한 조건 1건 제외**. 실제 localhost HTTP와 모의 CLI로 첨부·전송·삭제·외부 경로 보호를 확인했습니다.
- 설치된 Claude Code 2.1.296의 도움말과 실제 실행 인자를 확인했습니다. 일반 대화는 앱이 첨부 사본을 읽어 내용으로 전달하므로 Claude의 파일별 승인창이 필요하지 않습니다. 예외적 도구 승인 요청도 UI에 표시하지 않고 거절합니다. Windows ACL·전역 Claude 설정은 변경하지 않습니다.

이번 홈·권한 재검사에서는 실제 모델 질의를 실행하지 않았습니다. 앞선 실제 모델·파일 형식 검증과 구분합니다. 홈 시안은 Microsoft Copilot의 [최근 대화 중심 홈](https://blogs.windows.com/windows-insider/2025/08/20/copilot-on-windows-semantic-search-and-new-homepage-begin-rolling-out-to-windows-insiders/)과 [시작 질문](https://learn.microsoft.com/en-us/microsoft-copilot-studio/configure-starter-prompts) 구성을 참고했습니다.

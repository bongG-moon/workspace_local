# 0.23.4 — 시작 업데이트 안내와 프로젝트 소스 게시

## 사용자 동작

- 앱 창을 열 때 자동 확인 설정을 존중해 새 버전을 조회합니다. 평상시 12시간 캐시와 별도로 시작 확인은 60초 공통 제한을 적용합니다. 포커스 이동은 서버의 로컬 상태만 조회합니다.
- 새 버전의 변경 내용과 **업데이트하기 / 다음에 하기**를 표시합니다. 다운로드는 명시적인 업데이트 버튼에서만 시작합니다. 같은 창에서 닫은 안내는 반복하지 않으며 창을 명시적으로 다시 열면 다시 제안할 수 있습니다.
- 숨겨진 창, 다른 팝업, 입력·전송·승인 처리 중에는 자동 안내를 미룹니다. 변경 내용은 실행 가능한 HTML로 넣지 않습니다.
- 사내 배포 창의 **프로젝트에 소스·구성 파일도 함께 올리기**는 기본으로 켜져 있습니다. HTTPS 주소와 숫자 프로젝트 ID를 그대로 사용하며 소스 게시에는 `api` 범위와 기본 브랜치 쓰기 권한이 있는 Access Token이 필요합니다.
- **고급 설정 → 구성 파일만 올리기**는 SDK나 EXE 빌드 없이 소스만 게시합니다. Deploy Token으로 패키지만 게시할 때는 소스 게시 선택을 해제합니다.
- 소스 게시 후 배포 ZIP, 익명 다운로드 검증, 최신 채널 순서로 진행합니다. 원격 소스 충돌이나 권한 오류이면 패키지 게시로 넘어가지 않습니다. 만들어 둔 설치 파일은 재시도에 사용합니다.

## 소스 보존과 확인

검증된 원본 목록의 소스와 목록 파일만 한 커밋으로 게시합니다. 처음 README만 있는 프로젝트는 원본 README로 교체하고, 기존 소스가 사내에서 별도로 수정됐다면 충돌로 중단합니다. 소스 목록 밖의 파일과 기존 커밋 이력은 유지하며 삭제·강제 푸시·브랜치 정책 변경은 하지 않습니다. GitHub 전체 커밋 이력을 복제하는 기능은 아닙니다.

소스의 전체 경로와 부모 폴더 대소문자 충돌, 연결 파일, 비밀 설정 경로, 빌드와 원본의 불일치를 확인합니다. 커밋 뒤 해당 커밋에 고정된 ZIP을 읽어 모든 파일의 SHA256을 검증합니다. 토큰은 설정·로그·배포 앱에 넣지 않습니다. 한 번에 64 MiB 소스, 96 MiB 요청 및 원격 ZIP으로 제한합니다. 서버가 요청을 거절하면 원문 응답이나 토큰을 표시하지 않고 상태와 조치를 안내합니다.

## 검증 결과

- 업데이트 백엔드·경로·프런트엔드, GitLab 채널, 설치·패키징, 게시·GUI·CLI·SDK·압축·시작 진단 결합 검사: **293개 중 290개 통과, 환경 조건 3개 생략**.
- 최종 소스 게시·GUI·CLI·소스 연동·릴리스 기록 집중 검사: **100개 통과**. 위 결합 검사와 겹치는 항목이 있으며 합계로 더하지 않습니다.
- 시작 팝업 전용 32개 검사는 숨김·다른 팝업·입력 대기, 자동 확인 해제, 새 창의 재안내, Escape·포커스 복원, 오류, 변경 내용의 HTML 실행 방지를 포함합니다.
- 소스 게시 전용 15개 검사는 README 초기 프로젝트, 빈 프로젝트와 기본 브랜치, 같은 소스 재시도, 원격 수정·삭제·대소문자·부모 경로 충돌, HTTP 오류 및 토큰 비노출, 페이지별 파일 목록, 커밋 ZIP 검증을 포함합니다.
- 전체 원본 소스를 모의 GitLab에 한 커밋으로 게시하고 원격 ZIP의 모든 파일 해시가 일치하는 것을 확인했습니다. 실제 사내 네트워크나 토큰은 사용하지 않았습니다.
- 별도 검증용 앱을 브라우저로 조작해 시작 팝업, 변경 내용과 버튼 배치, 다음에 하기 후 화면 복귀·반복 표시 방지, 새 페이지 시작 후 재안내, 명시적인 버튼의 설치 요청·오류 안내를 확인했습니다. UI 검증에서는 실제 앱 설치를 실행하지 않았습니다.
- Windows에서 EXE 내장 파일 추출 검증과 EXE/VBS 공통 파일 **124개** 일치를 확인했습니다. Python은 포함하거나 설치하지 않습니다.

## 사내 적용과 남은 확인

Package Registry의 `company-workspace-channel/0.0.0/latest.json`이 버전·변경 내용과 배포 파일을 가리킵니다. **GitLab Releases 화면에 항목이 없어도 업데이트에 사용할 수 있습니다.** 0.23.2와 0.23.3은 시작 팝업이 없으므로 새 사내 버전을 게시한 뒤 설정의 **앱 업데이트 → 지금 확인**으로 먼저 설치해야 합니다.

실제 사내 GitLab의 버전·보호 브랜치·프록시 크기 제한·토큰 권한과 PC의 Python 3.11.5 조합은 현장에서 확인해야 합니다. 로컬 Windows 검증은 Python 3.13에서 수행했습니다. PC 보안 설정과 기존 Claude 인증·개인 설정은 변경하지 않습니다.

# Company Agent 시작하기

명령어 암기보다 작은 업무 하나를 맡기고 직접 확인하는 연습입니다.

처음에는 **1단계: 가상 자료 만들고 읽기**만 해보세요. 회사 자료나 참고 파일은 필요 없습니다. 익숙해지면 보고서 만들기, 기억 저장, 내 스킬 만들기로 이어갈 수 있습니다. 필요한 단계만 골라 진행하세요.

**먼저 세 범위만 구분하세요.** 회사 공통 / 개인 전체 / 이 프로젝트 안에서 기억·지식과 업무 구성을 확인합니다.

| 구분 | 쉬운 예 | 내가 할 수 있는 일 |
| --- | --- | --- |
| 회사 공통 | 배포 지식·회사 기준·공통 스킬·후크 | 읽기, 담당자에게 수정 제안 |
| 개인 전체 | 여러 프로젝트에서 사용할 선호·지식·개인 자산 | 범위 선택 후 저장·수정·사용 중단 |
| 이 프로젝트 | 이 업무에서만 사용할 기억·스킬·도구·지침 | 개인 자산과 공유 프로젝트 파일을 구분해 관리 |

**새로 저장할 때는 두 선택지입니다.** 개인 전체(여러 프로젝트) / 이 프로젝트(현재 작업에서만). 범위를 말하지 않았다면 한 번 질문하고 답변을 기다립니다. 이미 명시했다면 다시 묻지 않습니다. 회사 공통은 직접 저장하지 않습니다. ‘전역’이라고 모두에게 공유되지 않고 폴더에 있다고 모두 개인 소유도 아닙니다. 프로젝트 개인 자료는 로컬 개인 저장소에 있어 폴더 공유만으로 전달되지 않습니다.

실제 위치는 **기억·하네스 관리 → 구성 한눈에**에서 확인합니다. 회사 공통은 연결된 배포본, 개인 기억·자산은 선택한 로컬 저장소, 폴더 지침은 프로젝트 파일입니다. Claude 자체 자동 기억은 Company Agent 기억과 별도입니다. 기본 스킬 11개와 후크 7개의 역할·한계는 [핸드북](COMPANY_AGENT_HANDBOOK.md) 4~5장에서 확인할 수 있습니다.

**단계 고르기:** 0–5는 첫 업무, 6은 공통 기억·내 기억 비교, 7은 폴더별 적용 범위 비교, 8은 내 스킬·도구 만들기입니다. 생성·저장 예문을 보내면 실제 파일이나 기억이 생기므로, 실습 후 정리 방법도 확인하세요.

## 0. 준비하기

회사에서 사용을 승인한 Claude Code와 Python 3.11 이상이 필요합니다. 회사 모델·인증서·로그인 설정은 조직 안내를 따릅니다. Node.js·Git은 모든 직원 업무의 필수 준비물이 아닙니다. 필요한 앱과 라이브러리는 업무마다 다릅니다.

1. 기존 Claude Code가 정상 작동하는지 확인합니다. 이미 된다면 로그인·모델·API 키를 새로 설정하지 않습니다.
2. 승인된 Company Agent 직원 ZIP 전체를 풀고 `Install-CompanyAgent.cmd`를 실행합니다. “Claude 전체”와 “이 프로젝트만” 중 필요한 범위를 선택합니다. 다른 하네스 교체를 선택할 때는 백업과 변경 범위를 먼저 읽습니다.
3. 설치 후 Claude Code를 다시 엽니다. Workspace는 별도 미리보기 묶음입니다. 그 묶음의 `Company-Workspace.vbs`를 더블클릭합니다. 관리자 권한은 사용하지 않습니다.
4. 탐색기에서 새로운 빈 연습 폴더를 만들고 작업 폴더로 선택합니다. 실제 고객 자료·메일·공용 폴더는 연습에 쓰지 않습니다.
5. 신뢰하는 폴더인지 확인합니다. 이 동의는 모든 후속 행위를 무조건 허용한다는 뜻이 아닙니다.

**성공 확인:** 앱이 열리고 작업 폴더가 보입니다. AI 응답과 실제 업무 결과는 다음 단계에서 확인합니다. VBS·PowerShell 실행이 회사에서 제한돼 있으면 담당자에게 승인된 실행 방식을 요청하세요.

**원본 CLI를 선호한다면:** 기존 방식으로 해당 폴더의 Claude Code를 열고 아래 요청문을 입력합니다. `/plugin`, `/skills`, `/hooks`로 실제 등록을 확인할 수 있습니다. GUI가 이 터미널 메뉴 전부를 그대로 제공하는 것은 아닙니다.

## 1. 자료 하나 읽기

가지고 있는 파일이 없어도 시작할 수 있습니다. **먼저 가상 자료를 만들고, 다음 요청에서 읽습니다.** 생성과 읽기를 나누면 방금 만든 내용을 기억해서 답한 것인지 실제 파일을 읽었는지 비교하기 쉽습니다.

### 1-1. 준비물 없는 가상 자료 만들기

Office·참고 PPT·회사 자료가 필요 없는 첫 실습입니다. 빈 연습 폴더에서 아래 요청을 보냅니다. 다음 단계에서 쓸 파일은 이것 하나면 됩니다.

```text
실습용 가상 자료를 실습_가상자료.md 한 파일로 만들어줘.
회사 시스템·메일·다른 파일을 조회하지 말고 다음 내용만 사용해줘.
제목: 실습용 월간 실적 (가상 자료)
단위: 건. 6월 목표 100, 실적 90 / 7월 목표 100, 실적 110 / 8월 목표 100, 실적 130.
목표 합계 300, 실적 합계 330, 누적 달성률 110%를 계산해서 대조해줘.
가상 회의 메모: 점검표 수정 완료. 현장 확인 진행 중. 새 양식 적용일은 미정.
가상 비교 문구: 이전안은 월 1회 점검, 변경안은 월 2회 점검. 그 외 조건은 동일.
원인·연도·실제 사람 이름은 추가하지 마. UTF-8로 저장해줘.
같은 이름의 파일이 있으면 덮어쓰지 말고 기존 파일을 사용할지 먼저 물어봐줘.
실제 만든 파일 경로와 계산 확인 결과만 알려줘. 기억이나 회사 지식에는 저장하지 마.
```

**성공 확인:** 가상 자료라는 표시와 위 수치·문구를 확인합니다. 이 과정은 파일 쓰기·계산 연습입니다. 작업 폴더가 비어 있다면 하네스가 기본 `CLAUDE.md`를 만들 수도 있습니다. 이는 업무 결과 파일이 아닌 프로젝트 시작 안내입니다.

### 1-2. 만든 파일을 실제로 읽어 보기

```text
방금 만든 실습_가상자료.md 파일을 실제로 읽고 핵심 내용과 확인할 사항을 정리해줘.
다른 이름으로 저장됐다면 앞서 확인한 실제 경로만 사용해줘.
대화에 있는 수치를 그대로 답하지 말고 파일을 읽은 범위를 알려줘.
자료에 없는 이유는 추측하지 마. 원본 파일·설정·기억은 변경하지 마.
```

CLI에서는 `@`로 실제 파일을 고르고, Workspace에서는 **파일 선택**으로 첨부해도 됩니다. 파일을 만들고 싶지 않거나 쓰기 권한이 없다면 아래 텍스트 연습만 해도 됩니다.

```text
다음 가상 자료를 요약해줘.
6월 목표 100건·실적 90건, 7월 목표 100건·실적 110건, 8월 목표 100건·실적 130건.
자료에 없는 이유는 추측하지 마. 실제 확인한 범위와 미확인 부분을 알려줘.
이 작업은 대화에 입력한 텍스트를 요약하는 연습이야.
```

**성공 확인:** 세 달 수치가 맞고 증가 원인을 지어내지 않습니다. MD 파일을 지정했다면 실제 파일 내용과 읽은 범위를 대조합니다. 대화에 붙여 넣은 텍스트만 사용했다면 파일을 읽었다고 기록하지 않습니다.

**막혔을 때:** 파일 경로와 읽기 권한을 확인합니다. 파일을 만들거나 읽을 수 없다면 위 텍스트 예문으로 연습합니다.

## 2. 결과 만들기

```text
가상 월간 실적으로 HTML 보고서를 만들어줘.
6월 목표 100건·실적 90건, 7월 목표 100건·실적 110건, 8월 목표 100건·실적 130건.
먼저 새 디자인 또는 내가 첨부할 기존 양식을 선택하게 해줘.
내 답변을 기다린 뒤 제작해줘. 합계와 달성률을 검증하고 기존 파일은 덮어쓰지 마.
```

디자인 질문이 오면 예를 들어 **“글래스모피즘, 짧게, 스크롤 방식으로 만들어줘”라고** 답합니다. 추가 디자인 목록에서는 원하는 번호 또는 이름 하나를 선택합니다. 이미 정한 답을 다시 묻는다면 그 내용을 알려주고 반복 여부를 기록합니다.

질문 제목·선택지·설명은 기본 한국어로 나옵니다. 파일명·제품명과 Claude 자체 메뉴·권한 버튼은 원래 표기가 남을 수 있습니다. 영문 보고서를 만들더라도 대화 언어를 바꾸라고 요청하지 않았다면 선택 질문은 한국어를 유지합니다.

**성공 확인:** 질문에서 실제로 기다리는지, 결과 파일이 생성됐는지, 브라우저로 열리는지 확인합니다. 목표 합계 **300건**, 실적 합계 **330건**, 누적 달성률은 **110%입니다.** 이번 자료에 없는 원인·연도는 임의로 추가하지 않아야 합니다.

최종 전달 후 기본 제작기가 기록한 변경 없는 중간 파일은 자동 정리됩니다. 원본과 최종 결과는 남고, 수정했거나 출처가 불명확한 파일은 지우지 않습니다. 나중에 다시 정리를 요청하려면 “이번 작업에서 만든 불필요한 중간 파일만 정리하고 원본과 최종 결과는 남겨줘”라고 말하세요. 다른 도구의 파일이나 과거 작업 폴더 전체를 자동 삭제하는 기능은 아닙니다.

### 참고 파일 없이 PPT 만들기

앞 단계 파일이 없어도 아래 수치만으로 실행할 수 있습니다. 참고 PPT·캡처는 **선택 사항**이며 ‘새 디자인’이면 추가 파일을 준비하지 않습니다.

```text
실습용 가상 월간 보고 PPT 5장을 실습_가상실적.pptx로 만들어줘.
가상 자료: 6월 목표 100건·실적 90건, 7월 목표 100건·실적 110건, 8월 목표 100건·실적 130건.
참고 파일은 없어. 새 디자인으로 진행하고 준비된 디자인 목록에서 직접 하나 선택하게 해줘.
표지·핵심 요약·월별 비교 차트·상세 표·확인할 사항 순서로 구성해줘.
먼저 전체 5장의 HTML 초안을 보여주고, 내가 확인하면 편집 가능한 PPT로 제작해줘.
표·차트는 편집 가능해야 하고 기존 파일은 덮어쓰지 마. 자료에 없는 이유·연도는 추측하지 마.
초안·검사 이미지는 내부 작업 공간에 두고 최종 PPT 한 파일만 전달해줘.
도구가 없으면 필요한 준비물만 알려주고 자동 설치하거나 이미지형으로 바꾸지 마.
```

디자인을 고른 뒤 HTML 초안을 확인하고 **“확인했어. 이 초안대로 편집 가능한 PPT를 만들어줘”라고** 답합니다. 완성한 PPT를 열어 아래 기준을 확인합니다.

**성공 확인:** 실제 5장과 수치를 확인하고 표·차트를 선택해 수정 가능한 개체인지 봅니다. 화면 캡처로만 만들어진 표라면 편집 가능 조건을 통과한 것이 아닙니다.

HTML 초안은 Office 실행 없이 만듭니다. 초안의 내용·색상·배치를 수정하면 다시 확인한
뒤 PPT를 만듭니다. HTML에서 확인한 화면과 최종 PPT의 글꼴·차트 세부 모양이 완전히
같지는 않으므로 최종 PPT 확인도 필요합니다. 기존 PPT의 배치 유지 모드에서 HTML은
교체할 내용·위치만 보여주며 고정 그림·마스터까지 재현하지 않습니다.

**이미 카드형 HTML을 만들었다면:** 이렇게 요청할 수 있습니다.

이 연습은 2단계에서 만든 HTML을 첨부하면 됩니다. 파일이 아직 없다면 먼저 위 HTML 보고서 예문으로 생성하세요. 회사의 실제 보고서나 참고 캡처를 준비할 필요는 없습니다.

```text
이 HTML의 카드·둥근 모서리·그림자·태그 배치를 유지해서 편집 가능한 PPT로 만들어줘.
텍스트를 그림으로 바꾸지 말고, 먼저 변환한 미리보기를 보여줘.
지원하지 않는 효과와 실제 확인한 범위를 알려줘.
```

변환 후 텍스트·도형은 편집할 수 있지만, 웹 화면과 모든 효과가 같지는 않습니다.
수치를 바꿔 갱신할 차트가 필요하면 **“데이터도 수정 가능한 차트로 만들어줘”라고** 요청하세요.
지원하지 않는 효과와 부족한 준비물을 먼저 확인하고, 완성한 PPT를 PowerPoint에서 열어 점검합니다.

**변환이 멈추면:** 모든 장이 같은 고정 크기로 보이는 정적 HTML인지 확인합니다. 이동·회전·확대/축소된 장은 같은 초안에서 효과를 제거하고 다시 확인합니다. 카드의 원래 가로·세로 정렬을 임의로 바꾸거나 전체 슬라이드를 그림으로 대체하지 않습니다. 수정 뒤에도 제목·표·차트를 실제로 편집할 수 있는지 확인하세요.

**기존 PPT의 그림이 작다면 — 선택:** 그림이 들어 있는 PPT를 이미 가진 경우에만 시험합니다. 앞에서 만든 편집형 PPT에 그림이 없다면 이 실습은 건너뜁니다. “이 PPT 1~5장의 그림을 비율 유지해 슬라이드에 꽉 채워줘.
원본은 보존해줘”라고 요청합니다. 그림이 여러 개면 어떤 그림인지 확인하며, 가운데를
기준으로 잘리는 부분이 있을 수 있습니다. 그림 크기 변경만으로 그 안 글자가 편집되지는 않습니다.

**파일이 너무 많이 생기지 않나요?** HTML/PPT 제작은 한 요청에 최종 결과 한 개가 기본입니다.
초안 HTML·수정 시도·PPT 검사 이미지는 내부 임시 작업 공간에서 확인하고, 완료한 파일만
지정한 폴더에 전달합니다. 같은 요청의 재시도는 `초안2`·`v2` 파일을 늘리지 않습니다.
다음 질문에서 별도 결과나 HTML 대표 양식을 요청하면 새 파일로 만들 수 있습니다.
기존 파일은 덮어쓰거나 자동 정리하지 않습니다. 여러 형식·여러 결과를 명시적으로
요청했거나 프로그램의 여러 소스 파일을 만드는 작업은 한 파일로 제한하지 않습니다.

**마음에 드는 디자인을 재사용하려면:**

```text
확인한 이 디자인을 HTML 대표 양식으로 저장해줘.
내 PC 개인용으로 둘지, 이 프로젝트에 둘지 먼저 물어봐줘.
실제 보고서 내용과 숫자·참고 캡처는 양식에 남기지 마.
```

**성공 확인:** HTML 대표 양식 한 파일에 가상 예시와 색상·글꼴·페이지 규격이 저장됩니다.
카드형/자유 배치 디자인은 도형·그림자·텍스트 위치도 저장하고 업무 문구는 예시로,
그림은 빈 자리로 바꿉니다. 새 작업에서는 그 자리에 들어갈 내용만 전달합니다.
다음 요청에서 이 파일을 첨부하면 새 업무의 HTML 초안을 먼저 확인하고 PPT로 만듭니다.
회사 공통 설정이나 개인 기억에 자동 등록하지 않습니다. 회사 PPT의 원본 개체·마스터를
유지하려면 PPTX 원본이 필요하며, 일반 HTML 파일을 무조건 편집 가능한 PPT 양식으로
바꿀 수 있는 것은 아닙니다.

**막혔을 때:** 질문 대기는 오류가 아닙니다. 백그라운드 작업 진행 중에는 같은 제작을 재요청하지 않습니다. 완료 확인 안내만으로 제작 실패라고 보지 마세요. 같은 안내와 설정 조회가 반복되면 중지하고 마지막 상태와 실제 결과를 담당자에게 전달하세요.

## 3. 원하는 방식으로 고치기

```text
방금 결과에서 결론을 먼저 보여주고 확인한 사실과 확인할 사항을 구분해줘.
이번 결과만 수정하고 수치와 출처는 유지해줘. 장기 선호 저장은 아직 요청하지 않을게.
```

**성공 확인:** 순서는 바뀌고 원래 수치·출처는 유지됩니다. 전체 자료 읽기·파일 제작을 이유 없이 처음부터 반복하지 않는지도 살펴봅니다.

**막혔을 때:** 원하는 문장 하나를 예시로 보여주세요. 인코딩 표시만 깨졌다면 기존 파일부터 다시 확인하고 중복 생성하지 않습니다.

## 4. 내 방식 하나 저장하기 — 선택

연습용 선호를 실제 업무에도 사용할지 먼저 결정합니다. 원치 않으면 건너뛰어도 됩니다.

```text
회사 필수 기준은 유지하고 허용된 범위에서 내 보고서 표현 선호를 개인 기억에 저장해줘.
선호: 결론부터 간단히 설명하고 실제 확인한 범위와 미확인 부분을 구분해줘.
이 선호 외 문서 본문이나 계정 정보는 저장하지 마. 실제 저장한 내용과 적용 범위를 알려줘.
```

또는 **기억·하네스 관리 → 개인 전체 / 이 프로젝트 → 기억·지식 → 내 기억 추가**에서 변경안을 보고 저장할 수 있습니다. 출처가 있는 용어·계산식은 같은 화면의 **내 업무 지식 초안**을 사용합니다.

**성공 확인:** 기억 화면에 정확한 내용과 사용 상태가 나타납니다. 회사 기준이나 전역 설정이 덮어써지지 않습니다. 더 필요 없다면 사용 안 함으로 바꿀 수 있습니다.

**막혔을 때:** Project와 User 설치의 저장 범위가 같은지 확인합니다. 자동 학습 켜짐과 모든 내용 저장은 다릅니다. [핸드북](COMPANY_AGENT_HANDBOOK.md)에서 기억과 학습 범위를 확인하세요.

## 5. 새 업무에서 다시 쓰기

같은 작업 폴더에서 **새 업무 시작**으로 새 대화를 만들고 입력합니다.

```text
현재 적용 범위에 저장된 내 보고서 표현 선호를 찾아서 알려줘.
실제로 조회한 내용만 설명하고 찾지 못한 기억은 지어내지 마. 설정이나 기억은 변경하지 마.
```

**성공 확인:** 저장된 내용과 실제 조회 내용이 같습니다. 이어서 가상 자료를 요약해 달라고 하고 표현에도 적용되는지 봅니다. “저장됨 → 조회됨 → 결과 반영”을 따로 확인하세요.

**다른 곳에서 이어 쓰기:** 개인 전체는 같은 사용자 설치·저장소를 쓰는 다른 폴더에서도 참고합니다. 이 프로젝트의 개인 기억은 저장한 프로젝트 경로에 연결되므로 폴더 복사·이름 변경만으로 따라오지 않습니다. 다른 PC·계정에는 자동 동기화하지 않습니다. 담당자와 백업·이전·연결 설정을 확인한 뒤 같은 조회 시험을 다시 합니다.

**막혔을 때:** 다른 설치 범위나 다른 폴더인지 확인합니다. PC 전체를 검색하거나 기억 저장소를 합치도록 지시하지 않습니다.

## 6. 공통 기억과 내 기억을 비교해 보기

**이 실습에서 판단할 것:** “팀원이 같이 알아야 하는 내용인가, 나만 원하는 방식인가?” 같은 가상 자료를 다시 요청하며 저장·조회·반영을 구분합니다.

### 먼저 알아둘 차이

**공통 기억**은 회사·팀이 검토해 배포한 지식이고 **내 기억**은 내가 저장한 선호·업무 지식입니다. 현재 별도의 공동 쓰기·실시간 동기화 저장소는 없습니다. ‘내 기억에 저장’은 공통 배포가 아닙니다. 회사 규정·공통 스킬을 기억이라고 묶지 않고 **공통 하네스**로 구분합니다.

| 남길 내용 | 적합한 곳 | 누구에게, 언제 보이나요? | 변경·공유 방법 |
| --- | --- | --- | --- |
| 공통 용어·계산식·출처 자료 | 공통 기억 | 같은 지식 배포본을 사용하는 업무 | 담당자의 갱신·배포 |
| 나의 답변 순서·개인 업무 지식 | 내 기억 | 같은 개인 저장소를 쓰는 업무 | 나의 검토·저장·사용 중단 |
| 부서 필수 절차·공통 스킬 | 공통 하네스 | 그 구성을 배포받은 사용자 | 담당자의 검토·배포 |
| 내 반복 절차·계산 도구·폴더 지침 | 내 하네스 | 선택한 사용자/폴더 범위 | 내 자산만 수정, 공유 원본은 관리 주체 확인 |

Company Agent 개인 기억과 Claude Code 자체 자동 기억은 서로 다른 기능이며 자동으로 합치지 않습니다. 한쪽을 끄거나 지웠다고 다른 쪽도 바뀌지 않습니다. 공유 파일에 적은 문장도 운영체제 권한을 바꾸지는 않습니다.

### 6-1. 별도의 연습 폴더와 기준선 만들기

탐색기로 같은 부모 아래에 **연습-A**, **연습-B**라는 빈 폴더를 만듭니다. B를 A 안에 만들지 않습니다. 기존 폴더를 재사용하거나 회사 자료를 복사하지 마세요. 부모 폴더의 `CLAUDE.md`도 영향을 줄 수 있으므로, 기존 지침이 있다면 삭제하지 말고 시험 기록에 남깁니다.

A에서 새 대화를 열고 먼저 아래를 요청합니다. 이 단계는 조회만 합니다.

```text
실습 전 현재 적용 범위를 확인해줘. 아직 파일이나 기억을 만들지 마.
현재 작업 폴더, Company Agent 설치 범위(User/Project), 개인 저장소(stateRoot),
확인 가능한 회사 기준과 프로젝트 CLAUDE.md 경로를 짧게 알려줘.
Company Agent 개인 기억 중 보고서 표현 관련 내용이 있다면 제목과 식별자만 확인해줘.
관찰할 수 없는 값은 미확인으로 남기고 다른 폴더·계정 전체를 검색하지 마.
```

작업 폴더·저장소는 자신의 화면에서 비교하고, 다른 사람에게 보낼 기록에서는 사용자명 등 개인 경로를 가립니다. 기존 선호와 실습 선호가 겹치면 기존 값을 덮어쓰지 말고 비교 계획부터 받습니다.

### 6-2. 공통 기억은 읽고, 공유 여부를 확인하기

**기억·하네스 관리 → 회사 공통 → 기억·지식**에서 실제 등록된 항목 하나의 출처와 내용을 엽니다. 이어 **개인 전체 → 기억·지식**을 열어 공통 항목이 개인 편집 대상으로 섞이지 않는지 확인합니다. 공통 항목이 없으면 ‘현재 등록 없음/미확인’으로 남기고 억지로 만들지 않습니다.

```text
현재 설치에 연결된 공통 기억에서 월간 보고에 관련된 용어 또는 계산식이 있으면
항목 이름, 실제 출처, 확인한 내용만 알려줘. 없거나 읽지 못하면 구분해서 알려줘.
내 기억이나 회사 설정에 복사하지 말고, 동료에게 전송하지 마.
```

**성공 확인:** 공통 출처를 실제로 조회했으며 개인 기억에 복사하지 않았습니다. 동료와 비교하려면 같은 배포본의 같은 항목만 확인합니다. 같은 모델 응답이 나온다는 사실만으로 공통 기억이 같다고 판단하지 마세요. 내 기억을 공통 자료로 제안하려면 **검토용 내보내기 → 민감 내용 확인 → 담당자 검토·배포**를 거칩니다. 내보내기 자체는 공통 반영이 아닙니다.

#### 선택 실습: 공유 프로젝트 지침과도 비교하기

이하는 **지식 저장 시험이 아닌 폴더 지침 시험**입니다. `CLAUDE.md`는 사실과 작업 지침이 함께 적힐 수 있는 파일입니다. 파일 이름만으로 공통 기억·회사 규정이 되는 것은 아니며, Workspace의 공통 기억 목록으로 자동 수집하지 않습니다.

A에서 다음을 보냅니다. 실제 회사 기준이 아닌 **가상 프로젝트용 파일**을 만드는 단계입니다.

```text
현재 폴더가 내가 선택한 연습-A인지 확인해줘.
기존 CLAUDE.md가 없을 때만, 아래 가상 프로젝트 지침으로 새 CLAUDE.md를 만들어줘.
목적: 월간 보고 연습. 수량 단위는 건. 자료에 없는 원인은 추정하지 않는다.
결과 제목에 [연습 A]를 붙이고 실제 확인한 수치와 확인할 사항을 구분한다.
기존 지침이 있으면 덮어쓰지 말고 알려줘. 회사 설정과 개인 기억은 변경하지 마.
```

파일에 들어갈 최소 예시는 다음과 같습니다. 위 요청으로 만들었다면 다시 만들 필요는 없습니다.

<!-- onboarding-example: team-claude -->
```markdown
# 월간 보고 연습 — 가상 프로젝트 A
- 목적: 가상 월간 실적을 요약한다.
- 수량의 단위는 건이다. 자료에 없는 증가 원인은 추정하지 않는다.
- 결과 제목에 [연습 A]를 붙인다.
- 실제 확인한 수치와 확인할 사항을 구분한다.
```

**파일 생성 후 A의 새 대화에서** 아래를 요청합니다. 새 대화를 쓰는 이유는 방금 지침을 말한 대화의 기억만으로 답하는 효과를 줄이기 위해서입니다.

```text
월간 보고 연습으로 다음 가상 자료를 요약해줘.
6월 목표 100건·실적 90건, 7월 목표 100건·실적 110건, 8월 목표 100건·실적 130건.
실제로 참고한 프로젝트 지침과 개인 기억이 있으면 출처를 구분해 마지막에 짧게 알려줘.
새로운 기억 저장이나 설정 변경은 하지 마.
```

**비교 기준:** 제목의 `[연습 A]`, 단위 **건**, 합계 **목표 300·실적 330·달성률 110%**, 근거 없는 원인 없음. 파일 존재와 실제 로드는 다릅니다. 원본 CLI의 `/context`에서 Memory files를 확인할 수 있고, `/memory`는 Claude 자체 지침·기억을 확인하는 메뉴입니다. Company Agent 기억 목록을 대신하는 메뉴는 아닙니다. 출처를 확인하지 못했으면 ‘공유 지침 적용 미확인’으로 기록합니다.

### 6-3. 나만의 표현 선호를 더해 비교하기 — 저장 선택

4단계에서 이미 저장했다면 그 기억으로 비교해도 됩니다. 별도 실습용 선호를 원한다면 아래를 보냅니다.

```text
Company Agent 개인 기억에 '실습 요약 순서'라는 실습용 선호를 저장하고 싶어.
월간 보고 연습 자료를 요약할 때 '핵심 결론 → 수치 → 확인할 사항' 순서를 선호한다는 내용만 저장해줘.
기존 보고서 선호와 겹치면 덮어쓰거나 중복 저장하지 말고 차이를 먼저 물어봐줘.
회사 기준이나 프로젝트 지침을 바꾸지 마. 실제 저장 내용·식별자·적용 저장소를 알려줘.
```

A에서 다시 새 대화를 열고 **6-2의 같은 가상 자료 요청**을 보냅니다. 프로젝트 지침 선택 실습을 건너뛰었다면 1단계의 가상 자료로 비교하고 아래 표의 프로젝트 기준은 미시험으로 남깁니다. 이어서 실제 사용한 기억을 조회합니다. 첫 응답에 선호가 적용됐는지와, 조회를 요청한 뒤에야 적용됐는지는 따로 기록하세요.

| 비교 항목 | 개인 기억 저장 전 | 개인 기억 저장 후 |
| --- | --- | --- |
| A의 프로젝트 기준 | `[연습 A]`·단위·원인 비추정 | 그대로 유지 |
| 개인 표현 순서 | 기존 선호 또는 기본 표현 | 저장한 순서가 조회·적용되는지 확인 |
| 자료의 수치 | 목표 300·실적 330·110% | 동일해야 함 |
| 다른 사람에게 전달 | 공유할 것은 검토한 프로젝트 지침 | 개인 저장소·대화는 공유하지 않음 |

**한 번만 다르게 요청하기:** 같은 자료에 “이번에는 수치부터 설명해줘. 저장된 선호는 바꾸지 마”를 덧붙여 시험합니다. 이번 표현은 달라져도, 다시 조회한 개인 기억 원문은 그대로여야 합니다. 회사 필수 기준을 개인 선호로 해제하는 실습은 하지 않습니다.

**두 사람이 비교할 수 있다면:** 승인된 방법으로 가상 `CLAUDE.md`와 가상 입력만 동료에게 전달하고, 동료 자신의 환경에서 새 대화로 시험합니다. 프로젝트 기준은 공통이고 개인 표현은 다를 수 있습니다. 한 사람이 폴더만 바꾸는 시험은 다른 사용자 계정의 격리 시험을 대신하지 못합니다. 이 문서는 팀 공유 서버를 생성하거나 자료를 자동 전송하지 않습니다.

**막혔을 때:** 저장됐지만 조회되지 않으면 상태(active/사용 중)와 같은 stateRoot인지 먼저 확인합니다. 조회됐지만 적용되지 않으면 모델 적용 실패로 기록합니다. 다른 사람의 기억을 볼 수 있는지 확인하려고 그 계정 폴더를 탐색하지 않습니다.

**검색 결과와 저장 목록 비교:** 자동 참고 결과는 관련 항목 합계 최대 5개로 제한됩니다. 저장한 기억이 빠졌다면 범위와 제목을 지정해 조회하고 위 표와 비교하세요. 관련도가 같은 경우에만 프로젝트 기억이 먼저이며, 개인 전체의 더 관련 있는 내용을 모두 제외하는 방식은 아닙니다. 이 시험을 위해 관계없는 기억을 여러 개 만들 필요는 없습니다.

**정리:** 실습용 기억이 불필요하면 **선택한 범위 → 기억·지식**에서 이번에 만든 식별자만 사용 안 함으로 바꿉니다. 이는 이력까지 삭제하는 작업이 아닙니다. 기존 기억·자동 학습 설정·회사 기준은 그대로 둡니다.

## 7. 공통 하네스·내 하네스와 적용 폴더 비교하기

**한 줄로 이해하기:** 회사 공통은 함께 쓰는 기준, 개인 전체는 내 여러 업무, 이 프로젝트는 현재 업무 전용입니다. `CLAUDE.md`는 프로젝트 지침 파일 중 하나이며 하네스 전체나 자동 기억 저장소와 같지 않습니다. 작은 규칙 네 줄에 작업자·도구를 전부 새로 만들 필요는 없습니다.

### ‘누가 관리하는가’와 ‘어디에 적용되는가’는 다릅니다

| 구성 | 역할 | 적용 범위·공유 | 이 실습에서 바꾸나요? |
| --- | --- | --- | --- |
| 회사·팀 공통 하네스 | 공통 스킬·후크·업무 기준·검증 절차 | 설치·활성화한 범위와 회사 배포 대상 | 아니요. 읽어서 확인만 |
| 내 하네스 | 내 스킬·도구·폴더 지침과 내가 연결한 구성 | 내 사용자 범위 또는 해당 폴더 | 내 실습용 자산만. 외부·공유 원본은 보존 |
| User 설치 | 현재 Windows 사용자에게 플러그인 제공 | 그 사용자의 여러 작업 폴더; 전 직원 배포와 다름 | 아니요 |
| Project 설치 | 선택한 폴더에 플러그인 제공 | 해당 프로젝트; 다른 폴더에 있다고 가정하지 않음 | 아니요 |
| 프로젝트 `CLAUDE.md` | 목적·자료 단위·출력 조건 | 해당 폴더와 하위 작업, 공유 시 파일을 받은 팀원 | 새 연습 파일만 |
| Claude 사용자 `CLAUDE.md` | 사용자 공통 지침 | 보통 사용자 설정 루트의 파일; 개인 범위 | 아니요 |
| 프로젝트 하네스 생성기 | 여러 단계·전문 작업자·검증 연결 | 그 프로젝트의 생성 스킬·에이전트·규칙 | 필요할 때 별도 선택 |

화면은 **회사 공통 / 개인 전체 / 이 프로젝트**의 세 범위를 보여줍니다. 이 프로젝트 안에도 나만 쓰는 자산과 팀이 공유한 파일이 있으므로 공유 여부를 따로 확인하세요. 어느 쪽도 회사 필수 기준을 해제하지 않습니다. Claude의 여러 지침 파일은 함께 문맥에 들어갈 수 있으므로 ‘프로젝트 파일이 전역을 전부 덮어쓴다’고 가정하지 마세요. 지침과 실제 강제 권한 설정 역시 다릅니다. [Claude Code 공식 기억·지침 문서](https://code.claude.com/docs/en/memory)를 참고했고, 사내 배포 버전의 실제 로드는 별도로 확인합니다.

Workspace에서는 **회사 공통 → 업무 구성**에 배포 기준·스킬·후크를, **개인 전체 / 이 프로젝트 → 업무 구성**에 해당 범위 자산을 표시합니다. 폴더 지침 편집은 이 프로젝트에만 있습니다. 외부 플러그인을 설치해도 Company Agent가 그 원본을 소유하거나 자동 학습으로 수정하지 않습니다. 스킬 목록 확인은 실제 연결·실행 성공과 별개입니다.

### 저장 범위와 자동 학습을 함께 시험하기

1. A 폴더에서 “가상 보고서에 연습-A라고 표시하는 선호를 기억해줘”라고 요청합니다. **개인 전체 / 이 프로젝트** 질문이 나오면 이 프로젝트를 선택합니다. 회사 공통을 저장 대상으로 제시하면 잘못된 동작입니다.
2. 같은 사용자 설치의 B 폴더에서 새 대화를 열고 기억을 조회합니다. A 전용 기억은 나오지 않아야 합니다. A에서는 다시 조회되어야 합니다. 실제 저장·조회와 모델 답변 반영은 각각 확인합니다.
3. 별도의 가상 선호를 “개인 전체에 저장해줘”라고 요청합니다. 재질문 없이 해당 범위에 저장하고 A/B에서 조회되는지 확인합니다. 프로젝트 지침·회사 원본은 바뀌지 않아야 합니다.
4. 스킬 만들기도 같은 범위 선택을 사용합니다. “이 프로젝트에 저장할 월간 요약 스킬”처럼 명시하면 범위 질문을 반복하지 않습니다. 기존 항목 수정은 원래 범위이며 자동 이동하지 않습니다.
5. 자동 학습 카드의 **적용 범위**를 확인합니다. User 설치는 개인 전체, 별도 Project 설치는 해당 설치 저장소입니다. 화면 이동이나 위 저장 선택만으로 자동 학습 범위가 바뀌지는 않습니다. User 설치의 프로젝트 전용 개인 자산은 명시적 저장/수정용이며 자동 수정 대상이 아닙니다.

자동 학습 흐름은 **피드백 후보 → 업무 완료·검증 → 조건에 맞는 선호/기존 개인 스킬 점검 항목 반영 → 다음 사용 평가**입니다. 진행 중인 교정은 임시 후보이며 질문·승인 대기는 완료로 보지 않습니다. 장기적으로 쓸 명시적 교정은 기억 요청 없이 반영할 수 있고 추정한 선호는 독립된 업무의 반복 근거가 필요합니다. 같은 범위의 한 항목을 A → B → A로 고친 경우 마지막 A를 반영하고 기존 항목을 갱신하는지 확인하세요. 같은 업무의 재답변은 새 반복 근거가 아니며 서로 모순되는 점검 문장을 덧붙이지 않습니다.

**새 스킬은 별도 요청입니다.** 자동 학습은 이미 있는 개인 스킬의 작은 점검 항목을 개선합니다. 새 업무 절차를 스킬로 만들려면 직접 생성 요청을 하거나 제작 제안에 동의한 뒤 8단계로 진행합니다. 공통 스킬의 개인 복제본을 자동 생성하지 않습니다.

개인 스킬 개선은 실제로 전체 본문을 로드한 버전만 대상으로 합니다. 목록·파일 경로·일부분만 본 것은 충분하지 않으며, 본문을 읽었다는 기록과 업무에 적용해 성공했다는 증거도 구분합니다. 회사 정책·프로젝트 CLAUDE.md·도구 코드를 자동 변경하지 않습니다. 모델 훈련이나 모든 답변의 자동 저장이 아니며, 매 요청마다 별도 학습 모델을 자동 호출하거나 종료 후 백그라운드 학습하지 않습니다. 완료 시 교정 검토에는 현재 대화의 모델 처리 비용이 들 수 있고, 별도 작업자가 검토하면 그 비용도 추가됩니다.

자동 학습 카드 또는 `/company-agent:learning`에서 내역 확인·일시 중지·재개·선택한 변경 되돌리기를 요청합니다. 중지는 기존 기억의 사용 중단이나 삭제와 다릅니다. 되돌리기는 자동 선호를 비활성화하거나 스킬 점검 영역을 복원하며 업무 파일·발송 메일은 취소하지 않습니다. 여러 교정의 실제 반영 여부는 내역에서 확인하고, 현재 후보 보존 한계는 [핸드북](COMPANY_AGENT_HANDBOOK.md)의 관리자 참고를 확인하세요. 연습 후 불필요한 이번 항목만 사용 중단하고 원본은 보존하세요.

### 7-1. A와 B에서 무엇이 달라지는지 시험하기

먼저 **기억·하네스 관리 → 구성 한눈에**를 엽니다. 세 영역의 스킬·기억·지침에서 **위치 보기**를 펼쳐 A의 현재 폴더와 저장소를 확인하세요. **구성 지도 HTML 저장**으로 A의 스냅샷을 보관한 뒤 B에서도 같은 순서로 조회합니다. AI 호출이나 설정 변경 없이 비교할 수 있습니다. HTML에는 경로·항목 이름이 들어가므로 외부에 바로 공유하지 마세요.

두 화면에서 ‘사용 가능’ 항목이 같아도 모델이 사용했다는 뜻은 아닙니다. ‘본문 로드 기록’이 있으면 해당 대화에서 동일 본문을 읽은 기록까지만 확인한 것이며, 아래 가상 업무의 답변까지 대조해야 적용을 판단할 수 있습니다. 지도는 저장 시점의 상태이므로 설정을 바꾸었다면 Workspace에서 새로고침하세요.

스킬 선택을 비교할 때는 정확한 이름으로 지정한 요청을 먼저 확인합니다. 이름을 지정하지 않았고 같은 업무의 같은 역할을 맡는 후보가 명확히 겹치면, 실제 이름·출처·차이를 안내받고 선택한 뒤 본문을 로드하는지 봅니다. 읽기 → 제작은 서로 다른 단계이므로 둘 다 쓸 수 있고, 관련 스킬이 없으면 허용된 일반 방식으로 진행합니다. 모든 유사 표현을 정확히 분류한다고 가정하지 마세요. 별도 작업자·모델·도구 제한 등 원본 CLI 기능이 필요한 스킬은 본문 파일만 읽어 대신 실행했다고 표시해서는 안 됩니다.

6단계에서 만든 B 폴더를 선택해 새 대화를 열고, 같은 범위 조회 요청으로 **작업 폴더·설치 범위·stateRoot·부모 지침**을 먼저 비교합니다. A 지침 선택 실습을 건너뛰었다면 6-2의 가상 프로젝트 파일 실습부터 하거나 이번 비교도 건너뜁니다. A 대화를 그대로 이어서 B를 말로만 지정하지 않습니다. B에 Company Agent가 설치·활성화되지 않았다면 그 사실을 기록하고 멈춥니다. 비교 때문에 자동 재설치하거나 저장소를 복사하지 않습니다.

이어서 다음을 보냅니다.

```text
현재 폴더가 내가 선택한 연습-B인지 확인해줘.
기존 CLAUDE.md가 없을 때만 새 파일에 다음 가상 프로젝트 지침을 적어줘.
월간 보고 연습 자료를 요약한다. 수량 단위는 건이며 자료에 없는 원인은 추정하지 않는다.
결과 제목에는 [연습 B]를 붙이고 실제 확인한 수치와 확인할 사항을 구분한다.
A 폴더, 회사 설정, 개인 기억은 변경하지 마. 기존 파일이 있으면 덮어쓰지 마.
```

B의 새 대화에서 **6-2와 동일한 가상 자료 요청**을 사용합니다.

| 관찰할 것 | A | B | 의미 |
| --- | --- | --- | --- |
| 프로젝트 제목 표식 | `[연습 A]` | `[연습 B]` | 폴더별 지침의 차이 |
| 회사 스킬·후크 | 실제 등록 확인 | 실제 등록 확인 | 같은 User 설치라면 공통 구성이 사용 가능한지 비교 |
| 개인 기억 | 저장한 식별자 확인 | 같은 stateRoot이면 같은 기억 조회 가능; 다른 저장소면 별도 | 폴더 이동과 개인 저장소 변경은 다른 일 |
| 공통 수치·기준 | 300·330·110%, 원인 추정 없음 | 동일 | 표현 차이로 자료 의미가 바뀌면 실패 |

같은 User 설치라도 B의 설정·정책 때문에 플러그인이 비활성일 수 있습니다. Project 설치끼리라면 저장소가 달라 개인 기억이 따라오지 않는 것이 정상일 수 있습니다. **전역 설치 = 모든 팀원이 같은 기억을 쓴다**는 뜻은 아닙니다.

**막혔을 때:** B에서 `[연습 A]`가 보이면 새 대화인지, B가 A의 하위 폴더인지, 부모 지침 또는 별도 자동 기억에 A의 설명이 남았는지 확인합니다. 기존 지침을 지워서 시험을 통과시키지 않습니다. 내 하네스의 폴더 지침 편집기가 관리하는 `.claude/rules/company-workspace-brief.md`와 직접 만든 `CLAUDE.md`도 다른 파일입니다.

### 7-2. 프로젝트 하네스는 언제 만드는가? — 선택

단위·문체·목적만 정하면 `CLAUDE.md`로 충분합니다. 자료 취합 → 초안 작성 → 별도 검토가 반복되고 단계별 역할이 필요할 때만 프로젝트 하네스를 검토합니다.

```text
이 연습 프로젝트의 월간 보고를 '자료 확인 → 초안 작성 → 결과 검토'로 반복하고 싶어.
현재 CLAUDE.md만으로 충분한지 먼저 설명하고, 필요하다면 프로젝트 하네스 변경 계획만 보여줘.
기존 파일, 생성할 파일, 사용할 실제 스킬, 대표 검증 방법을 구분해줘.
아직 생성·설치·활성화하거나 회사 정책·모델·MCP 설정을 변경하지 마.
```

계획이 필요에 맞을 때만 생성 범위를 승인합니다. 현재 생성기는 자체 프로젝트 스킬·작업자·규칙과 소유권 기록을 만들며, 기존 `CLAUDE.md`를 교체하지 않습니다. 구조 검사 통과와 실제 보고서 생성 성공은 별개입니다. 초보자에게 하네스 생성을 필수 첫 단계로 요구하지 않습니다.

새 폴더에서 파일 읽기·작성·수정 같은 작업을 요청하면 기존 지침이 없는 경우 **기본 `CLAUDE.md`를 처음 한 번 자동 생성**합니다. 폴더를 열기만 하거나 대화·계획 모드·변경 금지 요청일 때는 만들지 않습니다. 기존 `CLAUDE.md`, `.claude/CLAUDE.md`, 부모 프로젝트 지침이 있으면 그대로 사용합니다. 홈·설치·시스템 폴더에는 만들지 않습니다. `/init` 명령이나 추가 AI를 실행하는 것이 아니라 짧은 시작 안내와 실제 존재하는 시작 파일 이름만 기록합니다. 프로젝트 실행법·검증 명령을 분석했다고 간주하지 마세요.

**시험:** 지침 없는 별도 연습 폴더에서 `테스트 메모를 새 파일로 작성해줘`라고 요청한 뒤 `CLAUDE.md`를 확인합니다. 다시 요청해도 내용이 덮어써지지 않아야 합니다. 위 A/B 실습에서 기본 파일이 먼저 만들어졌다면 기존 내용을 확인하고 `[연습 A]` 또는 `[연습 B]` 지침만 추가해 달라고 요청하세요. 파일을 삭제하거나 공통 설정을 바꿀 필요가 없습니다.

의미 있는 업무 후의 개인 자동 학습은 내 선호·제한된 개인 스킬을 대상으로 하며, 이 최초 생성과도 다릅니다. `/revise-claude-md`를 자동 실행하거나 프로젝트 문서를 계속 덮어쓰지 않습니다. 먼저 기존 파일·관리 주체·적용 폴더를 확인하고 필요한 변경만 요청하세요.

**정리:** A/B 파일을 유지해 다음 실습에 써도 됩니다. 없애려면 먼저 이번 실습에서 만든 정확한 파일 목록을 확인하고 그 파일만 휴지통으로 옮기세요. 폴더 전체·부모 지침·개인 저장소를 일괄 삭제하지 않습니다.

**판단 기준:** 기억은 ‘내 취향’, 지식은 ‘정의와 근거’, 스킬은 ‘반복 절차’, 도구는 ‘정해진 계산이나 동작’입니다. 새 기능부터 만들기보다 사용 가능한 목록에 같은 역할이 있는지 먼저 확인합니다.

| 원하는 일 | 가장 작은 시작점 | 이 실습 |
| --- | --- | --- |
| 결론부터 설명해 주기 | 개인 기억 | 6단계 |
| 회의 메모에서 결정·할 일·미정 구분 | 개인 스킬 | 8-1 |

| 다른 시스템과 지속적으로 연결 | 승인된 기존 도구, 필요할 때 MCP | 이번 기본 실습 제외 |

### 8-1. 코드를 쓰지 않는 개인 스킬

새 연습 대화에서 아래를 요청합니다. 생성 의사가 명확한 예문이므로 실행하면 개인 자산이 생깁니다.

```text
회의 메모에서 결정된 것·할 일·미정 사항을 구분하는 개인 스킬을 만들고 싶어.
먼저 사용 가능한 목록에 같은 역할이 있는지 확인하고, 겹치면 차이를 물어봐줘.
적합한 것이 없으면 'practice-meeting-check'라는 이름으로 만들어줘.
내가 제공한 회의 텍스트만 사용하고 외부 조회·메일 발송·파일 이동은 하지 마.
할 일은 내용·담당자·기한을 구분하고, 없는 담당자나 기한은 '미정'으로 표시해줘.
자료에 없는 결정을 만들지 마. 빈 입력에는 자료를 요청해줘.
실제 개인 저장소에 저장하고 설치된 회사 플러그인 파일은 수정하지 마.
이름이 충돌하면 덮어쓰거나 임의로 바꾸지 말고 알려줘.
생성한 파일 위치와 사용 가능한 상태, 구조 검사에서 확인한 범위를 알려줘.
실제 회의 예제 시험은 다음 요청에서 진행할게.
```

스킬은 `name`(이름), `description`(언제 쓰는가), 본문(어떤 절차인가)으로 이해하면 됩니다. 설명을 ‘모든 업무에 사용’처럼 넓게 쓰지 않습니다. **내용 예시**는 아래와 같으며, 하네스가 생성했다면 별도로 다시 설치하지 않습니다.

<!-- onboarding-example: personal-skill -->
```markdown
---
name: practice-meeting-check
description: 제공된 회의 메모에서 결정 사항, 담당자와 기한이 있는 할 일, 미정 사항을 구분할 때 사용합니다.
---
# 회의 메모 확인
- 제공된 텍스트만 사용한다. 입력이 없으면 메모를 요청한다.
- 결정 사항 / 할 일 / 미정 사항으로 나눈다. 없는 결정을 지어내지 않는다.
- 할 일은 내용·담당자·기한으로 정리한다. 없는 값은 미정으로 표시한다.
- 외부 조회, 메일 발송, 파일 이동은 수행하지 않는다.
```

**첫 시험은 이름 없이** 다음을 요청합니다.

```text
회의 메모를 결정 사항, 할 일, 미정 사항으로 정리해줘.
가상 메모: 다음 보고서에는 누적 실적을 포함하기로 했다.
지민은 금요일까지 표 초안을 만든다. 검토 담당자는 다음 회의에서 정한다.
문서 저장이나 기억 저장은 하지 마.
```

**기대 결과:** 결정은 ‘누적 실적 포함’, 할 일은 ‘표 초안 / 지민 / 금요일’, 미정은 ‘검토 담당자’입니다. 금요일의 날짜는 제공되지 않았으므로 특정 날짜를 만들어내면 안 됩니다. 실제로 생성된 스킬 본문을 읽었는지도 확인합니다. 결과만 비슷하다고 자동 선택 성공으로 보지 않습니다.

이어서 새 대화에서 “방금 만든 개인 회의 메모 스킬로 같은 가상 메모를 정리해줘”라고 비교합니다. 이름 없이 실패하고 명시하면 성공하는 경우에는 **자동 선택은 미확인/실패, 명시 사용은 성공**으로 나눠 기록합니다. 마지막으로 빈 메모를 보내 자료를 요청하는지 시험합니다.

**수정 연습:** “이 스킬에서 기한이 없으면 추측하지 말고 미정으로 두는 예시를 보완해줘. 기존 이름과 외부 동작 없는 범위는 유지해줘”라고 요청하고 정상·누락 예제를 다시 확인합니다. 새로운 이름의 스킬을 중복 생성하지 않습니다.

**저장 위치 주의:** Company Agent 자산 생성기는 선택한 범위의 저장소 아래 `personal-root/.claude/skills/<이름>/SKILL.md`에 저장하고 자체 목록으로 발견합니다. User 설치의 ‘이 프로젝트’ 자산은 개인 상태 저장소의 `project-scopes/<폴더 식별자>` 아래에 보관합니다. Claude 자체 개인 스킬 폴더나 프로젝트 공유 폴더와 같은 경로라고 가정하지 마세요. 일반 Claude의 개인·프로젝트 스킬 위치는 [공식 스킬 문서](https://code.claude.com/docs/en/skills)에 설명돼 있습니다. Company Agent 목록에 보인다는 것과 원본 CLI의 `/이름` 호출이 등록됐다는 것도 따로 확인합니다. 등록되지 않은 호출명을 반복 실행하지 않습니다.

### 8-2. 숫자를 일정하게 계산하는 로컬 도구

이번에는 입력과 출력이 정해진 작은 도구를 회사 표준 형식으로 만들고, 스킬이 그 도구를 호출하게 합니다. 회사 시스템이나 실제 자료는 필요하지 않습니다. 승인된 Python과 MCP SDK 1.28 이상·2 미만이 준비되어 있어야 하며, 없으면 필요한 준비물만 안내합니다. 인터넷 설치는 하지 않습니다.

```text
회사 표준 tools.py 형식으로 로컬 도구 'practice-achievement'를 만들어 검증 후 연결해줘.
저장 범위는 이 프로젝트야. 이 범위를 도구와 스킬 모두에 유지해줘.
먼저 같은 역할의 기존 도구와 이름 충돌을 확인하고, 겹치면 선택을 물어봐줘.
입력은 targets와 actuals라는 길이가 같은 비어 있지 않은 정수 목록이야.
각 값은 0 이상 1,000,000 이하, 항목은 12개 이하로 제한해줘.
출력은 targetTotal, actualTotal, achievementRate야.
달성률은 실적 합계 / 목표 합계 × 100을 소수점 둘째 자리까지 반올림해줘.
목표 합계가 0이면 달성률은 숫자가 아니라 null(계산 불가)로 반환해줘.
빈 목록, 길이 차이, 음수, 문자열·참/거짓 입력, 필수 항목 누락은 오류로 구분해줘.
승인된 MCP SDK와 Python으로 만들고 외부 통신·임의 파일 읽기/쓰기·다른 프로그램 실행은 하지 마.
정상 시험: targets=[100,100,100], actuals=[90,110,130]이면 합계 300·330, 달성률 110.
반올림 시험: targets=[3], actuals=[1]이면 33.33.
목표 0 시험: targets=[0], actuals=[30]이면 달성률 null.
앞서 정한 잘못된 입력도 실제로 시험해줘. 생성만으로 완료라고 하지 마.
검증 전에는 candidate 상태로 두고, 성공한 검증 기록으로만 활성화해줘.
합계를 설명하는 개인 스킬 'practice-achievement-report'도 만들고, 방금 도구를 호출하도록 연결해줘.
기존 회사 설정, 개인 스킬, 다른 MCP 등록은 변경하지 마. 회사 플랫폼에는 배포하지 마.
```

여기서 파일 읽기/쓰기 제한은 **생성된 도구의 업무 동작**에 대한 것입니다. 하네스가 개인 도구 소스·시험 입력·검증 기록을 저장하고 승인된 Python 프로세스로 실행하는 단계는 필요합니다. 입력 검증과 시간 제한이 있다고 OS 샌드박스가 생기는 것은 아닙니다.

| 시험 | 입력 | 기대 결과 |
| --- | --- | --- |
| 정상 | targets `[100,100,100]`, actuals `[90,110,130]` | 목표 300, 실적 330, 달성률 110 |
| 반올림 | targets `[3]`, actuals `[1]` | 33.33 |
| 목표 0 | targets `[0]`, actuals `[30]` | 달성률 null; 0%·무한대라고 하지 않음 |
| 잘못된 입력 | 빈 목록, 길이 차이, 음수, 문자열·참/거짓, 필드 누락 | 오류; 성공한 계산값으로 꾸미지 않음 |

**확인 순서:** 후보 도구 → 정상/오류 입력 시험 → 검증 기록 → 현재 프로젝트의 연결 등록 → Claude 재시작 → 스킬로 같은 입력 재실행. 스킬은 첫 사용에 도구 연결을 확인합니다. 현재 대화에서 변경이 없으면 확인 결과를 재사용합니다. 도구가 안 보이면 연결 상태를 안내해야 하며 별도 계산 코드로 몰래 대체하면 안 됩니다. 검증 기록은 시험한 코드·설정에 묶이며 모든 수학적 경우나 안전성을 증명하지는 않습니다.

**이미 만든 도구에 재시험 안내가 나오면:** 도구를 새 이름으로 만들거나 지우지 말고 같은 저장 범위에서 위의 정상·오류 입력을 다시 시험합니다. 성공한 현재 검증 기록으로 활성화·연결을 확인하세요. 잘못된 값이 통과하면 검사를 약하게 바꾸지 말고 원인을 수정합니다. 지원하지 않는 입력·출력 조건이 있다면 그 조건을 무시한 채 성공으로 처리하지 않습니다.

아래는 위 조건의 최소 계산 예제입니다. 안내서를 열어도 실행되지 않으며, 전체 AssetSpec이나 CLI 명령이 아닙니다. 자산 생성기는 별도로 입력·출력 스키마를 구성합니다. 연습 검사는 이 코드와 입력을 임시 저장소에서 사용하며 실제 개인 설정을 바꾸지 않습니다.

<!-- onboarding-example: tool-code -->
```python
import json
from mcp.server.fastmcp import FastMCP
from pydantic import StrictInt

def register_tools(mcp: FastMCP) -> None:
    @mcp.tool()
    async def achievement(targets: list[StrictInt], actuals: list[StrictInt]) -> str:
        """최대 12개 가상 실적의 합계와 달성률을 계산합니다."""
        for values in (targets, actuals):
            if not 1 <= len(values) <= 12:
                raise ValueError("provide 1 to 12 values")
            if any(not 0 <= value <= 1000000 for value in values):
                raise ValueError("values must be between 0 and 1000000")
        if len(targets) != len(actuals):
            raise ValueError("list lengths must match")
        target_total, actual_total = sum(targets), sum(actuals)
        rate = round(actual_total / target_total * 100, 2) if target_total else None
        return json.dumps({"targetTotal": target_total, "actualTotal": actual_total,
                           "achievementRate": rate}, ensure_ascii=False)
```

### 8-3. 언제 팀에 나누고, 어떻게 정리하나요?

개인 스킬·도구를 만들었다고 회사 전체에 배포되는 것은 아닙니다. 팀에 유용하다면 **목적, 입력·출력, 정상/실패 시험, 권한·준비물, 담당자**를 정리하고 민감 내용이 없는 소스만 담당자에게 검토 요청합니다. 회사 공통 반영은 별도 배포 작업입니다. 검증 기록을 다른 PC에 복사해 활성화를 대신하지 않습니다.

**정리:** 이번 실습에서 만든 스킬·도구만 확인하고 정리안을 받으세요. 대상을 확인한 뒤 정리하며, 기존 스킬·기억·회사 설정은 유지합니다. 안전한 정리 방법이 확인되지 않았다면 그대로 두세요.

**막혔을 때:** 스킬 목록, 본문 로드, 도구 시험, 연결 등록, 현재 세션 호출을 나눠 확인합니다. 준비물이 없으면 자동 설치하지 않습니다. 단순 글쓰기 스킬에 도구를 억지로 추가하거나, 연습을 이유로 전체 후크를 끄지 않습니다. 기존 스크립트 도구를 사용 중이라면 형식을 바꾸지 않고 같은 제작 스킬로 유지보수할 수 있습니다.

### 8-4. 선택 실습: 전사와 같은 형식으로 MCP 만들기

전사 제출용 독립 개발 폴더도 같은 `company-agent:asset-factory`로 만듭니다. 8-2의 도구와 업무 파일 형식은 같지만, 이 실습은 회사의 HTTP 연결 조건을 시험하는 **소스 개발**입니다. 개인 도구 자동 연결·전사 배포는 하지 않으며, 기존 도구를 복사할 필요가 있는지도 먼저 확인합니다.

```text
전사 표준 tools.py / register_tools 형식으로 MCP를 개발하고 싶어.
이 프로젝트에서만 연습할 거야. 새 개발 폴더는 [실제 절대 경로]야.
먼저 합성 한글 문자열을 되돌려 주는 예제로 로컬 시험까지 진행해줘.
MCP 연결 등록, 인터넷 패키지 설치, 회사 플랫폼 업로드는 하지 마.
```

**만들어지는 것:** `src/mcp/tools.py`가 업무 코드입니다. 함께 제공하는 `config.py`·`local_server.py`·`requirements-local.txt`는 **로컬 시험 전용**이며 전사 파일을 교체하지 않습니다. `test_tools.py`는 실제 MCP SDK로 목록·입출력·실패 입력을 확인합니다. 기존 폴더를 덮어쓰지 않습니다. Python과 승인된 SDK 1.x 환경이 없으면 준비물을 안내하며 자동 설치하지 않습니다.

**이렇게 되면 성공:** 한글 응답이 원래 입력과 같고, 잘못된 입력은 오류로 구분되며, 검사한 코드 경로와 결과를 확인할 수 있습니다. 이 기본 검사는 포트를 열지 않는 로컬 HTTP 전송 시험입니다. 사용자가 별도 연결 시험을 요청하면 내 PC의 `127.0.0.1`에만 서버를 열어 확인합니다. 소스가 생성됐다고 CLI에 MCP가 등록되거나 다른 프로젝트에서 자동 사용되는 것은 아닙니다.

**전사에 전달할 때:** 기본 제출물은 `src/mcp/tools.py`와 추가 의존성·필요한 설정 항목명·사용 예제·시험 결과입니다. 업무용 보조 모듈이 있다면 목록을 함께 냅니다. 로컬 설정, 비밀값, 개인 기억, 개발 환경은 제외합니다. 담당자가 실제 전사 SDK·인증·권한을 검증한 뒤 배포합니다. “로컬 시험 통과”와 “전사 배포 완료”는 다릅니다. Markdown 스킬도 공유할 수 있지만 필요한 상대 참조 파일까지 포함하고, 개인 경로나 하네스 전용 호출을 그대로 전사에 적용하지 않습니다.

## 9. 사용량과 결과 확인하기

**사용 현황 · 결과 확인**을 엽니다. 토큰이 미제공이면 0으로 해석하지 않습니다. 실행 구간과 질문·승인 대기를 구분하고 CLI 보고값을 무조건 요청별로 합산하지 않습니다.

**준비·결과 확인**에서 내용·범위·파일을 직접 확인한 뒤 통과/실패/미확인/중지를 기록합니다. 스킬 목록의 개수나 준비물 점수가 실제 업무 정확도를 대신하지 않습니다. 확인 기록 내보내기는 자동 전송하지 않으며, 기록 비우기는 대화·기억·결과 파일 삭제와 다릅니다.

**성공 확인:** 확인하지 않은 항목은 미확인으로 남고, 같은 예제로 재시험할 때 전후 결과를 비교할 수 있습니다. 일반 업무를 위해 매번 진단 화면을 열 필요는 없습니다.

## 10. 마무리 체크리스트와 의견

- [ ] 실제 설치 범위와 작업 폴더를 구분했다.
- [ ] 자료의 수치·범위를 직접 확인했다. 실제 파일 읽기와 대화 텍스트 요약을 구분했다.
- [ ] 디자인 질문에 답하고 실제 결과 파일을 열었다.
- [ ] 이번 결과 수정과 장기 선호 저장을 구분했다.
- [ ] 선택한 경우 기억을 새 대화에서 조회·비교했다.
- [ ] 팀의 공유 기준과 개인 기억, Claude 자체 자동 기억이 다른 저장 방식임을 구분했다.
- [ ] A/B 폴더에서 프로젝트 지침과 개인 저장소의 적용 범위를 따로 비교했다.
- [ ] 개인 스킬은 발견·본문 로드·실제 결과를, 도구는 생성·시험·활성화를 구분했다.
- [ ] 토큰·시간의 미제공 값과 실제 관찰값을 구분했다.
- [ ] 불필요하거나 바꾸고 싶은 기능을 핸드북의 개선 의견 양식에 적었다.

선택 실습을 하지 않았다면 해당 항목은 ‘미실행’으로 두세요. 다음 양식으로 관찰한 것만 남깁니다. 단순히 ‘모두 성공’이라고 쓰지 않습니다.

```text
실습 번호 / 날짜 / 설치 버전:
작업 폴더: A / B / 동료의 별도 환경
설치 범위와 개인 저장소: 같음 / 다름 / 미확인 (공유 기록에는 개인 경로 제외)
확인한 지침·기억·스킬의 출처:
저장·발견·로드·실행·결과 중 실제 확인한 단계:
기대 결과 / 관찰 결과:
결론: 통과 / 실패 / 미확인 / 미실행
유지할 자산 / 사용 안 함 또는 정리한 항목 / 남은 한계:
```

앱을 끝낼 때는 오른쪽 위 전원 버튼을 사용합니다. 창의 X만 닫으면 서버가 남을 수 있습니다. 연습 파일·기억은 자동으로 지우지 않습니다. 유지할 것과 정리할 것을 직접 선택하세요.

# Workspace 0.17.0 검증 기록

검증일: 2026-09-30. 창 재사용, Claude 실패 후 복구, 목록 밀도, 업무 이름 중복, 앱 브라우저 선택, 이전 세션 이어가기, 연결 기능 목록을 확인했습니다.

## 자동 검사

- 전체 979개: 948개 통과, 31개 건너뜀, 실패·오류 0개(211.899초).
- 현재 로그인 사용자 환경의 실행기 검사 9개 별도 통과. 다른 버전 충돌, 숨긴 실행기 재실행, 현재 사용자 Claude 경로·별칭 검증 포함.
- 31개 건너뜀: 선택적 Company Agent 통합 19개, 심볼릭 링크 권한 4개, 별도 Windows 네이티브 검사 7개, 이 호스트에서 실행 불가한 WSH/VBS 검사 1개. 특정 하네스 설치는 요구하지 않습니다.
- 추가 검사: 창 재열기 동시 요청 합치기, 배경 창 재발견, Edge 실패 시 Chrome 앱 모드, 인증 없는 창 열기 차단, 긴 이름·두 자리 번호·자동 업무 이름 충돌, 가져온 세션의 재시작 후 ID 유지, 다른 ID로 바뀌는 CLI 거부, 오류 결과와 잔여 승인 정리, 하위 작업의 결과가 부모 작업을 종료하지 않음, MCP 메타데이터의 비밀 설정 제외, 목록 연결의 늦은 응답·취소·작업 전환 경계.

초기 회귀 검사에서 목록 준비가 `mcp_status` 읽기 제어를 추가한 만큼 두 검사의 프레임 수 기대값이 달라졌습니다. 초기화·목록 조회만 전송하고 사용자 메시지는 전송하지 않는다는 계약을 유지하여 기대 프레임을 갱신한 뒤 전체 검사를 다시 통과했습니다.

## 실제 EXE와 창

- EXE만 있는 한글 경로와 별도 검증 상태·캐시에서 시작했습니다. 기존 Python 3.13.5와 Claude Code 2.1.285를 확인했습니다. Python 포함·설치·다운로드 없음.
- 최초 Edge 앱 창 생성 후 재열기 API 4회가 모두 `activated`였습니다. 실제 EXE를 다시 실행해도 검증된 앱 창은 1개였습니다. 실행 파일, 사용자, 로그인 세션, 임의 제목이 일치하는 창만 관찰·정리했습니다.
- Chrome 앱 모드 전환은 프로세스 호출 검사로 검증했습니다. Chrome만 있는 회사 PC와 모든 회사 보안 정책 조합을 실제 시험한 것은 아닙니다.
- 검증 서버·CLI 정상 종료 후 개인 설정 5개 파일의 해시 변경은 0개였습니다.

## 실제 Claude 대화 이어가기와 목록

앱 밖의 기존 Claude CLI에서 검증용 폴더에 짧은 대화를 생성했습니다. 읽기 도구만 노출한 CLI 호출로 임의 검증 문구를 전달한 뒤, 세션 UUID로 앱 업무에 추가했습니다. 앱 후속 질문에는 검증 문구를 다시 넣지 않았으며 이전 문구를 기억해 답변하는지 확인했습니다.

- 원래 세션 UUID와 업무 폴더 유지, 후속 요청 `done`, 이전 문구 정확히 재현, 승인 대기 0개.
- AI 질문 전 연결 준비: 실제 모델 `claude-sonnet-5-5`, Effort `medium`, 명령 141개, MCP 서버 9개. 도구는 CLI 미제공 상태였습니다.
- 실제 후속 응답 이후: 도구 43개, MCP 9개, 명령 141개가 CLI 보고값으로 표시됐습니다.
- 검증은 테스트 대화 기록을 생성했습니다. 개인 설정·인증·모델 기본값·UAC·회사 정책은 변경하지 않았습니다.

`ede_diagnostic` 자체를 실제 CLI에서 강제로 재현하지는 않았습니다. 동일 진단의 합성 오류 프레임을 이용해 실패 처리, 잔여 승인 정리, 세션 보존과 이후 결과 수신을 확인했습니다. 상류 CLI의 모든 실행 실패를 해결했다는 의미가 아닙니다.

## 화면

개인 데이터가 없는 가상 CLI·대화·문서 환경에서 1280×720 화면을 조작했습니다.

- 공통 스킬 화면이 살아 있는 업무 연결을 고르고 도구·MCP·명령 숫자를 표시.
- 이전 대화 미리보기에서 고정된 추가 버튼으로 업무를 만들고 원래 폴더·세션 안내를 확인.
- 실제 UI 입력창에서 후속 요청을 보내 가상 응답을 수신. 화면을 다시 연 뒤에도 기존 대화와 후속 메시지 및 같은 세션 연결 안내 유지.
- 왼쪽 영역 250px, 업무 행 여백 축소, 입력창과 우측 자료 영역 유지.
- UI 검증용 폴더 신뢰 동작은 최초 자동 승인 검토에서 차단됐습니다. 빈 검증 폴더·격리 설정·가상 CLI만 사용한다는 근거를 확인한 후 재검증이 허용되어 완료했습니다. 실제 개인 설정의 접근 권한을 확대하지 않았습니다.

창 탐색은 명시적인 재열기 요청에만 실행하며 상시 창 감시기를 추가하지 않았습니다. 연결 목록 조회는 제어 응답 대기를 제한하고 인증 정보·MCP URL·설정을 화면으로 전달하지 않습니다. 기존의 대화 지연 로딩·파일 비교 보관 한도를 유지합니다.

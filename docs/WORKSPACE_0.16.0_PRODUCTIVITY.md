# Workspace 0.16.0 — 알림, 빠른 실행, 변경 비교, 대화 분기

이 문서는 네 기능의 사용법과 구현 범위를 설명합니다. 특정 Company Agent 설치에 의존하지 않으며 기존 Claude Code 환경을 사용합니다. 사용법 문서만으로 최종 검증이나 공개 배포가 완료됐다는 뜻은 아닙니다.

## 한곳에서 찾아가기

| 기능 | 여는 위치 | 하는 일 |
| --- | --- | --- |
| 통합 알림함 | 상단 **알림** | 완료·응답 대기·확인할 일을 분류하고 해당 업무로 이동 |
| 명령 팔레트 | 왼쪽 **빠른 실행**, `Ctrl+K` | 업무와 앱 기능을 이름으로 검색해 열기 |
| 파일 변경 비교 | **이번 결과 → 파일 변경 비교** | 저장된 요청 전후의 텍스트를 읽기 전용으로 비교 |
| 대화 분기 | 업무 제목 옆 **대화 분기** | 마지막 완료 대화에서 별도 Claude 세션 준비 |

팔레트에서도 알림함·변경 비교·대화 분기를 찾을 수 있습니다. 아직 업무를 선택하지 않았거나 현재 실행 상태에서 사용할 수 없는 기능은 비활성화합니다.

## 통합 알림함

**전체 / 읽지 않음 / 응답 필요 / 완료 / 확인 필요**로 목록을 좁힙니다. 업무 이름을 누르면 해당 대화로 이동합니다. **읽음**은 그 알림만, **모두 읽음**은 보관 중인 알림을 읽음으로 표시합니다.

**읽음과 응답 완료는 다릅니다.** 알림을 읽어도 승인·질문·선택 요청은 처리되지 않습니다. 아직 기다리는 요청은 읽은 뒤에도 **응답 필요**에 남습니다. 실제 대화에서 응답하거나 요청이 종료되어야 이 분류에서 빠집니다. 지난 요청의 알림은 전체 목록에서 **현재 대기 없음**으로 구분합니다.

한 업무에 여러 응답 요청이 있으면 현재 요청을 한 항목에 모아 개수를 표시합니다. 오래된 승인 알림을 현재 요청처럼 중복 표시하지 않습니다. 읽음 상태는 각각의 실제 알림 식별자에 연결하므로, 앞선 요청을 읽었다는 이유로 새 요청도 읽음 처리하지 않습니다.

PC 알림과 브라우저 알림 설정은 기존 설정 화면에서 유지합니다. 알림함을 여는 것만으로 알림 권한을 요청하거나 Windows 설정을 바꾸지 않습니다. Windows 배너가 표시되지 않아도 앱 안의 기록은 확인할 수 있습니다.

## 명령 팔레트와 기존 입력창

`Ctrl+K` 또는 **빠른 실행**으로 열고 업무 이름·폴더 이름·기능 이름을 입력합니다. `↑`/`↓`로 항목을 고르고 `Enter`로 열며, `Esc`로 닫으면 원래 입력 위치로 돌아갑니다. 한글 조합 중에는 입력 확정을 우선합니다. 다른 확인창이 열려 있으면 그 창의 조작을 우선합니다.

| 위치 | 입력의 의미 |
| --- | --- |
| 대화 입력창의 `/`, `/effort` | 기존 Claude 스킬·명령 후보와 연결 설정 변경 |
| 대화 입력창의 `@` | 업무 폴더의 파일 후보와 자료 참조 |
| 빠른 실행의 검색어 | 업무·스킬 화면·결과·설정 등 앱 안에서 이동할 위치 검색 |

팔레트의 검색어나 선택을 AI 질문으로 보내지 않습니다. 모델·Effort·승인 모드를 선택하면 기존 입력창의 설정 목록을 엽니다. 실제 값 변경과 적용 확인은 기존 연결 제어를 사용합니다. 팔레트가 `/`·`@` 자동완성이나 `Shift+Tab` 승인 모드를 대신하지 않습니다.

검색은 이미 불러온 업무 메타데이터와 고정된 앱 기능 목록만 사용합니다. 파일 전체나 대화 전문을 별도로 검색·색인하지 않습니다.

## 파일 변경 비교

1. 업무 폴더를 확인하고 평소처럼 요청합니다. 신뢰한 업무를 실제로 실행할 때 전후 기록을 수집합니다.
2. **이번 결과 → 파일 변경 비교**에서 요청 기록을 고릅니다.
3. 파일을 선택하여 추가·변경·삭제 상태와 `− 이전 내용 / + 이후 내용`을 확인합니다.

비교 대상은 요청 경계에서 앱이 보관한 내용입니다. 화면을 여는 순간의 원본 파일을 다시 읽어 비교하지 않습니다. 0.16.0 이전 요청의 원래 내용이나 수집 범위에서 빠진 파일은 소급 복원하지 않습니다. 같은 폴더를 사용하는 업무에서는 그 폴더의 보관 기록을 함께 표시합니다. 보관 한도는 업무별이 아닌 **앱 전체 최근 요청 8개**입니다.

텍스트는 파일당 **128 KiB**, 한 번의 수집에서는 합계 **512 KiB**까지만 보관합니다. 따라서 요청 전과 후는 각각의 512 KiB 한도를 적용합니다. 지원하는 텍스트 파일에서만 줄 단위 차이를 제공합니다. Office·PDF·이미지·압축파일은 파일명·크기·수정 여부 같은 메타데이터를 확인하며, 문서 내부 비교는 제공하지 않습니다.

현재 범위는 업무 폴더와 바로 아래 하위 폴더입니다. 숨김 파일·일반적인 비밀정보 파일명·개발 빌드 폴더·링크 등은 제외합니다. 이 제외 규칙은 파일 내용에 민감한 정보가 전혀 없다는 보증이 아닙니다. 수집된 텍스트는 앱의 로컬 상태 폴더에 보관되며 이 비교 기능 자체가 외부로 전송하지 않습니다.

시간·크기·파일 수 제한이나 읽기 오류가 있으면 일부만 확인했다고 표시합니다. 확인하지 못한 파일의 부재를 삭제나 추가로 단정하지 않습니다. 다른 프로그램이 같은 폴더를 수정한 내용도 포함될 수 있으므로 변경의 원인을 모두 Claude로 확정하지 않습니다.

**이 기능은 읽기 전용입니다.** 파일을 되돌리거나 이전 버전으로 덮어쓰지 않습니다. 메일 발송이나 외부 시스템 작업을 취소하는 기능도 없습니다.

## 대화 분기

1. 원래 대화의 작업과 승인·질문을 마칩니다.
2. 업무 제목 옆 **대화 분기**에서 원본 대화와 폴더를 확인하고 **분기 만들기**를 누릅니다.
3. 새 업무에 원본 맥락이 표시됩니다. 새 업무의 첫 연결에서 폴더 실행 권한을 확인합니다.
4. 원하는 후속 질문을 보내면 별도 Claude 대화로 이어갑니다. 원래 업무는 그대로 남고 **원래 대화 보기**로 돌아갈 수 있습니다.

분기 생성은 앱 안에 새 업무와 분기 준비 정보를 저장합니다. 이 단계만으로 AI 요청을 보내지 않습니다. **독립된 Claude 대화 기록은 첫 요청을 보낼 때 만들어집니다.** 준비 상태로 앱을 닫아도 원본 확인 정보를 보존하며, 재개할 때 다시 확인합니다.

분기는 Claude가 지원하는 기본 분기 기능을 사용합니다. 설치된 CLI에서 필요한 옵션을 확인하지 못하거나 원본 기록·폴더를 확인하지 못하면 이유를 안내합니다. 원본 대화를 대신 사용하면서 분기가 된 것처럼 표시하지 않습니다. 첫 요청 전에 원본 기록이 달라지면 원본 업무에서 새 분기를 만들어야 합니다.

현재 지원 범위는 **마지막 완료 기록에서 분기**입니다. 과거의 임의 메시지를 선택해 그 시점에서 분기하는 기능은 없습니다. 화면에 보이는 맥락은 기존 가져오기와 같은 제한된 표시용 복사본이며, 실제 대화 기록의 재개·분리는 Claude가 담당합니다.

**대화는 분리되지만 작업 폴더는 같습니다.** 두 대화에서 파일을 수정하면 같은 원본에 반영됩니다. 폴더 복제나 Git worktree 생성은 하지 않습니다. 파일까지 별도로 실험하려면 먼저 별도 폴더를 마련해야 합니다.

첨부 대기 목록·예약·미처리 승인·작성 중 초안과 앱에서 임시로 선택한 모델·Effort·승인 설정은 새 업무에 복제하지 않습니다. 새 연결의 실제 적용 값은 연결 후 입력창에서 확인합니다. 기존 개인 Claude 설정은 유지합니다.

## 화면과 자원 사용 설계

새 화면은 기존 글꼴·색·테두리·뉴모피즘 표면을 사용하고, 검색과 필터를 위에 두고 긴 목록만 내부에서 스크롤합니다. 키보드 조작, 명확한 선택 상태, 닫은 뒤 포커스 복원을 지원합니다. 대화 입력창에 같은 기능의 버튼을 더 쌓지 않습니다.

| 부분 | 처리와 보관 한도 |
| --- | --- |
| 알림 | 기존 저장 기록 최대 50개와 현재 응답 요청 메타데이터 사용. 화면은 한 번에 30행만 표시하며 다음 페이지로 이동 |
| 알림 갱신 | 기존 대기 상태 조회를 재사용. 같은 결과이면 목록·업무 사이드바를 다시 만들지 않음 |
| 팔레트 | 이미 불러온 업무 최대 500개 검색, 화면 결과 최대 24개. 별도 폴더 탐색·상시 색인·타이머 없음 |
| 비교 수집 | 파일 최대 200개, 디렉터리 항목 최대 2,000개, 하위 폴더 최대 30개, 반복 탐색 시간 예산 0.5초 |
| 비교 텍스트 | 파일당 128 KiB, 수집 시점별 합계 512 KiB. 전체 최대 8개 요청 기록, 기록 파일 하나 최대 4 MiB |
| 비교 계산 | 선택한 파일만 필요할 때 계산. 입력 최대 2,000행과 계산량 제한, 출력 최대 500행·64 KiB |
| 대화 기록 | 저장된 대화의 본문은 선택할 때 읽음. 유휴 본문은 최근 8개만 캐시하며 진행·연결·승인 처리 중인 업무는 보호 |
| 응답 표시 | 화면 최대 150개 메시지·50만 자, 메시지별 10만 자. 긴 응답은 표시 제한을 안내하며 Claude 원본 기록은 유지 |
| 스트림 | 대기 버퍼 합계 10만 자·16개 블록. 숨겨진 창에서도 프레임 정지로 버퍼가 누적되지 않도록 기존 배치 타이머에서 처리 |
| 분기 확인 | 선택한 Claude 기록만 제한 범위에서 확인. 원본 지문은 64 KiB씩 읽어 계산하고 전문의 추가 상시 캐시를 만들지 않음 |
| 창을 닫았을 때 | 팔레트 결과·알림 목록·비교 화면의 DOM과 비교 응답 참조 해제. 새 기능용 백그라운드 감시 루프 없음 |

이 수치는 각 기능의 처리·보관 상한입니다. Python 서버·브라우저·Claude 프로세스를 모두 합친 앱 전체 메모리 사용량을 뜻하지는 않습니다. 파일 시스템 응답 시간에 따라 실제 작업 시간이 탐색 예산보다 길어질 수 있습니다.

## 기존 기능과 설정 유지

기존 단축키, 드래그 첨부, 업무 정렬·핀, 공통/폴더 스킬, 후속 요청·예약, 트레이 실행, 모델·승인 제어를 각각의 기존 경로로 사용합니다. 새 화면이 질문 전송이나 승인을 대신 수행하지 않습니다.

UAC·Windows 보안 정책·Python 설치·Claude 인증·개인 설정·설치 플러그인을 바꾸지 않습니다. 스킬 목록에 사용자가 설치한 Company Agent가 있으면 일반 Claude 플러그인과 동일하게 취급하며, 이 네 기능의 전제 조건으로 삼지 않습니다.

회귀 검증 대상은 읽음과 요청 완료의 구별, 읽음 응답보다 늦게 온 조회 결과, 닫힌 창과 업무 전환 뒤의 늦은 응답, 한글 조합·단축키 충돌, 비교 한도·부분 수집·원본 무변경, 원본 보존·첫 요청 전후 분기·미지원 CLI 처리입니다. 최종 통합 검사와 실제 환경 확인 결과는 별도 검증 기록에 남깁니다.

# Workspace 0.11.2 스킬 분류·개수 수정

## 발견한 원인

기존 화면은 설치 목록의 `user-invocable` 속성을 받지 못해 내부 보조 스킬을 일반 스킬로 표시했습니다. 탭 숫자는 현재 CLI 연결 목록만 세어 첫 요청 전 설치 스킬이 보이더라도 `—`로 남았습니다.

활성 Company Agent 1.4.23 설치의 읽기 전용 메타데이터 조회에서는 일반 스킬 48개, 내부 보조 3개, 호출 이름이 없는 참고 자료 1개, 합계 52개가 확인됐습니다. 내부 보조 항목은 `codex-cli-runtime`, `codex-result-handling`, `gpt-5-4-prompting`입니다. Ouroboros의 `auto`, `help` 등은 실제 SKILL.md이므로 이름만으로 제거하지 않습니다. 이 수치는 이 PC의 조회 시점 결과이며 다른 설치에 고정하지 않습니다.

## 수정

- 등록된 설치와 Python을 재검증하는 독립 메타데이터 helper를 배포합니다. 기존 Company Agent 설치나 Claude 설정은 수정하지 않습니다.
- 각 SKILL.md의 제한된 frontmatter만 읽고 `user-invocable: false`를 내부 보조로 분류합니다. 직접 요청 전용인 `disable-model-invocation: true`는 일반 스킬로 유지합니다. 호출 이름이 없는 자료는 별도 참고 자료로 표시합니다.
- 정확한 플러그인 포함 호출 이름으로 설치·현재 연결의 중복을 합칩니다. 일반 스킬은 상단 개수에, 내부 보조와 참고 자료는 별도 접힌 영역에 표시합니다. 검색어가 전체 개수를 바꾸지 않습니다.
- 도구·연결 서버·명령은 `연결 전`, `미확인`, 실제 보고된 개수를 구분합니다. 명시적 빈 목록만 0입니다.
- 미지원 설치, 읽기 실패, 폴더 신뢰 확인 필요 안내를 보존합니다. 조회는 AI 요청이나 후크·MCP 실행을 시작하지 않습니다.

## 검증과 적용

- 카탈로그 API 18개, 메타데이터 helper 10개, 카탈로그 화면 12개, 기존 화면 상태 7개, 종료 화면 4개: 51개 통과.
- 서버·설치 선택·재실행·시작 진단: 85개 중 82개 통과, 3개 환경 조건 건너뜀. 실제 로그인 사용자 판정이 필요한 실행기 3개는 격리 환경에서 WS-31을 확인한 뒤 정상 Windows 사용자 환경에서 모두 통과했습니다.
- 실제 설치 조회: 48 + 3 + 1 = 52, 읽기 실패 0, 부분 목록 아님.
- ZIP: `dist/company-workspace-preview-0.11.2-20260928-221727.zip`, 41개 파일 소스 일치, 진단 해시·상태/자격증명 제외 검사 통과. SHA-256 `e0501b60c27ac246d4786aadcead3a94a2dbf3882cdb95d481be323fdd68d25f`.
- 기존 `dist/company-workspace-preview-0.11.1-20260928-214617/Company-Workspace` 폴더에 수정 파일 9개를 적용했습니다. 폴더 이름을 유지했고 내부 실행 버전은 0.11.2입니다. 실행기 종료 코드 0, API의 실행 폴더·버전을 확인했으며 설치 파일 41개가 새 ZIP과 일치합니다.

- 화면 QA는 실제 설치와 분리된 가상 48 + 3 + 1 데이터로 수행했습니다. 1280px·390px에서 일반 개수, 내부/참고 접힘, 내부 항목 검색 시 호출명 숨김, 검색 후 전체 숫자 유지, 연결 전 상태를 확인했습니다. 390px 탭 너비와 스크롤 너비는 모두 336px이며 가로 잘림이 없었습니다. 브라우저 오류·경고 로그는 없습니다.
- 실제 실행 폴더의 화면에서는 재시작 후 `needs-trust` 안내와 연결 전 상태를 확인했습니다. 폴더 신뢰를 다시 켜는 동작은 자동 승인 검토에서 보안 경계 변경으로 거절되어 사용자 승인을 요청했습니다. 실제 폴더의 신뢰 설정은 변경하지 않았고 AI 요청은 보내지 않았습니다. 실제 설치 목록의 48 + 3 + 1은 별도의 읽기 전용 helper 조회 결과이며 가상 화면 QA와 구분합니다.

# Workspace 0.11 스킬·도구 탭 구현·검증

선택한 업무에서 Claude가 제공하는 기능을 GUI에서 찾도록 왼쪽에 **스킬·도구**를 추가했습니다. 기존 뉴모피즘 화면 안에서 스킬, 도구, 연결 서버, 명령을 분류하고 이름·설명·출처로 검색합니다.

## 정보의 근거

- 현재 연결 목록은 기존 CLI 초기화 응답과 `system/init` 보고값을 사용합니다. 명령 설명은 초기화 메타데이터를 보존하며 이후 명령 목록을 받은 경우 실제 보고된 이름만 유지합니다.
- 설치된 스킬은 신뢰한 업무 폴더에 대해 기존 Company Agent의 `snapshot/checks` 읽기 전용 조회를 사용합니다. 화면에서는 설명·출처·범위만 추려 표시합니다. 현재 연결의 목록과 구분하며, 설치 조회를 지원하지 않는 환경에서도 CLI 보고 목록은 표시합니다.
- 항목 미제공과 명시적으로 비어 있는 목록을 구분합니다. 연결 종료 후에는 마지막 연결 정보라고 표시합니다. MCP 상태도 현재 상태와 마지막 상태를 구분합니다.
- 목록 조회는 Claude 프로세스를 새로 시작하거나 모델 요청·도구 실행을 하지 않습니다. 기존 설정과 승인 흐름을 변경하지 않습니다. 비밀 설정, 환경변수, 원본 오류, MCP 실행 인수는 카탈로그 응답에 포함하지 않습니다.
- 조회 중 업무 전환·연속 새로고침·창 닫기에서 늦게 도착한 응답을 버립니다. 탭을 닫아도 대화와 작성 중 초안을 유지합니다.

| 서버, 시작 진단, 기존 화면 상태 | 40개 중 38개 통과, 2개 환경 조건 건너뜀 |

가상 CLI로 브라우저에서 업무 미선택, 첫 연결 전 설치 목록, 연결 후 네 종류의 목록, 검색, MCP 성공·실패, 명령 설명, 질문 대기 안내, 초안 복원, 연결 종료 후 마지막 목록을 확인했습니다. 1440px 데스크톱과 390px 좁은 화면에서 확인했으며 좁은 화면의 가로 넘침은 없었습니다. 브라우저 오류·경고 로그는 없었습니다.

화면 검증에는 실제 모델 대신 로컬 가상 CLI를 사용했습니다. 실제 회사 HCP 연결이나 개별 스킬·도구 실행 성공을 검증한 결과는 아닙니다. CLI 버전이 보고하지 않는 기능을 임의로 사용 가능하다고 채우지 않습니다.

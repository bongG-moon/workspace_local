# 이어 할 일 클릭과 드래그 검증

## 원인과 수정

- 행 전체의 native draggable 설정 때문에 삭제/지금 반영 버튼을 누른 채 마우스가 7px 움직이면 dragstart 대상은 버튼이 아닌 행이 됩니다. 기존 버튼 제외 조건이 작동하지 않아 pointercancel이 발생하고 click/API 호출이 누락되는 것을 실제 Edge에서 재현했습니다.
- 손잡이만 draggable로 지정하고 dragstart 대상도 손잡이로 제한했습니다. 행의 grab 커서도 제거했습니다.
- 드래그 도중 전체 dispatch revision 변경만으로 취소하던 조건을 실제 queued 항목 ID/순서 비교로 좁혔습니다. 업무 전환, 잠금, 항목 구성/순서 변경 시 보호 조건은 유지합니다.

## 확인

- 관련 Python/Node 회귀 테스트 179개 통과.
- 실제 배포 HTML/JS와 합성 HTTP 응답을 사용하는 scripts/test-lab/verify-workspace-queue-pointer.cjs 추가.
- 출력 이벤트 없음/20ms 간격 assistant_delta 및 상태 갱신 조건 각각에서 삭제/지금 반영 클릭 중 마우스 이동 0, 4, 7, 10px 모두 한 번에 처리: 16개 조건.
- 두 조건에서 손잡이 순서 변경 2개 조건 추가: 총 18개 통과, 페이지 오류 없음.
- 기존 브라우저 검증에서 초안 보존, 줄바꿈 전송, 입력창 지금 반영, 삭제 및 순서 변경 통과.
- 실제 Claude 프로세스나 사내 환경은 호출하지 않았습니다. 이 결과는 클릭 이벤트 충돌을 입증하며 사용자 PC의 모든 부하 요인을 배제하는 측정은 아닙니다.

## 재검증

저장소 루트에서 Playwright가 있는 node_modules를 NODE_PATH로 지정한 뒤 실행합니다.

```text
node scripts/test-lab/verify-workspace-queue-pointer.cjs
```

버전 0.23.29 유지. 동일 버전 릴리즈 갱신에 포함합니다.

## 입력 영역 위치 변경 추가 검증

- 사내 최신 설치본에서 목록 관리 취소는 작동하지만 인라인 휴지통이 간헐적으로 무반응이라는 후속 보고를 받았습니다. 사내 실행 환경을 직접 확인하지 못했으므로 동일 원인이라고 단정하지 않습니다.
- 로컬 브라우저에서 pointerdown 뒤 입력창 높이를 변경하면 휴지통 위치가 71px 이동하고 기본 click/API 요청이 누락되는 것을 재현했습니다. 이는 레이아웃 변동 조건을 강제로 만든 검증입니다.
- 인라인 삭제/지금 반영 버튼에 포인터 캡처를 적용했습니다. 처음 누른 버튼에 정상적인 release를 전달하고 후속 native click을 소비해 중복 실행을 막습니다. 누를 때는 실행하지 않으며, 12px 초과 이동이나 원래 클릭 범위 밖 release, context 변경, 비활성 상태에서는 실행하지 않습니다.
- SVG와 내부 요소는 클릭 대상을 가로채지 않도록 하고 버튼 전체 영역이 입력을 받게 했습니다. 키보드 Enter 활성화는 기존 click 동작을 유지합니다.
- 기존 출력 중/출력 없음 테스트에 버튼 여백/아이콘, 레이아웃 이동, 바깥 release 취소, 키보드 실행 검증을 추가했습니다. 전 조건 통과 및 페이지 오류 없음.
- 이 추가 수정은 소스만 변경했으며 아직 배포하지 않았습니다.

## 실제 HTTP 서버 연결 검증

- 브라우저와 실제 LocalApp/Server를 연결하고 ClaudeSession만 격리 테스트 대역으로 교체했습니다. 실제 /api/dispatch의 삭제, 순서 변경, apply_now 처리를 사용했습니다.
- 3개 요청 중 가운데 요청 삭제 → 마지막 요청을 처음으로 드래그 → 지금 반영 클릭을 순서대로 실행했습니다.
- 서버에서 선택 요청이 기존 실행 중지 후 정확히 한 번 전달됐고, 다른 요청은 queued 상태로 유지됐으며 선택 요청은 submitted 상태인 것을 확인했습니다. 작성 중 문장도 그대로 유지됐습니다.
- 재검증 스크립트: scripts/test-lab/verify-workspace-queue-http.py 및 .cjs. Python 임시 폴더만 사용하며 실제 사용자 Claude 설정을 바꾸지 않습니다.
- 1000×700, 1280×800, 1600×900 세 창 크기에서 기존 포인터/연속 출력/위치 이동/드래그/키보드 조건을 반복 검증했고 모두 통과했습니다.
- 사내 PC 및 실제 Claude 응답은 직접 검증하지 않았습니다. 추가 수정은 아직 설치 파일에 포함되지 않았습니다.

## 입력 지연 측정

- 실제 HTML/JS와 모의 HTTP 환경에서 PerformanceObserver longtask 및 pointerdown event timestamp를 측정했습니다. 이 수치는 서버 응답 시간이나 사내 PC 프로세스 사용량 측정이 아닙니다.
- 기본 조건: 삭제 10회 모두 처리, 최대 입력 지연 약 0.7ms, 50ms 이상 긴 작업 0회.
- 긴 대화 150개를 생성하고 20ms 간격 출력/상태 이벤트 및 브라우저 CPU 4배 감속 적용: 삭제 10회 모두 처리, 최대 입력 지연 약 20.1ms, 긴 작업 2회(최대 198ms). 긴 작업은 초기 대화 생성도 포함합니다.
- 표본이 작은 로컬 부하 검사이므로 실제 사내의 반복 클릭 누락 원인을 단정하거나 부하 문제를 배제하는 근거로 사용하지 않습니다. 같은 증상의 정확한 분류에는 사내 발생 시 입력 수신→핸들러 실행→HTTP 발송→응답의 시간과 장시간 작업 기록이 필요합니다.

# WS-40 출력 혼입 및 연결 수명 검증

검증일: 2026-11-03. 0.23.42에서 수정한 뒤 0.23.43으로 배포하는 변경의 검증 기록이다.

## 확인한 원인과 수정

- 기존 권한 확인은 PowerShell stdout 전체가 `normal` 또는 `administrator`인지 비교했다. 보고서처럼 진단 문자열이 붙으면 실제 권한 검증에 성공했어도 WS-45로 거절했다. Python 서버의 예외 종료가 실행기에서 WS-40으로 표시되는 경로도 확인했다.
- 권한 검증은 기존 Windows 사용자, 세션 및 토큰 확인을 그대로 수행한다. 검증이 끝난 뒤 이번 호출에만 사용하는 임의 식별자로 결과의 시작과 끝을 표시한다. 시작/끝 밖의 진단 문자열은 무시하되, 손상/중복/다른 호출의 결과와 명시적으로 요청한 권한 불일치는 거절한다. 출력은 64KiB로 제한한다.
- 서버와 실행기 사이에 확인된 시작 오류 코드를 보존한다. 권한 응답 자체를 판독할 수 없는 경우 WS-45 안내를 제공한다.
- CLI 버전 조회는 `숫자.숫자.숫자 (Claude Code)`만 추출한다. 서로 다른 버전이 섞였거나 형식을 확인하지 못하면 빈 버전으로 남겨 버전에 의존하는 기능을 임의로 활성화하지 않는다. 도움말 기반 기능 확인은 유지한다.
- 업데이트 사전 준비 응답도 호출별 식별자로 구분한다. 자식 프로세스의 정상 종료와 정확한 성공 응답이 모두 있어야 진행한다. 기존 식별자 없는 Python CLI의 JSON 출력 형식은 유지한다.
- 대화 스트림의 JSON 처리에는 일반적인 문자열 제거를 추가하지 않았다. 정상 답변/도구 결과 안의 진단문처럼 보이는 내용은 보존한다.

SoftCamp DLL의 주입 및 제조사 귀속은 전달받은 PC 보고서의 근거다. 이 개발 PC에서 해당 DLL을 주입하거나 설치하지 않았다. 동일한 stdout 문자열을 실제 PowerShell 및 합성 CLI에 섞어 실패 조건과 수정 결과를 검증했다.

## 메모리와 오래된 연결

- 연결 수 상한은 5개이며, 실행 중인 요청을 보호하면서 보관 연결을 3개 수준으로 줄이는 기존 정리 기능을 확인했다. 실행/승인 대기/이어 할 일/종료 미확인 상태는 정리 대상에서 제외될 수 있다. 보관 목표 3개가 모든 시점의 강제 상한은 아니다.
- 답변 중지는 연결 자체를 끊지 않으므로 빠른 재개를 위한 Claude 프로세스가 남을 수 있다. 저장된 세션 기록의 개수와 실행 중인 프로세스 개수는 구분해야 한다.
- 격리된 PowerShell 래퍼와 합성 CLI로 연결, 승인 모드 변경, 실행, 답변 중지, 후속 요청, 연결 종료를 8회 반복했다. 매 회 연결 종료 뒤 해당 작업이 만든 프로세스는 0개였다. 추가로 실행 중 앱 종료 후에도 0개였고, 소유한 모든 Windows Job의 정리가 확인됐다. 실제 개인 Claude 요청은 보내지 않았다.
- 별도의 메모리 문제를 재현했다. stderr 한 줄이 매우 길고 줄바꿈이 없으면 기존의 무제한 `readline()`이 문자열을 자르기 전에 큰 버퍼를 만들었다. 4KiB 단위로 읽고 전체 출력을 계속 비우면서 실제 한 줄당 2,000자, 최대 30개 진단만 유지하도록 수정했다.
- 16MiB 무개행 합성 입력에서 해당 읽기 함수의 Python 최대 할당량은 수정 전 약 32.2MiB, 수정 후 약 19KiB였다. 64MiB 입력에서도 약 19KiB였다. 앱 전체 RSS나 실제 Claude 메모리 절감률을 뜻하지 않는다.

## 검증 범위

- 직접 시작 및 실제 현재 사용자 권한 확인 17개: 정상/관리자 결과, 앞뒤/같은 줄 진단문, 결과 누락/중복/오염, 잘못된 호출 식별자, 자식 실패, 명시적 권한 불일치.
- CLI 탐색 및 영향받는 연결/모델/승인/재시작 테스트 165개. 샌드박스에서 로컬 소켓이 차단된 4개는 격리된 로컬 테스트만 일반 사용자 환경에서 다시 실행해 통과했다.
- 프로세스 소유권/Windows Job/유휴 연결/동시 업무/재연결/종료/stderr 테스트 97개. 위 그룹과 일부 중복하므로 합산 수치로 취급하지 않는다.
- 시작 출력, 다시 열기, 업데이트 전환, Python 진단, 실행 진단 및 버전 동기화 회귀 검증은 116개 통과, 현재 샌드박스가 일반 사용자 토큰이 아니어서 조건부 테스트 1개 건너뜀. 실제 일반 사용자 권한 확인은 위의 직접 시작 테스트에서 별도로 통과했다. 로컬 소켓 차단 3개는 격리된 일반 사용자 테스트에서 통과했다. 예전 다시 열기 테스트의 버전 추출과 빌드 식별값 fixture도 현재 실행기 계약에 맞췄고 22개 전체를 재실행해 통과했다. 운영 코드의 빌드 일치 검사는 유지했다.
- 독립 코드 검토에서 이번 변경을 차단할 결함은 발견되지 않았다.

## WS-40 발생 PC에 수정본을 적용하는 경로

- 사내 배포 도구가 만든 `AX-Workspace-Install.exe`는 예전에 받은 파일도 그대로 사용할 수 있다. 같은 서버와 프로젝트의 고정 최신 채널에서 최신 Setup을 직접 내려받으므로 앱의 권한 확인 실패 경로를 먼저 실행하지 않는다. 수정된 새 버전의 파일과 체크섬을 검증한 뒤 최신 채널까지 게시해야 한다.
- PC에 저장해 둔 버전별 `AX-Workspace-<버전>-Setup.exe`와 일반 `AX-Workspace-Setup.exe`는 그 파일을 만들 당시의 앱을 포함한다. 최신 파일을 새로 내려받아야 한다. 서버의 파일을 바꿔도 이미 내려받은 파일의 내용은 바뀌지 않는다.
- 이번 WS-40은 앱의 업데이트 서비스가 시작되기 전 권한 확인에서 발생한다. 따라서 실행되지 않는 옛 앱이 서버 갱신만으로 자동 복구된다고 안내하면 안 된다. 실행기의 `updates/current.json` 연결은 이미 해당 PC에 설치가 완료된 더 높은 버전을 찾아 여는 기능이다.
- 사내 배포 도구는 이미 게시된 버전의 다른 내용을 덮어쓰지 않는다. 이번 수정본의 정식 배포는 기존보다 높은 버전으로 진행한다.

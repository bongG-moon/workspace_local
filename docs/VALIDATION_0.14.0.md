# Company Workspace 0.14.0 검증 기록

전체 검사는 Company Agent 외부 코어 없이 실행했습니다. 32개 생략은 선택적 Company Agent 통합 20개, 심볼릭 링크 권한 4개, 실제 Windows 사용자·토큰·트레이·알림·제목 표시줄 opt-in 7개, 시험 프로세스에서 실행되지 않은 Windows Script Host 1개입니다. 네이티브 트레이·알림·제목 표시줄은 별도 opt-in으로 실행했습니다. 부분 검사와 전체 검사는 중복되므로 합산하지 않습니다. 전체 검사 중 추가된 마지막 키보드 동작은 최종 UI 71개 재검사로 별도 확인했습니다.

브라우저와 Bypass 검사는 실제 모델 요청을 금지하는 격리된 제어 전용 CLI를 사용했습니다. 실제 Claude의 Bypass 업무를 실행하지 않았습니다. 거절·정책 제한·잘못된 적용 응답에서는 완료로 표시하지 않는 경로와 동일 UUID 재연결·기존 모델/Effort 복원을 검사했습니다.

세션 가져오기는 현재 설정 위치에 한정합니다. 실제 로컬 기록 일부도 읽기 전용으로 확인했으며 대화 본문이나 개인 세션 식별자는 공개 기록에 포함하지 않았습니다. 손상 JSON의 과도한 중첩·잘못된 필드 유형·단독 surrogate가 HTTP 응답을 깨뜨리지 않도록 보완했습니다. 원본 바이트 보존, 중복 불러오기, 폴더 확인, 설정 위치 변경 차단을 검사했습니다.

실제 EXE 검사는 `--no-browser`를 사용했습니다. 실제 기존 인증에 대한 연결 초기화까지 확인했으며 새 AI 업무를 보내지 않았습니다. 실제 네이티브 창 전체 사용 흐름이나 운영 회사 PC를 재검증한 결과는 아닙니다.

## 확인 범위와 한계

- 제목 표시줄은 검증된 앱 HWND에만 Windows 색상 적용을 요청합니다. 실제 Windows 11에서 색 설정 API는 성공하지만 해당 색 속성의 조회 API는 E_INVALIDARG를 반환하는 점을 확인하여, 조회 성공을 적용의 전제 조건으로 삼던 코드를 수정했습니다. 성공 상태는 `native_colors_requested`로 요청 수락을 의미합니다. 테스트 창의 실제 외관을 확인했다는 뜻이 아니며 Windows 10·Edge가 그리는 제목 표시줄은 색을 반영하지 않을 수 있습니다.
- 고대비 상태를 유지하며 Windows·브라우저 전체 테마 설정을 쓰지 않습니다. 부분 실패 시 이번 호출이 적용한 속성만 Windows 기본값으로 되돌리도록 요청합니다.
- 네이티브 알림 API와 소유 콜백은 시험했지만 Windows의 배너 실제 표시를 보장하지 않습니다. 집중 모드·알림 설정에 따라 표시가 억제될 수 있고 앱 알림함에는 기록을 남깁니다.
- 가져오기 자체는 원본 Claude 기록을 수정하지 않습니다. 이후 사용자가 요청을 보내면 Claude가 같은 UUID의 기록을 이어 쓰며, 외부 터미널과 같은 UUID를 동시에 실행하지 않도록 안내합니다.
- 일반 Claude Code와 기존 인증을 사용하고 Company Agent를 필수로 요구하지 않습니다. 개인 설정·UAC·회사 보안 정책을 수정하지 않습니다. Bypass는 사용자가 위험 확인을 거쳐 명시적으로 요청하는 현재 업무의 실행 모드입니다.

# 개인 스킬 단일 원본 및 Claude 호환성 검증

검증일: 2026-10-11 (한국 시간). 앱 버전: 0.23.21 유지.

## 변경 사항

- 기존 개인 스킬 원본을 복사하는 대신 Claude 표준 스킬 폴더의 로컬 정션·심볼릭 링크를 읽습니다. 개인/프로젝트 `skills` 루트 또는 직계 스킬 폴더만 허용하며 설정, 플러그인, 명령 파일의 경로 제한은 유지합니다.
- 원본이 같은 스킬은 한 번만 표시합니다. 개인 스킬 우선순위와 숨김 설정을 유지합니다. 다른 사용자 프로필, 네트워크·장치 경로, 끊어진 연결, 순환 연결은 허용하지 않습니다.
- 연결 후 추가·수정한 스킬도 기존 5초 메타데이터 캐시 만료 후 자동완성 후보에 반영합니다. 파일 복사, 상시 동기화, 파일별 프로세스 실행은 없습니다.
- CLI가 보고한 `/apps/web:deploy` 같은 하위 폴더 호출명을 보존합니다. 입력 도중에도 자동완성이 유지되며 선택 시 명령 전체를 바꾸고 기존 인수와 초안을 보존합니다. 첫 Enter는 선택만 하고 다음 Enter가 전송합니다.

## 실제 환경 적용

사용자가 지정한 업무의 표준 `.claude/skills`를 해당 업무 전용 개인 저장소에 연결했습니다. 프로젝트 범위 해시와 원본·기존 사본의 SHA256이 일치하는 것을 확인한 뒤 직전 작업에서 만든 사본만 제거했습니다. 개인 원본, Claude 설정, 플러그인 등록, 프로젝트 설정·MCP·CLAUDE.md의 변경이 없음을 비교했습니다. 실제 사용자 스킬은 실행하지 않았습니다.

실제 파일 기준 `/mumu-pocket-launch` 자동완성을 확인했으며, 공통 범위에서는 이 업무 전용 스킬을 추천하지 않는 것을 확인했습니다. 이 검사는 실제 파일과 의도적으로 오래된 CLI 보고 목록을 결합한 검사이며, 개인 CLI 세션에 업무 요청을 보내는 검사는 아닙니다.

## 검증 근거

- 실제 설치된 Claude Code 2.1.296을 격리된 설정으로 초기화하여 `skills` 루트 정션의 합성 스킬을 인식함을 확인했습니다. 원본 설명 수정·새 스킬 생성 후 새 CLI 초기화에서도 두 변경이 확인됐습니다. 실제 모델 요청·사용자 스킬 실행·개인 설정 변경은 없습니다.
- 동일 프로세스의 `initialize` 제어 요청을 다시 보내면 초기 명령 목록을 반환했습니다. 이어 실제 CLI를 로컬 전용 가짜 Messages API에 연결하여 합성 `/스킬명` 요청 3회를 보냈습니다. 원본 최초 본문 → 원본 수정·신규 생성 후 6초 대기 → 새 스킬 본문 → 수정된 기존 본문이 실제 요청에 포함됐고 모두 정상 완료됐습니다. **같은 CLI 프로세스 안에서 신규 생성·수정의 실제 슬래시 확장까지 확인**했습니다. 외부 모델 요청과 실제 개인 스킬 실행은 0회이며, 테스트 API는 도구 호출 없이 고정 텍스트만 응답했습니다.
- 실제 Windows 정션을 사용하는 회귀 검사는 원본 생성·수정, 캐시 만료, 해시·수정시간 보존, 범위 분리, 중복 제거와 차단 경계를 검사합니다. 정션 자체를 비재귀로 해제하여 원본 파일을 지우지 않습니다.
- 로그인·설정 루트·환경 변수·작업 폴더·실행 래퍼·세션 이어가기·Effort·승인 모드의 기존 격리 회귀 68개를 통과했습니다.
- 자동완성의 경로 포함 호출명, 기존 인수 보존, 한글 조합, 선택과 전송 구분을 검증했습니다.
- 최종 통합 회귀: 175개 중 172개 통과, 3개 환경 제약으로 건너뜀(심볼릭 링크 생성 권한 2개, 선택적 구형 하네스 소스 부재 1개). 실제 Windows 정션 테스트는 실행하여 통과했습니다.
- 실제 업무의 파일 기반 자동완성 재측정: 최초 조회 약 82ms, 캐시 조회 20회 평균 약 1.7ms. 측정 당시 로컬 결과이며 환경별 성능 보장은 아닙니다. 별도 상주 프로세스나 동기화 작업을 추가하지 않았습니다.

## 기존 Claude와의 경계

실행은 기존 Claude CLI와 설정을 사용하며 앱 전용 인증·MCP·후크·스킬 사본을 만들지 않습니다. 다만 앱은 CLI의 JSON 입출력 연결을 사용하므로 터미널의 대화형 메뉴와 완전히 같지는 않습니다. `/theme`, `/terminal-setup` 등 터미널 전용 기능은 앱 기능으로 동일하게 제공한다고 표시하지 않습니다.

래퍼 함수가 실행 내부에서만 `CLAUDE_CONFIG_DIR`을 변경하는 경우, 앱이 미리 읽는 설치 메타데이터는 실제 CLI 설정 위치와 다를 수 있습니다. 실행 래퍼는 그대로 유지하며 실제 연결이 보고한 같은 호출명을 우선합니다. 개인 설정을 추측해서 덮어쓰거나 다른 사용자 프로필을 검색하지 않습니다.

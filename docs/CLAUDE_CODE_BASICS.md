# Claude Code 기본 사용법

Claude Code가 처음인 분을 위한 설명입니다. 명령어를 외우기 전에 **어느 폴더에서, 어떤 자료로, 무엇을 만들지** 정하면 됩니다. 작은 실습은 [시작하기](ONBOARDING_COURSE.md), 키와 명령은 [명령어·단축키](CLAUDE_CODE_COMMANDS.md)에서 확인하세요.

## 1. Claude Code와 Company Agent는 무엇이 다른가요?

Claude Code는 요청을 이해하고 파일 읽기·수정·명령 실행 같은 도구를 사용할 수 있는 프로그램입니다. 대화만 하는 것과 달리 실제 파일이나 외부 시스템에 영향을 줄 수 있습니다. 실행할 수 있는 범위는 연결된 도구와 권한에 따라 달라집니다. [공식 소개](https://code.claude.com/docs/en/overview)

| 구분 | 하는 일 |
| --- | --- |
| AI 모델 | 요청을 해석하고 답이나 작업 계획을 만듭니다. 사내에서는 승인된 모델을 사용합니다. |
| Claude Code | 모델과 대화하면서 파일·명령·도구를 연결합니다. |
| Company Agent | 회사 기준, 업무 스킬, 기억 관리, 실행·결과 확인 절차를 더합니다. 별도의 AI 계정을 만드는 기능은 아닙니다. |
| Workspace | 기존 Claude Code를 사용하는 별도 입력·파일 선택·확인 화면입니다. 원본 CLI의 모든 메뉴와 단축키가 같은 것은 아닙니다. |

이미 회사 환경에서 Claude Code가 된다면 개인 API 키·모델·로그인을 새로 설정하지 않습니다. 연결 문제를 해결하려고 기존 설정 전체를 초기화하지 마세요.

## 2. 작업 폴더부터 확인하세요

작업 폴더는 이번 업무의 출발점입니다. 처음에는 빈 연습 폴더를 사용하고 회사 문서·메일·공용 폴더는 넣지 않습니다. CLI·VS Code·Workspace 중 회사에서 허용한 화면으로 그 폴더를 선택하세요.

폴더를 선택했다고 PC의 다른 경로에 접근할 수 없게 되는 것은 아닙니다. 요청에 대상과 제외 범위를 적고, 승인 화면의 실제 경로를 확인합니다.

```text
지금 선택한 연습 폴더가 어디인지 알려줘.
바로 아래 파일 이름만 확인하고, 다른 폴더나 파일 본문은 읽지 마.
파일·설정·기억을 만들거나 변경하지 마.
```

파일을 지정할 때는 CLI의 `@` 목록이나 사용 중인 화면의 파일 선택을 이용합니다. 파일을 첨부한 것과 전체 내용을 실제로 읽은 것은 다릅니다. 페이지·시트·읽은 범위를 결과에서 확인하세요.

## 3. 요청하고 확인하는 기본 순서

1. **요청:** 목적, 자료, 결과 형식, 하지 말아야 할 일을 적습니다.
2. **선택:** 디자인·저장 위치처럼 필요한 질문에 답합니다.
3. **확인:** 파일 읽기·변경·발송 안내가 나오면 대상과 범위를 봅니다.
4. **실행:** 같은 요청을 다시 보내지 말고 결과나 추가 질문을 기다립니다.
5. **검증:** 실제 결과 파일과 숫자를 열어 확인하고 미확인 부분을 구분합니다.

설명·계획만 원하면 실제 변경을 하지 말라고 적으세요. 실제 작업을 원하면 확인한 계획의 어느 범위를 실행할지 말합니다.

```text
가상 실적 3개월치를 설명할 보고서를 만들고 싶어.
먼저 필요한 자료와 진행 계획만 알려줘.
아직 파일 생성, 프로그램 설치, 설정 변경은 하지 말고 내 답변을 기다려줘.
```

Company Agent는 관련 스킬이 있으면 설명서 본문을 읽어 적용하고, 없으면 허용된 일반 방식으로 진행합니다. 스킬이 둘 이상 같은 역할을 한다면 기존 우선 선택이나 내 답변을 따릅니다. “스킬 사용”이라는 말뿐 아니라 실제 본문 로드와 업무 결과를 따로 확인합니다.

## 4. 승인·중단·되돌리기는 다릅니다

| 상황 | 먼저 확인할 것 |
| --- | --- |
| 자료 전달 | 어떤 파일의 어느 범위인지, 본문이 AI 대화에 전달되는지 |
| 변경·실행 승인 | 원본 보존 여부, 저장 위치, 외부 연결이나 설치 여부 |
| 메일·업로드 | 초안·미리보기인지 실제 발송·전송인지 |
| 중단 | 멈추기 전에 이미 생성·변경·전송된 것이 있는지 |
| 되돌리기 | 실제 복구 가능한 대상과 복구되지 않는 외부 작업이 무엇인지 |

Claude Code의 실행 승인과 Company Agent의 업무 범위 확인은 별도 절차일 수 있습니다. 하나를 승인했다고 모든 후속 작업을 허용한 것은 아닙니다. 자주 묻는다는 이유로 회사 정책이나 승인 절차를 끄지 않습니다.

`Esc`로 응답을 멈추거나 `/rewind`를 열어도 모든 작업이 취소되는 것은 아닙니다. 특히 이미 보낸 메일, 외부 변경, 일부 명령 실행은 별도로 확인해야 합니다. [공식 되돌리기 안내](https://code.claude.com/docs/en/checkpointing)

Workspace의 **작업 중지**도 이미 수행한 일을 되돌리지 않습니다. 앱이 시작한 CLI의 종료 확인을 기다리며, 종료를 확인하지 못하면 중지 성공으로 표시하지 않습니다. 직접 시작한 CLI가 끝나도 모든 하위 프로그램의 종료를 보장하지는 않습니다. 같은 요청을 다시 보내기 전에 실제 결과와 남은 작업을 확인하세요.

## 5. 대화·프로젝트 지침·기억을 구분하세요

| 종류 | 언제 쓰나요? | 주의할 점 |
| --- | --- | --- |
| 현재 대화 | 이번 작업의 자료와 수정 요청을 이어갈 때 | 긴 대화는 필요한 내용 중심으로 정리합니다. |
| 프로젝트 `CLAUDE.md` | 해당 프로젝트의 목적·실행법·완료 기준을 알려줄 때 | 회사 공통 정책 전체나 원본 문서를 복사하는 곳이 아닙니다. |
| Claude 자체 기억 | Claude Code가 제공하는 기억 기능을 사용할 때 | 버전·설정에 따라 동작하며 Company Agent 저장소와 다릅니다. |
| Company Agent 개인 기억 | 다음 업무에도 쓸 선호·맥락을 저장할 때 | 개인 전체 / 이 프로젝트 중 범위와 내용을 확인합니다. |

`/compact`는 대화 요약, `/clear`는 새 대화, `/resume`는 이전 대화 이어가기입니다. 영구 기억 저장이나 파일 복구를 대신하지 않습니다. [공식 대화 관리](https://code.claude.com/docs/en/sessions)

Company Agent의 기본 프로젝트 안내 생성과 개인 자동 학습도 서로 다릅니다. 자동 학습이 회사 규정이나 프로젝트 `CLAUDE.md`를 마음대로 고치는 것은 아닙니다. 저장·적용 범위의 비교는 [하네스 이해하기](COMPANY_AGENT_HANDBOOK.md)를 참고하세요.

## 6. 사용량을 줄이고 완료를 확인하세요

- 필요한 파일과 읽을 범위만 지정합니다. 같은 안내서나 전체 대화를 매번 붙이지 않습니다.
- 이미 고른 디자인·분량은 유지해 달라고 말합니다. 대기 중에 같은 결과 생성을 다시 요청하지 않습니다.
- 같은 업무는 이어가고, 무관한 업무는 새 대화로 나눕니다. 큰 작업마다 무조건 압축하지 않습니다.
- 사용량이 표시되지 않으면 0원이나 토큰 0개로 해석하지 않습니다. 사내 모델의 요금·한도는 회사 기준으로 확인합니다.
- “완료”라는 답보다 **실제 파일, 자료와 일치하는 수치, 확인한 범위와 미확인 부분**을 봅니다.

다음 요청으로 마무리를 확인할 수 있습니다.

```text
이번 요청의 최종 결과와 실제 확인한 범위만 알려줘.
파일이 있다면 정확한 경로를 알려주고, 확인하지 못한 것은 구분해줘.
새 파일을 더 만들거나 기억에 저장하지 마.
```

문제가 반복되면 같은 동작을 계속 실행하지 말고 실제 오류와 현재 파일 상태를 남깁니다. 공유할 로그에서는 업무 내용·인증 값·불필요한 개인 경로를 가리세요. 업무별 예문과 오류 대응은 [업무별 사용법](USER_GUIDE.md)에 있습니다.

# 완료 결과의 확인 상태

검증일: 2026-10-26. 앱 버전 0.23.35에 포함합니다.

## 화면 동작

- 진행 중인 업무는 초록색 점으로 표시합니다. 라이트 모드와 다크 모드의 배경에 맞춰 색상을 구분합니다.
- 완료한 결과가 미확인이면 보라색 점과 굵기 650의 제목을 표시합니다. 확인 후에는 표시를 해제합니다.
- 실행 중에 이전 완료 결과가 미확인이면 초록색 점과 굵은 제목을 함께 유지합니다.
- 승인·질문 대기 배지와 오류 표시는 기존 우선순위를 유지합니다.
- 접힌 업무 폴더, 최근 업무, 전체 업무, 일반 대화에서도 미확인 결과를 알립니다. 실행 개수와 미확인 여부를 혼합하지 않습니다.

## 확인 기준과 저장

해당 업무의 최종 결과가 실제로 렌더됐고 앱이 활성 상태이며 화면에 300ms 이상 보이는 경우만 확인 처리합니다. 설정 팝업, 스킬·확장 화면, 숨김·비활성 창, 과거 대화 스크롤에서는 확인하지 않습니다. 도구 출력만 있는 완료는 해당 요청의 완료 시간 표시를 기준으로 합니다.

업무별 `resultReceipt`는 `revision`, `seenRevision`, `runId`를 보존합니다. 정상 완료한 요청에서만 새 revision을 만들며, 기존 기록을 새 기능 도입 시 일괄 미확인으로 만들지 않습니다. 중복 완료·중지·오류·연결 준비는 새 미확인을 만들지 않습니다. 이후 요청 실행이나 앱 재실행에도 유지됩니다.

`POST /api/session/result-read`는 화면에서 확인한 revision만 반영합니다. 이전 결과의 늦은 확인 응답이나 과거 메타데이터가 새 결과를 지우지 않도록 단조 증가 방식으로 병합합니다. 업무 전환 실패 시에도 실제로 표시했던 revision만 복원합니다. 저장 실패 시 미확인을 유지합니다.

## 성능 범위

새로운 주기 조회나 토큰별 처리를 추가하지 않습니다. 기존 attention 조회에 작은 메타데이터만 포함하며 대화 본문을 불러오지 않습니다. 확인 상태가 바뀌지 않으면 목록을 재렌더하지 않습니다. 화면의 결과 관찰 대상은 현재 업무의 결과 하나이며 캐시는 최대 500개 업무로 제한합니다. 실제 확인 상태가 바뀔 때 기존 기록 저장 경로로 한 번 저장합니다.

## 검증

- 백엔드·프런트엔드·기존 업무 목록·알림·기록 캐시·패키지 구성 관련 테스트 224개 통과.
- 실제 앱 UI와 격리 HTTP 서버를 사용하는 Edge 브라우저 시나리오 12개 통과, JavaScript 오류 0건.
- 라이트·다크 모드, 제목 굵기, 새로고침 후 유지, 다른 업무 초안 보존, 과거 대화·팝업·스킬 화면의 확인 보류, 다음 요청 중 이전 미확인 유지, 늦은 읽음 응답, 중복 완료 확인.
- Windows 최소화 자체는 실행하지 않았습니다. 비활성 창 조건은 브라우저의 포커스 상태와 이벤트를 모사해 확인했습니다. 실제 Claude 실행·개인 설치 앱 변경은 없습니다.
- 배포 번들 생성 목록과 검증 목록에 `result-receipts.js`를 추가하고 파일 누락 검증을 통과했습니다. 배포 시 요청 시간 표시 파일과 함께 EXE·업데이트 ZIP에 포함합니다.

검증 산출물은 작업 디렉터리의 `outputs/unread-results-20261026/`에 보관합니다.

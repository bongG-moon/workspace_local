주요 확인 범위:

- 정지·재개·수정·삭제, 실행 중인 요청을 취소하지 않는 예약 정지
- 앱 재시작 보존, 불확실한 전송의 자동 재전송 방지
- 저장 실패 시 CLI 전송 차단, 완료 기록 저장 실패 후 임의 재실행 방지

## 확인된 결함

### 1. 재시작 후 ‘이어 실행’이 폴더 확인으로 이어지지 않음

- 재현: 미래 예약 저장 → 완전히 종료 → 재실행 → 해당 업무 → 이어 할 일 → 이어 실행.
- 실제 결과: ‘업무 폴더를 다시 확인한 뒤 대기·예약을 실행해 주세요’만 표시하고 필요한 확인창을 열지 않습니다. 사용자 요청은 전송되지 않았습니다.
- 원인: 재시작 시 작업의 `trusted` 값이 초기화되는데, `workflow.js`의 재개 버튼은 폴더 확인 없이 `resume`을 전송합니다. 서버의 폴더 확인 요구는 정상입니다.
- 수정 방향: 재개 동작에서 기존 폴더 확인창으로 연결하고, 확인 성공 후 원래 요청한 재개 동작을 이어가야 합니다. 기존 신뢰 확인을 생략하면 안 됩니다.

### 2. 완료된 일회성 예약을 미래 시각으로 수정해도 자동 실행이 다시 활성화되지 않음

- 재현: 한 번 예약 완료 → 수정 → 미래 시간 선택 → 저장.
- 실제 결과: 저장 성공 안내가 나오지만 목록은 ‘일시 정지’이고 `enabled=false`입니다. 별도로 ‘예약 재개’를 눌러야 합니다. 실제 EXE 화면과 자동 재현으로 확인했습니다.
- 원인: 일회성 예약이 소진되면서 자동 비활성화된 상태를 편집 화면이 사용자가 명시적으로 정지한 상태와 동일하게 취급합니다.
- 수정 방향: 완료·소진 상태와 명시적 정지를 구별해야 합니다. 완료된 예약을 미래로 수정하면 다시 활성화하거나 저장 화면에서 활성 여부를 분명하게 선택하게 해야 합니다.

### 3. Claude 연결 3개 제한에 걸린 새 예약이 대기하지 않고 확인 필요 상태로 고정됨

- 재현: 세 업무에 열린 Claude 연결이 있는 상태에서 네 번째 업무 예약 시각 도달 → 연결 하나 종료.
- 실제 결과: 예약은 `needs_review`, 이유는 `delivery_unknown`으로 남고 연결이 비어도 실행되지 않습니다. 실제 전송과 사용자 메시지 기록은 모두 0개였습니다.
- 원인: 예약을 먼저 전송 중으로 확정한 후 일반 전송 경로에서 연결 한도를 검사합니다. 전송 전의 일시적 연결 부족이 전송 여부를 알 수 없는 실패로 분류됩니다.
- 수정 방향: 전송 확정 전에 연결 수용 가능 여부를 검사해 대기시키거나, 확실한 미전송과 불확실한 전송 실패를 구분해야 합니다. 불확실한 요청을 일괄 재시도하면 안 됩니다.
- 검증 범위: 이 항목은 격리된 실제 앱 컨트롤러·기록용 가짜 CLI 연결로 재현했습니다. 실제 Claude 연결을 네 개 생성하지 않았습니다.

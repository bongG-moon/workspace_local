# Workspace 0.21.5 검증 결과

검증일: 2026-10-01. 변경 범위: 기존 창 재사용과 새 버전으로의 정상 종료·재실행.

## 동작

- 실행 폴더가 달라도 같은 버전이나 더 최신 버전이 열려 있으면 기존 창을 활성화합니다. 더 오래된 실행기로 현재 앱을 내려서 시작하지 않습니다.
- 새 버전은 Python·앱 파일·WebView2 조건을 확인한 뒤 별도의 숨김 전환 프로세스를 시작합니다. 최초 실행기는 장시간 업무가 끝날 때까지 붙잡혀 있지 않습니다.
- 전환 프로토콜을 지원하는 앱은 실행·승인·질문·결과 검토·연결 변경·첨부 전송 중에는 기다립니다. 화면의 초안 저장 확인 후 작업 접수와 종료를 같은 보호 구간에서 결정합니다. 진행 중인 작업을 PID로 강제 종료하지 않습니다.
- 작성 중인 업무·홈 입력과 첨부 경로를 최대 256 KiB의 임시 기록으로 보관합니다. 한도를 넘으면 잘라내지 않고 전환을 중단합니다. 복원을 확인하면 기록을 제거합니다. 새 입력과 충돌한 이전 초안은 따로 보관해 확인·복사할 수 있습니다.
- 전환 대기는 최대 2시간, 유휴 상태의 화면 보관 확인은 45초입니다. 취소·만료·저장 실패는 현재 내용을 보존합니다. 종료 실패나 확인할 수 없는 응답을 성공으로 처리하지 않습니다.
- 원래 승인 정책, 개인 Claude 설정, Windows 설정, 기존 배포 폴더를 변경하지 않습니다. 재시작 후 대기열·예약과 연결별 실행 설정 확인은 기존 정책을 따릅니다.

## 자동 검사

- 관련 회귀 검사 569개 실행: 566개 통과, 환경 조건에 따른 3개 제외.
- 최종 초안 충돌·중복 저장 보완 후 백엔드 및 프런트엔드 검사 41개 통과.
- 실행기·종료·실제 HTTP 프로토콜 및 32비트 Python용 사전 검사 분기 47개 통과.
- 샌드박스 사용자 차이로 앞서 WS-31이 발생한 기존 실행기 검사 3개는 로그인 사용자로 다시 실행하여 모두 통과했습니다.
- 별도 실행 진단 검사 11개 중 10개 통과, 실제 사용자 토큰 명시 실행 검사 1개 제외. 반복 실행한 검사 수는 합산하지 않습니다.

승인 대기·새 작업 접수·저장 응답 경합, 잘못된 nonce/revision, 초안 충돌, 저장 실패, 종료 실패, 대상 버전 불일치, 리디렉션 차단, 중복 실행 잠금, 확인 파일 정리, 연결 타임아웃과 실제 연결 거부를 구분하는 종료 판정을 검사했습니다. 제외 항목은 명시적 실제 토큰 진단, Windows 심볼릭 링크 권한, 네이티브 알림 표시 검사입니다.

## 실제 Windows 창 및 EXE

개인 업무와 분리된 체험 상태에 새 전환 프로토콜을 가진 검증용 이전 호스트를 띄우고 실제 0.21.5 EXE로 전환했습니다. 이전 호스트의 버전 표시는 비교 분기를 시험하기 위해 0.21.4로 설정한 가상 조건입니다. 실제 배포된 0.21.4에 초안 보관 기능이 있다는 의미가 아닙니다.

Computer Use로 다음을 확인했습니다.

1. 보내지 않은 한글 초안과 `/effort high @자료.csv` 문자열을 입력했습니다. AI 요청은 보내지 않았습니다.
2. 검증용 업무를 실행 중으로 유지한 채 새 EXE를 실행했습니다. 실행기는 약 8초 안에 반환하고 기존 창에는 전환 대기와 취소 안내가 나왔습니다.
3. 가상 실행 상태를 유휴로 바꾸자 이전 호스트가 정상 종료되고 실제 0.21.5 EXE의 새 창이 열렸습니다.
4. 새 창의 입력란에 원문이 그대로 복원됐습니다. 업무 목록도 남았고 임시 초안 파일은 복원 확인 후 제거됐습니다.
5. 동일 버전의 소스 실행기를 다른 폴더에서 다시 실행해 같은 네이티브 창 하나를 재사용하는 것을 확인했습니다.

신규 화면 자산 경로 누락은 첫 네이티브 검사에서 발견해 고친 뒤 다시 검증했습니다. 체험 창의 첫 검증 준비에서는 알림 객체를 비활성화하여 호스트 연결에 실패했으며, 검증 도구를 실제 호스트 구성과 같게 고친 후 재실행했습니다.

별도 한글 경로의 EXE만 있는 폴더에서도 실제 실행했습니다. 기존 Python 3.13.5, Claude Code 2.1.285를 인식했고 연결 초기화에서 `claude-sonnet-5-5`, effort `medium`, 명령 141개를 확인했습니다. AI 질문은 0건입니다. 두 번째 EXE 실행의 서버·캐시 재사용과 개인 설정 파일 5개 불변을 확인했습니다. 검증용 앱·서버·Claude 연결은 정상 종료했습니다.

## 배포 및 확인 범위

EXE와 VBS ZIP의 앱 소스 107개 및 네이티브 자산 7개가 동일합니다. ZIP CRC, 파일 목록, 실행 진단 핀, 네이티브 빌드 해시를 확인했습니다. VBS 묶음을 압축 해제해 실제 로그인 사용자로 서버 진입점·인증 API·화면 자산·한국어 폰트·도움말·정상 종료를 검사했습니다. 실제 VBS 더블클릭은 이 검사와 별개입니다. Python 설치 파일, 개인 인증·대화·검증 상태는 배포하지 않습니다.

0.21.4 이하에는 초안 추출과 원자적 유휴 종료 API가 없습니다. 최초 호환 전환은 작업 상태를 검사하고 한 번 확인받은 직후 다시 검사한 다음 기존 정상 종료 API를 호출합니다. 작성 중인 내용은 사용자가 먼저 보관해야 합니다. 구버전의 마지막 검사와 종료 사이에 발생하는 동시 요청까지 새 프로토콜과 같은 수준으로 보호한다고 주장하지 않습니다. 구버전 확인창 수락부터 재실행까지는 자동 계약 검사 범위이며, 이번 실제 GUI 전환 검사는 새 프로토콜 경로입니다.

32비트 Python 분기는 시스템 64비트 PowerShell 선택과 오류 처리 검사 범위이며 실제 32비트 Python 설치로 실행하지 않았습니다. 일반 단일 네이티브 창을 검증했고, 사용자가 같은 서버를 여러 브라우저 탭으로 직접 여는 경우 모든 탭의 미전송 입력을 일괄 수집한다고 보장하지 않습니다. 통신이 끊기면 종료를 추정해 다른 앱을 띄우지 않고 확인 가능한 상태에서만 전환합니다.

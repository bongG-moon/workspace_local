# Company Workspace 0.22.0 — 앱 업데이트

검증일: 2026-10-02 (한국 시간).

## 사용자가 보는 변화

- 설정에서 현재 버전과 새 버전을 확인하고 Release 변경 내용을 볼 수 있습니다. 새 버전이 있으면 설정 옆에 표시합니다.
- 자동 확인은 기본 12시간 간격이며 설정에서 끌 수 있습니다. 다운로드와 설치는 사용자가 버튼을 눌러야 시작됩니다.
- 진행 중인 업무가 끝난 뒤 기존 버전 전환 절차를 사용합니다. 작성 중인 내용과 첨부를 보관하며 전환 취소·실패 뒤에는 재시도할 수 있습니다.
- 새 버전이 정상 시작된 뒤에만 다음 실행 위치를 저장합니다. 기존 0.22.0 이상 EXE 또는 VBS의 공통 실행기를 다시 열어도 최신 설치 버전으로 연결됩니다.
- 0.21.10 이하 사용자는 처음 한 번 새 배포본을 직접 받아야 합니다. 소스 커밋만으로 업데이트가 표시되지는 않으며, 정식 GitHub Release와 배포 파일을 등록해야 합니다.

## 검증한 범위

- 최종 전체 자동검사 1,535건 중 1,502건이 통과하고 33건은 필요한 환경·권한·선택 연동이 없어 건너뛰었습니다. 실패와 오류는 0건입니다. 건너뛴 검사를 통과한 것으로 집계하지 않았습니다.
- 실제 공개 GitHub 0.21.10 메타데이터와 VBS ZIP을 익명으로 내려받아 API 해시·SHA256SUMS·압축 파일 경로·내용 검사를 통과했습니다. 이전·같은·더 높은 실행 버전의 비교 결과를 확인했습니다.
- 고정 저장소, 정식 버전, 인증 경계, 다운로드 한도, 잘못된 압축 경로·체크섬·중복 파일, 취소, 오프라인 오류, 설정 보존, 실패 후 재시도에 대한 자동검사를 수행했습니다.
- 실제 앱 창에서 새 버전 표시, 설정의 버전 정보와 한국어 변경 내용 화면을 확인했습니다. 버튼 동작과 설치 요청 중복 방지는 프런트엔드 자동검사로 확인했습니다.
- 현재 코드의 시험용 0.22.1 패키지를 만들어 별도 상태 폴더에서 업데이트를 실행했습니다. 이 시험 버전은 공개하지 않았습니다. 다운로드 소스는 격리된 시험 응답이며, 실제 설치·PowerShell 실행·네이티브 창·업무 전환은 제품 코드로 동작했습니다.
- 인증된 업데이트 요청 후 기존 시험 앱의 정상 종료, 새 0.22.1 창 하나의 생성, 한국어 초안의 화면 복원, 업무 ID 보존, 122개 파일의 실행 위치 등록을 확인했습니다.
- 새 앱을 정상 종료한 후 원래 0.22.0 EXE로 다시 열어 0.22.1 실행과 업무 보존을 확인했습니다. VBS 배포본의 공통 PowerShell 실행기로도 같은 결과를 확인했습니다. WSH 더블클릭 전체 경로를 재시험한 것은 아닙니다.
- 시험 중 발견한 PowerShell 숨김 실행 옵션 충돌을 수정했습니다. 종료 코드뿐 아니라 실제 스크립트 실행 증거를 확인하는 검사를 추가했습니다.
- 전체 검사에서 기존 HEAD에서도 재현되는 오래된 테스트 자료 4건을 확인해 현재 모델·승인·예약·도움말 계약에 맞게 수정했습니다. 해당 기능의 제품 동작은 변경하지 않았습니다.
- EXE 내장 파일 122개 검증, EXE/VBS 공통 파일 122개 일치, VBS ZIP의 격리된 실행·화면 자산·인증·업무 API·정상 종료 검사를 통과했습니다. 배포에는 소스 115개와 빌드 자산 7개만 포함합니다.

## 제한과 설정 보존

현재 PC의 격리된 시험과 공개 파일 다운로드를 확인한 결과입니다. 모든 회사 PC의 네트워크·실행 정책을 확인했다는 의미는 아닙니다. GitHub 접속이 차단된 경우 기존 앱과 수동 ZIP 업데이트를 계속 사용할 수 있습니다. 기존 Python·WebView2·Claude Code가 필요하며 설치기나 인증 정보는 포함하지 않습니다. 사용자 Claude 인증·모델·스킬·MCP·후크 설정, Windows 정책과 실제 업무 파일을 수정하지 않습니다.

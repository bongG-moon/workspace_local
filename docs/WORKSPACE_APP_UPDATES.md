# 앱에서 새 버전 확인과 업데이트 — 0.23.28

0.23.0부터 사내 GitLab 배포본도 지원합니다. 사내 배포 도구가 실행 파일에 업데이트 서버 설정을 넣으며, 사용자는 키나 토큰을 입력하지 않습니다. GitLab Package Registry에서 공개 다운로드를 허용한 버전 정보·변경 내용·ZIP을 가져옵니다. 사내 배포본은 GitLab 접속 실패 시 공개 GitHub로 바꾸어 접속하지 않습니다. 배포자는 [사내 배포 도구 안내](WORKSPACE_GITLAB_PUBLISHER.md)를 참고하세요.

이 기능이 포함된 버전을 한 번 설치한 뒤부터, 앱 안에서 다음 버전을 확인하고 업데이트할 수 있습니다. 기존 0.21.10 이하에는 업데이트 확인 기능이 없으므로 첫 전환은 Release 파일을 받아 실행해야 합니다.

**0.23.2·0.23.3 사용자는 설정 → 앱 업데이트 → 지금 확인**에서 0.23.4 이상을 한 번 설치하세요. 새 버전 팝업은 0.23.4부터 제공하므로 이전 앱이 새 배포 파일을 발견하는 것만으로 팝업 기능이 추가되지는 않습니다.

## 사용 방법

1. 0.23.4부터 앱 창을 열면 새 버전을 확인합니다. 현재보다 높은 버전이 있으면 **변경 내용 팝업**을 보여 줍니다. 숨겨진 창, 다른 대화상자, 입력 중인 화면이나 진행 중인 업무를 방해할 상황에서는 안내를 미룹니다.
2. 팝업에서 변경 내용을 읽고 **업데이트하고 다시 시작** 또는 **다음에 하기**를 선택합니다. **다음에 하기**, 닫기 또는 Esc로 닫으면 같은 창에서 상태를 다시 읽거나 포커스를 옮겨도 반복해서 열리지 않습니다. 이후 앱 창을 명시적으로 다시 열 때는 다시 안내할 수 있습니다.
3. **업데이트하고 다시 시작**를 눌렀을 때만 필요한 앱 파일을 내려받고 무결성을 확인합니다. 버전 확인이나 팝업 표시만으로 설치하거나 실행 중인 업무를 종료하지 않습니다.
4. 다운로드 중에는 진행률을, 파일 확인 후에는 재시작 준비 상태를 보여 줍니다. **작업으로 돌아가기**로 창을 닫아도 작은 진행 안내가 남습니다. 진행 중인 업무·승인·질문을 마칠 때까지 기다리며, 실제 종료가 시작되기 전에는 **전환 취소**가 가능합니다.
5. 전환이 시작되면 **업데이트를 적용하고 있어요 → 앱을 다시 시작하고 있어요 → 새 화면을 준비하고 있어요** 안내창이 앱 종료 사이에도 유지됩니다. 새 화면의 준비가 확인되면 대기창을 닫습니다. 보내지 않은 내용과 첨부는 복원하고, 복원이 완료된 새 버전 화면에서 업데이트 완료를 안내합니다. 실행이나 복원에 문제가 있으면 완료로 표시하지 않고 확인 방법을 안내합니다.
6. 이후 원래 사용하던 EXE나 VBS를 실행해도 정상적으로 전환된 최신 버전으로 연결됩니다. 다음 버전이 정상 시작되기 전에는 기존 실행 위치를 대체하지 않습니다.

새 버전이 있으면 왼쪽 아래 **설정 바로 위**에 작은 다운로드 아이콘과 알림 점이 표시됩니다. **다음에 하기**를 눌러도 아이콘은 남습니다. 마우스를 올리면 새 버전을 확인할 수 있고, 클릭하면 변경 내용 팝업을 다시 엽니다. 사이드바를 접어도 아이콘을 사용할 수 있으며 아이콘을 누르는 것만으로 설치하지 않습니다.

나중에 다시 보려면 **설정 → 앱 업데이트**에서 현재 버전과 새 버전, 배포 서버와 변경 내용을 확인합니다. 공개 배포본에는 GitHub Release 링크도 표시됩니다. 사내 배포본은 로그인 없이 앱 안에서 변경 내용을 읽습니다.

자동 확인은 설정에서 끌 수 있습니다. 꺼진 상태에서는 창을 열어도 자동 확인과 새 버전 팝업을 실행하지 않으며, **지금 확인**으로 직접 확인할 수 있습니다. 배포 서버에 연결할 수 없어도 기존 앱은 그대로 사용할 수 있습니다. 다른 PC에서 받은 EXE/VBS ZIP으로 직접 업데이트하는 방식도 유지합니다.

창 시작·명시적인 다시 열기는 일반 자동 확인의 12시간 간격과 별도로 새로 확인하되, 같은 앱 프로세스에서는 반복 요청을 **60초 간격**으로 제한합니다. 창의 일반 포커스 이동과 표시 상태 확인은 로컬 상태를 읽으며 그때마다 배포 서버에 새 확인을 요청하지 않습니다. 다운로드나 확인이 이미 진행 중이면 중복 작업을 시작하지 않습니다.

## 지난 업데이트 내역 보기

**설정 → 앱 업데이트 → 업데이트 내역**에서 버전별 변경 사항을 확인합니다. 현재 버전이 최신이어도 이 버튼은 표시됩니다. 버전을 선택하면 제목과 변경 내용, 확인할 수 있는 배포 날짜를 보여 줍니다. 이 창에서는 설치나 이전 버전으로 돌아가기를 실행하지 않습니다.

- **배포 이력**: 현재 배포 서버에 기록된 내용입니다. 사내 배포본은 해당 GitLab 프로젝트의 이력만 조회합니다. 사내 배포 도구가 기존 기록을 가져오면 이미 배포된 이전 버전도 표시합니다.
- **사내 배포 설명 / GitLab 릴리스 설명**: 사내 담당자가 배포 채널이나 GitLab Release에 남긴 내용을 출처와 함께 표시합니다. 개발 소스에 포함된 기본 설명으로 덮어쓰지 않습니다.
- **배포 파일 기록**: 버전별 패키지만 확인된 경우입니다. 날짜는 패키지 등록일이며, 당시 설명을 확인하지 못하면 그 사실을 표시합니다. 삭제된 설명을 추정해 채우지 않습니다.
- **앱 변경 이력**: 앱에 함께 들어 있는 이전 버전의 설명입니다. 사내에 실제로 배포한 버전이나 날짜를 의미하지 않습니다. 과거 사내 배포 기록이 남아 있지 않으면 날짜를 만들어 표시하지 않습니다.

창을 열 때 저장된 내역을 먼저 보여 주고 필요한 경우에만 서버를 확인합니다. 최근 확인 결과는 5분간 재사용하며 **다시 확인**도 60초 안에 반복 요청하지 않습니다. 한 번에 최대 30개 버전을 표시하고, 창을 닫으면 화면의 조회 상태 확인을 멈춥니다. 연결에 실패해도 앱에 포함된 내용과 같은 서버에서 마지막으로 확인한 내역을 읽을 수 있습니다. Claude 연결이나 대화 요청은 실행하지 않습니다.

## 공개 GitHub 배포자가 할 일

- 소스 커밋만 올리는 것으로는 업데이트가 표시되지 않습니다. `bongG-moon/workspace_local` 저장소에 더 높은 `v숫자.숫자.숫자` 버전의 정식 GitHub Release를 게시하고 최신 Release로 지정합니다.
- 기존 배포 스크립트가 만드는 VBS ZIP, EXE ZIP, `SHA256SUMS.txt`를 함께 등록합니다. 앱 내부 업데이트는 두 배포 방식에 공통인 VBS ZIP의 앱 파일을 사용합니다.
- Release 본문에 변경 사항을 작성하면 앱에서 그대로 확인할 수 있습니다. 초안·사전 공개 버전과 현재보다 낮은 버전은 설치하지 않습니다.

사내 GitLab은 [Python 배포 도구](WORKSPACE_GITLAB_PUBLISHER.md)가 **Package Registry**에 버전별 ZIP·체크섬과 `company-workspace-channel/0.0.0/latest.json`을 게시합니다. 최신 채널 검증 후 `release-history.json`에 배포 이력을 누적하고, 권한이 있는 경우 해당 버전의 **GitLab Release**도 만듭니다. 앱은 Package Registry의 이력을 읽으므로 사용자에게 GitLab 로그인이나 토큰을 요구하지 않습니다. Releases 페이지에 접근하려면 회사 GitLab 로그인이 필요할 수 있습니다. 소스만 기본 브랜치에 올리고 최신 패키지 정보를 게시하지 않으면 앱 업데이트는 바뀌지 않습니다.

## 구현 범위

- 재시작 대기창은 앱과 같은 글꼴과 라이트·다크 색상의 작은 카드로 표시합니다. 화면 배율에 맞춰 글자를 다시 그리며 모니터를 옮겨도 크기를 조정합니다. 진행선은 대기 중임을 나타내며 완료율을 의미하지 않습니다. 글꼴은 이 프로세스에서만 사용하고 종료 시 해제하며 Windows 글꼴을 설치하지 않습니다.
- 재시작 대기창은 전환 담당 프로세스 안에서 일시적으로 표시합니다. 별도 PowerShell을 반복 실행하지 않으며, 정상 완료·취소·실패 후에는 대기창을 정리합니다. 새 화면 준비는 현재 실행의 인증된 로컬 상태로만 확인하며 이전 실행의 진단 로그를 성공 근거로 쓰지 않습니다.
- 네트워크 작업은 별도 작업자에서 실행하며 확인 결과를 재사용합니다. 앱 시작이나 채팅 응답을 네트워크 확인 완료까지 기다리게 하지 않습니다.
- 시작 팝업은 실제로 더 높은 정식 버전에만 표시합니다. 현재 버전, 이전 버전, 사전 공개 버전이나 확인 실패를 새 업데이트로 안내하지 않습니다. 변경 내용은 일반 텍스트로 표시하며 설치 버튼은 실행 환경과 현재 진행 상태에 따라 비활성화될 수 있습니다.
- 공개 배포본은 고정된 GitHub 저장소, 사내 배포본은 앱에 포함된 GitLab 프로젝트의 HTTPS 패키지 주소만 조회합니다. 다운로드 크기, 압축 경로, 파일 개수, 체크섬과 배포 서버 일치를 확인합니다. 앱 내부에서 변경 안내의 HTML이나 스크립트를 실행하지 않습니다.
- 업데이트 파일은 앱 사용자 데이터 안의 별도 버전 폴더에 저장합니다. 개인 Claude 인증·스킬·모델·MCP 설정, Windows 정책, 작업 폴더 파일을 수정하지 않습니다.
- Python이나 WebView2 Runtime을 설치하거나 회사 실행 정책을 바꾸지 않습니다. 기존 앱과 같은 실행 조건이 필요합니다.
- 공개 배포는 [GitHub Releases 공식 API](https://docs.github.com/en/rest/releases/releases), 사내 배포는 [GitLab Generic Package API](https://docs.gitlab.com/user/packages/generic_packages/)를 사용합니다. 실제 검증 범위는 해당 버전 검증 문서를 따릅니다.

자동 검사와 모의 서버 검증은 사내 GitLab의 실제 정책·인증서·네트워크 확인을 대신하지 않습니다. 최초 사내 배포에서는 사용자 PC의 익명 다운로드, 변경 내용 표시와 업데이트 후 기존 업무 복원을 확인합니다.

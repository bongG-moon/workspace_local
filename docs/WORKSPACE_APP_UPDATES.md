# 앱에서 새 버전 확인과 업데이트 — 0.23.5

0.23.0부터 사내 GitLab 배포본도 지원합니다. 사내 배포 도구가 실행 파일에 업데이트 서버 설정을 넣으며, 사용자는 키나 토큰을 입력하지 않습니다. GitLab Package Registry에서 공개 다운로드를 허용한 버전 정보·변경 내용·ZIP을 가져옵니다. 사내 배포본은 GitLab 접속 실패 시 공개 GitHub로 바꾸어 접속하지 않습니다. 배포자는 [사내 배포 도구 안내](WORKSPACE_GITLAB_PUBLISHER.md)를 참고하세요.

이 기능이 포함된 버전을 한 번 설치한 뒤부터, 앱 안에서 다음 버전을 확인하고 업데이트할 수 있습니다. 기존 0.21.10 이하에는 업데이트 확인 기능이 없으므로 첫 전환은 Release 파일을 받아 실행해야 합니다.

**0.23.2·0.23.3 사용자는 설정 → 앱 업데이트 → 지금 확인**에서 0.23.4 이상을 한 번 설치하세요. 새 버전 팝업은 0.23.4부터 제공하므로 이전 앱이 새 배포 파일을 발견하는 것만으로 팝업 기능이 추가되지는 않습니다.

## 사용 방법

1. 0.23.4부터 앱 창을 열면 새 버전을 확인합니다. 현재보다 높은 버전이 있으면 **변경 내용 팝업**을 보여 줍니다. 숨겨진 창, 다른 대화상자, 입력 중인 화면이나 진행 중인 업무를 방해할 상황에서는 안내를 미룹니다.
2. 팝업에서 변경 내용을 읽고 **업데이트하기** 또는 **다음에 하기**를 선택합니다. **다음에 하기**, 닫기 또는 Esc로 닫으면 같은 창에서 상태를 다시 읽거나 포커스를 옮겨도 반복해서 열리지 않습니다. 이후 앱 창을 명시적으로 다시 열 때는 다시 안내할 수 있습니다.
3. **업데이트하기**를 눌렀을 때만 필요한 앱 파일을 내려받고 무결성을 확인합니다. 버전 확인이나 팝업 표시만으로 설치하거나 실행 중인 업무를 종료하지 않습니다.
4. 진행 중인 업무·승인·질문을 마친 뒤 기존 버전 전환 절차로 이동합니다. 입력 중인 내용과 첨부는 보관해 복원합니다. 전환을 취소하면 기존 앱에서 계속 작업할 수 있습니다.
5. 이후 원래 사용하던 EXE나 VBS를 실행해도 정상적으로 전환된 최신 버전으로 연결됩니다. 다음 버전이 정상 시작되기 전에는 기존 실행 위치를 대체하지 않습니다.

0.23.5부터 새 버전이 있으면 왼쪽 아래 설정 옆에 **작은 원형 다운로드 아이콘**이 표시됩니다. **다음에 하기**를 눌러도 아이콘은 남습니다. 마우스를 올리면 새 버전을 확인할 수 있고, 클릭하면 변경 내용 팝업을 다시 엽니다. 사이드바를 접어도 아이콘을 사용할 수 있으며 아이콘을 누르는 것만으로 설치하지 않습니다.

나중에 다시 보려면 **설정 → 앱 업데이트**에서 현재 버전과 새 버전, 배포 서버와 변경 내용을 확인합니다. 공개 배포본에는 GitHub Release 링크도 표시됩니다. 사내 배포본은 로그인 없이 앱 안에서 변경 내용을 읽습니다.

자동 확인은 설정에서 끌 수 있습니다. 꺼진 상태에서는 창을 열어도 자동 확인과 새 버전 팝업을 실행하지 않으며, **지금 확인**으로 직접 확인할 수 있습니다. 배포 서버에 연결할 수 없어도 기존 앱은 그대로 사용할 수 있습니다. 다른 PC에서 받은 EXE/VBS ZIP으로 직접 업데이트하는 방식도 유지합니다.

창 시작·명시적인 다시 열기는 일반 자동 확인의 12시간 간격과 별도로 새로 확인하되, 같은 앱 프로세스에서는 반복 요청을 **60초 간격**으로 제한합니다. 창의 일반 포커스 이동과 표시 상태 확인은 로컬 상태를 읽으며 그때마다 배포 서버에 새 확인을 요청하지 않습니다. 다운로드나 확인이 이미 진행 중이면 중복 작업을 시작하지 않습니다.

## 공개 GitHub 배포자가 할 일

- 소스 커밋만 올리는 것으로는 업데이트가 표시되지 않습니다. `bongG-moon/workspace_local` 저장소에 더 높은 `v숫자.숫자.숫자` 버전의 정식 GitHub Release를 게시하고 최신 Release로 지정합니다.
- 기존 배포 스크립트가 만드는 VBS ZIP, EXE ZIP, `SHA256SUMS.txt`를 함께 등록합니다. 앱 내부 업데이트는 두 배포 방식에 공통인 VBS ZIP의 앱 파일을 사용합니다.
- Release 본문에 변경 사항을 작성하면 앱에서 그대로 확인할 수 있습니다. 초안·사전 공개 버전과 현재보다 낮은 버전은 설치하지 않습니다.

사내 GitLab은 [Python 배포 도구](WORKSPACE_GITLAB_PUBLISHER.md)가 **Package Registry**에 버전별 ZIP·체크섬과 `company-workspace-channel/0.0.0/latest.json`을 게시합니다. `latest.json`의 최신 버전과 변경 내용을 앱이 읽으므로 **GitLab Releases 페이지는 필요하지 않습니다**. 비공개 Release 페이지나 소스 저장소를 읽기 위해 사용자에게 인증을 요구하지 않습니다. 소스만 기본 브랜치에 올리고 최신 패키지 정보를 게시하지 않으면 앱 업데이트는 바뀌지 않습니다.

## 구현 범위

- 네트워크 작업은 별도 작업자에서 실행하며 확인 결과를 재사용합니다. 앱 시작이나 채팅 응답을 네트워크 확인 완료까지 기다리게 하지 않습니다.
- 시작 팝업은 실제로 더 높은 정식 버전에만 표시합니다. 현재 버전, 이전 버전, 사전 공개 버전이나 확인 실패를 새 업데이트로 안내하지 않습니다. 변경 내용은 일반 텍스트로 표시하며 설치 버튼은 실행 환경과 현재 진행 상태에 따라 비활성화될 수 있습니다.
- 공개 배포본은 고정된 GitHub 저장소, 사내 배포본은 앱에 포함된 GitLab 프로젝트의 HTTPS 패키지 주소만 조회합니다. 다운로드 크기, 압축 경로, 파일 개수, 체크섬과 배포 서버 일치를 확인합니다. 앱 내부에서 변경 안내의 HTML이나 스크립트를 실행하지 않습니다.
- 업데이트 파일은 앱 사용자 데이터 안의 별도 버전 폴더에 저장합니다. 개인 Claude 인증·스킬·모델·MCP 설정, Windows 정책, 작업 폴더 파일을 수정하지 않습니다.
- Python이나 WebView2 Runtime을 설치하거나 회사 실행 정책을 바꾸지 않습니다. 기존 앱과 같은 실행 조건이 필요합니다.
- 공개 배포는 [GitHub Releases 공식 API](https://docs.github.com/en/rest/releases/releases), 사내 배포는 [GitLab Generic Package API](https://docs.gitlab.com/user/packages/generic_packages/)를 사용합니다. 실제 검증 범위는 해당 버전 검증 문서를 따릅니다.

자동 검사와 모의 서버 검증은 사내 GitLab의 실제 정책·인증서·네트워크 확인을 대신하지 않습니다. 최초 사내 배포에서는 사용자 PC의 익명 다운로드, 변경 내용 표시와 업데이트 후 기존 업무 복원을 확인합니다.

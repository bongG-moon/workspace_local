# Company Agent 업무별 사용 가이드

하고 싶은 업무의 예문을 복사하고 자료·범위·결과 형식을 바꿔 요청하세요. Company Agent는 기존 Claude Code의 회사 계정·모델·권한을 그대로 사용합니다.

Workspace 앱을 사용할 때 실행 권한은 Windows에서 프로그램을 연 방식에 따릅니다. 일반 환경의 EXE 더블클릭은 일반 권한이고, EXE 우클릭의 **관리자 권한으로 실행**은 앱과 Claude·도구에 관리자 권한을 적용합니다. 관리자 터미널에서 실행하면 그 권한을 그대로 유지합니다. 앱 안에서 권한을 전환하거나 다음 실행용으로 저장하지 않습니다. 바꾸려면 **완전 종료** 후 다시 여세요. 창의 X는 트레이로 숨기는 기능입니다. [Windows 실행 권한 안내](WORKSPACE_EXECUTION_MODE.md)

작업 중에도 **승인** 목록이나 **Shift+Tab / Alt+M**으로 현재 연결이 지원하는 승인 모드를 바꿀 수 있습니다. 변경 응답을 확인한 뒤 이후 도구 호출에 적용합니다. 이미 화면에 나온 승인·질문은 사라지거나 자동으로 허용되지 않으므로 직접 답하세요. 연결된 CLI가 실시간 변경을 거절하거나 제공하지 않으면 현재 모드를 유지하고 이유를 안내합니다. 모델·Effort 변경과 Windows 관리자 실행은 이 기능과 별개입니다.

## 1. 요청은 목적·자료·결과·제한 순서로

| 알려줄 것 | 예 |
| --- | --- |
| 목적과 독자 | 부서장에게 월간 실적을 설명 |
| 자료와 범위 | 가상 세 달 수치, 또는 첨부 파일 1~5장 |
| 결과 | 핵심 요약과 확인할 사항, 편집 가능한 PPT |
| 제한과 완료 조건 | 원인 추측 금지, 원본 보존, 직접 확인한 범위만 보고 |

어렵다면 “필요한 정보만 한국어로 물어봐줘”라고 시작합니다. 질문이 오면 번호나 이름으로 답하고, 답변 대기 중 같은 제작 요청을 다시 보내지 않습니다.

질문 제목·선택지·설명·추천 표시는 기본 한국어입니다. 흔한 영문 선택 문구는 추가 AI 호출 없이 바꿉니다. 파일명·명령어·제품명은 유지하며, 대화 언어를 따로 요청하면 그 범위를 따릅니다. Claude 자체 메뉴·권한 버튼이나 외부 도구의 원문까지 번역하는 기능은 아닙니다.

참고 파일은 필수가 아닙니다. [시작하기](ONBOARDING_COURSE.md) 1단계에서 가상 자료를 만들어 연습할 수 있습니다. PPT는 2단계의 새 디자인 예문으로 제작합니다.

## 2. 문서 읽기와 비교

실제 파일은 CLI의 `@` 또는 Workspace의 파일 선택으로 지정합니다. 처음에는 가상 MD·텍스트 자료로 연습하세요. 파일 형식별 읽기 지원은 실제 설치된 스킬과 도구에서 확인합니다. 문서 본문이 대화에 전달될 수 있으므로 승인된 자료만 사용합니다.

```text
첨부한 실습_가상자료.md를 읽고 핵심 내용·월별 수치·확인할 사항을 정리해줘.
원본은 수정하지 말고 실제 읽은 범위와 미확인 부분을 알려줘.
자료에 없는 증가 원인은 추측하지 마.
```

실패·시간초과·개수 차이만으로 DRM 원인을 단정하거나 실제 접근 제한을 다른 사본으로 우회하지 않습니다.

문서 비교 파일이 없어도 아래 예문으로 시작할 수 있습니다.

```text
다음 가상 문구 두 개를 비교해줘.
이전안: 월 1회 점검. 변경안: 월 2회 점검. 그 외 조건은 동일.
바뀐 항목과 바뀌지 않은 항목만 표로 정리해줘. 실제 회사 규정으로 기억하지 마.
```

## 3. 보고서·HTML·편집 가능한 PPT

원하는 모양을 말하기 어렵다면 [디자인 용어 참고](DESIGN_TERMS.md)에서 느낌과 요청 예문을 골라 보세요. 참고 용어가 모두 기본 디자인 메뉴로 제공되는 것은 아닙니다.

먼저 디자인·분량·결과 형식을 정합니다. HTML은 새 디자인 또는 참고 HTML, PPT는 새 디자인·참고 캡처 2~3장·기존 PPT·저장한 HTML 양식 중 필요한 방식을 사용합니다. **새 디자인에서는 참고 파일을 요구하지 않습니다.**

이미 알려준 조건은 다시 묻지 않습니다. 처음에는 필요한 선택만 질문하며, 선택을 시작하려고 임시 파일을 만들거나 설치 폴더를 검색할 필요는 없습니다. 선택이 끝나면 본문과 HTML 초안을 준비합니다. “초안 필요”나 “확인 대기”는 제작 오류가 아닙니다.

선택한 양식 안에서 내용에 맞게 배치합니다. 비교 자료는 차이를, 의사결정 자료는 결론과 근거를 먼저 보여주며 모든 보고서에 큰 숫자나 카드를 붙이지 않습니다. 이미 선택한 디자인·글꼴은 유지하고, 흐름도·관계도 같은 설명용 다이어그램은 흐름이나 구조를 그림으로 설명해 달라고 했을 때 사용합니다.

보고서·PPT·메일 초안의 한국어는 작성하면서 불필요한 반복·번역투·과장을 줄입니다. 별도 글 다듬기 스킬 선택이나 추가 승인 없이 기존 작성·확인 과정에서 적용합니다. 수치·날짜·인용·회사 고정 문구와 “미확인”, “가능성이 있다” 같은 조건은 보존하며, 보고서의 표·목록을 억지로 줄글로 바꾸지 않습니다. 지정한 말투나 관련 개인 선호가 있으면 그 범위에서 따릅니다. 승인한 파일·메일을 나중에 몰래 고치는 기능은 아닙니다.

“이 문단만 더 자연스럽게 다듬어줘”, “원문 표현을 그대로 써줘”라고 요청할 수 있습니다. 문체 기준은 작성 지침이지 AI 작성 여부를 판별하거나 정확성을 보증하는 검사가 아닙니다.

```text
가상 월간 실적으로 짧은 HTML 보고서를 만들어줘.
6월 목표 100건·실적 90건, 7월 목표 100건·실적 110건, 8월 목표 100건·실적 130건.
참고 파일은 없어. 새 디자인 목록에서 하나 고른 뒤 스크롤 방식으로 만들어줘.
목표 300건·실적 330건·달성률 110%를 대조해줘. 원인과 연도는 추측하지 마.
최종 HTML 한 파일만 전달하고 기존 파일은 덮어쓰지 마.
```

PPT는 전체 HTML 초안 → 사용자 확인 → 편집 가능한 PPT → 결과 확인 순서입니다. 카드·둥근 모서리·그림자·태그를 지원하지만 웹 화면과 모든 효과가 같지는 않습니다. 복잡한 효과·움직이는 내용·병합 표는 변환 가능 여부를 먼저 확인하세요. 차트 수치도 바꾸려면 “데이터도 수정 가능한 차트로 만들어줘”라고 요청합니다.

이미 만든 HTML을 변환할 때는 **모든 장이 같은 고정 크기로 보이는 정적 초안**을 사용합니다. 원래 카드의 가로·세로 정렬은 유지합니다. 보이지 않는 장이나 이동·회전·확대/축소 효과 때문에 변환이 멈추면 같은 초안을 수정하고 다시 확인하세요. 이를 “PowerPoint는 카드를 만들 수 없다”는 뜻으로 해석하거나 전체를 이미지로 바꾸지 않습니다.

HTML 초안·변환 시도·검사 이미지는 내부 임시 작업 공간에 두고 한 요청에서는 최종 결과 한 개가 기본입니다. 여러 결과를 명시적으로 요청하거나 다음 질문에서 다른 형식을 요청하면 별도로 생성할 수 있습니다. 기존 결과는 자동 삭제하지 않습니다.

최종 파일을 확인해 전달하면, 기본 제작기가 생성·기록한 변경 없는 중간 파일은 자동 정리합니다. 원본·최종 결과·대표 양식·개인 기억과 스킬은 남깁니다. 사용자가 수정한 파일, 등록되지 않은 파일, 이전 버전의 중간물도 임의로 지우지 않습니다. 최종 결과가 참조하는 파일과 열려 있어 지우지 못한 파일은 보존합니다. 정리 때문에 결과물을 다시 만들거나 계속 재시도하지 않습니다.

```text
이번 작업에서 만든 불필요한 중간 파일만 정리하고 원본과 최종 결과는 남겨줘.
확실히 구분되지 않는 파일은 지우지 말고 알려줘.
```

이 정리는 기본 HTML·PPT 제작기의 등록된 작업 파일에 적용됩니다. 폴더 전체를 비우거나 다른 도구가 만든 모든 파일을 자동으로 찾아 지우는 기능은 아닙니다.

대표 디자인은 내용·숫자·캡처를 제거한 **HTML 양식**으로 저장하고 개인 전체/이 프로젝트 중 범위를 고릅니다. 실제 파일이 있어야 저장 성공이며 기억에 선호를 적는 것과 다릅니다. 기존 PPT 이미지 크기만 수정하는 작업은 원본을 보존하며 별도 결과를 만듭니다. 그림을 키운다고 글자가 편집 가능해지는 것은 아닙니다.

### 끝난 작업을 그림으로 이해하기

“방금 작업의 흐름을 그림으로 보여줘”, “이 구조를 HTML로 설명해줘”라고 요청하면 확인한 내용을 바탕으로 작은 설명 도표를 만듭니다. 일반 보고서나 작업 완료 때 자동으로 붙이지 않습니다. 단순한 “정리해줘”는 글 요약부터, “글로만”은 도표 없이 답합니다.

```text
방금 작업한 흐름을 HTML 한 파일로 설명해줘.
확인된 결과·남은 일·미확인을 구분하고 단계별 설명 재생을 넣어줘.
업무를 다시 실행하거나 실제 진행률처럼 표시하지 마.
```

전체 그림이 먼저 보이고 **설명 재생·한 단계씩 보기·일시정지**로 순서를 짚어봅니다. 실제 업무를 다시 실행하는 버튼이 아닙니다. 움직임 줄이기 설정·인쇄·스크립트 없는 미리보기에서는 정적 내용을 봅니다. SVG/PNG 저장은 버튼을 눌렀을 때만 하며 상세 설명·근거는 HTML에 남습니다. 편집 가능한 PPT 도표로 자동 변환하는 기능은 아닙니다.

Google Fonts를 사용하고 싶으면 요청에 적어 주세요. 이때 글꼴 서비스에 연결하며, 연결할 수 없으면 PC 글꼴로 표시됩니다. 기본은 외부 연결 없는 PC 글꼴입니다. 새 디자인 설문 없이 현재 선택이나 간단한 기본 양식으로 진행합니다.

## 4. 회의 메모와 메일 초안

```text
다음 가상 회의 메모를 결정 사항·진행 중·확인할 사항으로 정리해줘.
점검표 수정 완료. 현장 확인 진행 중. 새 양식 적용일은 미정.
담당자와 날짜를 만들어 넣지 마. 이어서 팀에 공유할 메일 초안도 대화에 보여줘.
메일에 연결하거나 발송하지 마.
```

메일 초안은 연결 없이 작성할 수 있습니다. 실제 메일 조회·발송·PST 이동은 별도 승인된 연결과 본인 계정 범위가 필요합니다. 선택적 로컬 Outlook 점검기는 읽기 전용입니다. 초안 작성이나 조회 승인을 실제 발송 승인으로 해석하지 않습니다. 보호된 본문·첨부는 권한 범위에서만 처리합니다.

## 5. 파일 정리와 회사 데이터

```text
지금 연습 폴더 바로 아래 파일의 정리안만 보여줘.
이동 전후 위치를 설명하고 아직 이동·삭제·덮어쓰기는 하지 마.
내 답변을 기다려줘. 회사 공용 폴더와 다른 프로젝트는 확인하지 마.
```

이동은 계획 확인 후 허용된 범위에서만 합니다. 되돌리기도 이후 파일 상태와 기록을 확인해야 합니다. 파일이 없다면 ‘정리할 파일 없음’이 정상입니다. 실습을 위해 업무 파일을 복사할 필요는 없습니다.

회사 DB 조회는 승인된 연결의 읽기 범위 안에서 수행합니다. 담당자가 제공한 테이블·필터·기간을 확인하고 임의의 회사 DB 접속이나 데이터 변경을 하지 않습니다. 연결이 없으면 가상 표로 계산 연습만 합니다.

## 6. 기억·지식·스킬을 구분하기

| 내용 | 예 | 관리 방식 |
| --- | --- | --- |
| 기억 | 결론부터 짧게 답하는 선호 | 저장할 범위와 내용 확인 |
| 지식 | 출처가 있는 용어·계산식 | 출처·기준일 확인, 개인 초안 검토 |
| 스킬 | 반복 보고서를 만드는 절차 | 설명서 생성 후 발견·로드·결과 시험 |
| 도구 | 달성률을 계산하는 프로그램 | 후보 생성 → 실제 시험 → 검증 → 활성화 |
| 하네스 | 스킬·도구·규칙·후크를 연결한 구성 | 누가 관리하고 어디에 적용되는지 확인 |

회사 공통 / 개인 전체 / 이 프로젝트를 먼저 구분합니다. 회사 공통은 담당자가 배포하고 사용자는 읽기·개선 제안을 합니다. 새 개인 기억·스킬·도구는 개인 전체 또는 이 프로젝트 중 하나를 선택하며 범위를 이미 명시하면 다시 묻지 않습니다. 폴더 공유가 개인 저장소의 자동 공유를 뜻하지 않습니다.

**구성 한눈에**에서 연결된 회사 배포본과 로컬 개인 저장소의 실제 위치를 확인합니다. 개인 전체는 같은 사용자 설치·저장소를 쓰는 여러 폴더에, 프로젝트 개인 기억은 저장한 프로젝트 경로에 적용됩니다. 폴더 복사나 다른 PC·계정으로 자동 동기화되지 않으며 이전 후에는 연결과 조회를 다시 확인합니다. Claude Code 자체 자동 기억은 별도 저장소입니다.

```text
내 보고서 표현 선호를 저장해줘. 결론부터 설명하고 미확인 내용은 구분하는 방식이 좋아.
이 선호만 저장하고 원본 문서는 넣지 마.
개인 전체와 이 프로젝트 중 어디에 저장할지 먼저 물어봐줘.
```

저장 후 새 대화에서 실제 조회하고 결과에 적용됐는지 각각 확인합니다. 자동 학습은 의미 있는 업무의 완료·검증 후 재사용할 교정만 검토하며, 진행 중에는 임시 후보로 둡니다. 장기적인 명시적 교정은 기억 요청 없이 반영할 수 있지만 추정한 선호는 독립된 업무의 반복 근거가 필요합니다. 같은 범위·같은 항목을 A → B → A로 고치면 마지막 교정을 사용하며, 같은 업무의 반복 답변을 독립 근거로 늘리지 않습니다.

자동 학습은 User 설치의 개인 전체 또는 Project 설치의 해당 저장소에서만 작동합니다. 저장 범위를 선택했다고 이 설정이 바뀌지는 않습니다. User 설치의 프로젝트 전용 자산과 공통 정책·프로젝트 `CLAUDE.md`는 자동 수정하지 않습니다. 이미 전체 본문을 읽은 개인 스킬의 작은 점검 항목을 개선할 수 있으며, **새 스킬 생성은 별도 요청이나 제작 제안에 대한 동의 후 진행**합니다. 공통 스킬의 개인 복제본을 자동으로 만들지 않습니다.

매 답변이나 닫힌 Claude를 대상으로 학습하지 않습니다. 별도 학습 모델을 매번 호출하지 않지만 완료 시 교정 검토에는 현재 모델의 처리 비용이 들고, 별도 작업자가 검토하면 그 비용도 추가됩니다. 자동 학습 카드나 `/company-agent:learning`에서 내역·일시 중지·재개·선택한 변경 되돌리기를 확인합니다. 중지는 기존 기억 삭제나 사용 중단이 아니며, 되돌리기도 업무 파일·발송 메일을 취소하는 기능은 아닙니다. 자세한 조건과 현재 후보 보존 한계는 [핸드북](COMPANY_AGENT_HANDBOOK.md) 7장, 비교 실습은 [시작하기](ONBOARDING_COURSE.md) 6~8단계를 참고하세요.

기억이 안 보이면 삭제됐다고 단정하지 말고 저장 범위·사용 상태·제목을 확인합니다. 자동 참고 목록은 관련 내용을 골라 짧게 전달하는 것이지 저장된 기억 전체가 아닙니다. “개인 전체의 ‘실습 요약 순서’를 조회해줘. 수정하지 마”처럼 범위와 제목을 지정해 비교할 수 있습니다.

## 7. 겹치는 스킬과 프로젝트 지침

기본 스킬 11개와 호환용 이전 이름 1개, 후크 7개의 실제 역할·한계는 [핸드북](COMPANY_AGENT_HANDBOOK.md) 4~5장에 정리되어 있습니다. 스킬은 필요한 업무 절차를 읽어 적용하고, 후크는 요청 시작·도구 실행·종료 시 자동으로 안내·관찰·정책 확인을 수행합니다. 목록에 있다는 사실만으로 이번 업무에서 실행됐다고 판단하지 않습니다.

스킬 이름을 외우지 않고 업무부터 요청합니다. 정확한 이름을 명시했다면 그 선택을 먼저 따릅니다. 같은 업무의 같은 역할을 맡는 후보가 여럿으로 명확히 확인되고 우선 선택이 없으면 실제 이름·출처·차이를 질문하고, 선택을 반영한 뒤 해당 본문을 읽어 적용합니다. 이름이 같아도 출처가 다르면 별도 후보입니다. 읽기 → 제작처럼 서로 다른 단계의 스킬은 함께 사용할 수 있습니다. 관련 스킬이 없으면 허용된 일반 작업을 하며, 단어가 비슷한 모든 스킬을 같은 역할로 판단하거나 선택 질문을 강제하지는 않습니다. 이번 선택과 지속적인 우선 설정 저장은 별개입니다. 없는 스킬을 설치하거나 추측 이름 `company`로 실행하지 않습니다.

목록에서 경쟁 후보가 확인되면 본문을 읽기 전에 한국어로 선택을 묻습니다. Claude 세션에만 있는 별도 스킬은 로컬 목록에 없을 수 있습니다. 그런 스킬의 실제 로드가 확인되면 공통 제작 스킬과 역할을 비교해 선택하며, 사용자의 선택을 무시하고 공통 스킬로 다시 만들지 않습니다. 이미 선택한 제작 절차에 디자인 보조가 필요한 경우에만 함께 사용합니다. 선택 답변은 현재 작업에 반영하며 별도 저장 명령을 매번 실행할 필요는 없습니다.

“이미지 읽기 스킬 ZIP을 설치해줘”는 설치 요청이지 이미지 읽기 요청이 아닙니다. 설치·제작·설명과 실제 업무 실행을 구분하며, 약한 단어 일치만으로 무관한 스킬을 강제하지 않습니다.

목록 확인·단순 파일 탐색마다 오류를 내는 방식은 아닙니다. 이번 작업에 맞는 스킬이 확인됐는데 본문을 건너뛰거나 경쟁 후보의 선택을 생략하면 짧은 `[스킬 확인]` 또는 `[스킬 선택]` 안내가 나올 수 있습니다. 해당 도구는 아직 실행되지 않았고 파일 권한 오류도 아닙니다. 같은 실행을 반복하지 말고 필요한 선택·본문 로드를 마칩니다. 본문 로드가 실패하면 실제 실패를 알리고 멈춥니다. 회사 정책·도구 권한은 별도로 적용됩니다.

자료 요약 다음에 HTML 작성을 요청하면 `html-report` 등 작업에 맞는 스킬을 다시 확인합니다. 이전 목록을 봤거나 다른 스킬을 읽었다는 사실만으로 새 작업의 준비를 마친 것은 아닙니다. 일반 스킬은 같은 스킬의 변경 없는 전체 본문이 현재 대화에 남아 있다면 다시 읽지 않아도 됩니다. 별도 작업자 실행이나 모델·도구 제한 등 원본 CLI의 실행 기능이 필요한 스킬은 현재 요청에서 정확한 스킬 호출이 성공해야 합니다. 본문 파일을 읽은 것만으로 이 기능을 대신하지 않으며, 정확히 호출할 수 없으면 그 제한을 안내합니다. 관련 스킬이 없는 작업에는 스킬 설치·로드를 강제하지 않습니다.

새 작업 폴더에서 실제 작업 요청을 하면 조건에 따라 기본 `CLAUDE.md`를 한 번 생성합니다. 기존 지침·상위 지침은 보존하며 계획/변경 금지 요청이나 시스템·설정 폴더에는 만들지 않습니다. 이는 짧은 시작 안내이며 CLI `/init`의 프로젝트 분석을 실행하는 것은 아닙니다. 프로젝트 지침은 목적·단위·완료 기준부터 짧게 유지하세요.

## 8. 느릴 때와 비용을 줄이는 방법

대상·기간·범위를 한 번에 지정하고 이미 답한 선택을 유지합니다. 같은 결과 생성·파일 이동·메일 발송을 대기 중에 재요청하지 않습니다. 필요한 자료만 첨부하고 읽을 페이지나 기간을 좁히면 불필요한 처리를 줄일 수 있습니다.

짧은 문서 읽기·요약·상태 조회는 현재 대화에서 처리합니다. 단순 읽기 때문에 별도 작업자를 호출하거나 계획 파일·완료 검증·빈 학습 기록을 만들 필요는 없습니다. 파일 작성·수정, 복잡한 분석, 명시한 작업자 요청은 필요한 위임과 검증을 유지합니다.
짧은 요청이라고 문서가 작다는 뜻은 아닙니다. 실제 읽기는 지정한 범위와 도구의 분량 제한을 따릅니다.

파일 오류가 나면 첨부한 실제 경로와 오류 내용을 비교합니다. 한글이 들어 있다는 이유만으로 인코딩 문제라고 단정하지 않습니다. 파일 없음·지원하지 않는 형식·접근 제한은 구분하고 실제 결과를 확인한 뒤 필요한 부분만 다시 시도합니다.

Workspace 사용 현황에서는 실제 CLI 토큰 보고와 실행·질문·승인 대기를 구분합니다. 미제공 값은 0이 아니며 누적값을 요청별 값처럼 합산하지 않습니다. 사내 가격을 모르면 금액이나 절감률을 단정하지 않습니다. 대화가 길 때는 원본 CLI의 `/context`·`/compact`를 사용할 수 있지만 업무마다 강제 압축하지 않습니다. 압축은 영구 기억 저장이나 결과 검증의 대체가 아닙니다.

이미지·PPT는 처음에는 전체를 확인하고, 수정 후에는 변경된 부분과 영향을 받은 부분을 다시 확인합니다. 공통 폰트·배치가 바뀌거나 영향 범위가 불분명하면 전체를 다시 확인합니다. 같은 이미지를 반복해서 대화에 넣기보다 파일 버전과 확인 결과를 짧게 남깁니다. 압축 뒤에는 유효한 현재 작업의 로컬 스킬 선택을 이어가되 필요한 본문만 다시 읽습니다. 이미 읽었다는 기록이나 검증 성공을 임의로 복원하지 않습니다.

## 9. 오류가 났을 때

| 상황 | 먼저 할 일 |
| --- | --- |
| 목록은 있는데 스킬을 안 씀 | `/skills`와 정확한 본문 로드 기록, 업무 실행을 따로 확인 |
| `locked by plugin` | 플러그인 관리 표시인지 확인. 비활성·미설치로 단정하지 않음 |
| `Unknown skill` | 현재 목록의 정확한 네임스페이스 확인. 캐시 존재만으로 호출 가능하다고 하지 않음 |
| 승인 전 대기 | 실행 준비·권한 판정·도구 실행을 구분. 승인 응답 대기라고 미리 단정하지 않음 |
| 파일 없음 | 요청한 파일명·현재 폴더를 확인. 다른 폴더까지 자동 검색하거나 보호 오류로 단정하지 않음 |
| 위험 명령이 차단됨 | 그 명령은 실행하지 않음. 대상과 필요성을 검토하고 우회·보호 해제 없이 안전한 계획 확인 |
| 기존 개인 도구에 재시험 필요 | 같은 저장 범위에서 정상·오류 입력을 다시 시험. 소스 삭제·재설치·검사 조건 제거로 해결하지 않음 |
| 작업 중지 후 계속 진행 중 | 종료 확인 결과를 기다리고 마지막 실행 상태 확인. 같은 작업 재요청이나 다른 프로그램 전체 종료 금지 |
| 한글 깨짐 | 기존 파일과 표시 인코딩부터 확인. 반복 생성·원본 손실 변환 금지 |
| 스크립트 오류 | 마지막 예외와 정확한 경로를 확인. 한글 문제로 단정하거나 중첩 실행하지 않음 |
| 앱만 인증 실패 | 기존 CLI 로그인과 앱의 실행·설정 환경을 비교. 인증 값 공유·전체 초기화 금지 |
| 검증 오류 반복 | 마지막 상태·파일 유무를 남기고 중지. 미검증을 성공으로 기록하지 않음 |

설치 ZIP을 모두 푼 뒤 **Diagnose-CompanyAgent.cmd**를 열고 실제 작업 폴더를 지정하면 설치·스킬 기록·준비물을 읽기 전용으로 확인할 수 있습니다. 문서·메일·DB 본문이나 모델을 자동 조회하지 않습니다. 로그를 공유하기 전 개인 경로·업무 내용·인증 값을 가리세요.

작업 중지는 이미 만든 파일·보낸 메일을 되돌리지 않습니다. Workspace가 직접 시작한 CLI의 종료를 확인했어도 모든 하위 프로그램이 종료됐다는 뜻은 아닙니다. 중지가 확인되지 않으면 마지막 상태를 담당자에게 전달하고 실제 결과부터 확인합니다.

## 10. 업데이트와 의견 보내기

[최신 Release](https://github.com/bongG-moon/claude_base_repo/releases/latest)의 직원용 설치 ZIP 전체를 풀고 기존과 같은 범위를 선택해 업데이트합니다. `Source code (zip)`은 직원용 설치 파일이 아닙니다. Workspace 사용자는 같은 Release의 별도 미리보기 ZIP을 사용합니다. 개인 기억·스킬·지식·모델·MCP·다른 플러그인을 임의로 초기화하지 않습니다. 업데이트 후 Claude Code를 다시 시작하세요.

```text
설치 버전 / 사용 화면 (CLI·VS Code·Workspace):
실제 요청 (가상 자료로 재현):
기대한 결과 / 관찰한 결과:
확인한 파일·수치·범위 / 미확인 부분:
개선하거나 선택 기능으로 바꾸고 싶은 점:
```

실제 사용 PC에서 작은 가상 예제로 확인한 뒤 업무에 적용하세요. 조직의 권한·보안 설정에 따라 사용할 수 있는 기능이 다를 수 있습니다.

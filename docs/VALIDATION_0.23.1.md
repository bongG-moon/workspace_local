# 0.23.1 — Download ZIP으로 사내 배포하기

## 변경 내용

- GitHub Code → Download ZIP에 포함된 소스 확인 목록으로 Git 이력 없이 빌드·게시합니다.
- 소스 ZIP에는 EXE·DLL·WebView2 SDK 패키지를 넣지 않습니다. EXE와 VBS 배포본은 사내 빌드 PC에서 생성합니다.
- SDK 상태 확인, 승인된 SDK 파일 선택, 명시적 HTTPS 다운로드를 GUI와 CLI에 추가했습니다. 고정된 버전·해시와 다운로드 경로를 검사합니다.
- 소스 ZIP에서는 Git 소스 반영만 비활성화하고, 기존 Git clone 방식은 유지합니다.
- 소스 누락·변경·추가 파일을 확인하며, 원본과 복사본을 빌드 전후 비교합니다. 확인 목록은 전송 일치 검사이며 서명이 아닙니다.

## 검증 기록

- 게시 도구 결합 검사 105개 중 103개 통과, Windows 심볼릭 링크 권한 관련 2개 생략. GUI 실제 작업 흐름에서 빌드 후 게시 실패, 원본 변경, 재시작, 동일 배포 파일 재게시까지 확인했습니다.
- 이후 소스 파일 읽기 크기를 줄인 변경은 소스 ZIP 검사 15개 중 14개 통과, 심볼릭 링크 권한 관련 1개 생략. 파일이 검사 중 커지는 경우에도 변경을 거부합니다.
- SDK 캐시가 없는 별도 폴더에서 공식 NuGet 다운로드와 승인된 로컬 파일 가져오기를 실제 실행했습니다. 두 경로 모두 고정 버전과 SHA256이 일치했습니다.
- Git archive로 만든 362개 소스 파일의 ZIP을 `.git` 없는 폴더에 풀고 실제 EXE/VBS를 빌드했습니다. Git 함수 호출은 0회였으며 원본 소스 확인값도 유지했습니다. 두 패키지의 공통 앱 파일 125개와 사내 업데이트 설정을 비교했습니다.
- 저장한 빌드 복원 후 모의 GitLab에 파일 4개를 게시하고 인증 없는 다운로드 8회와 해시 일치, 최신 정보의 마지막 게시를 확인했습니다. 실제 사내 GitLab에 게시한 것은 아닙니다.
- 소스 확인을 같은 362개 파일에서 측정했을 때 약 11.5초에서 0.25초로 줄었습니다. 이 PC의 단일 측정값이며 다른 PC의 보장 시간이 아닙니다.
- 공개용 EXE/VBS도 별도로 빌드했습니다. EXE 내장 파일 추출 검증과 공통 앱 파일 124개 일치, 소스 117개·빌드 자산 7개 검사를 통과했습니다. 공개 배포본에는 사내 예제 주소가 들어 있지 않습니다.
- 전체 앱 회귀 1,667개 실행: 1,632개 통과, 선택형·환경 조건 34개 생략, 임시 파일 교체 중 Windows 접근 거부 1개. 해당 작업 대기열 모듈 32개를 같은 사용자 환경에서 다시 실행해 모두 통과했습니다. 최초 접근 거부의 외부 원인은 확정하지 않았습니다. 별도로 실행하는 현재 사용자 실행기 3개도 통과했습니다.

소스 ZIP의 EXE·DLL·SDK 제외 검사는 소스 확인 목록 생성 시 확장자와 파일 형식을 함께 확인합니다. 글꼴·아이콘·이미지와 Python·PowerShell·VBS 같은 원본 코드는 포함됩니다. 회사가 스크립트까지 차단하는 경우의 반입 허용을 보장하지 않습니다.

공개용 VBS ZIP SHA256: `28a0e8831c8d46e9028843b61a08816f19ab60416c5e899e967299672b411075`.

## 현장 확인 범위

사내 GitLab, 인증서, NuGet 또는 사내 SDK 저장소 접속, 메일 반입 정책은 외부에서 확인할 수 없습니다. [단계별 안내](WORKSPACE_GITLAB_PUBLISHER.md)의 현장 검사를 최초 배포 때 진행하세요. SDK가 없고 승인된 다운로드도 불가능하면 SDK 준비 후에 빌드할 수 있습니다.

기존 Workspace 창과 실제 Claude 작업을 시작하거나 종료하지 않으며, 사용자·PC 설정을 바꾸지 않는 범위에서 검증합니다.

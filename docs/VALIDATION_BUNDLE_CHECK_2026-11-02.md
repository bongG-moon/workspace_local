# 0.23.41 사내 배포 검사 수정

## 원인과 재현

공개된 `AX-Workspace-0.23.41-vbs.zip`에 기존 `scripts/test-lab/check-workspace-bundle.py`를 실행하면 다음 오류가 발생한다.

```text
AssertionError: Company-Workspace/local_app/_vendor/__init__.py
```

XLS 지원을 추가하면서 빌더에는 새 판독기와 의존 파일 14개를 넣었지만 독립 검사기의 필수 허용 목록을 함께 갱신하지 않았다. 중복 파일이나 사내 PC의 권한 문제는 아니다.

이전 공개 릴리즈 검증은 같은 빌더에서 만든 EXE와 VBS의 일치를 확인했다. 사내 `Publisher.build()`가 추가로 실행하는 독립 검사기와 목록이 다른 것은 발견하지 못했다. 실제 빌더 목록으로 검사기를 실행하는 기존 테스트도 당시 선택한 회귀 묶음에 포함되지 않았다.

## 변경

- 검사기에 XLS 판독기 14개 경로를 명시적으로 추가했다. `_vendor` 전체를 허용하지 않는다.
- `New-WorkspaceRelease.ps1`도 새 VBS 번들을 만든 직후 같은 검사기를 실행한다. 업데이트 주소와 사용량 주소 설정은 동일하게 전달한다. 누락 또는 실패 시 릴리즈 파일을 생성하기 전에 중단한다.
- 실제 검사기를 실행하는 테스트에 XLS 파일별 누락, 중복, 변조와 미등록 vendor 파일 사례를 추가했다.
- PowerShell 릴리즈 진입점에서 검사기 실패와 누락이 생략되지 않는지, 두 설정 인자가 전달되는지 검증한다.

## 검증 범위

- 기존 공개 VBS ZIP에서 보고된 오류를 재현했다. 수정 후 같은 ZIP은 소스 200개와 빌드 파일 7개를 통과했다.
- `test_workspace_bundle_check`, `test_workspace_release_bundle_gate` 및 관련 게시 도구 회귀 테스트를 실행한다.
- 커밋에서 생성한 소스 ZIP을 별도 폴더에 풀고 실제 `Publisher.build()`를 실행한다. 예시 GitLab 및 사용량 주소, 기존 NSIS 컴파일러와 검증된 SDK 캐시를 사용하며 운영 서버에 게시하지 않는다.
- source manifest, 원격 커밋 및 태그, 소스 ZIP과 체크섬을 확인한다.

수정 파일은 앱 실행 자료에 포함되지 않는 빌드 검사기와 빌드 스크립트, 테스트 및 설명 자료다. 앱 버전은 0.23.41이며 기존 공개 설치 EXE와 업데이트 ZIP은 유지한다. 새 소스 ZIP과 `SHA256SUMS.txt`만 갱신한다. 사내 배포 담당자는 새 소스 ZIP을 새 폴더에 풀어 다시 빌드한다.

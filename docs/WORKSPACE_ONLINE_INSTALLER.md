# 사내 최신 버전 설치 EXE

0.23.26부터 사내 배포 도구는 **`AX-Workspace-Install.exe`**를 함께 만듭니다. 이 파일을 처음 한 번 공유하면, 같은 서버와 프로젝트를 사용하는 동안 사용자들은 같은 파일로 최신 버전을 설치할 수 있습니다.

## 사용자는 이렇게 설치합니다

1. 기존 앱을 사용 중이라면 업무를 마치고 트레이 아이콘의 **완전 종료**를 선택합니다. 사내망에 연결한 상태에서 `AX-Workspace-Install.exe`를 실행합니다.
2. 화면에 표시된 최신 버전과 변경 내용을 확인합니다.
3. **최신 버전 설치**를 누릅니다. 설치 파일을 내려받아 검증한 뒤 설치 화면을 엽니다.
4. 설치를 마치고 시작 메뉴의 **AX Workspace**를 실행합니다.

예를 들어 0.23.26 배포 때 받은 설치 EXE도, 담당자가 다음 버전을 정상 게시하면 그 다음 버전을 설치합니다. 0.23.26을 먼저 설치하고 앱 안에서 다시 업데이트할 필요가 없습니다. 기존에 받은 일반 실행 EXE나 버전별 Setup 파일 자체가 이 방식으로 바뀌는 것은 아니므로, 최초 한 번은 새 `AX-Workspace-Install.exe`를 받아 주세요.

앱 실행에는 기존과 같이 **Python 3.11 이상, 최신 Claude Code 설치·인증**과 Windows 실행 환경이 필요합니다. 설치 EXE를 실행하는 데 Python이나 NSIS 제작 도구가 필요한 것은 아닙니다. 사용자 PC에 새로운 서비스나 자동 시작 항목을 추가하지 않습니다.

## 배포 담당자는 이렇게 준비합니다

1. 0.23.26 이상 소스를 사내 PC로 가져옵니다. 기존에 게시한 버전보다 높은 버전을 사용합니다.
2. `Publish-Workspace.py`로 배포 창을 열고 **HTTPS GitLab 서버 주소, 숫자 Project ID, 게시 토큰**을 입력합니다.
3. 기존 WebView2 SDK와 승인된 **NSIS 3 컴파일러**를 준비합니다. **NSIS 설치 파일 만들기 (권장)**는 켜 둡니다.
4. 변경 내용을 확인하고 **배포하기**를 누릅니다. 사내 주소가 들어간 앱·Setup·최신 설치 EXE를 함께 만들고 다운로드까지 검증합니다.
5. 게시 완료 후 해당 버전 패키지의 **`AX-Workspace-Install.exe`**를 공유합니다. 다음 버전부터는 같은 프로젝트에 새 버전을 게시하면 됩니다.

파일은 `build/publisher/build-<작업번호>/release/` 아래에 생성됩니다. 사내 GitLab의 Package Registry에도 같은 이름으로 게시됩니다. 경로는 다음 형태입니다.

```text
https://<GitLab 서버>/api/v4/projects/<숫자 ID>/packages/generic/company-workspace/<배포 버전>/AX-Workspace-Install.exe
```

처음 공유한 EXE는 실행할 때 고정 채널 `company-workspace-channel/0.0.0/latest.json`을 조회하므로, 다운로드 링크에 처음 배포 버전이 있어도 설치 대상은 최신 채널 버전입니다. 처음 파일을 받는 사람을 위해 그 패키지는 보존하세요. 서버·프로젝트·패키지 경로를 바꾸면 해당 정보가 들어간 EXE를 새로 공유해야 합니다.

**Allow anyone to pull from package registry**와 사내망의 실제 익명 다운로드가 허용되어야 합니다. 앱과 설치 EXE에는 토큰이나 SSH 키를 넣지 않습니다. 별도 로그인 페이지로 이동하거나 인증서 검증에 실패하면 설치를 중단하고 안내합니다. 공개 GitHub의 Setup은 사내 주소를 알 수 없으므로 이 사내 전용 파일을 대신하지 않습니다.

## 파일별 역할

| 파일 | 용도 |
| --- | --- |
| `AX-Workspace-Install.exe` | 실행할 때 최신 정보를 조회하고 그 버전의 Setup을 내려받아 설치 |
| `AX-Workspace-<버전>-Setup.exe` | 파일에 포함된 특정 버전을 설치. 최신 조회 없이 설치 가능 |
| EXE·VBS ZIP | 기존 실행 방식과 앱 내부 업데이트 유지 |
| `SHA256SUMS.txt`, `latest.json` | 다운로드 무결성 확인과 최신 버전 안내 |

최신 설치 EXE는 채널에 연결된 SHA256 목록부터 검증한 뒤 Setup의 SHA256·파일 형식·제품 버전을 확인합니다. 불완전하거나 다른 파일을 실행하지 않으며, 임시 다운로드는 완료·실패·취소 후 정리합니다. 설치 화면이 열린 뒤에는 그 설치 화면에서 취소할 수 있습니다. 네트워크가 끊겼다고 예전 버전을 자동 설치하지 않습니다.

기존 앱 업데이트의 채널 형식은 유지합니다. 새로운 Setup과 최신 설치 EXE를 추가해도 예전 앱은 계속 ZIP으로 업데이트합니다. Package Registry에 파일을 모두 올리고 익명 다운로드를 확인한 다음에만 최신 채널을 바꿉니다.

# 0.23.3 — 사내 빌드의 파일 공유 충돌 보완

## 확인한 원인과 변경

사내 `standalone` 빌드에서 Windows PowerShell `Compress-Archive`가 `input-keys.js`를 열지 못한 로그가 보고됐습니다. 이 PC의 Windows PowerShell Archive 1.0.1.0은 입력 파일을 읽기 접근으로 열지만 공유하지 않는 `File.Open(path, Open, Read)`를 사용합니다. 따라서 다른 프로그램이 읽기만 하고 있어도 충돌할 수 있습니다. 사용자 PC에서 점유한 프로그램은 확인되지 않았습니다.

- 기존 Python 표준 라이브러리로 ZIP을 만듭니다. Windows 파일 읽기에 공유 읽기·쓰기·삭제를 허용하되, 기존 독점 잠금을 깨거나 파일 접근 권한을 바꾸지 않습니다.
- Windows 공유·잠금 오류 32/33만 최대 4회 재시도합니다. 권한 거부 5 등 다른 오류는 재시도하지 않고 안내합니다.
- 파일별 크기·SHA256, 전체 파일 목록과 원본 변경 여부를 확인하고 ZIP을 다시 읽어 CRC·크기·SHA256을 검증합니다. 원본이나 ZIP의 누락·추가·변조를 성공으로 처리하지 않습니다.
- 검증한 임시 ZIP을 기존 출력을 덮어쓰지 않는 방식으로 완료 처리합니다. 실패 시 이번 실행이 만든 임시 파일만 정리하고, 정리도 실패하면 최초 오류와 함께 안내합니다.
- EXE에 검증된 앱 ZIP을 그대로 내장합니다. 중간 압축 해제·재압축을 없애고 기존 EXE 내장 파일 추출 검증은 유지합니다.
- Python이나 추가 압축 프로그램을 설치하지 않습니다. 기존 PC 보안 정책, 인증서, Claude 인증·개인 설정과 게시 토큰 설정을 변경하지 않습니다.

## 검증 기록

- 최종 압축·시작 진단·릴리스 기록·GitLab 업데이트 검사 73개: 71개 통과, 환경 조건 2개 생략. 이 중 새 압축 검사는 19개로 18개 통과, 심볼릭 링크 생성 권한 1개 생략입니다. 실제 Windows junction 거부 검사는 통과했습니다.
- 게시 코어·EXE 실행기 회귀 검사 53개 모두 통과했습니다.
- 같은 `input-keys.js`에 공유 읽기 핸들을 유지한 상태에서 기존 `Compress-Archive` 실패와 새 ZIP 생성 성공을 비교했습니다. 실제 독점 잠금 해제 후 재시도 성공, 지속 잠금의 제한된 실패, 권한 거부 즉시 중단도 확인했습니다.
- 읽기 전용 속성 보존, 260자 초과 한글 경로, 스트리밍 읽기 상한, 기존 출력과 경합 출력 보존, 소스·ZIP 내용 변조와 추가·누락 거부를 확인했습니다.
- Windows에서 경로와 열린 핸들의 실행 권한·생성 시각 보고가 다른 경우를 보정하고 EXE 파일을 포함한 검사를 통과했습니다.
- 실제 공개용 EXE 내장 파일 추출 검증과 VBS 공통 앱 파일 124개 일치, 소스 117개·고정 빌드 자산 7개 검사를 통과했습니다.
- 새 ZIP은 `Company-Workspace/...` 하위 경로를 유지하며 루트 폴더만 있는 항목을 추가하지 않습니다. 실제 공개용 ZIP을 기존 앱 업데이트 검사기로 검사해 통과했습니다.
- `.git` 없는 소스 ZIP에서도 실제 EXE/VBS를 생성하고 공통 파일 125개와 사내 설정을 검증했습니다. 원본 소스 확인값 유지, Git 호출 0회, 모의 게시 오류 후 동일 파일 재시도, 인증 없는 다운로드와 최신 정보 검증을 확인했습니다.

공개용 VBS ZIP SHA256: `fa37e054fb8f68ef21ed9a5663a7deb94b2e7d39fc1241b169c3c3a122aca229`.

## 현장 확인

로컬 검증은 Windows/Python 3.13에서 수행했습니다. 소스는 기존 Python 3.11 이상을 대상으로 하며 사내 PC의 3.11.5, 보안 프로그램과 파일 시스템 조합에서 실제 빌드를 다시 확인해야 합니다. 실제 독점 잠금이 계속 유지되는 파일은 읽을 수 없으며 대상 파일과 오류를 안내하고 중단합니다. 파일을 건너뛰거나 보안 설정을 해제해 완료시키지 않습니다.

0.23.3 **소스 ZIP**을 새 폴더에 풀고 `Publish-Workspace.py`를 실행하세요. 이전 폴더의 `build/desktop-sdk/` 파일을 선택하면 SDK를 다시 다운로드하지 않아도 됩니다. [사내 배포 가이드](WORKSPACE_GITLAB_PUBLISHER.md)

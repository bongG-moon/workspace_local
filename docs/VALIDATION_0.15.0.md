# Company Workspace 0.15.0 검증 기록

기준일: 2026-09-30. 일반 Claude Code 중심의 실행·설치 조회, 공통 목록의 연결 정보 복구, 최근 업무 정렬, 자동완성과 승인 모드의 연결 준비 경합을 대상으로 합니다. Company Agent 전용 관리 기능 제거는 앱의 런타임·배포 범위 변경이며 사용자의 기존 플러그인을 삭제하는 작업이 아닙니다.

코드 회귀, 포인터 드래그를 포함한 화면 검사, 0.15.0 빌드와 실제 EXE의 기존 Claude 연결 초기화를 확인했습니다. **공개 게시·익명 다운로드와 회사 운영 PC의 실행은 아직 확인하지 않았습니다.** 아래 실제 연결 검사는 AI 업무 요청 없이 초기화까지만 진행했습니다.

전체 회귀 보고서는 검증 작업공간의 `build/qa-workspace-0.15.0-tests.json`에 보관합니다. 조건부 생략은 필요한 외부 환경·사용자 권한·명시적 네이티브 실행 조건을 갖추지 않은 검사이며 성공으로 합산하지 않습니다. 전체 회귀 이후의 포인터 드래그 보완은 최종 영향 범위 143개와 브라우저에서 확인했습니다. 확대 검사 69개와 별도 현재 사용자 검사는 다른 검사와 겹칠 수 있으므로 수를 단순 합산하지 않습니다. 화면 기록은 `build/qa-workspace-0.15.0-browser.json`에 보관합니다.

화면의 도구·서버·명령 숫자와 모드 적용은 격리된 가상 CLI 근거입니다. 실제 Claude 모델 업무나 회사 MCP에 대한 요청 성공을 뜻하지 않습니다. 설정 선택이나 자동완성 준비만으로 업무 요청이 전송되지 않는 경계를 확인합니다.

## 변경과 보존 범위

- **일반 Claude 조회:** 공통 설치 스킬과 선택한 업무 연결의 도구·MCP·명령을 분리합니다. 목록 조회는 새 Claude 실행·업무 전환·폴더 신뢰 부여가 아니며 서로 다른 폴더나 세션의 목록을 합치지 않습니다.
- **하네스 전용 관리 제거:** Company Agent의 학습·기억 관리·등록 연동을 이번 앱 런타임과 배포에서 제외합니다. 기존 Claude 설정에서 발견되는 플러그인은 일반 플러그인으로 조회하며 사용자 설치·개인 데이터는 제거하지 않습니다.
- **최근 업무 정렬:** 같은 고정 그룹 안에서 순서를 변경하고 앱 상태에 저장합니다. 업무 내용·실행 폴더·개인 Claude 설정을 이동하거나 바꾸지 않습니다.
- **연결 준비 공유:** `/` 자동완성과 Shift+Tab이 겹칠 때 같은 업무의 연결 준비를 공유하고, 다른 업무로 바뀐 뒤 도착한 응답을 새 화면에 적용하지 않습니다.
- **기존 호환성:** Company-Workspace 실행 이름과 `%LOCALAPPDATA%\CompanyAgent\local-ui`, `%LOCALAPPDATA%\CompanyAgent\workspace-runtime` 경로를 유지합니다. 이 이름이 전용 하네스의 필수 설치를 의미하지 않습니다.

모델·Effort·승인 모드는 기존 CLI의 실제 제공값과 적용 응답을 따릅니다. 앱이 개인 설정을 일괄 덮어쓰지 않으며, 사용자가 승인 카드에서 명시적으로 선택한 지속 허용 규칙은 기존과 같이 해당 CLI 저장 범위로 전달합니다. 실제 실행 전후 비교한 설정 파일 5개의 해시는 같았고 변경은 0건이었습니다.

EXE와 VBS 모두 외부에 이미 설치된 Python 3.11 이상을 사용하며 Python 실행 환경·설치 프로그램을 포함하거나 다운로드·자동 설치하지 않습니다. 실제 EXE 검사에서는 기존 Python을 자동 발견했고 별도 Python 경로를 지정하지 않았습니다. 기존 Claude 인증에 대한 연결 초기화까지 확인했으며 실제 모델 업무 요청·회사 MCP 작업은 보내지 않았습니다. 회사 운영 PC나 실제 VBS 더블클릭의 성공을 뜻하지 않습니다.

실행·초기화·종료 결과는 `build/qa-standalone-0.15.0-public/startup-result.json`, `prepare-result.json`, `finish-result.json`에 보관합니다. 공개 문서에는 인증 값·개인 계정 경로·대화 원문을 포함하지 않습니다.

# 0.21.1 시작·복구·예약 안정성 검증

검증일: 2026-10-01. Windows 개발 PC에서 실제 앱 화면과 격리된 테스트 상태를 사용했습니다. 기존 계정·Windows 보안 설정·개인 Claude 설정을 유지했습니다.

## 수정 내용

- 첫 실행의 화면 파일 로딩: Python HTTP 서버의 연결 대기 한도를 5에서 64로 지정했습니다. 네이티브 창 초기화와 HTTP 처리 시작 사이에 몰리는 연결을 수용하며, 로컬 주소 제한과 기존 창 시작 순서는 유지합니다.
- 화면 준비와 복구: 주요 화면 모듈과 버튼 준비 상태를 확인하고 실패 시 안내합니다. 사용자가 복구를 누르면 같은 탭의 업무·초안·첨부를 복원합니다. 로딩 중 새 입력과 명시적으로 비운 초안을 우선하며, 업무 요청이나 승인을 자동 재전송하지 않습니다.
- 진단: 화면 준비·모듈 오류·WebView 상태를 크기와 빈도가 제한된 코드로 기록합니다. 대화·초안·파일 경로·인증 토큰·오류 원문은 기록하지 않습니다. 네이티브 IPC 수신은 디스크 기록을 기다리지 않습니다.
- 사용 안내: 정확한 같은 서버의 `/manual/guide` 경로를 기본 브라우저로 엽니다. 다른 경로·포트·쿼리·인증 정보가 포함된 주소는 허용하지 않습니다.
- 표 복사: Markdown 표는 렌더링된 텍스트 기준으로 복사합니다. CSV에 원래 들어 있는 기호는 바꾸지 않습니다.
- 예약: 재시작 후 폴더 확인과 이어 실행을 연결하고, 완료된 일회성 예약의 미래 수정은 다시 활성화합니다. 사용자가 직접 정지한 상태는 유지합니다. 동시 연결 한도에 걸린 예약은 전송 확정 전에 대기하며, 같은 업무의 수동 연결과 예약 전송 경합을 차단합니다.

## 실제 앱 시작 비교

새 WebView 프로필마다 별도 상태를 만들고 실제 로그인 사용자로 실행했습니다.

| 조건 | 전체 화면 준비 | 결과 |
| --- | --- | --- |
| 기존 대기 한도 5 | 4회 중 2회 | 일부 JS 요청이 서버 처리기에 도달하지 않음. 받은 응답은 전부 200 |
| 비교용 대기 한도 64 | 4회 중 4회 | 매회 정적 파일 요청 26개 성공 |
| 수정된 제품 기본값 64 | 8회 중 8회 | 208개 정적 요청 전부 200, 모듈·네이티브 오류 0 |

제품 기본값 검사는 강제 대기값 없이 상속된 64를 확인했습니다. 화면 준비는 115–571ms였고 만든 창은 모두 종료했습니다. 샌드박스 계정에서 WebView 자식 프로세스가 시작 전에 실패한 선행 실험은 이 비교에서 제외했습니다. 이 결과를 모든 운영 PC의 시작 시간이나 성공 보장으로 일반화하지 않습니다.

재현 도구:

```powershell
python -B scripts/test-lab/check-native-startup-assets.py --native --trials 4 --backlog 5 --compare-backlog
python -B scripts/test-lab/check-native-startup-assets.py --native --trials 8 --backlog production
```

## Computer Use로 확인한 기능

- 실제 Claude 연결 초기화, CLI가 제공한 모델·effort 목록, 클릭 및 `/effort medium` 변경 후 idle 유지와 사용자 메시지 0개
- `/eff` 자동완성·Tab 선택, `@pre` 파일 선택과 첨부 표시
- 테스트 PNG, CSV 표, Python 문법 색상과 접기, Markdown 표 복사 후 붙여넣기
- 실제 연결의 스킬 49개·서버 9개·명령 141개 표시와 공통/폴더별 전환. 도구 목록 미제공은 0개와 구별
- Ctrl+K 명령 팔레트, 알림함, 좌우 패널 접기, 도움말, 새 업무의 기존 세션 팝업
- 화면 파일 실패를 주입한 후 동일 창에서 명시적 복구와 업무·초안·첨부 복원

개수는 이번 PC의 연결 보고값입니다. 서버 목록 표시를 서버별 실제 도구 실행 성공으로 간주하지 않았습니다. 개인 설정 5개 파일의 해시가 동일했습니다.

## 검증 한계

- Chrome의 사용 안내 창 호출·제목은 확인했지만 Computer Use가 현재 주소를 확인하지 못해 Chrome 본문 조작은 완료하지 못했습니다. 같은 안내 본문은 별도 내장 브라우저에서 확인했습니다.
- 이번에는 실제 AI 예약 요청이나 여러 날짜에 걸친 반복 실행을 다시 수행하지 않았습니다. 예약 결함 수정은 실제 컨트롤러와 기록용 가짜 CLI·가상 시각을 사용하는 재현 검사로 확인합니다. 이전 실제 AI 예약 결과는 [0.20.1 예약 검증](VALIDATION_0.20.1_SCHEDULING.md)에 별도로 남아 있습니다.
- 탐색기 drag-and-drop, 파일 선택기, 승인 모드 Shift+Tab, 알림 토스트 클릭, 개인 세션 가져오기 후 실제 대화 재개 전체 흐름은 이번 Computer Use 범위에 포함하지 않았습니다.
- PC 절전·완전 종료 중 예약 실행이나 PC 깨우기는 지원하지 않습니다. 전송 여부가 불확실한 요청을 임의로 재실행하지 않습니다.

## 자동 검사

- 변경에 관련된 25개 모듈: **486개 실행, 484개 통과, 심볼릭 링크 생성 권한으로 2개 제외**. 실패·오류·예상 실패·예상하지 못한 성공 0개입니다. 초안 복구·재시도의 새 재현 검사도 포함합니다.
- 버전·진단·실행기 모듈: **61개 실행, 59개 통과, 2개 제외**. 제외는 심볼릭 링크 생성 권한 1개와 별도 선택 실행하는 실제 사용자 토큰 진단 1개입니다. 샌드박스 계정에서 WS-31로 중단된 실행기 3개는 실제 로그인 사용자로 다시 실행해 통과했습니다. 보안 검증을 생략하지 않았습니다.
- 네이티브 사용 안내 경로 정책: 67개 통과. 허용 주소와 토큰이 없는 정확한 목적지를 검사하며 이 정책 검사는 브라우저를 실행하지 않습니다.
- 기존 예약 결함 3개를 예상 실패로 남기지 않고 통과시키며, 폴더 확인 취소·업무 변경·정지 상태·동시 연결·전송 불확실성 경계도 검사합니다.
- 검사 결과 파일은 로컬 `build/dots-ui-release-tests.json`입니다. 실행 상태와 개인 인증 자료는 Git·배포 ZIP에 포함하지 않습니다.

## 최종 EXE와 ZIP

- 최종 `Company-Workspace-0.21.1.exe`를 EXE만 있는 별도 한글 경로에 복사해 실행했습니다. 전용 WebView2 창으로 열렸고 두 번째 실행은 기존 서버 PID와 캐시를 재사용했습니다. 최종 EXE의 화면 준비 기록도 정상이며 화면 파일·네이티브 오류는 0개였습니다.
- PC에 설치된 Python 3.13.5와 Claude Code 2.1.285를 자동 탐지했습니다. Python 런타임·설치 파일·자동 다운로드는 포함하지 않습니다.
- 기존 Claude 인증으로 초기화에 성공했습니다. 모델 `claude-sonnet-5-5`, effort `medium`, 명령 141개를 확인했고 사용자 질문은 보내지 않았습니다.
- 기본 승인 모드·plan·acceptEdits·auto, effort high·기본 복원, 재연결 후 선택 유지의 재검사 8개를 통과했습니다. 개인 설정 변경은 0개이며 테스트 서버와 연결을 정상 종료했습니다.
- VBS ZIP을 별도 폴더에 풀어 포함된 서버 진입점으로 시작·화면 파일·API 권한 경계·테스트 업무·파일 목록·정상 종료를 검사했습니다. 이것은 VBS 아이콘 더블클릭을 Computer Use로 다시 수행했다는 의미는 아닙니다. 공통 실행기 경로는 별도 실행기 검사와 EXE 실행으로 확인했습니다.
- VBS ZIP의 소스 96개와 고정된 네이티브 빌드 파일 7개, 총 103개를 확인했습니다. EXE 내장 파일 103개와 VBS ZIP 파일은 바이트 단위로 일치하며 런타임 상태·개인 인증을 포함하지 않습니다.

### 재연결 검사에서 남은 관찰 사항

첫 제어 검사에서 마지막 빠른 재연결 요청이 한 번 HTTP 400을 반환했습니다. 당시 오류 본문은 최초 검사 도구가 보존하지 않아 원인을 특정하지 못했습니다. 이후 연결은 살아 있었고 선택한 auto·high와 사용자 메시지 0개가 유지됐습니다. 오류 본문을 수집하도록 감싼 같은 검사를 다시 실행했을 때는 8개 단계 모두 통과했고, 앱 이벤트에는 제어 오류가 남아 있지 않았습니다.

최초 실패를 통과로 처리하거나 원인이 수정됐다고 주장하지 않습니다. 일반 시작·기존 인증 초기화와 재검사 성공은 별도로 확인했으며, 빠른 재연결의 해당 간헐적 응답은 추가 재현이 필요한 제한으로 남깁니다.

# Native notification fonts

These static Noto Sans KR faces come from the existing, verified offline font at
`local_app/web/fonts/NotoSansKR-Variable.woff`. They retain its complete character
map: 23,174 code points, including all 11,172 modern Hangul syllables. They are not
a subset of the application's current Korean messages, so task titles can use
characters outside those messages. Characters outside the source font still
need the operating system's font fallback.

| Asset | Actual weight | Legacy family | Font style to request |
| --- | --- | --- | --- |
| `NotoSansKR-Regular.ttf.gz` | 400 | Noto Sans KR | Regular |
| `NotoSansKR-SemiBold.ttf.gz` | 600 | Noto Sans KR SemiBold | Regular |

The second face contains real weight-600 outlines. It must not be requested as
`FontStyle.Bold`, which can cause synthetic emboldening. Separate private font
collections let the native host select the exact family for each face.

The desktop build embeds the compressed font resources. At runtime the host
loads them into process-private GDI+ font collections; it does not install
fonts, write the Windows font registry, or change other applications' fonts.
Normal runtime use needs no fontTools or additional Python packages.

Rebuild offline with fontTools 4.63.0 on the build machine:

```powershell
python -B -X utf8 scripts/test-lab/build-notification-fonts.py
python -B -X utf8 scripts/test-lab/build-notification-fonts.py --check
```

The check recreates both faces in memory and compares every generated byte.
The generator preserves source timestamps, updates static face names and style
metadata, and omits file paths and timestamps from gzip headers. Source and
output hashes are recorded in `SOURCE.json`. The supplied SIL Open Font License
and copyright notice are retained in `OFL.txt` and the font name tables.
